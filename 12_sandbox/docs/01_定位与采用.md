# 定位与采用：免费开放版

**日期**：2026-11-27  
**前提**：这个项目**永久免费、开源、不商业化**。不卖数据、不设付费墙、不做商业授权。  
**问题不是商业化**，而是：**免费放到网上之后，怎么被看见、被用、被引用、被贡献。**

## 0. 一句话

这个项目不收费，也不靠收费活着。模型公司会用（免费）的是「研究级、可验证、有出处、抗污染的任务和判断数据」。所以目标不是收入，是**成为中文研究级数学形式化的公共基础设施**：有人用最好，没人用也是一份可检索、可训练的语料。

## 1. 免费公开的采用链：四可

免费不等于会被看见。一个公开项目要被用起来，至少要过四关：

1. **可发现**：在 GitHub / HuggingFace / arXiv 上，有英文 README、有标签、有数据集卡片；不是只在一个中文静态站里。
2. **可复现**：陌生人 clone 后一条命令跑通；Docker + 钉死 Lean/mathlib；CI 绿灯；版本号可引用。
3. **可引用**：有 DOI（Zenodo/HF）、有技术报告、有版本（v0.1/v0.2）；别人写论文能引。
4. **可贡献**：schema 清楚、issue 模板、PR 流程；不需要许可，也不需要付费。

这四关里，**可复现是第一道硬门槛**。现在仓库缺 `lakefile` / `lean-toolchain` / `lake-manifest`，`make verify-all` 在干净机器上跑不起来——这比任何 API 都优先。

## 2. 谁会用，怎么用（免费）

| 使用者 | 他们会怎么用 | 我们需要做什么 |
|---|---|---|
| 大模型公司（评测/RL） | 拿研究级任务做 eval 或 RL 环境；拿判断数据做 reward model | 300+ 题、private held-out、判分脚本、抗污染说明 |
| 大模型公司（语料） | 中文高级数学的 SFT/继续预训练 | clean-room 导出、license map、英文 datasheet |
| 研究者（形式化/autoformalization） | 对比 baseline、做 faithfulness 研究 | 论文、基线表、失败 taxonomy、可复现环境 |
| mathlib / Lean 社区 | 找缺口、补定义、做库扩展 | Gap Atlas、页码锚、建议签名、issue 模板 |
| 学生/自学者 | 按依赖图学习、看中英对照、跑一张卡 | 静态站、Lean4Web demo、中文说明 |
| 评测机构 | 收录 benchmark、引用数据 | 公开 leaderboard、版本号、DOI |

关键证据（为什么值得做）：

- **FATE**（ICLR 2026）：最好模型 FATE-H 3/100，FATE-X 零有效证明；38% 的题需要新定义（平均 2.4 个/题）；代数博士生 2.5h 内 73%/21%。说明研究级代数远未饱和，瓶颈是定义。
- **TCSEXAM**（2026-11）：研究级 Lean，GPT-6 Astra 70%、Kimi K3.1 Pro 38.3%，其余个位数/零；给中间引理提示后 Kimi 3→7、DeepSeek 0→6。说明「提示/课程」有效，模型缺「自己找中间引理」。
- **FrontierMath T4**：2026-09 被 GPT-6 Astra 刷到 97.6%，Epoch 宣布饱和；miniF2F 已被 Leanstral 1.5 打到 100%。说明「又一个 proof benchmark」窗口很短。
- **OpenReward**：330+ RL 环境、450 万任务、ORS 协议；NVIDIA/Nemotron-Math-Proofs、OpenAI Math 369 已在上面。说明环境层已被平台化，我们不该自建基础设施，应该把内容做成别人能接的形状。
- **ProofGate / The Faithfulness Gap**：typecheck ≠ 忠实；他们缺研究级 ground truth。这正是我们有、别人没有的。

## 3. 三种公开物（都免费）

### A. Gap Atlas（mathlib 缺口地图）— 最便宜、最独特

- **内容**：每条 gap = 缺失定义/定理 + 页码锚 + 依赖 + 建议签名 + 为什么 mathlib 没有 + 难度。
- **用户**：mathlib 社区、形式化团队、想训练「库扩展」的 lab。
- **价值**：FATE-X 38% 需要新定义，说明「定义缺口」是 scaling 的瓶颈；系统化的缺口地图目前没人做。
- **成本**：低。现有 19 条 gap + 67 张 nLab DAG + 154 张 GLC 卡就能起。
- **形态**：静态站（可浏览、可搜索、可引用），数据放 HF，代码放 GitHub。

### B. Judgment Dataset（形式化判断数据）— 最像护城河

- **内容**：每条 = 中文/英文陈述 + 出处 + 候选 Lean 形式化 + 判定（忠实 / 弱化 / 错误 / 缺口）+ 理由 + 缺失定义。
- **用户**：做 autoformalization / reward model / faithfulness 的 lab；他们缺研究级 ground truth。
- **价值**：判断数据是 RL reward model 的原料，比 proof 数据稀缺；而且它直接对应「模型是不是在胡说」这个痛点。
- **成本**：中。需要生成候选 + 人审；现有 40 卡 + 100 张审计 + 1,676 卡是种子。
- **形态**：HF dataset + datasheet；附一份「怎么用这份数据训练 judge」的说明。

### C. 窄口 Research Benchmark（几何朗兰兹 / 中文）— 最像论文

- **内容**：100–300 条研究级陈述，分 full / skeleton / gap；公开 leaderboard；private held-out。
- **用户**：Epoch/Vals 类评测、lab 的内部 eval、论文引用。
- **价值**：FATE/TCSEXAM 证明研究级是前沿；中文/几何朗兰兹是空位；页码锚提供抗污染故事。
- **成本**：高。每条要形式化 + 人审；6–12 个月。
- **风险**：FATE/TCSEXAM 已占位；小 benchmark 容易被忽略；饱和快。

**推荐顺序**：A（1–2 个月）→ B（3–6 个月）→ C（6–12 个月）。沙盒 API 不是产品，是 demo；用 Lean4Web / HF Spaces / OpenReward 托管，不自建集群。

## 4. 竞争地图：别做什么

- **通用 proof benchmark**：miniF2F（饱和）、ProofNet、PutnamBench、FATE、TCSEXAM、FrontierMath（T4 饱和）、ProofBench。→ 不做「又一个 miniF2F」。
- **环境/基础设施**：OpenReward、Harmonic Aristotle、Lean4Web、Prove2Me、miniCTX-v2、LeanExplore。→ 不自建 Docker/API 集群。
- **拼体量数据**：Lean Workbook（14 万题）、Formal Math Autoformalization（2,926 对）、AutoMathText-V2（2.46T）。→ 不拼体量。
- **中文 K-12/奥赛**：CMM-Math、OlymMATH。→ 不重复。

空位：**研究级 × 中文/双语 × 页码锚 × 判断（不是证明）**。这四个条件的交集，目前没人占。

## 5. 对 v0.1 报告的七条修正

1. **影子 vs 真定理**：把 certified 拆成 `certified-full`（真陈述、无额外公理）和 `certified-shadow`（特殊/离散情形）。Headline 只用 full；shadow 放 D1 热身。否则「研究级」名不副实，KPI 还会激励继续造影子。
2. **难度模型**：依赖闭包数是循环论证（它衡量你形式化了多少，不是题有多难）。改用：缺口数、专家时间（FATE 用 2.5h）、博士基线正确率、与 mathlib 最近邻距离、证明长度。先对 40 卡做 3–5 位博士的计时基线，这就是一篇短文。
3. **防作弊**：只禁 axiom/sorry 不够。要防「弱化陈述/空泛/改量词/加假设」。Harness 固定 statement 文件（hash），只允许改 proof 文件；检查 `#print axioms`、`False`/空类型、statement 等价性；用 ProofGate 式审计做抽检。
4. **KPI**：不是「外部调用次数」（早期不可测），也不是商业收入。用采用信号：HF downloads、引用、fork/PR、leaderboard 提交、被别的 benchmark 收录、外部合作邀约。内部 KPI：它是否让你自己读/写/形式化更快。
5. **法律隔离**：译文是演绎作品，不能商业授权。做 clean-room 导出：只留「事实性陈述 + 页码锚 + Lean + 自写注记 + 术语」，去掉译文段落。发布物带 license map；明确「哪些能商用、哪些不能」——虽然项目免费，但别人用的时候要清楚边界。
6. **单人瓶颈**：设计成 versioned release（论文 + 静态数据集 + 年度版本），不是 live service。找 3–5 个合作者（mathlib、中文数学 PhD、benchmark 人）再冲 300；否则 12 个月后无人维护。
7. **竞争与饱和**：报告没有竞争地图。补上 FATE/TCSEXAM/ProofBench/FrontierMath/OpenReward/Harmonic；设计 private held-out + 年度 refresh；不要做「又一个 miniF2F」。

## 6. 维护：免费项目怎么活得久

- **版本化发布**：v0.1（40 卡 preview）→ v0.2（100 卡）→ v1.0（300 卡 + benchmark）。每个版本有 DOI、有 changelog、有兼容性说明。
- **社区**：issue/PR 模板；把「补一条 gap」「修一个 proof」「加一个 baseline」做成低门槛任务；公开致谢。
- **托管**：GitHub + HuggingFace + Zenodo；不自己养服务器。API 用 HF Spaces / Lean4Web / OpenReward。
- **免费**：不接受付费墙、不接受「专家服务」包装、不把知识锁起来。可以接受机构托管/镜像，但不改变免费属性。
- **可持续**：靠合作者、靠引用、靠生态位；不靠商业收入。
