# 数译沙盒 · 顶层设计报告（v0.1 草案）

> 定位：本报告是「数译」工程下一阶段的顶层设计。核心立场调整一句话——
> **译文、语料、资料卡、术语规范，全部降格为原料层；终局产物只有一个：一个 AI 可以像解棋局一样反复攻打的、带编译器裁判的中文数学形式化沙盒。**
> 依据：对 atomgit.com/lzxSUSUY/mathtranslate 全仓实测（commit 033747e，2026-11-25），数据见 companion 测评报告。

---

## 0. 终局图景：一个"数学残局库"

把目标说成棋类游戏的比喻，整个系统就是五样东西：

| 棋类隐喻 | 本系统对应物 | 已有资产 | 缺口 |
|---|---|---|---|
| **棋盘与规则** | 钉死的 Lean 4 + mathlib 环境（走子规则唯一合法来源） | leanstmt 已钉 Lean 4.36.0 + mathlib commit | 环境绑在作者 Windows 本机路径，第三方无法复跑 |
| **残局库** | 页码锚定的中文数学陈述 + 形式化命题 + 依赖关系（每一局就是一个"残局"） | 1,446 张资料卡（页码锚）+ 39 条对齐卡 | 卡未升级为可对局的任务；39 条太少；无依赖图 |
| **棋谱** | 证明项 / tactic 脚本（对局记录） | verification.jsonl 逐文件 exit code | 只有"已解局"，无对局接口 |
| **裁判** | 编译器：0 error + sorry=0 = 胜；typed hole = 可续局面 | 已跑通（certified/gap 双轨） | 无自动判分 API，靠手跑 |
| **段位** | 难度分级（依赖深度 × mathlib 覆盖 × 陈述长度） | 卡有 track/scope 字段 | 无统一难度模型 |

**一句话定义沙盒**：给定一个中文数学陈述（残局），AI 的工作是产出一段 Lean 代码（走子），编译器判定胜负（裁判），产出的证明项进入棋谱库供复用（学习），难度由依赖图的深度决定（段位）。

这个定义里最关键的一点：**沙盒的价值不依赖"几何朗兰兹主线被完整形式化"这个不可能短期实现的目标**。残局库里同时容纳三种局面：
1. **终局**（certified）：编译器证明完毕、无 sorry——如 $\mathrm{SU}(N)$ 中心的 $\mathbb{Z}_N$ 计算；
2. **中局**（skeleton）：代数/组合骨架已证，几何前提以公理/类型类形式"封存"——如 Hitchin 系统的维数账；
3. **死局标注**（gap card）：明示 mathlib 缺口，缺口清单本身就是任务列表。

AI 沙盒在三种局面上都能产生训练信号：终局教"怎么走"，中局教"怎么在约束下推理"，死局教"知道自己不会什么"。

## 1. 目标函数与不做什么

### 1.1 北极星指标（唯一 KPI）

> **certified 残局数 × 可复现率 × 被外部调用次数**

- certified 残局数：`lake env lean` 0 error 且 sorry=0 的、带页码锚的中文陈述条数（现在 21，2027-Q2 目标 500）
- 可复现率：第三方在 README 给出的命令下一次性复跑成功的比例（必须 = 100%，做不到就不发布）
- 被外部调用次数：沙盒 API / 数据集被外部项目（评测、训练、检索）实际使用的次数

**退役指标**：页数、部数、卡数、token 产出量。这些是原料库存，不是产出。仓库现有 `ASSESSMENT_产出作用.md` 的审计口径已经悟到了这一点，沙盒阶段把它变成常态制度。

### 1.2 明确不做的事（负空间，比做什么更重要）

1. **不做全量形式化**。Gaitsgory–Raskin 证明数千页、建立在 ∞-范畴与 IndCoh 之上，mathlib 十年内追不上。主线证明只做**骨架封存**（见 §3.2 中局策略），把人力砸在数学结构可判定的部分。
2. **不再新增译书产能**。138 部已够当原料，继续译书是库存膨胀不是价值增长（边际价值递减，作者自己的审计也承认）。
3. **不让沙盒依赖任何未核验卡**。published 66 张之外的字段一律不许进残局定义。
4. **不绕过编译器造"软验证"**。LLM 自评、回译相似度可以当辅助信号，但 `verification.status` 只认编译器。

## 2. 总体架构：五层一闸门

```
L4 对局层   沙盒 API · 评测任务生成器 · 模型段位榜          ← 对外交付物
L3 环境层   Docker/Nix 钉死环境 · 编译服务 · 判分 harness    ← 沙盒地基
L2 形式层   残局库（certified / skeleton / gap 三轨）        ← 核心资产
L1 陈述层   页码锚定中文陈述库（从资料卡升级而来）            ← 桥梁
L0 原料层   语料 · 术语规范 · 轨迹 · 既有卡                  ← 已建成
              ↑ 每层入口有闸门（机器可校验），闸门即 CI
```

### 2.1 L0 原料层（已建成，只做两件修缮）

现状合格：5.1 万段语料 / 417 万汉字 / 86% 含公式 / QA flags 完整 / 术语 2,214 条 / 数语规范 v1.0 有 `--check` 闸门。

修缮项（两周内）：
- **M0.1** 展开 harvest 队列里"未展开宏"段落（`\R`→`\mathbb{R}` 类机械映射脚本化 + 5% 抽样人审）——这一步不解锁，下游陈述层检索会持续被污染。
- **M0.2** 数语规范 `--check` 从提交闸门升级为 CI 必经步骤（AtomGit Pipeline 已有 pages.yml，加一个 job 即可）。

### 2.2 L1 陈述层（新 built，3 个月）

**这是从"语料"到"残局"的翻译器**。每条陈述一条记录：

```jsonc
{
  "id": "stmt/SY02-10/p14/thm-mellin-betti",
  "nl_zh": "（去心直线上的）Betti 梅林变换给出局部系统范畴与
            拟凝聚层范畴的等价 Loc(C×_z) ≃ QCoh(C×_t)",
  "nl_en": "The Betti Mellin transform gives an equivalence ...",
  "anchor": {"paper": "arXiv:2605.23167v1", "page": [8, 9], "display": "§1.3.2"},
  "kind": "theorem",            // definition | theorem | lemma | example
  "deps": ["stmt/SY02-10/p12/def-local-system"],
  "terms": ["term/梅林变换", "term/局部系统"],   // 必须可解析到数语规范 ID
  "cards": ["glc/concept/affine-grassmannian"],  // 关联资料卡
  "formalizable": "full | skeleton | gap | out-of-reach",
  "status": "draft | aligned | certified"
}
```

设计要点：
- **陈述与证明分离**。陈述层只管"命题是什么"，不管"怎么证"。一句中文陈述先做成 `aligned`（与原文页码互证），再进 L2 形式化。这拆掉了现在"造卡慢"的瓶颈：陈述层可流水线生产（每工程 30–80 条），形式化按需挑选。
- **deps 字段构成依赖 DAG**——这就是"残局的难度来源"。一条陈述的段位 = 其依赖闭包中 full 级陈述的数量。
- **formalizable 四档**由人工+LLM 初判、人工终裁，判定依据写进 `reason`（如"依赖 IndCoh"→gap，"线性代数骨架"→full）。
- 生产管线：从已有 1,446 张卡的 `key_points/theorems` 字段批量抽取候选 → 人工裁决 → 自动校验（术语 ID 可解析、页码存在、DAG 无环）。**目标 2027-Q2：5,000 条陈述，其中 800 条 formalizable=full。**

### 2.3 L2 形式层（残局库，持续建设）

三轨并行的形式化策略——这是整个设计里最重要的取舍：

**轨 A：full（终局）**。mathlib 可达的陈述，完整证明。
- 优先级排序：`GL₁ 几何类域论与梅林变换族`（现有 leanstmt 已覆盖一批）→ `GNO 电磁对偶代数骨架`（G06 已有）→ `一般 Satake 的组合层`（权格、支配权、余根数据）。
- 这条轨的标准动作：陈述层选品 → Lean 建模（定义选择须登记进数语规范，"一中文概念一 Lean 定义"）→ `lake env lean` 闸门 → 双盲回译（把证明项反译回中文，与原陈述比对，第二 reviewer 引入）→ certified。

**轨 B：skeleton（中局）**。超出 mathlib 但结构可分解的定理，把不可形式化的几何/范畴前提**显式公理化**：
```lean
/-- Hitchin 系统的谱曲线前提，以公理封存（对照 arXiv:2605.23167 §4.1）-*/
axiom hitchin_spectral_curve (E : VectorBundle …) : …
```
- 硬约束：每条 axiom 必须带页码锚与"应被未来 mathlib 替换"的 `todo_ref`；公理数量计入残局难度（公理越多段位越低）。
- 价值：中局残局教模型的是**在承认未知前提下的严密推理**——这是现在所有数学 RL 环境都缺的东西。

**轨 C：gap（死局标注）**。现有 18 条 gap 卡的做法制度化：typed hole（`sorry` 带缺口类型标签：缺定义/缺引理/缺假设）+ 缺口清单作为独立交付物。**gap 卡直接就是沙盒的任务生成器**：每条缺口 = 一道"补步题"。

### 2.4 L3 环境层（沙盒地基，1 个月内必须建成——最高优先级）

现状是最脆弱的一环：验证环境钉在 `C:\Users\admin\Desktop\数译发布\shuyi\formal`。改造方案：

```
sandbox/
  Dockerfile          # leanprover/lean4:v4.36.0 + mathlib d33c49ca + ShuyiFormal
  lakefile.lean       # require mathlib 固定 rev
  api/server.py       # POST /compile {file} → {exit, errors, sorry_count, elapsed}
                      # POST /judge   {stmt_id, candidate} → {win | fail | gap_hit}
                      # GET  /endgame/random?tier=full&depth≤3
  harness/eval.py     # pass@k、 Elo 记分、防作弊检查（禁 axiom 绕过 / sorry）
  Makefile            # make verify-all 一键复跑全库验证
```

- **make verify-all 必须在 CI 里跑**：verification.jsonl 每次提交全量重算，杜绝"纸面 certified"。
- 编译服务加资源上限（超时 120s / 内存 4G）与缓存（同文件 hash 直接回缓存）。
- 这一层是纯工程，成本极低（一台常驻容器 + GitHub Actions/AtomGit Pipeline），但它是沙盒化与否的分水岭。**建议作为作者的下一次发版（v1.1）的核心交付物。**

### 2.5 L4 对局层（沙盒玩法，3–6 个月）

四种"玩法"，按难度递进——每种玩法 = 一个任务模板 + 一个判分函数：

| 玩法 | 输入 | AI 任务 | 胜负判定 | 对应棋类隐喻 |
|---|---|---|---|---|
| **P1 复谱** | 中文陈述 + 依赖闭包里已证的引理 | 复现已有 Lean 证明 | 证明项等价（compile + 摘要比对） | 打谱 |
| **P2 补步** | 中局局面：skeleton 定理 + 1 个 typed hole | 补出该 hole 的证明 | 编译器 0 error | 解残局 |
| **P3 对译** | 仅中文陈述（不给引理提示，但给术语表与规范） | 从零写出完整 Lean | 编译器 | 盲棋 |
| **P4 出题** | 一页原文 | 找出该页所有可形式化陈述并形式化 | 抽样人审 + 编译器 | 让 AI 自己摆棋 |

- **防作弊是判分函数的一部分**：候选代码不得引入新 axiom、不得 `sorry`、`#print axioms` 输出必须 ⊆ 白名单（Thunderbird 之外只许 mathlib 标准公理 + 显式登记的 skeleton 公理）。
- **段位榜**：按依赖深度分 D1–D5；模型在每档 pass@k 入榜。榜单从第一版就公开——哪怕上面只有 3 个基线模型，"公开被衡量"本身就是资产。
- 任务打包发布：HuggingFace `shuyi-endgames`（自产层 CC BY 4.0，无版权风险——陈述是数学事实，形式化是自产）。

## 3. 主线图谱：几何朗兰兹怎么进沙盒

对"把几何朗兰兹纲领主线证明做成沙盒"这个具体诉求，给出可执行的分解。原则：**沿主线做"可判定切片"，不做整体形式化**。

```
主线依赖图（DAG 顶层设计，节点=陈述层条目，标注 formalizable 档位）

GL₁ 几何类域论（D1, full）────────────┐
  ├─ 梅林变换三版（Betti/de Rham/D-模） │
  ├─ Bun_G 定义与 Hecke 算子（D2, full）│
  │    └─ Hecke 特征层性质（D3, skeleton）│
  ├─ 朗兰兹对偶群 / 根数据（D1, full）──┤
  │    └─ GNO 电磁对偶（D2, full）✅ 已有 G06│
  ├─ 仿射 Grassmannian 组合层（D2, skeleton）│
  │    └─ 几何 Satake 组合骨架（D3, skeleton）│──→ GLC 主陈述
  ├─ 特征簇 Loc_Ğ 定义（D2, full/skeleton） │      （D5, gap→skeleton）
  └─ Hitchin 系统 / Abelianization（D3, gap）┘
```

- **绿色已通段**（GL₁、GNO）：继续滚雪球，这是 certified 数量的主要来源；
- **黄色可封存段**（Satake 组合层、特征簇）：skeleton 策略的用武之地，公理化范畴前提后，权格匹配、支配权计数、参数对应等命题都是可判定残局；
- **红色深水区**（IndCoh、∞-范畴、Hitchin 量子化）：只做 gap 卡，等 mathlib 生态（已有 IndCoh 社区尝试）成熟。
- 每个节点连回陈述层的页码锚（Ben-Zvi 导论 34 页、Fargues 综述 46 页、Gaitsgory 非正式导论……），**沙盒里每一局都能回答"这局棋出自哪本书第几页"**——这是它区别于 miniF2F 类题库的根本特征。

## 4. 治理与可持续性

| 事项 | 设计 |
|---|---|
| 版权 | 沙盒层零风险：陈述=数学事实不受版权保护，Lean 形式化与判分代码是自产（CC BY 4.0）。原料层的图书译文风险隔离在 L0，沙盒发布物不打包 L0 内容 |
| 单人瓶颈 | 分工化：L1 陈述层可流水线外包（裁决权留作者）；L2 按轨招社区贡献（每轨给 CONTRIBUTING + 样例局）；L3/L4 纯工程可交给协作者 |
| 资金 | 沙盒是可讲资助故事的部分：形式化基准在 AI4Math 赛道有明确资助方；现库 2,437 元成本审计本身就是极好的透明度背书 |
| 质量闸门 | 四道机器闸门进 CI：① 数语规范 --check（术语唯一）② 陈述层 DAG 校验（无环/锚存在）③ verify-all（全库重编译）④ 判分防作弊（axiom 白名单） |
| 审计制度 | 沿用现有 ASSESSMENT 模板，季度一次，只考核北极星三指标 |

## 5. 路线图与里程碑

| 阶段 | 时长 | 交付物 | 验收标准 |
|---|---|---|---|
| **P0 复现** | 1 个月 | Docker 环境 + verify-all CI + leanstmt 全量复跑报告 + 陈述层 schema v1 | 第三方 `make verify-all` 一次通过；39 条对齐卡复算结果与 verification.jsonl 一致 |
| **P1 陈述层** | 3 个月 | 5,000 条中文陈述（800 条 full 档）+ 依赖 DAG + 术语 ID 全解析 | 抽样 100 条：页码锚 100% 命中，DAG 无环 |
| **P2 沙盒 API** | +2 个月 | compile/judge API + 三种玩法任务生成器 + 防作弊判分 | API 在 3 个外部模型上跑通；防作弊测试集（含故意 axiom 作弊样本）全部拦截 |
| **P3 基准发布** | +2 个月 | HuggingFace `shuyi-endgames` v1（300 局：200 full 终局 + 80 中局 + 20 补步）+ 首版段位榜 | ≥3 个基线模型有公开分数；≥1 个外部团队复用 |
| **P4 滚雪球** | 持续 | certified 500 局；gap→skeleton 转化率作为 mathlib 生态观测指标 | 季度审计达标 |

**P0 是全局关键路径**——它最便宜、最不依赖任何人，且没有它后面全部是空中楼阁。

## 6. 风险登记

| 风险 | 概率 | 缓解 |
|---|---|---|
| mathlib 覆盖不足，主线大部分停在 gap | 高（已证实） | 三轨设计本身就是对冲：中局与死局都产训练信号；跟踪社区 IndCoh 进展择机升级 |
| 陈述层人工裁决成为新瓶颈 | 中 | 用"LLM 批量草拟 + 作者只做终裁"的流水线（现库 402 条轨迹就是 agent 产能证明）；先做 SY02-10 这类导论文本（陈述密度低、好裁） |
| 单人失联/断更 | 中 | 治理章节的分工设计；数据格式全部文档化（现库 DATASHEET 文化已达标） |
| 沙盒被刷榜/作弊 | 低 | 防作弊判分 + axiom 白名单从第一天内置 |
| 原料层版权事件波及沙盒 | 低 | §4 版权隔离：发布物与 L0 解耦 |

## 7. 结语：这个设计的赌注是什么

现库已经证明了三件事：**口径纪律可复算、判断可带证据留痕、编译器验证可跑通**。这个设计把赌注押在一句话上：

> 中文数学语料不缺产量，缺的是**每一个判断都能被机器裁定对错的那个环境**。谁先把中文数学陈述做成可对局、可判分、可溯源的残局库，谁的语料就从"文本资产"升格为"训练环境资产"。

原料层（译文+语料+卡+术语）它已经建成了 80%，而且质量超出同类一个身位；从陈述层开始的每一层都是新的，但每一层都踩在已有资产上。**第一块砖是把验证环境从一台 Windows 机器里解放出来——建议作者把 v1.1 发版做成"沙盒地基版"。**
