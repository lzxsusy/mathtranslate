## 一句话结论

“每篇文章一个 AI 研讨班”**成立**，但产品不是 dossier 十件套，而是**一篇能让没读过原文的学生从头读到尾的读书笔记**（20–35 页）；评分也不是“再写一段评语”，而是一条**独立、可审计、以 held-out 表现为准的闭环**：L1 机器判定 + L2 盲评 + 人类终审 → playbook 小步修改 → bench 认证 → 才允许进入下一场。

第一次闭环的硬教训：研讨班本体只占 14% 调用，用户读稿 2h17m 是最大人时成本；`quality_gate: self-assessed` 从未真正执行；综合层 `merged.jsonl` 乱码且与 errata 矛盾。**新版的第一优先级不是加角色，而是把闸门变成可执行证据。**

## 下一步（Phase 0，按顺序）

1. 让人类签字 B2–B4 的答案 key（未签字不得用于判定 patch）。
2. 同产物重评 5 次，实测 L2 的 σ；没有 σ 就不要设 2σ 阈值。
3. 建 6 份 anchor（3 优 3 差，含 v1 注疏体与编造样本），校准 L2。
4. 用新 rubric 回测 SEM-9407087，要求命中已知 6 个问题中的 ≥5 个。
5. 哨兵首跑：bad 上浮、good 下低、gap 缩 >20%、σ>5、无证据扣分率>10%、长度相关>0.5、人机分歧>30%。
6. 然后才开 JP11；第一周只让 3 位 Reader 各交一份合格报告，由人类校准“什么叫合格”。

## 关键设计（不要轻易改）

1. **S3 独立研读**：Reader 写报告前不能互看。
2. **证据锚点**：任何实质断言必须有 `[src p.N]` / `[eq x.y]` / `[fig x.y]`；无锚点只能算问题。
3. **三路核对**：文字层定位、页图定符号、译本对表述；公式真值永远是页图。
4. **译者是被告，不是法官**。
5. **质询必须有靶子**，且要统计「驳回正确率」，不能只数 accept。
6. **综合不是拼接**：先论证图，再写成品；结论分级。
7. **质量闸门一票否决**，且必须留执行证据；`self-assessed` 不算通过。
8. **版权三层**：L0 公开、L1 私有、L2 本地。
9. **评分与生产分离**：Mentor 全新上下文、盲评、扣分必须带锚点。
10. **改进只认 held-out**：不认「同一产物重评更高」，不认「只挑好任务汇报」。

## 与既有工程的关系

本工程是「学术翻译总纲」的**下游**：翻译负责“文本可信”，研讨班负责“理解可查 + 可教学”，网站负责“公共可用”。不替代翻译，不重复翻译，不公开全文。
