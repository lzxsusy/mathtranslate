## 0. 这一版要解决什么

### 0.1 用户提出的问题

> 研讨班不仅要研读，还要对表现打分；leader 智能体应该扮演导师；下一次按导师的反馈优化。

这不是一个附加功能，而是对整个工程性质的改变：从「一次性生产」变成「可评价、可迭代的生产」。本版回答三个问题：

1. **工程上可不可行？** —— 可行，但必须把「递归改进」限定在正确的对象上，并给「真的变好」一个统计判据（§2、§7）。
2. **架构长什么样？** —— 生产、评价、改进三个平面，以文件为接口；评分分三轨（机器 / 盲评 / 人类）（§3、§6）。
3. **第一版具体怎么做？** —— 新增 S9/S10、Mentor、L1+L2+H 三轨评分、lessons/playbook、held-out 基准（§4–§9）。

### 0.2 七条判断（本版的设计前提）

1. **递归的对象是工程资产，不是模型权重。** 模型不会因为被批评就变聪明；真正变的是下一次的输入、检查表、模板和流程。准确的名字是「工程递归改进」（engineering recursive improvement），「自我递归改进」作为长期愿景保留。这是整件事能否落地的分水岭。
2. **生产与评判必须分离。** 一个人既写又判，必然自夸；这是结构性的，不是态度问题。但「leader 当导师」可以实现：Chair 在 S9 换一顶「Mentor 帽」——**全新上下文、不同模型族优先、只读、盲评、证据绑定**。同一个模型可以勉强做形成性评价，但不能做对外发布的唯一裁判。
3. **评分必须分三轨，不能合成单一目标。** 约 60 分是确定性的，交给脚本（L1）；约 40 分需要判断，交给盲评 Mentor（L2）；人类抽查是金标准（H）。三者可以合成一个「发布判定」，但**绝不能合成一个「优化目标」**——数学上不存在不可 hack 的单一代理。
4. **评分的目的不是排名，而是开处方。** 只有分数的评分卡是成绩单；带「下一次改哪条流程、怎么验证」的评分卡才是导师反馈。没有处方的评分不进 playbook。
5. **「改好了重评更高」不算进步。** 同一份产物被 Mentor 指出问题、改完再评，分数当然会高——那测的是「响应性」，是最容易造假的指标。改进只在 **held-out 新文献的第一次运行**上认证。主 KPI 是首次通过率（first-pass yield），不是平均分。
6. **人类时间是北极星，分数是影子。** 目标不是「打到 90 分」，而是「人类每篇净投入从 2h17m 降到 45 分钟以内，同时新手五问通过率上升」。
7. **第一版只做一层递归。** 篇内改稿（L0）已有；本版做篇间改流程（L1）；「评价体系评价自己」（L2 元递归）由人类每 10 篇主持一次，不自动化。

### 0.3 北极星指标与主 KPI

| 指标 | 现状 | v0.3 目标 | 测量方式 | 能否被改写输出刷高 |
|---|---|---|---|---|
| **首次通过率**（主 KPI） | 未测（SEM-9407087 为 B+ 自评） | 基线后 +1 篇/周期；10 篇时 ≥50% | 新文献第一次 S8 提交即过发布闸的比例 | **不能**（换新文献） |
| 人类净投入/篇 | 2h17m | ≤45 min（内部）/ ≤90 min（公开） | 人类计时日志 | 不能 |
| 新手五问通过率 | 未系统测 | ≥4/5 | Advocate + 真人抽测 | 较难 |
| 硬错误逃逸率 | ≥1 条 | ≤1 条/20 claims | incidents 统计 | 不能（页图核对） |
| 返工率 | v1 全废 1 次（144 次调用 + 2.3h） | ≤1 次/篇，且不晚于 S6 | manifest 版本 | 不能 |
| L1 机器分 | 未建 | ≥48/60（80%） | `check_l1.py` | 不能（确定性） |
| L2 盲评分 | 未建 | ≥28/40（70%） | Mentor | 较难（盲+证据） |
| 单篇 token | 25 页 30–50 万 | +10–15% 以内 | usage | — |
| 评分噪声 σ | 未测 | Phase 0 实测 | 同产物重评 3–5 次 | — |

**首次通过率定义**：一篇**未参与开发**的论文，从 S0 一次跑到 S8，首次提交即满足发布闸（§6.8），且 S9 未要求退回 S6 的比例。分子/分母都只算 held-out 新文献；同一篇改稿后通过不算。

**分数不是目标。** 如果平均分上升而首次通过率、人类时间、硬错误逃逸率没有改善，视为评分体系失效：先修评分，不加新规则。

### 0.4 本版不做什么

- 不自动修改模型、不做 fine-tune、不做「让 agent 自己给自己改 prompt」的无人闭环。
- 不做全自动发布：公开发布必须人类签字。
- 不在第一版做二阶/三阶递归（评价体系自评、改进流程自改）。
- 不追求跨篇统一分数排名；不同论文难度不同，分数只在同一 rubric 赛季内可比。
- 不把评分卡或 rubric 细则贴进生产阶段的 prompt（防「对着答案写」）。
- 不允许「重评 N 次取最高」「只报最好一轮」「让 Mentor 看上一轮分数」——这三条是明令禁止的。

## 1. 从 v0.2 继承了什么，又缺什么

### 1.1 继承（不改）

- **产品定义**：reading_note，20–35 页，9 章骨架，第一次读这篇论文的学生能从第一页读到最后一页；读完知道问题、主线、推导、假设、哪里没证明。
- **两条原则**：对经典的态度可以像古人，做学问的体裁不能像古人。
- **S0–S8 主流程**、七类角色、G0–G7 闸门、版权三层、`seminars/SEM-XXXX/` 数据模型。
- **v0.1 注疏体是反面教材**：四家异同表、注疏标签、未消化术语堆，一律禁止。

### 1.2 第一次闭环暴露的缺口（SEM-9407087）

| 缺口 | 证据 | 后果 |
|---|---|---|
| 评分是自评 | `manifest.json` 的 `quality_gate: "self-assessed"` | 没有外部视角，B+ 这个等级无法复核 |
| 没有过程分 | 只有产品验收表 | 不知道是「读者不行」「题目太难」还是「流程有病」 |

### 1.3 v0.3 补的四件事

1. **评价平面**：S9 三轨评分（L1 脚本 / L2 盲评 / H 人类），产出产品判定 + 过程分 + incidents + 处方。
2. **改进平面**：S10 复盘 → lessons → 每周期 ≤3 条 patch → playbook 版本化。
3. **基准**：Tier-1 微任务（每周期）+ Tier-2 整篇对照（每 3 篇/大版本）+ Tier-3 真人阅读（季度）。
4. **判据**：σ 实测 + 2σ 规则 + 首次通过率 + 哨兵漂移监控，让「真的变好」可判定。

### 1.5 第一次闭环的审计结论（2026-11-10，`_meta/artifact_audit.md`）

审计了 SEM-9407087 的全部产物与 26 条可计分事件，得到三个必须写进本版的硬结论：

1. **闸门从未真正执行。** `seminar.yaml:17`、`manifest.json:64`、`tools/build_sem_claims.py:75` 都写 `quality_gate: "self-assessed"`；但运行手册只有 G0 的定义，G1–G7 存在三套互不相同的版本（计划书 v0.2、v0.1、`engineering_memo.tex`）；`argument_graph.json`、`coverage.csv`、`page_map.tsv`、`build/`、`copyright_report.md`、`tools/validate.py` 全工程不存在；manifest 只有 2 个哈希（原文/译本），没有模型、prompt、输出、评分卡哈希。**结论：`status: completed` 没有验证支撑，v0.3 的 L1 必须真的跑起来，而不是写「已检查」。**
2. **综合层不可机读，账本自相矛盾。** `claims/merged.jsonl` 20 行中文乱码（GBK/UTF-8 混写，反向解码有 U+FFFD）；`type=assumption`、`confidence=medium` 越出 brief 词表；78 条 claim 只有 20 条进综合层（26%），且无上游 claim id。`errata.md:47`（E11）称 c27/c29 作废、新增 c30/c31，而 `reports/r03.md:185–189` 仍把 c27/c29 标 accept、c30/c31 讲的是 M11。**结论：schema 校验与编码校验是 L1 的前置条件，不是加分项。**
3. **角色缺位不会被发现。** Examiner 与 Editor 在产物中均为 0 产物，但 manifest 仍记 completed；过程账本只统计「谁被质询」，不统计「谁该质询却没质询」。**结论：过程分必须包含「角色是否执行」，且「驳回正确率」要单独记——否则被质询方一律 accept 就能刷高接受率。**

**方法学警告（直接写进工具约束）**：`Get-Content` 默认 ANSI 读 UTF-8 会把同一份报告字数测成 8705（真实 5013，虚高 1.7×）。所有字数、claims 数、行数一律用脚本以 UTF-8 读取并落盘；人工目测的数字不得进评分卡。

**对 anchor 的影响**：SEM-9407087 的**产物**可作为 `good_01`（阅读笔记质量锚点），但其**流程**不可作为「好流程」锚点；anchor 说明里必须写清这一点，避免 Mentor 把「闸门没跑但产物还行」当成可接受样板。

## 2. 核心概念：三级递归及其边界

### 2.1 定义

设系统状态

```
S_t = (P_t, R_t, T_t, K_t)
P: playbook（规则、角色卡、检查表、prompt）
R: rubric 与 judge 配置（赛季冻结，带 hash）
T: 模板与工具（模板仓、脚本、schema）
K: 知识资产（术语表、claims 索引、雷区库、benchmark、anchor set）
```

一次研讨班是一个 episode：产生产物 A_t 与轨迹 τ_t（工具调用、耗时、返工、争议）。

```
生产：  (S_t, 论文)        → A_t, τ_t
评价：  (A_t, R_t)         → L1_t（脚本）+ L2_t（盲评）+ H_t（人类）
诊断：  (L1_t, L2_t, H_t, τ_t) → L_t（lessons）+ I_t（incidents）
修补：  S_{t+1} = S_t ⊕ Δ_t,  |Δ_t| ≤ 3
放行：  仅当在 held-out 新文献上 first-pass 提升（或非劣）且无闸门回退，否则回滚
```

这就是「递归」的准确含义：**每一轮的评分与教训成为下一轮系统状态的一部分**。递归的是工程资产，不是模型。

### 2.2 三个层级，各管各的

| 层级 | 对象 | 周期 | 谁主持 | 本版是否自动化 |
|---|---|---|---|---|
| L0 产品递归 | 一篇笔记的稿子 | 篇内（S6→S7） | Chair + Reader Advocate | 已有，保留 |
| L1 流程递归 | playbook / rubric / 模板 / 工具 | 每 3 篇或一个批次 | Mentor + Diagnostician + 人类批准 | **本版新增，主战场** |
| L2 元递归 | 评价体系与改进机制本身 | 每 10 篇或每季度 | 人类 | 不自动化，只出审计报告 |

**为什么 L2 不自动化**：评价体系自评会形成「我说我准，所以我就准」的闭环；benchmark 自己改自己会失去外部效度。L2 只在人类主持下做，输出是「评分体系审计报告」，不是新规则。

### 2.3 什么才算「改进」（本版的硬判据）

| 现象 | 测的是什么 | 是否算系统改进 |
|---|---|---|
| 同一产物，Mentor 提意见后重做再评，分更高 | 产物对意见的响应性 | ❌ 只记 `responsiveness`，是最容易造假的指标 |
| 同一产物，重评 N 次 | 判官噪声 | ❌ 只用于估 σ；禁止取最高分 |
| **新文献，新流程第一次跑，首次通过率上升** | **流程质量** | ✅ 唯一算数 |
| 新文献，首次通过率不变但人类时间显著下降 | 效率 | ✅ 算改进（成本轨） |
| 新文献，L1 上升但 L2 下降 | 可能只是格式更规范 | ⚠️ 需看首次通过率与人工判断 |

**判定规则**（实现见 `tools/meta/compare_rounds.py`）：

```
改进成立 ⇔ 全部满足：
1. 硬闸：无 veto、schema/manifest 通过；
2. 成本护栏：墙钟 ≤1.5×、人类时间 ≤+30 min；
3. L1 不降（−2 分内）；
4. 人类金标准不降；
5. 新文献上的首次通过率上升，或 L2 提升 > max(2σ, 3)；
6. rubric/judge hash 未变；若变了，必须双尺并行重评。
```

### 2.4 递归的终止条件（防止无限自嗨）

满足任一条件即暂停 L1，转入根因审查：

1. 连续 2 个周期，新文献首次通过率无提升，且 Tier-1 全部在 2σ 内。
2. 人类净投入连续 2 篇 > 75 分钟。
3. playbook 规则数超过 40 条，或角色卡 prompt 超过 6000 token。
4. 同一类 lesson 连续 3 次出现且 patch 无效（说明不是流程问题，是模型/题目/人手问题）。
5. 评分者漂移：anchor gap 缩小 >20%，或重评 σ >5 分（先修校准，不加规则）。

暂停不是失败，是承认「当前瓶颈不在流程」。此时的选择是：换模型、换题目难度、加人手、或接受现状。

│  L2 Mentor（25 min）→ scores_l2.json（盲评：论证/主线/可读性/边界，每条扣分带证据）      │
│  H  人类（15 min）  → scores_human.json（抽 claim 对页图 + 一页纸复述 + 分歧裁决）       │
│  Mentor 汇总        → scorecard.yaml + incidents.jsonl + feedback.md                     │
│  人类 Principal     → 批准/改写评分卡 + 公开发布签字                                     │
└───────────────────────────────────────┬────────────────────────────────────────────────┘
                                        │ 汇总
                                        ▼
┌──────────────────────────── 改进平面（_meta/）──────────────────────────────────────────┐
│  S10 复盘 → lessons.jsonl（带证据/根因/处方/指标）                                       │
│  周期评审（每 3 篇）→ 选 ≤3 条 patch → 哨兵/bench 资格赛 → playbook v+1 → changelog      │
│  资产：playbook.yaml / lessons.jsonl / rounds/ / anchors/ / drift.md / ledger.jsonl     │
└───────────────────────────────────────┬────────────────────────────────────────────────┘
                                        │ 下一次 S0 读取 playbook 版本
                                        └──────────────► 生产平面
```

### 3.2 平面之间的四条铁律

1. **只通过文件通信。** 平面之间不共享对话上下文；所有交接是可 diff、可归档的文件。
2. **评价平面只读。** Mentor 不得修改任何生产产物；只写 `score/`。
3. **改进平面不改历史。** patch 只影响 `playbook.yaml` 的未来版本，不回改已发布的笔记。
4. **生产平面在 S8 前看不到评分卡与 rubric 细则。** 避免应试；上一轮的教训只以规则形式进入 playbook，不以「你上次 72 分」的形式进入对话。

### 3.3 「Leader 当导师」怎么实现

用户的心智模型是「leader 智能体扮演导师」。本版保留这个直觉，但把它拆成两顶帽子：

| | Chair 帽（生产） | Mentor 帽（评价） |
|---|---|---|
| 时机 | S0–S8 | S2.5/S3.5/S6.5 形成性 + S9 总结性 |
| 上下文 | 全程参与，知道所有纠结 | **全新上下文**，只看冻结产物 + rubric + anchor 说明 |
| 权限 | 写 note、主持圆桌 | 只读；只写 `score/` |
| 目标 | 把笔记写好 | 把问题找出来，并开处方 |
| 偏见 | 自我辩护、沉没成本 | 无（理论上） |
| 模型 | 任意 | 形成性：同模型可；总结性：不同模型族优先，人类终审 |

**关键工程细节**：Mentor 必须用 **fresh context**（新会话/新 teammate），**不得 fork Chair 的对话**。fork 会把 Chair 的自我辩解、写作意图、踩过的坑一起继承，盲评立刻失效。这是本架构里最容易被做错的一步。

同一模型当 Mentor 够不够？分两级：

- **形成性评价（S2.5/S3.5/S6.5、内部笔记）**：同模型 + 干净上下文 + 证据绑定，够用。它的价值是「换一双眼睛按清单检查」，不是「更高的智慧」。
- **总结性评价（S9、对外发布）**：同模型不够。需要异模型交叉，或人类完整签字。两者都没有时，只能发 L1 私有，不能发 L0 公开。

### 3.4 「下一次按反馈优化」怎么落地

不是让 agent「下次更努力」，而是改下一次的输入与检查表：

```
Mentor 的 feedback.md
   ├─ 立即修（P0）：本轮内改产物，改完重评该维度
   ├─ 下一轮改（P1）：改 playbook 规则 / 模板 / 检查表 → 人类批准 + held-out 验证
   └─ 长期观察（P2）：进 watchlist，连续 2 个周期有数据再决定
```

只有 P1 会进入 `lessons.jsonl` 并可能变成规则。P0 是产品返工，P2 是研究假设，三者不能混。

## 4. 角色与职责（v0.3）

### 4.1 角色表

| 角色 | 平面 | 核心职责 | 明确不能做 | 主要产出 |
|---|---|---|---|---|
| **Chair / Lead** | 生产 | 主持、分配、复核关键公式、圆桌裁决、从零重写 | 不能给自己打分；不能私改他人报告；不能替读者读 | `note/`、`transcript.md`、裁决记录 |
| **Reader r01/r02/r03** | 生产 | 各自视角独立通读，写五段式报告 | 第一轮不得互看；不得引用他人报告 | `reports/rXX.md` |
| **Examiner** | 生产 | 红队：专找硬错误、伪论证、锚点不实 | 不得只凭印象；每条质疑必须有靶子 | `challenges/exm_on_rXX.md` |
| **Textual Critic** | 生产 | 页图/文字层/译本三路核对，维护 errata | 不得把译本当原文 | `errata.md` |
| **Reader Advocate** | 生产 | 新手五问；可读性评审；指出「读者会卡在哪」 | 不得改论证；不得代替作者补推导 | `reviews/readability.md` |
| **Editor** | 生产 | 体例、术语一致、引用、版式 | 不得改论证内容 | `note/` 编辑稿 |
| **Mentor**（新，必设） | 评价 | 盲评 L2；复核 L1 异常；写 scorecard / incidents / feedback；开处方 | 不得改产物；不得看生产对话/历史分/round 号；不得代写 | `score/*` |
| **Diagnostician**（新，可 Mentor 兼） | 改进 | 把评分卡变成 lessons；提 patch 提案；维护 playbook | 不得自行批准 patch；不得改历史产物 | `lessons.jsonl`、patch 提案 |
| **Human Principal**（用户） | 全部 | 选题、裁决、抽查、批准 patch、公开发布签字 | 不可被替代；不可被「自动通过」 | 决策记录、签字 |
| Bench Steward（可选，Mentor 兼） | 改进 | 维护 benchmark/seeded/golden/anchor set；跑 Tier-1 | 不得泄露 bench 内容给生产 agent | bench 运行记录 |

### 4.2 Mentor 的七条禁令（写进 prompt 的硬约束）

1. **不得访问**：`transcript.md`、Chair 的计划/待办、round 编号、历史评分、上一轮 feedback、任何其他 Mentor 的分数（仲裁除外）。
2. **不得修改**：产物、rubric、anchor 标准分、评分脚本。
3. **不得代写**：只能指出问题与改法，不能给成品段落；代写会把 judge 变成 producer。
4. **每个扣分项必须绑证据**：`claim_id` / `[src p.N]` / `[eq x.y]` / `文件:行号`；无证据扣分不计分，但**计入「无证据扣分率」**（这项本身是判官质量指标）。
5. **先描述后判断**：先写「我看到了什么」，再写「这值几分」；禁止先给分再找理由。
6. **分开三种错**：事实错误（可定位）、论证错误（可复算）、表达错误（可指认）。三者不得互相抵扣。
7. **允许说不知道**：置信度 <0.6 的维度标 `low_confidence`，不强行给分；不奖励长度、字数、claim 数。

### 4.3 人类只做五件事（目标 ≤45 min/篇）

1. 选题与定深度（S0，5 min）。
2. 圆桌裁决 3 题（S5，10 min）。
3. 抽查 claim 对页图（S9 后，10–15 min）。**主动抽样**：分歧最大的、证据最稀薄的、含展示公式的，不随机抽。
4. 读 scorecard 与 feedback，批准/改写（10 min）。
5. 周期评审批准 ≤3 条 patch（每 3 篇一次，30–45 min）。

公开发布另加：完整 skim 一遍笔记 + 签字（30–45 min）。这是 L0 的额外成本，不能省。

## 5. 流程：S0–S10

### 5.1 主流程表

| 阶段 | 名称 | 关键动作 | 闸门 | 产出 | 负责人 |
|---|---|---|---|---|---|
| S0 | 立项 | 选题、定深度 A/B/C、版权层、预算 | G0 | `seminar.yaml` | Chair + 人类 |

| S3 | 独立研读 | 三读者各写五段式报告（禁互看） | G3 | `reports/rXX.md` | Readers |
| S3.5 | **导师二看** | 15 min：报告是否有靶子、锚点是否可查 | — | `reviews/checkpoint_S3.md` | Mentor |
| S4 | 交叉质询 | Examiner 红队 + 读者互质；每条带靶子 | G4 | `challenges/` | Examiner + Readers |
| S5 | 圆桌 | 只裁 3 个真分歧；裁决必须可定位 | G5 | `transcript.md` | Chair + 人类 |
| S6 | 重写 | Chair 从零写；**先交两页样张**；按章节推进 | G6 + 样张闸 | `note/` v1 | Chair |
| S6.5 | **导师三看** | 20 min：样张/前三章是否可读、是否有伪论证 | — | `reviews/checkpoint_S6.md` | Mentor |
| S7 | 可读性评审 | Reader Advocate 新手五问；Editor 体例 | G7 | `reviews/readability.md` | Advocate + Editor |
| S8 | 出版 | 冻结 manifest，记录版本与哈希 | 发布闸 | `manifest.json`、`note/` 终稿 | Chair |
| S9 | **导师评分** | L1 脚本 + L2 盲评 + H 人类；写 scorecard/incidents/feedback | — | `score/*` | Mentor + 人类 |
| S10 | **复盘** | 汇总 metrics、提 lessons、确认 incidents | — | `retro.md`、`lessons.jsonl` | Diagnostician + 人类 |

### 5.2 三个 formative 检查点（本版最重要的防返工设计）

v1 著书体全废的根因不是「写得不好」，而是**没有人在地图/样张阶段说“方向错了”**。因此加三个廉价检查点：

- **S2.5**：地图里有没有真问题？雷区清单是否覆盖了 M1–M12 中与本篇相关的项？章节骨架是否服务论证而不是服务原文目录？
- **S3.5**：三份报告是否各自有靶子？锚点能不能随手抽查 3 条都成立？有没有「看起来完整但没验证」的段落？
- **S6.5**：两页样张 + 前三章。读起来像不像给同学讲？有没有未定义的符号？有没有「因为原文这样所以这样」的伪论证？

每个检查点输出 `must_fix` 列表（最多 5 条），**未清空不得进入下一阶段**。成本约 50 分钟/篇，预期省下 ≥1 次全稿返工（144 次调用 + 2.3h）。

### 5.3 S9 评分流程（约 50 分钟，机器与人类并行）

1. 跑 L1 脚本：`check_l1.py`、`check_anchors.py`、`gate_check.py`（10 min，机器）。
2. Mentor 盲评 L2：读 note、one_pager、errata（不看 transcript/reports 之外的对话），每条扣分带证据（25 min）。
3. 人类 H：主动抽 5–10 条 claim 对页图 + 一页纸复述测试（15 min）。
4. 汇总：Mentor 写 scorecard + incidents + feedback；人类批准/改写（10 min）。

**注意**：L1 先跑，但**不把 L1 分数给 Mentor**（防止锚定）；Mentor 只看到产物与 rubric。L1 与 L2 的差异本身是诊断信号。

### 5.4 周期评审（每 3 篇，60–90 分钟）

1. 汇总 3 份 scorecard：首次通过率、趋势、重复 incidents、各角色均分。
2. 跑哨兵：6 份 anchor（3 优 3 差）给当前 Mentor 打分，看 gap 与 σ。
3. 归因：哪些是流程问题（可 patch），哪些是模型/题目/人手问题（不 patch）。
4. 从 lessons 里选 ≤3 条，写成 patch 提案（文件、diff、预期效果、验证指标、回滚方式）。
5. 跑 Tier-1 bench（旧 playbook vs 新 playbook）。
6. 人类批准/拒绝；批准的进 `playbook.yaml`，版本号 +0.1；拒绝的留在 lessons 标 `rejected` 并写理由。
7. 更新 `changelog.md` 与 `_meta/rounds/round-XXXX/verdict.md`。

## 6. 评分体系：三轨，不合成优化目标

### 6.1 三轨总表

| 轨 | 内容 | 分值 | 谁执行 | 用途 | 能否被改写输出刷高 |
|---|---|---|---|---|---|
| **L1 机器判定** | 锚点、结构、schema、公式核对标记、manifest | 60 | 脚本 | 硬闸、主证据 | 不能 |
| **L2 Mentor 盲评** | 论证质量、主线、可读性、边界判断 | 40 | Mentor | 诊断、处方 | 较难 |
| **H 人类金标准** | claim 对页图、一页纸复述、分歧裁决 | 不折分 | 人类 | 校准、终审 | 不能 |
| **P 过程分** | 每个角色的表现 | 100/角色 | L1 指标 + Mentor 评 | 带教、定位 | 部分 |
| **M 元分** | 改进机制本身 | 100/周期 | 人类 | 判断评分体系是否可信 | — |

**发布判定**用 L1 + L2 + H + veto 合成一个通过/不通过（§6.8）；**优化目标**只用首次通过率、L1、人类时间、硬错误逃逸率。L2 只做诊断，不单独当目标。

### 6.2 L1 机器判定（60 分）

| 编号 | 项目 | 分值 | 判据 | 数据来源 |
|---|---|---|---|---|
| L1-C1 | 锚点覆盖率 | 12 | 有合法锚点的实质断言 / 全部实质断言 ≥90% | `check_anchors.py` |
| L1-C2 | 锚点有效性、无编造 | 8 | 页码在 `page_map` 范围内、公式号存在；编造=veto | `check_anchors.py` |
| L1-F1 | manifest/schema 完整 | 6 | `playbook_version`、`rubric_sha`、`judge_model`、prompt hash 齐全 | `gate_check.py` |
| L1-F2 | 术语与体例一致 | 2 | 术语表唯一；同一符号不两义 | 脚本 + 词表 |
| L1-A1 | 骨架完整性 | 8 | 9 章齐全；每章有「真问题/推导/边界」字段 | `map.yaml`/`note` 结构 |
| L1-B1 | 展示公式核对率 | 8 | 展示公式中标 `checked` 的比例 ≥90% | `formula_checked` 字段 |
| L1-E1 | 证据分级覆盖 | 8 | 每条结论有甲乙丙丁戊等级 | schema |
| L1-E2 | claims/questions 结构 | 4 | `open` 必须有 rationale；target 必须存在 | schema |
| L1-D1 | one-pager 可解析 | 4 | ≤800 字，含问题/做法/疑点三段 | 脚本 |

合计 60。**L1 的每一项都必须可复算**；做不到的条目不要放进 L1，放 L2。

**L1 前置检查（不计分，失败即 L1=0 并 veto）**：

- 全部 `.md` / `.jsonl` / `.yaml` 能以 UTF-8 解码；出现 U+FFFD 或乱码 → 停。
- `score/gate_report.json` 存在，G1–G7 每项有 `pass/fail/na` 与证据路径；只有 `self-assessed` 字样 → 视为未执行。
- `manifest.json` 至少含：原文 sha256、译本 sha256、note 输出 sha256、`playbook_version`、`rubric_sha`、`judge_model`、`scorecard_sha256`。
- claims 的 `type` / `confidence` 必须在 brief 词表内；越界即 schema 失败。

### 6.3 L2 Mentor 盲评（40 分）

只评 L1 无法判定的四类：

| 编号 | 维度 | 分值 | 核心问题 | 证据要求 |
|---|---|---|---|---|
| L2-A2 | 主线连贯 | 8 | 九章是否服务一条主线？转折是否自然？ | 至少 2 处章节衔接 + 1 处反例 |
| L2-B2 | 推导质量 | 12 | 关键推导是否正确、可复算？假设是否写明？ | 至少 3 处逐步核对，指出跳步 |
| L2-D | 可读性 | 15 | 第一次读的学生能否从第一页读到最后一页？ | 新手五问逐条 + 卡点定位 |
| L2-E3 | 边界判断 | 5 | 已证/conditional/gap 的分级是否诚实？ | 至少 2 条结论的分级理由 |

合计 40。每条扣分必须带 `文件:行` 或 `[src p.N]`；无证据扣分不计分。

### 6.4 过程分（100/角色，诊断用，不进发布闸）

| 维度 | 判据 | 数据来源 | 机器/人工 |
|---|---|---|---|
| P1 指令遵循与边界 15 | 越界写作、禁看/禁改、格式 | 文件时间线、写作用域 | 人工 |
| P2 证据纪律 20 | 锚点密度、页图核对率、译本当原文 | `check_anchors.py`、errata | 机器为主 |
| P3 对抗质量 20 | 质疑命中率、类型分布、有靶子比例 | challenges + 回应 | 机器统计 + 人工判质 |
| P4 错误发现与自纠 15 | 抓到的硬错误、自己错误的更正 | incidents | 人工 |
| P5 协作与交接 10 | `.done` 及时、无轮询、无越界 | 事件日志 | 机器 |
| P6 成本与效率 10 | token/页、墙钟/页、返工 | usage | 机器 |
| P7 资产增量 10 | 新术语/模板/脚本/雷区 | 资产 diff | 机器 + 人工 |

按角色调权：Reader 重 P2/P4；Examiner 重 P3/P2；Chair 重 P1/P4/P5；Editor 重 P1/P6/P7。Mentor 本身由元分评。

### 6.5 元分（每周期，人类打）

| 维度 | 分值 | 问题 |
|---|---|---|
| M1 诊断质量 | 25 | lessons 是否命中根因？patch 是否真的解决了？ |
| M2 变更纪律 | 20 | 是否 ≤3 条？一条一变？失败是否回滚？ |
| M3 基准可信 | 25 | bench 是否区分得出好坏？是否被污染/过拟合？ |
| M4 成本 | 15 | token 与人类时间是否在预算内？ |
| M5 人类负担 | 15 | 人类是否被迫做本该机器做的事？ |

元分 <70 时，暂停加规则，先修评价体系。

### 6.6 发布判定（不是优化目标）

```
发布 ⇔ 全部满足：
1. L1 ≥ 48/60（80%）
2. L2 ≥ 28/40（70%）
3. 无 veto（编造、译本当原文、关键公式未核对页图）
4. H：抽 5–10 条 claim 全部一致；一页纸复述通过
5. manifest 完整、版权层正确
```

- L1≥48 但 L2<28：退回 S7（可读性/论证问题）。
- L2≥28 但 L1<48：退回 S6（证据/结构问题）。
- 两者都过但 H 不过：人类签字否决，记 incident（说明评分体系漏检）。
- 公开发布（L0）：再加异模型双评或人类完整 skim。

  total: 0
  dims:
    L2-B2: {score: 0, max: 12, evidence: ["note/ch02.md:44"], note: ""}
human:
  claim_checks: [{claim: C-007, verdict: consistent, anchor: "[src p.21]"}]
  retell: pass | fail
  disagree_with_l2: false
verdict: publish | revise | reject
process:
  roles: {r01: {grade: B, total: 82, dims: {...}, incidents: []}}
incidents: [I-0007]
top_fixes:
  - {priority: P0, target: "note/ch03.md:44", issue: "...", action: "...", owner: chair, verify: "..."}
confidence: {l2: 0.75, low_confidence_dims: []}
human_review: {ratified: null, overrides: [], spot_check: "active"}
```

**证据规则**：L2 每个维度至少 1 条证据；`scorecard_lint.py` 拒收无证据的评分卡。

### 6.8 校准、哨兵与仲裁

| 机制 | 做法 | 报警条件 |
|---|---|---|
| **黄金件校准** | 3 优 3 差 anchor，每周期让当前 Mentor 打分 | bad 组 > 金标上限，或 good 组 < 下限 |
| **gap 监控** | `gap = mean(good) - mean(bad)` | gap 缩小 >20% → 判官区分度下降 |
| **重评噪声 σ** | 同一产物重评 3 次（Phase 0 做 5 次） | σ >5 分 → 评分不可用，先修 rubric/prompt |
| **无证据扣分率** | 无证据扣分项 / 总扣分项 | >10% → Mentor 在编造理由 |
| **长度相关性** | corr(L2, len_tokens) | >0.5 → 长度偏差主导 |
| **人机分歧率** | `|L2 - H| > 15` 的班次占比 | >30% → judge 与该任务不匹配 |
| **双评仲裁** | 发布级或边界件用第二个 Mentor（异模型/异上下文） | 分差 >8–10 分 → 第三人/人类只裁争议维度 |
| **反向测试** | 每 5 篇混入一份已知缺陷旧产物 | 抓不住 → Mentor 校准失败 |
| **季度双尺** | 新产物同时用旧 rubric 与新 rubric 评 | 「新尺−旧尺」在历史产物上已存在 → 是尺子松了 |

**σ 是本版的待测参数**：Phase 0 用 SEM-9407087 让同一 Mentor 重评 5 次，测出 σ。2σ 阈值由此确定，不能拍脑袋。

## 7. 改进机制：lessons → playbook → held-out 认证

### 7.1 lessons.jsonl

一行一条，追加写，不修改历史。字段：

```json
{
  "id": "L-0001",
  "cycle": "CYCLE-0000",
  "date": "2026-11-10",
  "seminar": "SEM-9407087",
  "category": "SPEC",
  "symptom": "v1 按注疏体写成 40 页，用户判全废",
  "evidence": ["研讨班提效建议_v0.1.md:31", "transcript.md:88"],
  "root_cause": "把「像古人注疏」当成体裁规格；brief 未定义产品形态",
  "patch": "两页样张闸 + brief 预置产品定义 + 章节内容清单",
  "metric": "首次通过率；S6 返工次数",
  "status": "adopted",
  "playbook_rule": "PB-001"
}
```

分类决定 patch 类型：`SPEC`（定义不清）、`ASSET`（缺模板/工具）、`HUMAN`（浪费人时）、`QUALITY`（闸门漏检）、`ANTI`（走捷径）。

### 7.2 playbook.yaml

playbook 是「下一次的输入」的唯一来源。规则示例：

```yaml
version: 0.3.0
updated: 2026-11-10
rules:
  - id: PB-001
    title: 两页样张先过闸
    status: active          # active | trial | deprecated
    category: SPEC
    applies_to: [S6, Chair]
    rule: "S6 必须先提交两页样张（含一个完整推导），Mentor/人类通过后才写全稿。"
    evidence: [L-0001]
    verify: "checkpoint_S6.md 记录样张路径与结论；无样张的 S6 视为未开始"
    since: 0.3.0
```

**规则预算**：≤40 条；角色卡 prompt ≤6000 token。每条规则必须有 `evidence` 与 `verify`，否则 lint 拒绝。**日落条款**：上线 2 个周期后无证据显示有效，标 `deprecated` 并删除。

**规范迁移**：能写成确定性脚本的规则，一律从 prompt 迁到 `tools/`；prompt 每周期净增 ≤20 行且必须删等量。这是防 prompt 膨胀的唯一硬约束。

### 7.3 变更纪律

- **每周期 ≤3 条**。超过 3 条无法归因，宁可不改。
- **一条 patch = 一个假设**：不允许「顺便把措辞也改了」。
- **必须写验证计划**：改哪个指标、看哪几篇新文献、什么算成功、什么算失败。
- **必须能回滚**：patch 前复制到 `_meta/playbook/archive/vX.Y.Z.yaml`。
- **失败也记录**：patch 无效 → 标 `reverted`，写清「为什么没用」，这是更贵的教训。
- **rubric 只能人类改**：Mentor 只能提「哪条无法判定」，不能提「应该加分/减分」。改 rubric 必须双尺并行重评。

### 7.4 benchmark

#### Tier-1：微任务（每周期必跑，≤45 min，≤5 万 token）

| 任务 | 输入 | 输出 | 评分 | 防什么 |
|---|---|---|---|---|
| B1 地图 | 固定 10 页论文 | `map.yaml` | 8 个必含概念 + 3 个预埋陷阱 | 地图漏主线、踩雷 |
| B2 质询 | 固定报告，预埋 6 个缺陷（符号错、条件漏、编造页码、方向反、能标混、术语误译） | `challenges/` | 检出率/误报率/F1 | Examiner 抓不住硬错误 |
| B3 可读性 | 固定笔记章节 + 5 个新手问题 + 3 处预埋晦涩 | `readability.md` | 五问通过数 + 晦涩命中 | 自嗨式写作 |
| B4 锚点 | 固定 10 条 claim（4 条锚点错） | 核对表 | 锚点判定准确率 | 只数锚点不看真假 |

**通过标准**：任一任务不得低于上一版 −2σ（σ 由重评测得；未测前用 −5 分保守值）；至少 1 个任务提升 >2σ；无闸门回退。达不到 → patch 回滚。

#### Tier-2：整篇对照（每 3 篇或 playbook 大版本，2×约 50 万 token）

选一篇未参与开发的 20–30 页论文，旧 playbook 与新 playbook 各跑一次，Mentor 盲评 pairwise（只知 A/B，不知版本），**A/B 顺序交换各评一次取平均**，人类抽看。成本高，只在 Tier-1 模糊或准备发布大版本时做。

#### Tier-3：外部效度（每季度）

找 1–2 位真实初学者读笔记，做新手五问 + 15 分钟访谈；或请一位同行盲审。这是唯一能验证「可读性」不是自欺的办法。频率低，但不能没有。

**污染控制**：bench 论文永不进入生产批次；`bench/` 默认 L2 本地，不进公开仓；Mentor 的生产 prompt 不得包含 bench 内容；每 2 个季度轮换 1 个 Tier-1 任务。

### 7.5 判断「真的变好」的五条证据

一条改进声明必须同时给出：

1. **首次通过率**：新文献上上升（主 KPI）。
2. **L1**：不降（确定性证据）。
3. **成本**：墙钟、人类时间不劣化（≤1.5× / +30 min）。
4. **人审**：claim 抽查与一页纸复述不降。
5. **统计**：L2 提升 > max(2σ, 3)，且 rubric/judge hash 未变（变了就双尺并行）。

只满足「平均分变高」不算。记录在 `_meta/rounds/round-XXXX/verdict.md`。

### 7.6 反作弊与反 Goodhart

| 失效模式 | 本项目的表现 | 对策 |
|---|---|---|
| 自评偏好 | Chair 给自己打高分 | 盲评 + fresh context + 异模型/人类 |
| 共享上下文放大 hacking | 同一 session 里「提意见—改—重评」 | Mentor 禁止 fork；评分输入不含 round 号/历史分 |
| 奖励长度 | 堆页数、堆 claim、堆术语 | 只按内容清单与可读性评；长度记为协变量 |
| 讨好评分者 | 写得「像评分标准」但没内容 | L1 确定性 + held-out 任务 B1–B4 |
| rubric 过拟合 | 针对评分点写作 | held-out 新文献 + 任务轮换 + 行为锚点 |
| 评测污染 | rubric 原文贴进 Chair 的 prompt | 明令禁止；prompt 净增 ≤20 行 |
| 分数膨胀 | 每轮 +2 分，首次通过率不变 | 黄金件校准 + 膨胀监控 + 主 KPI 用首次通过率 |
| 选择性披露 | 重评 3 次取最高、只报最好一轮 | 取均值 + σ；禁止取最高；所有轮次进 ledger |
| prompt 膨胀 | 规则越加越多 | 40 条上限 + 日落条款 + 规范迁移 |
| 虚假完成 | 有锚点但页码错、有推导但跳步 | `check_l1.py` + 页图核对 + 主动抽查 |
| 互相吹捧 | 读者互评说好话 | 独立研读 + 交叉质询 + Mentor 不看互评 |
| 人类橡皮图章 | 用户直接点通过 | 主动抽样 + override 记录 + 10% 全量审计 |
| 评审者共谋 | Mentor 与 Chair 同模型同上下文 | 禁止 fork；发布级换模型；记录 session id |

**数学领域的额外防线**：公式真值只认页图；关键公式必须独立复算（量纲、极限、已知特例）；约定（如 Λ=1）必须显式写出；方向性结论（凝聚→禁闭）必须单独核对；能标/有效理论范围必须标注。这五条直接对应 M1–M12 的六类雷区。

## 10. 试点与排期

### 10.1 Phase 0：先校准评分体系（1 周，零新论文）

按顺序做四件事：

1. **测 σ**：拿 SEM-9407087 的产物，让同一 Mentor 盲评 5 次，算均值和 σ。这决定 2σ 阈值，**不做这一步，后面全是猜**。
2. **建 anchor set**：3 优（含 SEM-9407087 终稿）+ 3 差（含 v1 注疏体、一份已知编造 claim 的样本）；人类定死金标分区间并签字。
3. **哨兵首跑**：当前 Mentor 给 6 份 anchor 打分，记录 good/bad/gap/σ。
4. **回测**：用新 L1+L2 rubric 盲评 9407087，验证能否命中已知 6 个问题（M5 理由错、r01 根号错、p42 证据地位、§6 唯一性 gap 等），至少命中 5 个。

**通过标准**：σ 可测（哪怕很大）；anchor gap 方向正确；6 个问题命中 ≥5。失败 → 改 rubric 锚点或 Mentor prompt，不改历史产物。

成本：约 1–2 小时 Mentor + 45 分钟人类，零 token 生产。**这是整个 v0.3 最便宜、信息量最大的一步。**

### 10.2 Phase 1：JP11 试点（第 2–3 周）

- 完整跑 S0–S10，启用三个 formative 检查点。
- 只允许 1 条 patch（最明显的流程问题），且必须走 Tier-1。
- 人类记录每小时在做什么，验证「≤45 min」是否现实。
- 记录首篇 first-pass 基线（大概率不通过，重要的是数据）。

### 10.3 Phase 2：批次前三篇 + 第一次周期评审（第 4–6 周）

- 完成 JP11、JP02、2016LEC。
- 建立 Tier-1 基线；第一次选 ≤3 条 patch；发布 playbook 0.3.1。
- 对比：有无检查点时的返工次数、人类时间、首次通过率。

### 10.4 Phase 3：整篇对照与决策（第 7–12 周）

- 完成首批 5 篇；做一次 Tier-2（旧 vs 新 playbook，同一篇 held-out）。
- 决策 D5：若连续 2 篇 G4 不过，暂停扩量，先修模板。
- 决定是否启动网站 L0（推迟到 ≥10 篇的决策不变）。

| 周 | 里程碑 | 关键交付 |
|---|---|---|
| 1 | 评分体系校准 | σ、anchor set、哨兵首跑、回测报告 |
| 2–3 | JP11 试点 | 首份正式三轨评分卡、human-time 日志 |
| 4–6 | 前三篇 + CYCLE-0001 | playbook 0.3.1、Tier-1 基线、首次通过率基线 |
| 7–9 | 第 4–5 篇 | 第 2 个周期、Tier-2 对照 |
| 10–12 | 复盘与决策 | v0.4 计划、是否扩量 |

## 11. 成本与收益

### 11.1 增量成本（相对 v0.2）

| 项 | 25 页 | 45 页 | 说明 |
|---|---|---|---|
| 生产 token | 30–50 万 | 60–100 万 | 不变 |
| L1 脚本 | 可忽略 | 可忽略 | 本地计算 |
| L2 盲评 | +15–25k | +20–30k | 读产物 + rubric |
| 检查点 | +5–10k | +8–12k | 三次短评 |
| 哨兵/bench 摊销 | +3–6k | +3–6k | 每周期 |
| **合计** | **+10–15%** | **+10–15%** | 可接受 |
| 人类时间 | 45–60 min | 60–90 min | 目标值；公开发布另加 |
| 周期评审 | 每 3 篇 60–90 min | 同 | 人类主持 |

### 11.2 收益从哪来

- **早停**：三个检查点把「方向错」从 S8 提前到 S2/S6，省 ≥1 次全稿返工（实测 144 次调用 + 2.3h）。
- **不重复**：lessons → playbook 让同类错误第二次不再犯；日落条款防止规则腐化。
- **可比**：有了 bench 与 σ，才知道换模型/换流程/换题目哪个真的有用，而不是凭感觉。
- **可交付**：三轨评分卡 + incidents 让「这篇为什么没过」可复核，用户不必通读全部产物。
- **主 KPI 不可刷**：首次通过率只能靠「新文献上第一次就做对」，这会逼着流程真的变好。

### 11.3 什么时候不值得

- 单篇一次性、不再复用的阅读：评分开销 > 收益。
- 题目难度远低于当前能力：全过，bench 无区分度，改进信号消失。
- 人类不愿做裁决与抽查：盲评退化成形式，分数不可信。
- 模型/工具极不稳定：σ 大于改进幅度，先稳定环境再加评分。

## 13. 决策记录（D1–D15）

| 编号 | 决策 | 理由 |
|---|---|---|
| D1 | 产品仍是 reading_note（继承 v0.2） | 第一次闭环证明注疏体不可读；产品形态是地基 |
| D2 | 生产与评判分离；Mentor 用 fresh context 盲评，禁止 fork | 自评偏差是结构性的；共享上下文会放大 hacking |
| D3 | 三级递归；L2 元递归由人类主持，不自动化 | 防止评价体系自说自话 |
| D4 | 评分分三轨：L1 机器 60 / L2 盲评 40 / H 人类金标准；不合成优化目标 | 单一代理必然被 hack；确定性项不可表演 |
| D5 | 发布闸门：L1≥48/60、L2≥28/40、无 veto、H 通过 | 防止「总分够但关键维度塌」 |
| D6 | 每周期 ≤3 条 patch，一条一变，可回滚 | 超过 3 条无法归因 |
| D7 | 改进只在 held-out 新文献的第一次运行上认证 | 「改好了重评更高」测的是响应性，不是质量 |
| D8 | 主 KPI 是首次通过率，不是平均分 | 平均分可被重评/选择性披露/尺子松动抬高 |
| D9 | Tier-1 每周期必跑；Tier-2 每 3 篇/大版本；Tier-3 每季度 | 成本与信号频率的平衡 |
| D10 | 评分卡与 rubric 细则不进生产上下文，只进 playbook 规则 | 防应试、防「对着答案写」 |
| D11 | 人类只做五件事，目标 ≤45 min/篇 | 人类时间是最稀缺资源 |
| D12 | 所有产物记录 playbook/rubric/model/prompt 版本 | 否则跨篇比较无意义 |
| D13 | 连续 2 周期无增益 → 停改流程，先查基准/模型/题目 | 递归也有边际收益递减 |
| D14 | rubric/judge 一个赛季冻结并 hash；改动必须双尺并行 | 尺子变了，跨轮比较无效 |
| D15 | 禁止重评取最高、禁止 Mentor 看历史分/round 号 | 选择性披露与锚定会系统性抬高分数 |

## 附录 C：术语

- **reading_note**：20–35 页可读读书笔记，本项目的产品形态。
- **L1 / L2 / H**：机器判定 / Mentor 盲评 / 人类金标准，三轨评分。
- **formative / summative**：形成性评价（过程中改进）与总结性评价（结束时判定）。
- **held-out benchmark**：未参与开发、只用于评测的任务集。
- **first-pass yield**：新文献第一次运行就过发布闸的比例，主 KPI。
- **playbook**：规则、角色卡、检查表、模板的集合，是「下一次的输入」。
- **lesson**：一条带证据、根因、处方的教训。
- **veto**：一票否决项（编造、译本当原文、关键公式未核对页图）。
- **responsiveness**：同一产物按意见改后再评的分数提升，不算系统改进。
- **2σ 规则**：L2 差异必须超过两倍重评标准差，才算非噪声。
