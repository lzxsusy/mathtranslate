# 研讨班提效建议 v0.1

> 依据：第一次闭环（SEM-9407087 + 配套译注 + 阅读笔记）的会话记录实测，以及 `seminars/SEM-9407087/` 全部产物。
> 一句话：**瓶颈不在 agent 的阅读能力，在「需求规格化」「资产复用」「人时分配」这三件事上。** 先做 §3 六条，能把每班墙钟砍掉一半；再做 §5 四条，才能把「50 篇」从不可能变成一学期。

## 1. 实测数据（第一次闭环）

| 指标 | 数值 |
|---|---|
| 工具调用总数 | 416 |
| 墙钟 | 约 5 小时 |
| 其中你读稿/审阅 | 2 小时 17 分 |
| agent 净干活 | 约 2.5 小时（差额几乎全在等你） |
| 你发出的指令 | 6 条 |
| 工具分布 | pwsh 222、read 119、read_image 67、write 65、edit 62、协调类 47、compress 10 |
| 研讨班本体（P2） | 174 次调用 / 59 分钟 —— **只占 14%，却产出了核心价值** |
| 最大单笔损失 | v1「著书体」全废：144 次调用 + 你 2.3 小时等待 |

结论一：真正的研读（三人独立读 + 质询 + 圆桌）只花了 1 小时。**其余 4 小时是规格返工、版式试错、轮询空等和看自己排的版。**
结论二：你 2.3 小时的等待换来一次全废——这笔钱本可以用「两页样张」花 10 分钟省掉。

## 2. 三个真瓶颈

- **B1 规格化**：把比喻当规格。你说「像古人著书」，被实现成注疏体；你要的是「骨架 + 骨肉」的可读笔记。这是单笔最大浪费。
- **B2 资产化**：没有版式模板（现场写 test_ctex.tex）、没有唯一 source of truth（v2 又抽一遍正文）、没有事件通知（Chair 用 wait/list 轮询 20+ 分钟）、档案命名漂移（摘要叫「研讨班工作流」实际是翻译会话）。
- **B3 人时**：三个读者各自通读 45 页（3 倍冷读成本）；你独自通读 + 裁决。按这个节奏，50 篇需要 250 小时以上——不是 agent 不够快，是你的注意力不够分。

## 4. 你的更正 = 最高价值资产：雷区清单

M1–M12 不是零散意见，是**六类可复用的错误模式**。做成 `brief.md` 固定节 + `Examiner` 提示词第一段：

| 类型 | 实例（M 编号） | 固定检查动作 |
|---|---|---|
| 1. 伪论证 | M5「亚纯函数虚部调和故无界」（常数即反例） | 每步引理必须命名 + 写清条件；用反例检验 |
| 2. 能标/阶段混淆 | M10 u₀ 邻域是 **N=2 QED**，N=1 SQED 只在软破缺后 | 每条理论陈述标 UV/IR、N=几、是否破缺后 |
| 3. 方向反转 | M12 磁单极凝聚 → **电**禁闭（不是电凝聚→磁禁闭） | 所有因果/对偶句必须双向写一遍再定稿 |
| 4. 约定未注明 | M9 原文取 Λ=1，电荷基与基点决定单极/双荷子标签 | 每条 claim 附约定 |
| 5. 文字层陷阱 | E1/E2 丢上划线与 bar、E4 根号覆盖范围（p7、p8、p35） | 公式 100% 对页图；脚本标记可疑页 |
| 6. 文献误标 | E7 9701069 被误标为 Kapustin–Witten | 引用一律经 INSPIRE 核验 |

这一步不需要改流程，写 20 行模板即可，是**投入产出比最高的一条**。

## 5. P1：结构性改造（决定 50 篇做不做得成）

7. **三级深度（A/B/C）**：完整十件套 / 精简六件 / 论文卡。50 篇的人时从 65+ 小时降到约 33 小时（详见 `研讨班专题文献\阅读路线与批次计划.md`）。
8. **S0/S1 自动化 `preflight.py`**：PDF → 页图、文字层、页映射、章节树、公式/图清单、`seminar.yaml` 骨架，一次写好 50 篇共用。这是目前每班最耗人力的手工搬运。
9. **全局资产**：`glossary.tsv` 全局增量；claims 汇总成 `claims_index.jsonl` 可跨篇检索；用 INSPIRE 引用接口自动生成每篇的「外部连接 ≥4 条」候选，省掉人工找参考文献。
10. **唯一 source of truth**：页图 + 文字层 + 译注三者，禁止任何角色二次抽取或重排（v2 又抽一遍正文就是教训）。

## 6. P2：以后再说

11. **网站 L0 推迟到 10 篇 dossier 稳定之后**：版权与维护成本高，且它解决的是传播问题，不是理解问题。
12. **人机分工的边界**：你只做三件事——**选题、裁决（accept/reject/open）、抽查 10 条 claim**。其余全部 agent 化；你的阅读时间只花在「最可能有问题的 20% 段落」，不花在通读上。

## 7. 更远的一步：跨篇论证图谱

50 篇读完后，把每篇 `argument_graph.json` 按 `uses / proves / generalizes / analogous` 连起来，得到一张 Witten 数学物理地图——同一张图可以同时是：研讨班讲义的骨架、一本书的目录、网站导航的骨架。

这才是「最大化利用」的最终形态：**不是 50 份笔记，而是一张可导航的图**。每新增一篇，只需要接几条边。
