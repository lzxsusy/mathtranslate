# AI 研讨班宪章（v0.2）

**性质**：本工程的根本规则。与运行手册冲突时，以本宪章为准；与事实冲突时，以原文和页图为准。
**版本**：v0.2（2026-11-10）。在 v0.1 十条基础上新增第十一至第十五条，明确「评分独立」「递归改进」「held-out 认证」三件事；v0.1 原文保留在 `_meta/` 归档，不删除。

---

## 第一条 目的

研讨班不是为了“多写几份笔记”，而是为了把一篇文献变成**可核查、可教学、可复用的理解**：它要能回答“这篇文章问了什么、怎么答的、哪里可疑、与谁相关”，并且让**没读过原文的学生从第一页读到最后一页**。

## 第二条 证据优先

任何实质性断言必须有可定位的证据：页码、公式号、图号、定理号。没有锚点的内容只能进入“问题”，不能进入“结论”。

## 第三条 原文优先

原文是唯一底本；页图是公式与符号的唯一真值；译本只用于对照，不能作为研读的唯一依据。译者可能错，文字层可能坏，页图不会撒谎——但页图也会模糊，所以关键处要放大核对。

## 第四条 独立研读

每位讲读在写报告前只读自己负责的部分，不互看、不商量、不等“标准答案”。独立性是研讨班不退化为“合写综述”的前提。

## 第五条 对抗义务

质询人必须攻击，不得复述；每条质询要指向具体断言，并给出可检验的替代说法、边界条件或反例方向。“我觉得可能不严谨”不是质询。

## 第六条 综合责任

综合人必须重建论证链，不得拼接报告；论证图必须连通；成品必须让没读过原文的同行看懂“贡献与疑点”。**结论要分级**：作者证明的、我们推导的、我们猜的，必须分开写。

## 第七条 版权边界

公开层只放自写内容与短引用；不放整本译文、不放原文 PDF、不放页图。书籍译本默认私有；arXiv 逐篇看许可证。收到权利方通知，48 小时内下架。

## 第八条 可复现

每个研讨班必须有 `manifest.json`：模型、提示词、角色、时间、输入/输出哈希、**闸门执行记录**。没有 manifest 或闸门记录缺失的成果不发布。

## 第九条 人类终审

Agent 可以生产、质询、综合、评分，但不能单独决定“发布”。发布前必须有人类抽查并对分歧做最终裁决；人类也负责签字确认 bench 的标准答案。

## 第十条 不糊弄条款

禁止：
- 编造原文没有的陈述；
- 把“我推断”写成“作者证明”；
- 用模糊表述掩盖分歧；
- 用“已完成”掩盖未验证；
- 用页数/字数冒充质量。

违反任一条，该研讨班记 0 分，退回重做并记录 incident。

## 第十一条 评分独立（新增）

1. 评分者（Mentor）必须使用**全新上下文**，不得 fork 生产者，不得看生产者的推导过程、历史评分、轮次编号或“这次要改好”的提示。
2. 评分者不得代写、不得给“鼓励分”；每一处扣分必须指向锚点（页码/公式/claim id/行号），**没有锚点的扣分无效**。
3. 评分与生产**分离归档**：`score/` 只由评分者写，生产者不得修改；生产者只能提交，不能改分。
4. 高 stakes（发布、周期结算、bench 认证）**换一个模型或换一组评审**，不能与被评者同族同会话。
5. 评分者与生产者不得共享“标准答案”以外的中间结论；bench 答案 key 只给评分者。

## 第十二条 递归改进（新增）

1. 改进必须**留痕**：每次只改 `_meta/playbook.yaml` 中 ≤3 条规则（一条一变），记录 evidence、patch、metric、status，可回滚。
2. 改进的判据是**held-out 新文献上的首次通过率（first-pass yield）变好**，不是同一产物重评分数变高；后者只记 responsiveness。
3. 禁止：重评取最高、选择性披露失败轮、把 rubric 贴进生产者 prompt、为了让新规则通过而降低阈值或修改标准答案。
4. rubric 一个赛季内冻结并记 hash；必须改时，新旧两把尺并行评分至少一个周期，确认不是尺子变松。
5. 连续两个周期 bench 无显著改善 → 停止加规则，先修测量（σ、anchor、哨兵）。

## 第十三条 held-out 认证（新增）

1. 任何 playbook 新版本，必须先过 `bench/`（Tier-1 单项 + Tier-2 整篇对照），才允许进入生产。
2. bench 任务固定、论文 held-out、答案 key 人类签字；看过答案的 agent 不得担任该任务评分者。
3. 任一任务跌破上版 −2σ、或出现闸门回退，即回滚；新版本不得只挑“变好的那项”汇报。
4. bench 只用于认证，不用于生产选材；held-out 论文永不进入生产批次。

## 第十四条 分轨与防 hack（新增）

1. 评分分三轨：**L1 机器可判定**（锚点、结构、schema、哈希、字数）、**L2 盲评**（主线、推导、可读性、边界）、**H 人类**。三轨不得合并成单一总分做优化目标。
2. 数量型检查点（字数、claim 条数、页数）必须由脚本判定，且锁定 UTF-8；不得由 LLM 目测。
3. 反作弊为默认配置：盲评、双评仲裁、黄金件校准、主动抽样、分数漂移监控、驳回正确率（不能只数 accept）。
4. 任何“角色缺位”（如 Examiner/Editor 无产物）记 0 分并写“未执行”，不得用其他角色的产出替代。

## 第十五条 事故与回滚（新增）

1. incident 分三级：S1 硬错误/编造/闸门伪造，S2 流程缺失/角色缺位/编码错误，S3 表述与效率问题。
2. S1 必须在 48 小时内定位到 claim 与责任人，公开 errata；S2 进入下一周期 patch；S3 只记录不阻断。
3. 闸门“从未执行”视同未通过（GATE_SKIPPED），不得以 `self-assessed` 代替。
4. 每次回滚都要保留被回滚版本的 hash 与失败证据，供下一轮对照。
