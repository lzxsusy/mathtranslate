# 评分与递归改进规范 v0.1

- 版本：v0.1（2026-11-10）
- 适用：`AI研讨班工程` v0.3 及以后
- 上游：`AI研讨班工程计划书_v0.3.md`；配套：`00_制度与模板/研讨班宪章_v0.2.md`、`_meta/playbook.yaml`、`bench/README.md`
- 状态：待用户批准；Phase 0 校准后可能升 v0.2

本规范把计划书 v0.3 的 §6–§9 落成可执行的操作手册：谁在什么时候做什么、文件长什么样、分数怎么算、什么算「真的变好」。

---

## 1. 三条总则

1. **分数不优化，流程才优化。** 评分用于定位问题与开处方；任何「把分数当目标」的做法（重评取最高、只报最好一轮、对着 rubric 写）一律禁止。
2. **三轨不合并。** L1 机器判定、L2 盲评、H 人类金标准各自记录；允许合成「发布判定」，不允许合成「优化目标」。
3. **改进只在新文献上认证。** 同一份产物改好再评，只记 `responsiveness`，不进改进账本。

---

## 2. 术语

| 术语 | 含义 |
|---|---|
| SEM | 一次研讨班，`seminars/SEM-XXXX/` |
| CYCLE | 一个改进周期，通常 3 个 SEM |
| L1 | 确定性机器判定，60 分，进发布硬闸 |
| L2 | Mentor 盲评，40 分，诊断用 |
| H | 人类抽查，金标准，不折分 |
| P | 过程分，per-role，100 分 |
| M | 元分，per-cycle，100 分，人类打 |
| veto | 一票否决（编造、译本当原文、关键公式未核对页图） |
| first-pass | 新文献第一次 S8 提交即过发布闸，未退回 S6 |
| responsiveness | 同产物按意见改后再评的提升，不算系统改进 |
| σ | 同一产物重评的标准差，评分噪声估计 |
| anchor | 3 优 3 差校准件，带人类签字的金标区间 |
| season | rubric/judge 冻结周期，通常 10 篇或一个季度 |

## 4. S9 操作手册（按顺序执行）

### 4.1 准备（机器，5 min）

```powershell
python tools\score\check_l1.py --seminar seminars\SEM-XXXX --out seminars\SEM-XXXX\score\scores_l1.json
python tools\score\gate_check.py --seminar seminars\SEM-XXXX --out seminars\SEM-XXXX\score\gate.json
```

`check_l1.py` 失败（非零退出）时，先修数据/格式，不带病评分。

### 4.2 Mentor 盲评（25 min）

输入清单（只给这些）：

- `note/` 终稿（或 `note/*.md`）
- `one_pager.md`
- `errata.md`
- `claims/`、`questions/`（如为结构化文件）
- `map.yaml`
- `manifest.json`（**先删掉** `playbook_version`、`judge_model`、历史分字段，或提供一个 `manifest_blind.json`）
- `rubric.md`（赛季冻结版）
- `anchor` 说明（不给 anchor 分数）

**不得给**：`transcript.md`、`reports/`、`challenges/`、`retro.md`、上一轮 scorecard、round 号、Chair 的计划。

Mentor 输出 `scores_l2.json`：

```json
{
  "seminar": "SEM-XXXX",
  "judge_model": "...",
  "blind": true,
  "dims": {
    "L2-A2": {"score": 6, "max": 8, "evidence": [{"file": "note/ch01.md", "line": 12, "quote": "..."}], "note": "..."},
    "L2-B2": {"score": 8, "max": 12, "evidence": [...], "note": "..."},
    "L2-D":  {"score": 12, "max": 15, "evidence": [...], "note": "..."},
    "L2-E3": {"score": 4, "max": 5, "evidence": [...], "note": "..."}
  },
  "total": 30,
  "no_evidence_deductions": 0,
  "low_confidence": []
}
```

**硬规则**：每个 `score < max` 的维度至少 1 条 evidence；`no_evidence_deductions` 必须为 0，否则评分卡无效。

### 4.3 人类抽查（15 min）

**主动抽样**，不是随机：

1. 所有含展示公式的 claim（最多 3 条）。
2. L2 扣分最重的 2 条对应的 claim。
3. 证据最稀薄（锚点最少）的 2 条 claim。
4. 随机 1 条兜底。

合计 5–10 条，逐条对页图核对，填 `scores_human.json`：

```json
{
  "seminar": "SEM-XXXX",
  "sampling": "active",
  "claim_checks": [
    {"claim": "C-007", "anchor": "[src p.21 eq 5.21]", "verdict": "consistent|wording|anchor_wrong|fabricated", "note": "..."}
  ],
  "retell": {"question": "这篇论文解决了什么？", "pass": true, "note": "..."},
  "disagree_with_l2": false,
  "minutes": 14
}
```

`verdict=fabricated` 或 `anchor_wrong` → 触发 veto 复核；`retell=fail` → 发布否决。

### 4.4 汇总（Mentor + 人类，10 min）

Mentor 由 `scores_l1.json`、`scores_l2.json`、`scores_human.json` 生成 `scorecard.yaml`（模板见 §9），并写 `feedback.md`：

```markdown
# 反馈（SEM-XXXX）

## 一句话
L1 过、L2 差 2 分 → 退回 S7；主要问题是 §6 边界写得不够显式。

## 立即修（P0，本轮）
1. note/§6.3：补「存在性=构造定理 modulo Clemens+ansatz；唯一性=proof-gap」一句，带证据等级。
2. note/§2.2：公式 (5.21) 后补「乘积为一次方」的检查。

## 下一轮改（P1，进 lessons）
1. 关键公式必须独立复算并留痕（→ 新规则 PB-0XX）。
   验证：B2 质询任务中「符号/根号」类缺陷检出率 ≥80%。

## 长期观察（P2）
1. 三读者是否应该按章节而非按视角分工？需要 2 篇数据。
```

人类在 `human_review` 字段写 `ratified: true/false`、`overrides: []`。

## 5. L1 评分细则（60 分）

| 编号 | 分值 | 计算公式/判据 | 数据格式 | 失败处理 |
|---|---|---|---|---|
| L1-C1 | 12 | `12 × min(1, anchor_rate / 0.9)`；`anchor_rate = 有锚点实质断言 / 实质断言` | claims 表需 `source_anchor` | 缺 claims 表 → 0 分并标 `missing` |
| L1-C2 | 8 | 锚点全部可解析且页码在 `page_map` 内 → 8；每条坏锚点 −1，封底 0；编造 → veto | `[src p.N]`、`[eq x.y]`、`[fig x.y]` | 无法解析 → 计坏锚点 |
| L1-F1 | 6 | manifest 六字段齐全 → 6；缺一 −1 | `playbook_version/rubric_sha/judge_model/prompt_hashes/scored_at/scorecard_sha256` | 缺 → 扣分，不 veto |
| L1-F2 | 2 | 术语表存在且无「同一符号两义」→ 2 | `glossary.md` + 扫描 | 无术语表 → 0 |
| L1-A1 | 8 | 9 章齐全 4 分；每章有「真问题/推导/边界」字段，缺一章 −0.5，封底 4 | `map.yaml` + note 标题 | 结构不符 → 0 |
| L1-B1 | 8 | `8 × min(1, checked_ratio / 0.9)`；展示公式需 `checked: true` 与页图锚点 | note 中公式标记 | 无法统计 → 标 `unknown`，按 0 |
| L1-E1 | 8 | 每条结论有等级（甲乙丙丁戊）→ 比例 ×8 | note 结论段 | 缺等级 → 按比例扣 |
| L1-E2 | 4 | `open` 有 rationale 2 分；challenge 的 target 存在 2 分 | questions/challenges schema | 违规项按比例扣 |
| L1-D1 | 4 | ≤800 字 2 分；含问题/做法/疑点三段 2 分 | `one_pager.md` | 超长按 0 计该子项 |

**L1 总分 = 各项之和**。`veto=true` 时 L1 记 0，并在 scorecard 标 `veto_reason`。

**前置检查（不计分，失败即 L1=0）**：

1. 所有评分相关文件以 UTF-8 解码，无 U+FFFD；乱码 → 停，先修文件。
2. `gate_report.json` 存在且 G1–G7 有 `pass/fail/na` + 证据路径；`quality_gate: self-assessed` 不算执行。
3. manifest 含原文/译本/note/scorecard 四个 sha256 + playbook/rubric/judge 三个版本字段。
4. `claims` 的 type/confidence 在 brief 词表内；越界即 schema 失败。

审计教训：SEM-9407087 的三处 `self-assessed` 掩盖了「G1–G7 从未执行」，且 `merged.jsonl` 全乱码、`errata.md` 与 `r03.md` 互相矛盾。这些都不是扣分项，而是**评分的前置条件**——数据不可读时给分等于编分。

**可机械判定的边界**：L1 只做「有没有、格式对不对、比例够不够」；「写得好不好」一律不进 L1。

## 6. L2 评分细则（40 分）

### 6.1 行为锚点

每个维度用 0–4 级行为描述，再映射到分值。**禁止用「很好/一般/较差」这种无行为定义的词。**

#### L2-A2 主线连贯（8 分）

| 级 | 分值 | 行为描述 |
|---|---|---|
| 4 | 8 | 每章开头明确回答「上一章留下什么、本章解决什么」；九章可被一条 5 句话的主线串起；至少 2 处转折有原文依据 |
| 3 | 6 | 主线基本成立，但有 1–2 处章节像「原文目录的复述」 |
| 2 | 4 | 能看出主题，但章节间靠标题连接；删掉一章不影响主线 |
| 1 | 2 | 章节各自为政，读者不知道为什么读这一章 |
| 0 | 0 | 无主线，或主线与论文核心问题不符 |

#### L2-B2 推导质量（12 分）

| 级 | 分值 | 行为描述 |
|---|---|---|
| 4 | 12 | 关键推导（≥5 处）逐步可复算；假设/约定写在推导前；量纲/极限/特例至少核一处；错误率为 0 |
| 3 | 9 | 关键推导可复算，但有 1–2 处跳步未说明；无硬错误 |
| 2 | 6 | 能跟上大意，但至少 1 处关键步骤无法复算，或假设事后才提 |
| 1 | 3 | 多处「显然」「容易得到」；读者无法独立验证 |
| 0 | 0 | 有硬错误（符号/系数/方向），或核心推导缺失 |

#### L2-D 可读性（15 分）

| 级 | 分值 | 行为描述 |
|---|---|---|
| 4 | 15 | 首次读者五问全过；无需回看；未定义符号 0；每个术语首次出现有解释 |
| 3 | 12 | 五问过 4；有 1–2 处需回看，但不阻断 |
| 2 | 9 | 五问过 3；至少 3 处卡点（符号/跳步/长句） |
| 1 | 5 | 五问过 1–2；读者需要外部资料才能继续 |
| 0 | 0 | 五问全不过；或像注疏/词典而非讲解 |

#### L2-E3 边界判断（5 分）

| 级 | 分值 | 行为描述 |
|---|---|---|
| 4 | 5 | 每条主结论标「原文已证/conditional/gap」并给依据；至少 1 处明确指出「这里没证明」 |
| 3 | 4 | 大部分结论有分级，个别含混 |
| 2 | 2 | 有分级但依据不足，或把 conditional 写成已证 |
| 1 | 1 | 只在一处提「未证明」，其余笼统 |
| 0 | 0 | 全部写成「论文证明了」，无视 gap |

### 6.2 评分纪律

- 先写 evidence（引用原文/文件行），再定级；无 evidence 的扣分不计。
- 不因长度、术语密度、页数加减分。
- 三种错分开记：事实（F）、论证（A）、表达（E），在 note 里用前缀标注。
- 置信度 <0.6 标 `low_confidence`，并说明原因；该维度仍给分，但在汇总时标注。

## 7. H 人类抽查协议

### 7.1 抽样

主动抽样 5–10 条（见 §4.3）。**不随机**，因为随机抽样会漏掉最可能出问题的条目。

样本量依据：若编造率为 5%，随机抽 5 条检出概率约 23%，抽 10 条约 40%；主动抽样针对高风险条目，实际检出率显著高于随机。**不追求统计代表性，追求风险覆盖。**

### 7.2 claim 核对表

| 字段 | 取值 |
|---|---|
| claim_id | C-XXX |
| anchor | `[src p.N]` / `[eq x.y]` |
| verdict | consistent / wording / anchor_wrong / fabricated |
| note | 差异一句话 |

- `consistent`：表述与页图/原文一致（允许无损改写）。
- `wording`：意思对但表述可能误导，需修。
- `anchor_wrong`：页码/公式号错，内容可能对。
- `fabricated`：原文没有这个断言，或数字/公式编造。

### 7.3 一页纸复述

让人类（或真人读者）只看 `one_pager.md`，回答：

1. 这篇论文要解决什么问题？
2. 它的核心做法是什么？
3. 结论是什么？
4. 哪里还没证明？
5. 你会先读哪一章？

五问中 ≥4 个能答对 → pass。此测试同时用于 Tier-3 外部效度。

## 8. 过程分（100/角色）

### 8.1 计算

```
P_total = Σ (dim_score × role_weight)
```

每个维度先按 0–100 打分，再乘权重。机器可算的维度（P2/P5/P6/P7）由脚本给原始指标，按线性映射；人工维度（P1/P3/P4）由 Mentor 按行为锚点打分。

### 8.2 角色权重

| 维度 | Reader | Examiner | Chair | Editor | Textual Critic |
|---|---|---|---|---|---|
| P1 指令遵循 15 | 10 | 10 | 20 | 30 | 20 |
| P2 证据纪律 20 | 30 | 25 | 15 | 10 | 30 |
| P3 对抗质量 20 | 15 | 30 | 5 | 0 | 15 |
| P4 错误发现与自纠 15 | 25 | 20 | 25 | 0 | 20 |
| P5 协作交接 10 | 10 | 5 | 20 | 15 | 5 |
| P6 成本效率 10 | 5 | 5 | 10 | 25 | 5 |
| P7 资产增量 10 | 5 | 5 | 5 | 20 | 5 |

**P3 必须同时记两个数**：`accept_rate`（被质询方接受的比例）与 `reject_correct_rate`（正确驳回的比例）。只看 accept 率会奖励「一律接受」；只数质询条数会奖励「乱开枪」。两者都进 P3 的 20 分，权重大致各半。

**P2 的字数/claims 统计必须由脚本以 UTF-8 读取**；人工目测或 ANSI 读取的数字（审计中曾虚高 1.7×）不得进评分卡。

### 8.3 等级

| 等级 | 分数 | 含义 | 动作 |
|---|---|---|---|
| A | 90–100 | 可作模板 | 记录其做法进 playbook |
| B | 80–89 | 合格 | 正常 |
| C | 70–79 | 需带教 | 下一篇配更强 Reader/更细 brief |
| D | <70 | 需换人或换任务 | 触发复盘；连续 2 篇 D 停用该角色配置 |

过程分只用于带教与定位，**不进发布闸**。

## 10. incident 账本

### 10.1 严重度

| 级别 | 定义 | 例子 | 处理 |
|---|---|---|---|
| S1 | 硬错误/编造/方向反 | 根号套错、编造页码、把「电凝聚→磁禁闭」写反 | 产品 veto；角色记 D；必须进 lessons |
| S2 | 证据不足/条件漏/能标混 | 未写 Λ=1；把 N=2 QED 结论用于 N=1 SQED | 扣分；要求 errata 修正 |
| S3 | 流程/边界违规 | 越界改写、第一轮互看、轮询 | 过程分扣分；不改产品 |

### 10.2 字段

```json
{"id":"I-0001","seminar":"SEM-XXXX","severity":"S1","type":"HARD_ERROR","actor":"r01","detected_by":"r02","artifact":"reports/r01.md:123","anchor":"[src p.21 eq 5.21]","description":"...","status":"confirmed","resolution":"errata.md#L12","lesson":"L-0003"}
```

`type`：HARD_ERROR / FABRICATION / EVIDENCE_GAP / CONVENTION / DIRECTION / SCALE / PROCESS / GATE_SKIPPED / ROLE_ABSENT / ENCODING。

审计新增的三类：`GATE_SKIPPED`（声称过了闸但没有执行证据）、`ROLE_ABSENT`（该执行的角色 0 产物）、`ENCODING`（乱码/编码不一致）。这三类默认 S2；若掩盖了硬错误则升 S1。

**每条 S1 必须对应一条 lesson 或写明「无需流程改动」的理由。**

## 11. lesson 与 playbook

### 11.1 lesson 状态机

```
proposed → trialed → adopted → (deprecated)
              └────→ rejected
```

- `proposed`：S10 提出，带证据/根因/处方。
- `trialed`：已进一个周期试跑。
- `adopted`：人类批准，绑定 `playbook_rule`。
- `rejected`：人类拒绝，必须写理由。
- `deprecated`：规则日落，保留历史。

### 11.2 playbook 规则字段

```yaml
- id: PB-001
  title: "..."
  status: active          # active | trial | deprecated
  category: SPEC          # SPEC | ASSET | HUMAN | QUALITY | ANTI
  applies_to: [S6, Chair]
  rule: "..."
  evidence: [L-0001]
  verify: "..."
  since: 0.3.0
  sunset_after: 2         # 周期数；到期无效果则 deprecated
```

### 11.3 lint 规则

- 规则数 ≤40；每条 `evidence` 非空且指向存在的 lesson。
- `status=active` 的规则必须有 `verify`。
- prompt 渲染后总 token ≤6000（用 `playbook_render.py` 检查）。
- 同一规则不得同时出现两个 `status`。
- 每周期净增规则 ≤3，且必须删除等量或说明理由。

```markdown

- 来源 lesson：L-XXXX
- 假设：如果把 X 改成 Y，Z 指标会上升，因为……
- 改动：文件 + 具体 diff
- 影响范围：哪些角色/阶段
- 验证计划：
  - 指标：...
  - 样本：Tier-1 B? / 新文献 N 篇
  - 成功：≥2σ 或首次通过率 +1
  - 失败：回滚
- 回滚方式：`_meta/playbook/archive/vX.Y.Z.yaml`
- 成本：token/人时
- 风险：可能副作用
```

人类批准后：`playbook.yaml` 版本 +0.1，`changelog.md` 记一行，lesson 状态 `adopted`。

## 13. 周期评审议程（60–90 min）

1. **数据（10 min）**：首次通过率、L1/L2 分布、人类时间、incidents 类型 top3。
2. **哨兵（10 min）**：anchor good/bad/gap、σ、无证据扣分率、长度相关性。
3. **归因（20 min）**：每条重复 incident 问「是流程、模型、题目还是人手？」只有流程问题才 patch。
4. **选 patch（20 min）**：从 lessons 选 ≤3 条，写提案（§12）。
5. **bench（15 min）**：跑 Tier-1；看是否 ≥2σ 或非劣。
6. **决定（10 min）**：人类批准/拒绝；更新 playbook/changelog/ledger。
7. **记录（5 min）**：`_meta/rounds/round-XXXX/verdict.md`。

## 14. 哨兵与 σ 协议

### 14.1 Phase 0 测 σ（必须做）

1. 取 SEM-9407087 的盲评输入（§4.2 清单）。
2. 同一 Mentor、同一 rubric、temperature 固定，独立评 5 次（每次新 session）。
3. 记录 L2 总分与四维分数；算均值、σ、极差。
4. 若 σ >5：先改 rubric 锚点（更行为化）或降低 temperature，再测；仍 >5 → L2 只作诊断，不作发布闸的唯一依据。
5. 结果写入 `_meta/drift.md`，并作为 2σ 阈值的依据。

### 14.2 每周期哨兵

```
for anchor in good_01..03, bad_01..03:
    score = Mentor(anchor)   # 3 次取均值
record: good_mean, bad_mean, gap, sigma
```

报警：
- `bad_mean` > 金标上限 → Mentor 变松。
- `good_mean` < 金标下限 → Mentor 变严/漂移。
- `gap` 缩小 >20% → 区分度下降。
- `sigma` >5 → 评分不可用。

报警时：暂停新评分，先修 judge prompt/rubric；已评的分数标 `unreliable`，不进趋势。

### 14.3 双尺并行（rubric 变更时）

用旧 rubric 与新 rubric 同时评同一批历史产物（≥5 份）。若「新尺−旧尺」在历史产物上就已存在，说明是尺子变了，不是产物变好；此时不能宣布改进。

## 15. benchmark 协议

### 15.1 Tier-1 任务定义

见 `bench/tasks/*.yaml`。每个任务必须包含：

```yaml
id: B1
name: 地图任务
input: bench/papers/<注册表登记>   # 文件名与 sha256 见 bench/papers/README.md
expected:
  concepts: [..8 个..]
  traps: [..3 个..]
scoring: "命中数/8 - 误报数/3"   # 具体公式
pass: "≥ baseline - 2*sigma"
leak_control: "不得进入生产批次；Mentor 不得见"
```

### 15.2 通过标准

- 任一任务不得低于上一版 −2σ（未测 σ 前用 −5 分保守值）。
- 至少 1 个任务提升 >2σ。
- 无闸门回退（veto/schema/manifest）。
- 不满足 → patch 回滚，记 `reverted`。

### 15.3 污染控制

- `bench/papers/` 永不进入 `seminars/`；文件名与哈希登记在 `bench/README.md`。
- 生产 prompt 不含 bench 内容；Mentor 的 S9 prompt 不含 bench。
- 每 2 季度轮换 1 个 Tier-1 任务；旧任务退役但保留结果。
- 每篇论文只用于一个 Tier-1 任务，避免跨任务泄露。

## 18. Mentor prompt 骨架（赛季冻结版）

```markdown
你是 AI 研讨班的导师（Mentor）。你只做评价，不写作、不修改、不代写。

## 你能看到的
- 产物：note/、one_pager.md、errata.md、claims/、questions/、map.yaml、manifest_blind.json
- 评分标准：rubric.md（本文件）
- 校准说明：anchor 的行为描述（不含分数）

## 你不能看到的
- 生产过程：transcript.md、reports/、challenges/、Chair 的计划
- 历史：round 号、上轮分数、上轮 feedback
- 其他 Mentor 的分数

## 你必须做的
1. 逐维评分：L2-A2(8)、L2-B2(12)、L2-D(15)、L2-E3(5)。
2. 每个扣分给证据：文件:行 或 [src p.N] / [eq x.y]；无证据不得扣分。
3. 先写「我看到了什么」，再写「这值几分」。
4. 分开记事实错（F）、论证错（A）、表达错（E）。
5. 给三条处方：P0 立即修、P1 下一轮改、P2 长期观察；P1 必须写「改哪个文件哪条 + 怎么验证」。
6. 置信度 <0.6 的维度标 low_confidence。

## 输出格式
严格输出 JSON（schema 见 scores_l2.schema.json），不要输出 JSON 以外的文字。
```

`rubric.md` 由人类维护，赛季冻结；Mentor 不得改。
