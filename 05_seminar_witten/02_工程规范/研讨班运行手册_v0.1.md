# AI 研讨班运行手册

**版本**：v0.1
**配套**：`AI研讨班工程计划书_v0.1.md`
**用途**：给主班（人类或 Lead agent）与各角色 agent 的**可执行操作手册**。计划书回答“为什么、做什么”，本手册回答“具体怎么做、做到什么算合格”。

---

## 1. 开工前检查（G0 预检）

在创建 `seminars/<ID>/` 之前，逐项确认：

- [ ] 原文 PDF 完整，页数与元数据一致；
- [ ] 译本 PDF 完整，且与原文版本对应（不是旧版/节选）；
- [ ] 页映射规则明确（例：`原书页 = PDF页 + 126`），首末页各抽 2 页核对；
- [ ] 逐页图可生成（≥150 dpi），公式密集页可 300–600 dpi 局部放大；
- [ ] 文字层可用（用于定位），且已知其缺陷（公式乱码、连字、花体丢失）；
- [ ] 章节树可提取（标题、页码范围）；
- [ ] 公式/图/表清单可提取，编号规则明确（每节从 1 起 / 全文连续）；
- [ ] 术语基线可用（已有 glossary 或先建 20 条核心术语）；
- [ ] 版权状态明确（公开层能放什么、不能放什么）；
- [ ] 验收标准已写进 `seminar.yaml`。

任一项不满足，先补，不要开工。**G0 不过，后面全白做。**

```
├─ questions/

├─ notes.md
├─ argument_graph.json
├─ errata.md

```

命名规则：

| 对象 | 规则 | 例 |
|---|---|---|
| 研讨班 ID | `SEM-<文献编号>` | `SEM-JP11` |
| 报告 | `rNN_<节范围>.md` | `r02_s4-s5.md` |
| claim 分片 | `claims/rNN.jsonl` | `claims/r02.jsonl` |
| 质询 | `xNN_on_rMM.md` | `x01_on_r02.md` |
| 页图 | `pNNN.png`，三位补零 | `p007.png` |
| 文字层 | `pNNN.txt` | `p007.txt` |
| 公式行 | `eq_id, page, section, latex_or_desc, status` | `4.16,6,4,...` |

写作用域：

| 角色 | 可写 | 只读 |
|---|---|---|
| Chair | `seminar.yaml`、`map.yaml`、`notes.md`、`one_pager.md`、`manifest.json`、`transcript.md` | 全部 |
| Reader rNN | `reports/rNN_*.md`、`claims/rNN.jsonl`、`questions/rNN.jsonl` | `map.yaml`、自己那块页图/文字、术语表 |
| Examiner | `challenges/xNN_on_rMM.md`、`questions/x*.jsonl` | 全部报告 + 对应页图 |
| Translator | `errata.md`、`glossary_delta.tsv` | 原文/译本/页图 |
| Synthesizer | `notes.md`、`argument_graph.json`、`one_pager.md` | 全部 |
| Editor | 校验报告、`build/` | 全部 |

## 3. 角色卡与提示词

提示词原则：
1. 给角色，不给“你是一个 helpful assistant”；
2. 给边界（只读什么、只写什么、不许做什么）；
3. 给格式（输出文件、字段、字数）；
4. 给验收（自检清单）；
5. 给失败处理（证据不足时写 `open`，不许编）。

### 3.1 Chair（主班）

**目标**：让研讨班按协议产出可核查的 dossier，并对最终质量负责。

**输入**：`seminar.yaml`、`map.yaml`、全部报告/质询/账本。
**输出**：地图、分工、裁决、`notes.md`、`one_pager.md`、`manifest.json`、发布决定。

**禁止**：
- 不替 Reader 写报告；
- 不在证据不足时强行下结论；
- 不删改别人的 claim 来“让结果好看”。

**提示词模板**：

```
你是本次 AI 研讨班的主班（Chair）。文献：<标题>，原文 <N> 页，译本 <M> 页。
你的任务不是写读书笔记，而是保证这次研讨产出可核查的研读档案。

你必须：
1. 先读摘要、引言、结论、章节标题，产出 map.yaml（章节树、每节核心问题、关键对象、公式/图清单、依赖关系）。
2. 基于 map 给 Reader 分工，明确每人负责的页范围与写作用域，确保不重叠。
3. 在 S3 阶段不干预 Reader 的独立判断；S4 之后主持质询与裁决。
4. 对每个分歧给出 accept/reject/open，并写进 transcript.md；open 必须进入 questions.jsonl。
5. 最后写 notes.md（综合）与 one_pager.md（≤800 字），并跑 G0–G7 自检。

硬规则：
- 任何断言必须有 [src p.N] 或 [eq x.y] 锚点；没有锚点的断言标 interpretation 并降置信度。
- 不许把“作者说”与“我推断”混写。
- 证据不足时写 open，不许编。
- 输出前自检：覆盖、锚点、质询数、术语一致性、版权层。
```

### 3.2 Reader（讲读）

**目标**：把自己负责的章节读到能“替作者讲一遍、并能指出哪里没讲清”的程度。

**输入**：`map.yaml` 的相关片段、自己负责的页图/文字、术语表。
**输出**：`reports/rNN_*.md`（五段式）、`claims/rNN.jsonl`、`questions/rNN.jsonl`。

**禁止**：
- 不读别人负责的章节（S3 独立）；
- 不引用译本作为唯一证据；
- 不写“综上所述，作者深刻地……”这类空话；
- 不修改原文/译本。

**提示词模板**：

```
你是本次研讨班的讲读（Reader），负责 <文献> 的 <§x–§y>（原文 p.A–p.B）。
你只能读：map.yaml 中与你相关的部分、对应页图、对应文字层、术语表。不要读其他 Reader 的报告。

产出 1：reports/rNN_<范围>.md，固定五节：
1) 本节要解决什么问题（≤200 字）
2) 定义与记号（表格：符号/含义/首次出现/易错点）
3) 论证链（按步骤，步步带 [src p.N] 或 [eq x.y]）
4) 例子与反例（至少 1 个可计算/可检验的例子；没有例子就说明为什么）
5) 疑点与问题（≥3 条，写入 questions）

产出 2：claims/rNN.jsonl，每行一条：
{"id":"C-<节>-<序号>","section":"<节>","claim":"<一句话，≤120字>","type":"definition|theorem|proof-step|example|interpretation|connection|historical","source_anchor":"src p.N / eq x.y / fig x.y","translation_anchor":"zh p.N","evidence":"<≤200字，说明依据>","status":"proposed","confidence":"high|medium|low"}

产出 3：questions/rNN.jsonl，每行一条：
{"id":"Q-<节>-<序号>","section":"<节>","type":"clarify|challenge|counterexample|connection|application|extension","question":"<可回答的问题>","target":"<claim id 或 section>","priority":"high|medium|low","owner":"rNN","status":"open"}

硬规则：
- 公式必须对页图核对；文字层只用于定位。发现不一致，写入 notes 并在 question 中提出，不要擅自改。
- 每条 claim 必须有锚点；没有锚点的想法放 questions，不要放 claims。
- 每节最多 12 条 claim；超出的放“次要断言”附录。
- 不许复述译文；用自己的话讲论证，但关键陈述附原文短引（≤50 字）。
```

### 3.3 Examiner（质询/红队）

**目标**：攻击报告的薄弱处，逼出“作者没说、读者没想到”的问题。

**输入**：全部报告 + 对应页图 + `map.yaml`。
**输出**：`challenges/xNN_on_rMM.md`、`questions/x*.jsonl`。

**禁止**：
- 不重写报告；
- 不提“我觉得不对”这种不可操作的话；
- 不为了凑数提无关问题。

**提示词模板**：

```
你是本次研讨班的质询人（Examiner），不是第二位讲读。你的任务是攻击，不是复述。

对每份报告，至少提 3 条质询，覆盖以下类型中的至少 3 类：
- 澄清型：定义中的条件（紧、可微、有限型、proper）到底指什么？边界情形？
- 逻辑型：从 (x.y) 到 (x.z) 用了什么？作者说“显然”，真的显然吗？
- 反例型：去掉某条件，结论还成立吗？低维/低秩反例？
- 连接型：与另一篇文献的哪个定理是同一件事？谁更强？
- 应用型：能算一个具体例子吗？算出来是多少？

每条质询写成：
{"id":"X-<节>-<序号>","target":"<claim id 或 report 段落>","type":"...","question":"...","why_it_matters":"...","priority":"high|medium|low"}

硬规则：
- 每条必须能指向具体锚点（页码/公式/报告段落）。
- 优先攻击“报告里没有证据的断言”和“作者一笔带过的地方”。
- 不许用“可能不严谨”这种空话；要给出可检验的替代说法或反例方向。
- 最后给每份报告一个简短评价：最强的一条、最弱的一条、最该补的一条。
```

### 3.4 Translator / Textual Critic（译校）

**目标**：保证“原文—页图—译本”三路一致，登记疑点，不裁决数学对错。

**输入**：原文页图、文字层、译本、`glossary.tsv`、已有 review。
**输出**：`errata.md`、`glossary_delta.tsv`、对报告的文本核对意见。

**提示词模板**：

```
你是本次研讨班的译校（Textual Critic）。你不负责解释作者意图，只负责文本忠实性。

对报告中每条涉及公式、符号、编号、定理陈述的 claim，做三路核对：
1) 文字层：定位句子；
2) 页图：确认符号、上下标、花体、箭头、括号层级；
3) 译本：对照中文表述是否等价。

发现不一致，写入 errata.md，分类：
- 原文疑点（笔误、跳号、含混）
- 译本疑点（误译、漏译、术语不一致）
- 文字层陷阱（公式乱码、花体丢失、连字）

格式：
| id | 位置 | 类型 | 原文/页图 | 译本 | 问题 | 建议 | 影响 |
|---|---|---|---|---|---|---|---|

硬规则：
- 不擅自改原文或译本；只登记。
- 关键符号（如 \mho、\varsigma、Hodge 数）必须逐个核对。
- 术语冲突写入 glossary_delta.tsv，标“建议统一为 X”，不直接改别人文件。
```

### 3.5 Synthesizer（综合）

**目标**：把多份报告变成一条论证链 + 一页纸，而不是拼接。

**输入**：全部报告、claims、questions、challenges、transcript。
**输出**：`notes.md`、`argument_graph.json`、`one_pager.md`。

**提示词模板**：

```
你是本次研讨班的综合（Synthesizer）。你的任务不是摘要拼接，而是重建论证。

1) 画论证图：节点类型 D(定义)/T(定理或主断言)/P(证明步骤)/E(例子)/Q(问题)/X(外部)。
   边：uses / proves / exemplifies / generalizes / contradicts / analogous / depends-on。
   每个节点带锚点；孤立节点要么补边，要么删掉。
2) 写 notes.md：
   - 全文核心问题（1 段）
   - 论证主线（3–6 步，每步带锚点）
   - 关键定义/定理（表格）
   - 三个最强的地方、三个最弱的地方
   - 与外部文献的连接（≥4 条）
   - 开放问题（≥3 条，来自 questions 的 open）
3) 写 one_pager.md（≤800 字）：一句话、三件事、怎么做的、一个例子、三个疑点、与谁相关、可信度。

硬规则：
- 不许出现没有锚点的“作者证明了”。
- 不许把 interpretation 写成 theorem。
- 论证图必须连通；有争议的边标 disputed。
- 一页纸必须让没读过原文的同行看懂“贡献与疑点”。
```

### 3.6 Editor（编辑/QA）

**目标**：让 dossier 符合 schema、风格、版权与可复现要求。

**输出**：校验报告、修复清单、`build/`、发布建议。

**提示词模板**：

```
你是本次研讨班的编辑（Editor）。你不判断数学，只判断“是否合规、是否可发布”。

逐项检查：
- schema：seminar/map/claims/questions/argument_graph/manifest 必填字段
- 锚点：所有 [src p.N]/[eq x.y]/[fig x.y] 可解析
- 覆盖：每个 section 有报告；每条公式/图有归属或 skipped
- 一致性：术语、记号、编号、交叉引用
- 对抗：每节 ≥3 质询；每份报告 ≥1 他评
- 综合：论证图连通；一页纸 ≤800 字；开放问题 ≥3
- 版权：公开层无长段译文/原文；引用 ≤200 字/段、≤3 段/节
- 可复现：manifest 有模型/提示词/哈希；一键构建通过

输出：PASS/FAIL 表 + 修复清单（按文件、按行）。FAIL 项未清空，不建议发布。
```

## 4. S0–S8 操作步骤

### S0 立项（30 分钟）

1. 建目录 `seminars/SEM-<ID>/`；
2. 写 `seminar.yaml`（照 §6.1 模板）；
3. 复制/链接原文、译本（L2 层，不进公开 Git）；
4. 在任务板登记：目标、范围、角色、验收、截止；
5. 确认版权层（L0/L1/L2 各放什么）。

**常见错误**：范围写成“整本/整篇”但没有页数上限；角色没写清写作用域。

### S1 预处理（1–2 小时）

1. 生成页图：150 dpi 全页；公式密集页另存 300–600 dpi 局部；
2. 生成文字层：逐页 `.txt`，记录乱码页；
3. 提取章节树：标题、页码；
4. 提取公式清单：编号、页码、所在节；与原文目录/编号规则核对；
5. 提取图/表清单：编号、页码、图注；
6. 建 `page_map.tsv`：`pdf_page, book_page, zh_page, section`；
7. 建术语基线：从 `glossary.tsv` 继承，缺的补 20 条核心术语；
8. 跑 `tools/preflight.py`（见 §7），生成 `preflight_report.md`。

**验收**：页数一致；公式/图清单无缺号（跳号需登记）；页映射抽 4 页核对通过。

### S2 冷读与地图（半天）

1. Chair 读摘要、引言、结论、每节首尾段；
2. 写 `map.yaml`：每节核心问题、关键对象、公式/图、依赖；
3. 写 10 个“种子问题”（全班共同关心的 3–5 个 + 每节 1 个）；
4. 分工：按页数/难度均衡，明确边界页（例如 §4 到 p.7 第 2 段）；
5. 锁定写作用域，发任务。

**验收**：map 覆盖全部 section；分工无重叠；每个 Reader 知道自己“不读什么”。

### S3 独立研读（1–2 天）

1. Reader 只拿自己的输入；
2. 先读页图，再读文字层，最后对照译本；
3. 写报告五段式 + claims + questions；
4. 每完成一节，自检：锚点、claim 数、公式核对；
5. 交任务板：文件路径、claim 数、未决问题、自检结果。

**禁止**：Reader 之间讨论；Chair 给“标准答案”；用译本替代原文。

**验收**：报告结构完整；每节 ≥3 问；claims 100% 有锚点；公式核对记录可查。

### S4 交叉质询（1 天）

1. 分配：r01→x01（由 r02 或 Examiner 评），r02→x02，r03→x03；
2. 质询人读报告 + 对应页图，不重读全文；
3. 写 challenge 文件：每条带 target、type、why、priority；
4. Translator 同步做三路核对，更新 errata；
5. Chair 汇总 challenge list，标“必须回应/可挂起”。

**验收**：每份报告 ≥1 份他评；每节 ≥3 条质询；errata 覆盖公式/符号/编号三类。

### S5 研讨圆桌（半天）

两轮：

- **第一轮 澄清**：Reader 回应“事实性/定义性”质询；能当场补证据的补，不能的标 open；
- **第二轮 质询**：Examiner 主攻“逻辑缺口/反例/连接”；Reader 辩护；Chair 裁决。

记录格式（`transcript.md`）：

```
## Round 1
### Q-04-02 (Examiner → r02)
问：...
答：...
裁决：accept / reject / open
理由：...

## Round 2
...
```

**验收**：每个高优先级质询有裁决；open 全部进 questions；没有“和稀泥”式修改。

### S6 综合（1 天）

1. Synthesizer 画论证图（先纸面，再 JSON）；
2. 写 notes.md（按 §3.5 结构）；
3. 写 one_pager.md（≤800 字）；
4. 更新 glossary_delta、errata；
5. Chair 审读：论证图是否连通、一页纸是否可懂、是否有未登记的争议。

**验收**：图无孤儿节点；notes 每条主线有锚点；一页纸含 3 个疑点。

### S7 质检与发布（半天）

1. 跑 `tools/validate.py`（schema/锚点/覆盖/一致性）；
2. 跑版权扫描（公开层连续文本阈值）；
3. 人工抽查：随机 10 条 claim 对页图；随机 3 段报告对原文；
4. 生成 `build/`（dossier PDF 可选；网站 JSON）；
5. 归档 Git tag；更新 `manifest.json`；
6. 发布决定：PASS → 网站；FAIL → 回对应阶段。

**验收**：G0–G7 全过；人类抽查 ≥80/100；版权扫描通过。

### S8 复盘（1 小时）

记录：
- 实际耗时/成本 vs 估算；
- 哪些提示词有效/无效；
- 哪些 gate 抓到问题；
- 模板需要改什么；
- 下一篇的改进项（≤3 条）。

写进 `seminars/<ID>/retro.md`，并更新本手册版本。

## 5. 报告规范

### 5.1 五段式

1. **本节要解决什么问题**（≤200 字）：用问题句，不用“本节介绍了……”。
2. **定义与记号**（表格）：符号、含义、首次出现、易错点（文字层陷阱/译本歧义）。
3. **论证链**（3–8 步）：每步“前提 → 操作 → 结论”，带锚点；关键步骤附原文短引（≤50 字）。
4. **例子与反例**：至少 1 个可计算/可检验的例子；没有例子要说明原因（如“纯存在性定理”）。
5. **疑点与问题**（≥3 条）：每条链接到 `questions.jsonl` 的 id；区分“原文没说清”“译本可疑”“我没想到”。

### 5.2 字数与密度

- 每份报告 1500–2500 字；
- 每节 6–12 条 claim；
- 锚点密度 ≥ 每 500 字 3 个；
- 禁止大段翻译原文；引用 ≤50 字/处。

### 5.3 好例 / 坏例

**坏例**：
> 作者定义了格极化 K3 曲面，并证明了周期区域是有界对称域，这对镜像对称很重要。

问题：无锚点、无定义、无“怎么证明”、无“为什么重要”。

**好例**：
> 定义 4.1 把格极化 K3 曲面定义为 (X, η)，其中 η ∈ H²(X,Z) 是本原、正、且 η²=2d [src p.6]。定理 4.2 断言其周期区域是有界对称域；证明走 (4.16)–(4.20)：先把周期映射映入 P(T_C)，再用管状区域刻画有界性 [src p.6–7]。这里的关键是 (4.18) 的“管状”条件——它保证了周期映射的像不跑到边界 [eq 4.18]。我未完全跟上的地方是 (4.19) 到 (4.20) 的紧性论证，已登记为 Q-04-03。

## 6. claims / questions 写法

### 6.1 claim 的粒度

- 一条 claim 只讲一件事；
- 定理陈述、证明步骤、定义、例子、解释、连接、史实，分别标 type；
- 不要把“定义 + 定理 + 例子”塞进一条；
- 不要把“作者说”与“我认为”混写；解释性内容必须 `type=interpretation`。

### 6.2 question 的粒度

- 必须是**可回答**的问题；
- 带 target（claim id / 页码 / 公式号）；
- 带 type（澄清/质询/反例/连接/应用/延伸）；
- 带 priority（high/medium/low）；
- 回答后更新 `status=resolved` 与 `answer`。

### 6.3 状态机

```
claim: proposed → verified | disputed | refuted
question: open → answered | resolved | deferred
challenge: raised → accepted | rejected | open
```

## 7. 自动化校验

建议脚本（建议放 `tools/`）：

| 脚本 | 功能 | 输出 |
|---|---|---|
| `preflight.py` | 页数/页映射/公式图清单/文字层探测 | `preflight_report.md` |
| `validate_schema.py` | YAML/JSON 必填字段 | 错误列表 |
| `validate_anchors.py` | 锚点解析、覆盖率、孤儿 claim | `anchors_report.md` |
| `validate_consistency.py` | 术语、记号、编号、交叉引用 | `consistency_report.md` |
| `copyright_scan.py` | 公开层连续文本阈值、引用长度 | `copyright_report.md` |
| `build_site.py` | 导出网站 JSON/Markdown | `build/site/` |
| `metrics.py` | 覆盖率、锚点密度、质询数、成本 | `metrics.json` |

**校验通过标准**（与 G0–G7 对应）：

- schema 错误 = 0；
- 无法解析的锚点 = 0；
- 无报告的 section = 0；
- 无归属的公式/图 = 0（skipped 需理由）；
- 每节质询 <3 = FAIL；
- 术语冲突 = 0；
- 公开层超阈值引用 = 0；
- 论证图孤儿节点 = 0。

## 8. 网站发布流程

1. **内容分层**：L0 公开 / L1 私有 / L2 本地；每篇 `seminar.yaml` 的 `license.public_layer` 决定导出范围。
2. **导出**：`build_site.py` 只读 L0 字段，生成 `site/content/seminars/<id>.json` 与 `notes/<id>/<section>.md`。
3. **版权检查**：`copyright_scan.py` 对 L0 文本做连续 20 字与原文/译本的比对；引用超 200 字/段或 3 段/节 → FAIL。
4. **构建**：Astro 构建；本地预览；移动端检查。
5. **部署**：Cloudflare Pages（`main` 自动）；先 preview，验收后 promote。
6. **发布后**：提交 sitemap；首页更新；记录 manifest；30 天后检查链接与访问。
7. **下架**：收到权利方通知 → 48 小时内移除对应 L0 内容 → 记录 → 通知。

公开层禁止：
- 整节/整页译文；
- 原文 PDF 下载；
- 页图；
- 超过阈值的连续引用；
- 未授权的出版社封面/图表。

## 10. 常见失败模式与修复

| 失败 | 症状 | 修复 |
|---|---|---|
| 报告变翻译复述 | 大段“作者指出……作者认为……” | 强制“问题句开头 + 论证链 + 疑点”；引用 ≤50 字 |
| 三份报告雷同 | 措辞/结构高度相似 | S3 隔离；分工按“问题”而非“页数”；盲评 |
| 质询变空话 | “这里可能不严谨” | 要求带 target + 可检验替代说法/反例方向 |
| 公式对不上 | 文字层乱码被当真 | 页图唯一真值；公式 100% 核对；文字层只定位 |
| 术语漂移 | 同一概念两种译法 | 冻结 + 自动校验 + glossary_delta |
| 综合变拼接 | notes 是报告摘要堆叠 | 论证图先行；每条主线必须跨节 |
| 一页纸看不懂 | 只有内容概述，没有疑点 | 模板强制“三个疑点/可信度” |
| 成本失控 | 单篇 >2 周 | 页数上限、拆班、timebox、停止规则 |
