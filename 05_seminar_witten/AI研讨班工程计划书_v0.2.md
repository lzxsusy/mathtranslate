# AI 研讨班工程计划书 v0.2

### 以“可读读书笔记”为产品模板

> 后人哀之而不鉴之，亦使后人而复哀后人也。
> ——杜牧《阿房宫赋》

**版本**：v0.2（2026-11-10）  
**状态**：取代 v0.1；v0.1 保留，作为本计划书的反面例子。  
**一句话**：态度可以像古人，做学问的方式不能像古人；交付物必须是一份第一次读这篇论文的学生能走完的读书笔记，而不是一套“四家注疏”。

---

## 0. 这份计划书为什么重写

v0.1 把“AI 研讨班”的流程写对了，却把“产品”写错了。

它把 dossier 十件套——报告、claims、质询、圆桌、errata——当成了最终交付物；又把这套内部证据链直接排成了“题解、凡例、序、八卷、附录”的注疏体。结果是：信息很全，读者进不去。

新版《威腾文章阅读笔记》证明另一条路是可行的：先搭骨架，再补推导，最后标边界；四家的争论放在内部，正文只留经过裁决的叙述。这份 v0.2 就是把那条路固化成可复用的工程。

> 用你的话说：我们不能够到了经典，还像古人那样做学问，我们要有我们做学问的方式。但是我们对于这种经典的态度，要像古人那样。

这句话是整份计划书的纲。下面把它拆成两条互不混淆的原则。

---

## 1. 两条原则：态度与体裁

### 1.1 对经典的态度，可以像古人

- 逐字核对原文，不放过一个符号；
- 先定术语、再开译/开写；
- 对可疑处存疑，不替作者圆场；
- 把“版本、页码、文字层、页图”当作证据，而不是装饰；
- 对经典保持敬畏：不轻易说“作者错了”，但也不轻易说“作者对了”。

这些是研究方法，应该继承。

### 1.2 做学问的体裁，不能像古人

- 不能一开篇就是“题解、凡例、序、八卷”；
- 不能把【原文】【注】【疏】【按】【诸家】当成正文骨架；
- 不能要求读者“先懂，才能读”；
- 不能把“四家异同”放在正文最显眼的位置；
- 不能以“全”代替“通”。

**注疏是研究方法，不是交付格式。** 把注疏体直接当产品，是把“对经典的态度”误当成了“做学问的方式”。

### 1.3 产品的一句话定义

> 一份 20–35 页的读书笔记：第一次读这篇论文的学生，能从第一页读到最后一页；读完知道论文要解决什么问题、主线怎么走、哪些是推导、哪些是假设、哪些还没证明。

## 2. 反面例子：v0.1 与旧版 PDF

这一章不是自我批评表演，是把错误编码进流程，避免“后人复哀”。

### 2.1 事实

- v0.1 计划书：`<本地路径>`
  - 产物定义为 dossier 十件套；
  - 质量指标偏重覆盖率、claims 数、质询数；
  - 排版沿用“注疏体”。
- 旧版成品：`<本地路径>`
  - 14 页；
  - 标题页四家署名；
  - 题解、凡例、序、八卷、附录；
  - 正文以【原文】【注】【疏】【按】【诸家】组织。
- 用户评价：**“非常糟糕。”**

### 2.2 症状

1. **读者必须先懂，才能读。** 开篇是凡例和题解，不是“这篇文章要解决什么问题”。
2. **以“全”代“通”。** 四家异同、逐条注疏、M1–M12 裁决都堆在正文，主线被淹没。
3. **以“注疏体”冒充“古人态度”。** 形式复古，理解成本高；读者看到的是“经注”，不是“导读”。
4. **缺“骨架—推导—边界”的主线。** 读者不知道哪条是主线，哪条是旁枝。
5. **没有目标读者测试。** 质量由“写的人觉得全不全”判断，不由“第一次读的人能不能走完”判断。

### 2.3 根因

- **产品定义错误**：把 backstage 的 dossier 当成 final product。
- **质量定义错误**：以“全”为质量，而不是以“可读、可复现、边界清楚”为质量。
- **模板错误**：直接套用注疏体，把“研究方法”误当“交付格式”。
- **评审错误**：评审席上全是“已经读懂的人”，没有“第一次读的人”。

### 2.4 代价

- 返工：旧版 14 页基本作废，重写为 20 页可读版；
- 用户时间：用户要读完才发现“不是这个”；
- 信任：如果下一次还这样，研讨班工程就会变成“自嗨的注疏生产”。

### 2.5 鉴：三条硬规则

1. **先写目标读者与读完能做什么，再写正文。** 写不出来，不许开工。
2. **注疏标签只能出现在内部报告，不能出现在 final note。** 出现即退回。
3. **final note 必须通过“新手五问”测试。** 不过不发布。

> “后人哀之而不鉴之”——鉴不是记住一句教训，而是把教训变成闸门。这份计划书后面的 G4 可读性闸门、Reader Advocate 角色、反面清单，都是“鉴”。

## 3. 产品：`reading_note` 是主交付物

### 3.1 主交付物

`seminars/SEM-XXXX/note/` 下的读书笔记：

- 20–35 页（25 页原文约 20–25 页笔记；45 页原文约 25–35 页）；
- 9 章左右 + 附录；
- 四家署名；
- 可独立阅读，也可对照原文阅读；
- 有推导、有边界、有“我们自己的解释”。

### 3.2 后台证据

`dossier/` 下的报告、claims、questions、challenges、transcript、errata：

- 是证据，不是产品；
- 用于支撑 final note 的每一句实质断言；
- 不直接排版给读者；
- 需要时以“附录 C 档案索引”的方式指路。

### 3.3 验收：读者能做什么

一个没读过原文的学生，读完 note 后应该能：

1. 用三句话说清论文要解决什么问题、主线是什么、结论是什么；
2. 指出至少三个“这是推导 / 这是假设 / 这是条件性论证”的地方；
3. 复述至少三个关键推导的起点和终点；
4. 把 note 的章节对应回原文的 §1–§6；
5. 说出至少两个论文没有解决的问题。

这五条，就是第 8 章 G4 的测试题。

## 4. 模板：以《威腾文章阅读笔记》v2 为准

### 4.1 章节骨架

| 章 | 内容 | 必须回答的问题 |
|---|---|---|
| 写在前面 | 读者对象、读法、约定、原文对照表 | 这本书为谁写、怎么读 |
| 1 骨架 | 1994 年处境、论文五步、主要结论、影响、读法 | 论文到底在做什么 |
| 2 低能有效作用量 | 场内容、真空、预势、Kähler 度规、单圈、瞬子 | 为什么低能物理压到一个全纯函数上 |
| 3 电磁对偶 | $a_D$、$\tau$、SL(2,Z)、无微观 θ | 对偶为什么是坐标变换 |
| 4 模空间奇点 | 正调和函数引理、至少三个奇点、单值性矩阵、Γ(2) | 为什么必须有第三个奇点 |
| 5 SW 曲线 | 曲线、λ、周期、$dλ/du$、$f$ 常数、弱耦合检验 | 曲线怎么工作、没证明什么 |
| 6 单值性/T² | 双荷子民主、T² 指数、Z8 与 θ | 指数 2 从哪里来 |
| 7 唯一性 | 存在性、四个输入、两个缺口 | 哪些是证明、哪些是假设 |
| 8 谱与禁闭 | BPS、谱跳变、p42、软破缺、磁凝聚、电禁闭 | 物理图像怎么闭合 |
| 9 边界 | 证明了什么、没证明什么、影响、延伸阅读 | 这篇文章的边界在哪 |
| 附录 A | 关键推导 | 手算可核对 |
| 附录 B | 符号术语 | 查表 |
| 附录 C | 四家分工与档案 | 怎么复现 |

### 4.2 每章必须有三样东西

1. **一个真问题**：本章开头用一段话说清“这一章要回答什么”，不要用“下面我们讨论”开头。
2. **一个推导**：技术章至少有一个 derivation 框，从假设推到结论，不能只报公式。
3. **一个边界**：本章结尾说清“这里证明了什么、没证明什么、哪里是假设”。

### 4.3 每章不能有三样东西

1. **注疏标签**：【原文】【注】【疏】【按】【诸家】不得出现在正文。
2. **四家异同表**：放在内部 dossier；正文只在必要处用一句话交代“这一处有争议，我们取……”。
3. **未消化的术语堆**：第一次出现的术语必须有一句人话解释，或进附录 B。

### 4.4 排版规则

- 正常章节叙述，不写“卷一/卷二”；
- 推导用 `derivation` 框，要点用 `keypoint` 框，数量克制；
- “原文 p.N”只作辅助锚点，不逐句标注；
- 公式编号连续，不模仿原文编号；
- 标题页四家署名，正文不反复出现“某某说”；
- 目标 20–35 页，超过 40 页先删，不加页。

## 5. 流程 v0.2：S0–S8

| 步 | 名称 | 输入 | 输出 | 关键变化 |
|---|---|---|---|---|
| S0 | 立项 | 原文、译本、页图、目标读者 | `seminar.yaml`、读者画像 | 新增“读者画像” |
| S1 | 预处理 | PDF | 页图、文字层、页映射、术语基线 | 不变 |
| S2 | 地图 | 原文 | `map.yaml`、骨架五问 | 强调“骨架先于细节” |
| S3 | 独立研读 | 地图、章节 | 三份报告（内部） | 不变 |
| S4 | 交叉质询 | 报告 | 六份 challenge（内部） | 不变 |
| S5 | 圆桌 | challenge、回应 | 裁决、errata（内部） | 不变 |
| S6 | **重写** | dossier | `note/` 第一稿 | **新增，最关键** |
| S7 | **可读性评审** | 第一稿 | 评审记录、第二稿 | **新增** |
| S8 | 出版 | 第二稿 | PDF、网站 L0、归档 | 质量闸门换为 G4 |

### 5.1 S6 重写：不是拼接

S6 由 Lead 执笔，从零写，不是把三份报告剪贴。

- 先写“写在前面”和“第 1 章骨架”；
- 再按章节写，每章先写“本章要回答什么”；
- 技术章先写推导，再写解释；
- 每章结尾写“边界”；
- 四家争论只在必要处用一句话交代，不展开；
- 写完一章，立刻做一次“新手五问”自测，不过就改。

### 5.2 S7 可读性评审：让“第一次读的人”在场

- **Reader Advocate**：一个没有参与研读、没有读过原文的评审者（可以是另一个模型、一个学生、或用户本人）。
- 任务：只读 note，不查原文；读完每章回答五问；标出“我在哪里卡住”。
- 通过线：五问至少四问正确；每章“卡住点”不超过 3 个；否则重写该章。
- 评审记录存 `reviews/readability/`。

### 5.3 与 v0.1 的流程差异

v0.1 的 S7 叫“综合”，实际上是把 dossier 拼成注疏；v0.2 把“综合”拆成两步：

- S5 圆桌：内部裁决；
- S6 重写：面向读者的重新叙述；
- S7 评审：让目标读者验收。

**没有 S6/S7，就没有产品。**

## 6. 角色 v0.2

| 角色 | 职责 | 不做什么 |
|---|---|---|
| Chair / Lead | 主持、裁决、执笔 final note | 不替 Reader 读原文 |
| Reader ×3 | 分章精读、报告、claims | 不写 final note 的正文 |
| Examiner | 红队质询、反例 | 不做文献综述 |
| Textual Critic | 三路核对、errata | 不负责润色 |
| **Reader Advocate** | 代表第一次读的学生，做可读性测试 | 不参与研读，不查原文 |
| Editor | 排版、编译、版权检查 | 不改数学内容 |

25 页原文：5 个角色（Reader 可兼 Examiner）；45 页：6 个；100 页以上：拆班。

**Reader Advocate 是 v0.2 新增的必设角色。** 没有它，G4 就是自评。

## 7. 质量闸门 v0.2

### 7.1 100 分制

| 项 | 分值 | 判据 |
|---|---:|---|
| A 骨架 | 15 | 第 1 章能让学生说出问题、主线、结论 |
| B 推导 | 20 | 关键公式有起点、有步骤、有终点；至少 5 个 derivation |
| C 证据 | 15 | 实质断言有锚点；无编造；争议有交代 |
| D 可读性 | 25 | 新手五问 ≥4；每章卡住点 ≤3；无注疏体 |
| E 边界 | 15 | 明确“证明/假设/条件性论证”；至少 3 个未决问题 |
| F 编辑 | 10 | 无缺字、无 overfull、公式编号连续、术语一致 |

**≥80 且 D≥20 才发布；<70 退回 S6；编造一票否决。**

### 7.2 G0–G7

| 闸门 | 检查 | 失败动作 |
|---|---|---|
| G0 底本 | 原文/译本/页图/页映射齐 | 回 S1 |
| G1 骨架 | 第 1 章五问能答 | 回 S2 |
| G2 推导 | 关键推导可复算 | 回 S6 |
| G3 证据 | claims 与正文一致，无编造 | 回 S3/S6 |
| G4 可读性 | 新手五问、卡住点、注疏体检查 | 回 S6 |
| G5 边界 | 证明/假设/条件性论证标注 | 回 S6 |
| G6 编辑 | 编译零缺字、零 overfull | 回 Editor |
| G7 可复现/版权 | 源文件、PDF、L0 数据、版权分层 | 不发布 |

### 7.3 反面清单（出现即退回）

- 正文出现【原文】【注】【疏】【按】【诸家】；
- 目录出现“卷一、卷二、凡例、题解”；
- 开篇 3 页内没有“这篇文章要解决什么问题”；
- 技术章没有 derivation 框；
- 章末没有“边界”；
- 术语第一次出现没有解释；
- 正文大段“某某说、某某认为”，没有裁决；
- 页数超过 40 页且没有删减记录。

## 8. 数据模型与目录

```
seminars/SEM-XXXX/
  seminar.yaml          # 元数据、读者画像、状态
  source/               # 原文、译本、页图、文字层
  dossier/              # 后台证据，不直接发布
    map.yaml
    reports/
    challenges/
    transcript.md
    claims/
    errata.md
  note/                 # 主交付物
    outline.yaml        # 章节、每章问题、推导、边界
    chapters/*.tex
    figures/
    refs.bib
  reviews/
    readability/        # 新手五问、卡住点
  manifest.json
```

`outline.yaml` 的每章至少写：

```yaml
- id: ch05
  title: "SW 曲线：猜出来的解"
  question: "曲线怎么工作，它没有证明什么？"
  derivations: ["d lambda/du ~ lambda1", "f 常数"]
  boundaries: ["ansatz 必要性未证", "Torelli 只有 sketch"]
```

## 11. 风险

| 风险 | 表现 | 缓解 |
|---|---|---|
| 注释癖复发 | 正文又出现“注/疏/按” | G4 反面清单，出现即退回 |
| 专家盲区 | 作者觉得清楚，学生看不懂 | Reader Advocate 必设 |
| LLM 平滑 | 文字通顺但没信息 | 每章“问题—推导—边界”三件套 |
| 过度工程 | 模板越来越重 | 25 页只允许 5 个角色 |
| 读者测试形式化 | 五问太简单 | 五问必须覆盖骨架/推导/边界 |
| 版权 | 公开全文 | L0 只发自写内容 |
| 成本失控 | 重写无限改 | 两稿封顶；第三稿需决策 |
| 模板僵化 | 每篇都一个样 | 允许章节顺序按论文调整，但三件套不变 |

## 12. 决策点

- **D1**：JP11 note 完成后，D≥20 且总分≥80，才开第二篇；
- **D2**：3 篇后，固化模板；不再改章节骨架；
- **D3**：5 篇后，公开 beta；只发 L0；
- **D4**：10 篇后，启动专著系列；
- **D5**：如果连续 2 篇 G4 不过，暂停扩量，先修模板。

## 13. 结语

“不糊弄”不是把注疏写得更全，而是让第一次读的人能走完。

对经典的态度，要像古人：逐字、存疑、不放过。
做学问的方式，要是我们自己的：骨架、推导、边界、可读。

这份 v0.2 把 v0.1 留在反面，不是为了自责，是为了让下一次开工的人先看见坑。

> 后人哀之而不鉴之，亦使后人而复哀后人也。

## 附录 A：v0.1 反面例子检查表

开工前逐条打勾；任何一条“是”，先停下：

- [ ] 我的第一版目录像“题解、凡例、序、八卷”；
- [ ] 我的正文有【原文】【注】【疏】【按】【诸家】；
- [ ] 我准备把三份报告直接拼成 final note；
- [ ] 我的质量指标主要是“覆盖了多少 claims”；
- [ ] 我没有目标读者画像；
- [ ] 我没有让没读过原文的人试读；
- [ ] 我打算用“四家异同表”当正文亮点；
- [ ] 我觉得“读者看不懂是因为他们水平不够”；
- [ ] 我准备超过 40 页还不删；
- [ ] 我说不出“这篇笔记读完能让学生做什么”。

## 附录 B：v2 模板章节检查表

每章交稿前：

- [ ] 开头一段说清“本章要回答什么”；
- [ ] 至少一个 derivation 框；
- [ ] 至少一个“边界”段；
- [ ] 术语第一次出现有解释；
- [ ] 没有注疏标签；
- [ ] 没有大段“某某说”；
- [ ] 公式编号连续；
- [ ] 页末没有半截公式；
- [ ] 本章能对应回原文的节；
- [ ] 新手五问中至少一问能由本章回答。

## 附录 C：新手五问

给 Reader Advocate 的固定问题：

1. 这篇论文要解决什么问题？用三句话说。
2. 论文的主线是哪几步？请按顺序说。
3. 哪一处是“推导”，哪一处是“假设”，哪一处是“条件性论证”？各举一例。
4. 选一个关键公式，说出它的起点和终点。
5. 这篇论文还有什么没解决？至少说两个。

## 附录 D：不要再写

- 不要再写“卷一/卷二”；
- 不要再写“凡例”；
- 不要再把“四家异同”放在正文；
- 不要再用“注/疏/按”当章节骨架；
- 不要再用“全”来证明“好”；
- 不要在没有读者测试的情况下发布。
