# workflow · 第 19 篇 Kapustin（arXiv:0811.3264，18 页）

本篇实际走的路，不是理想流程。给后来做同类短文的人看。

## 1. 顺序与每步产出

| 步 | 动作 | 耗时感受 | 产出 |
|---|---|---|---|
| 1 | 读 TASK.md + BRIEF + SCHEMA | 短 | — |
| 2 | `extract.py 19` 分页 | 秒 | `txt/19/p001…p018.txt` |
| 3 | 通读摘要 + §1 + §6，定主线 | 约两成时间 | 主线：d.c. 膜 → 扭化余切丛量子化 → 参数映射 |
| 4 | 建 notes 骨架（节表 + 主命题清单） | 短 | `notes.md` 前半 |
| 5 | 写卡片（概念 8 / 推导 4） | 约五成时间 | `cards/` |
| 6 | 抽样回原文核公式与页码 | 约两成 | 抓出 q=0、页码、pitfalls 三处错 |
| 7 | 补 quote + 页码回查（子代理独立做） | 约一成 | 15 条 quote、1 处 pages、6 处 locator |
| 8 | 三项质检 + 打包 | 短 | exit 0 ×2，ship 成功 |

## 2. 哪一步最耗时

写推导卡。概念卡可以「定义 + 关键点 + 坑」三段成卡，推导卡必须把每一步的「为什么」写出来，
而原文明写的东西往往只有结论，中间步要我们重建、再标 B。4 张推导卡的心力约等于 8 张概念卡。

## 3. 哪一步最容易出错

**页码。** 而且不是随机错，是系统性错：脑子里做了「印刷页 = PDF 页 − 1」的换算，一错错一串。
第二容易错的是**替作者把话说满**（「可能存在」写成「存在」）。

## 4. 如果重做

1. 一开始就给每条出处填 `quote`，不要等 lint 报错再回头补——补的时候还得重新定位。
2. 建立卡片之前先把「本页第几行有哪个式」的索引列出来，页码就不会靠记忆。
3. 推导卡的 B 步当场标，不要留到最后统一标（最后一定会忘几条）。
4. 短文不要按页数配额硬凑卡数：18 页出 12 张已经偏多，再压会出空话卡。

## 5. 与流水线的差异

TASK.md 的 0–8 步里，本篇实际执行的顺序是 1→3→4→5→6→7→8，第 0 步（xref 外校）是在
卡片写完之后补做的。事后看，外校应该在最前面：如果先知道「本篇无编号定理」，
第 5 步的重心分配会不一样。以后的篇目按 TASK 的顺序从第 0 步开始。
