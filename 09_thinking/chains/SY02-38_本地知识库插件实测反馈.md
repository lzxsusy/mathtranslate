# 0. 审计结论

在翻译 Anschütz 讲义的过程中，用 6 条真实问题分两批测了本地知识库插件的三个工具（`kb_locate`、`kb_ctx`、`kb_get`），把结果写成 `kb_plugin_feedback.md`（6 用例表 + 6 条问题 + 5 条建议）。

一条改变交付物的判断：**不把覆盖率当相关性用**。`kb_locate` 的 top1 覆盖率从 13% 到 100% 都有，但 100% 那条是假阳性（问「Shimura 数据的定义」，返回的是「定理 58 讲同构」），真正贴题的排在第 4 位。如果按覆盖率阈值决定「查到了」，会把错的条目引进译注。

# 1. 任务

- 输入：翻译中真实卡住或需要交叉核对的概念（Eichler–Shimura 关系、Satake 参数、权 1 的 Galois 表示、Hasse 不变量与 E_{p−1} 同余、Shimura 数据、强重数一）。
- 约束：插件是本地索引（135 部讲义 / 110,286 条语义单元），不联网、不调模型；只负责定位到「书 + 节 + 编号 + 原书页」，判断由调用方做。
- 成功标准：每个问题能拿到可引用的坐标（uid/页码/节）与足够判断的摘录；把失效模式写清楚，供插件作者修。

# 2. 为什么值得看

这是「工具本身成为翻译质量变量」的一次实测：如果 `kb_locate` 的排序不可信，译注就会引用错文献，而错引比不引更糟。六条里出现了四种不同失效模式，合起来正好画出边界。

# 3. 关键片段（压缩摘录）

### 片段 1 · 第一次查询就遇到覆盖率悖论

> 问 Eichler–Shimura 为什么给出 `T_p=F+V`，top1 只有 13%，而且 gaps 里把「为什么给出」「上的」当成未识别词。第一反应是查询没写对——但把这几个虚词删掉，覆盖率上去了，命中的还是同一批。

### 片段 2 · 100% 覆盖率、但答的不是同一件事

> 问「Shimura 数据的三条件是什么」，第一条覆盖率 100%：SY02-20 定理 58「讲同构」。字面全中，语义全错。这让我把「覆盖率」在整个流程里降级为「是否值得点开」的提示，而不是结论。

### 片段 3 · kb_get 的 number 解析

> `kb_get(work=SY02-24, number=4.7)` 返回的是 §5.4.2 的「式 4.7」，不是要的 §4.7。坐标只给源码行、没有页码。要拿到正确条目得用 uid，或补节限定。

# 4. 决策与替代方案

1. **继续用 `kb_locate` 做第一跳，但只把它当候选生成器**：否决「按覆盖率阈值过滤」——见 §3 片段 2；改为人工看 uid 与摘录，必要时用 `kb_ctx` 展开证明上下文。
2. **`kb_ctx` 定为核对主力**：它对 `SY02-09:9.2:theorem:9.2.3` 正确给出【陈述】【证明】【引用它的正文】并明确提示「同节没有 proof 单元」，这正是译注需要的。
3. **`kb_get` 只在已知 uid 时用**：work+number 的消歧不可靠（见 §3 片段 3）。
4. **把英文专名加入库内词表的建议写进反馈**，但**不自行改索引/词表**：插件是共享资产，改动需所有者决定。

# 5. 自纠与回退

1. 最初把覆盖率低当作「库里没有」→ 用 `kb_ctx` 验证后发现库里其实有（SY02-09 定理 9.2.3 就在），是词表缺英文词导致匹配不上。
2. 最初想直接把 `kb_locate` 的 gaps 提示里的「建议改写」当查询改写器 → 实测它给的改写（删虚词）不改变命中集，放弃。
3. 第六章「Jouanolou」类专名查询多次缺英文词，改为先查本库中文译名再反查，命中率提升。

# 6. 验证证据

- 六用例均记录：查询原文、耗时（56–747 ms）、top1 覆盖率、命中 uid/书号/节、是否可用于译注。
- 反例：SY02-20 定理 58（100% 假阳性）、`kb_get(SY02-24, 4.7)` → `SY02-24:5.4.2:equation:4.7`。
- 正例：`kb_ctx(SY02-09:9.2:theorem:9.2.3)` 给出完整陈述与同节注记；SY02-24 §4.7 的正文（Deligne–Serre 的历史注）虽排第 3，但是译注真正引用的一处。
- 反馈文档：`工程文件/work/reports/kb_plugin_feedback.md`（6 用例表 + 6 问题 + 5 建议）。

# 7. 逆转条件

- 若插件引入英文别名索引或跨语言向量检索 → §3 的「英文专名不入词表致覆盖率系统性低估」结论需重测。
- 若 `kb_get` 修好 number 的节限定/页码输出 → §4.3 的建议可撤回。
- 若覆盖率改为按 `kind` 加权排序并经人工标定 → §4.1 的「只当候选生成器」可放宽。
