# 2. 为什么值得看

583 页、六位作者、横跨 $\ell$-进与 $p$-进两种语言，是典型的「单靠人名和标题无法判断怎么译」的文献：

- 同一个对象在不同篇里有不同记号（参数叠：$Z^1/\hatG$ vs $\mathcal L_G$ vs 钻石），统一记号会破坏原文自洽，不统一又会误导读者——这需要一条明确的决策规则，而不是临场发挥。
- 「coherent」在 Zhu 篇指导出凝聚（IndCoh），在别的篇可能指普通凝聚层；译错一个词，整段论证的意义就变了。
- 全书大量依赖「叠不是拟紧的」这一技术事实来安排论证顺序；译者若按普通概形的直觉断句，会把条件从句译成主句。

因此这份记录的价值不在「翻了什么」，而在「遇到 A/B 两种译法时怎么定，依据是什么」。

# 3. 关键片段（决策 + 原文依据）

## 3.1 编号：为什么不重排

原文每篇独立编号（第 1 篇定理 1.2.3，第 2 篇又从 1.1.1 开始）。若用 LaTeX 自动编号，需要 `\setcounter` 手工同步，且一旦漏掉一个 `\begin{theorem}` 就整篇错位。采用的办法：定理环境带一个必填参数，直接写入原编号：

```latex
\newtheorem{ithm}{定理}
\newenvironment{thm}[1]{\renewcommand{\theithm}{#1}\begin{ithm}}{\end{ithm}}
```

`\renewcommand` 在计数器步进（`\refstepcounter`）之前执行，因此 `\label` 记录的就是 `#1`。代价：编号完全靠译者手抄，抄错不会被 LaTeX 发现——所以另设审计：编译后用脚本比对「译文出现的定理编号集合」与「原文 PDF 抽出的编号集合」。

## 3.2 页锚：`\ysrc`

```latex
\newcommand{\ysrc}[1]{\marginpar{\raggedleft\scriptsize\color{black!55}#1}%
  \hypertarget{src:#1}{}}
```

放在每页起始处。`\marginpar` 在切口侧显示原书页码；`\hypertarget` 让「见 p.37」这类内部跳转可点。为什么不放页眉：页眉每页只有一个，而一篇内页界与 LaTeX 分页不重合，页眉会对不上；`\marginpar` 跟着正文流走，天然对齐。

## 3.3 术语：两级依据

术语表每行四列 + 首现：`english / 中文 / 等级 / 依据 / 首现`。等级沿用仓库既有体系：

- **A**：原书用法、经典教材、原始论文（如 Borel–Wallach 对「自守表示」的定义）。
- **I**：本库既有译法（经 `kb_search` 查到的同库译法，例如「参数叠 $\mathcal L_G$」「L-群」「几何朗兰兹对应」）。
- **B**：白名单（nLab、Stacks Project），须与 A 交叉。
- **禁用**：知乎、百度百科、CSDN 等（04_playbook/01 §2.5）。

「stack=叠、moduli stack=模叠」不是本工程首创，而是 `SY02-25` 术语表第 77–79 行已定的译法（I 级）；本工程沿用，避免同库内两套译名。

## 3.4 「coherent」的两义：加脚注而不改词

Zhu 篇的「coherent sheaves on the stack of Langlands parameters」实际指导出凝聚层（IndCoh），因为参数叠不拟紧、普通凝聚层范畴性质太差。若译成「凝聚层」并加脚注说明「此处实指导出凝聚层」，读者会以为原文用词随意；若改译「导出凝聚层」，又与标题不符。

决定：标题与正文照译「凝聚层」，首次出现处加译注：

> 译者注：本文的「凝聚层」多指导出意义下的凝聚层（IndCoh）；参数叠通常不拟紧，普通凝聚层范畴缺乏所需的完备性，故须在导出框架内工作。参见附录 B。

理由：标题是原文的招牌，不能改；脚注把技术含义补齐，读者按脚注进入导出语言，不会误解。

## 3.5 分片并行：为什么按 PDF 页切，不按节切

47 个 worker，每片 10–13 页。按页切的理由：

- 页是**物理**边界，页锚、页图、原文核对三者一一对应；按节切会出现一节跨 30 页的情况，单片过长易截断。
- 页边界处的句子被切断没关系：规则是「译到页末，下一片从下一页开头接着译」，译文拼接后仍是连续的（页锚提供了拼缝标记）。
- 按页切让「公式逐页回图核对」成为可执行的动作：worker 只需打开对应 `png/pNNN.png`。

代价：篇首、参考文献、附录会被切在片中间。处理办法：篇首片（第 1、2、3、4、5、6 篇的第一片）单独指定写 `\chapter`、作者、摘要、目录；参考文献片（各篇末片）单独指定用 `refs` 环境并保留英文条目。

## 3.6 不用 `\cite`：引用照抄方括号

原文引用形如 `[FS21]`、`[Hel20b, §4]`。若用 BibTeX，需要为六篇各建一个 `.bib` 并保证 key 与原文一致；一旦某条文献信息不全（底本常省略 DOI/MR 号），编译就会缺项。更简单也更忠实：正文直接写 `[FS21]`，参考文献表用 `refs` 环境手工排。代价：无法自动生成「被引」链接；收益：与原文逐字对应，且不会因缺条目而编译失败。

## 3.7 审计脚本化：三个脚本各管一件事

人工数页锚、数编号不可靠，所以把三件可机检的事写成脚本，放在 `工程文件/`：

- `pageaudit.py`：按块读 `\ysrc`，检查块内递增、跨块衔接、全书覆盖；篇界（37→39、123→125、165→167、419→421、470→471）白名单放行。
- `audit_num.py`：从译文抽 `\begin{thm|prop|…}{编号}` 的类型分布，与底本抽出的 `statements.tsv`（679 条）比对，给出检出率。
- `stats.py`：每块的页锚、字数、编号陈述、带号公式、译注、`\label` 计数，输出 U03 报告。

为什么值得：这三件事占复核时间的八成，却完全机械。脚本不进编译链，只读源码，失败也不影响交付；但它们的输出直接进 `reports/`，成为「审计证据」而不是「译者自述」。

## 3.8 环境配平必须跨块累计

初版 `lint.py` 逐块检查 `\begin`/`\end` 数量相等，结果每片都报错——因为证明常跨片断开（上一片 `\begin{proof}`，下一片 `\end{proof}`）。规则改为：按全书顺序把环境名压栈，只有栈顶不匹配才算错；单片的数量不等不是错。这条修正把「误报」从几十条降到 0。

## 3.9 tikzcd 指向空单元格：两次事故

1. `ch-a4-06.tex` 的 (5.3.9)：`D\arrow[u,hook,"\iota"]` 在第一行，`u` 指向第 0 行，编译报 `No shape named tikz@f@37-0-3`。回看 p242 页图，`\iota` 的箭头其实从下一行的 `D'` 上行到 `D`；改成在 `D'` 单元格写 `\arrow[u,hook,"\iota"]`、在最右 `z^N\mathcal R(\eta_2)` 写 `\arrow[u,hook]` 后正确。
2. `ch-a4-07.tex` 的五节点紧化图：`\arrow[d]`/`\arrow[ddl]` 指向矩阵中空着的单元格，同样报错；改用 `\arrow[ddll]\arrow[dl]\arrow[dr]` 与 `\arrow[dl]\arrow[drr]`，落点与原图逐一对应。

教训：tikzcd 的箭头只认**真实存在**的节点（空单元格不是节点）。写图时必须同时想「目标格有没有内容」，并在本片试编译；只看 exit 0 不够，pgf 的这类错误在 `-interaction=nonstopmode` 下不终止，但会印红字并丢箭头。

## 3.10 术语统一是「一次性决定」，不是逐片协商

第 3 篇里 `perfectoid` 在三片中出现 48 次，两片保留英文、一片译「完美胚」。这类分歧不能靠逐片提醒解决，只能：先定（glossary 写 `perfectoid space 完美胚空间 A`），再脚本批量替换（含首次出现的括注），最后 `lint.py` 把旧写法列为禁用词。同理适用于 `stack→叠`、`coherent→凝聚`。

## 3.11 对齐卡的 JSON 转义事故

`资料卡/对齐卡/index.jsonl` 初版由手写 JSON 生成，中文句子内嵌 Lean 代码 `\hat G`、`\Z[1/p]` 时反斜杠未转义，`json.loads` 直接报 `Invalid \escape: line 1 column 622`。修法不是逐个补 `\\`，而是**用 `json.dumps` 生成**：在 `lp2_work/fix_align.py` 里把卡片写成 Python 字典（字符串用 raw string 保留单反斜杠），由 `json.dumps(..., ensure_ascii=False)` 负责转义，写完立刻 `json.loads` 逐行回读校验。文件同时改名为 `alignment.jsonl`（与 SY02-25 一致），字段加上 `type/title/summary/statement/statement_en`，保留 `source_page/zh/gap/evidence`。

# 5. 自纠与回退

1. **`\cite` 事故**：第一片初稿写了 `\cite{FS21,...}`，但工程没有 `.bib`，编译不会报错（只会出 `[?]`）。发现后改为字面 `[FS21]`，并把「禁用 `\cite`」写进 STYLE_GUIDE §5 与 WORKER_BRIEF。教训：LaTeX 的「不报错」不等于「正确」，审计必须看 PDF 输出而非只看 exit code。
2. **页锚位置**：初稿把 `\ysrc{4}` 放在段落末尾（因为按页切时先看到页 4 的文本再回填）。规则改为「页锚只能出现在段落之间或节标题前」，写进 STYLE_GUIDE §2。
3. **模板勾选**：BRIEF 的交付勾选表初稿提前勾了「双校」，实际只做了抽读；已改回未勾，并在 STATUS 里记录第二轮待办。教训：勾选表是审计对象，不是愿望清单。
4. **书签编译错误**：节标题含 `$\overline\mathbb{Z}[\frac1p]$` 时，hyperref 生成书签串报 `! Argument of \math@egroup has an extra }.`。根因：`\overline` 只吞下一个 token `\mathbb`。修法：标题里写 `\overline{\Z}`，并关掉 `bookmarks=false`（书签收益小，编译稳定优先）。试过 `\pdfstringdefDisableCommands{\def\({}…}`，无效且有害，已删。
5. **`\Gal` 未定义**：某片用了 `\Gal`（宏表里没有），10 个 `! Undefined control sequence.`。修法：preamble 加 `\DeclareMathOperator{\Gal}{Gal}`，保留 worker 的写法而不是改 10 处正文。同类还有 `\Sp`（取 `\Sp(\Q_p)` 值点）。
6. **Overfull 归零**：`overfull.py` 初版按 `./chunks/…` 匹配日志，实际日志是 `(chunks/…`，命中 0 条；修正后逐条消：交换图 `\times_{…}` 折行、大类括号定义改 `aligned` 在 `\Big|` 后断、超长 URL 用 `\href{全长}{短显示}`。
7. **对齐卡 JSON**：手写 JSON 内嵌 Lean 反斜杠未转义，`json.loads` 报 `Invalid \escape`；改为 `json.dumps` 生成并回读校验（见 §3.11）。
8. **worker 写入竞态**：见 §3.12，等 inactive 再改文件。
9. **并发上限**：subagent 同时最多 8 个；第 9 个会直接报 `subagent limit reached`。批量派片时按「完成一个补一个」调度，不要一次算好 47 个一起发。
