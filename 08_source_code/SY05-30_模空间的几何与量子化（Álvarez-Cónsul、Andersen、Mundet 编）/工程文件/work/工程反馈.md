# 工程反馈（SY05-30 试点卷）

对 `04_playbook/01_数学文献翻译纪律.md`（v2.1）与仓库现有工序的实测反馈。凡标「建议」的都给了具体改法，可直接采纳或否决。

## 一、真管用的（建议保留、别改）

1. **§1.0 先通读后落笔**。本次通读时才发现第 2 章 §2.2.2 的「克莱因曲面范畴没有连通万有覆盖」这个反直觉点；若边读边译，这一段的论证会被译成「显然存在万有覆盖」，属于会误导读者的硬错。第 0 定律该保留，且应当**要求把通读结论写进 `work/`**（本次写了 `通读笔记.md`），否则「通读了」不可复核。
2. **§1.4 先用一章做样板**。42 页的一章跑完整条管线，暴露了从抽取到插件反馈的 4 个 bug（`\D_A` 未定义、tikz 标签 `''`、长等式 Overfull、术语回扫漏「Klein」）。若先译 216 页再编译，这四个 bug 会乘以 5 倍工作量。建议把「样板章 ≤ 50 印刷页」直接写进纪律。
3. **术语先冻结**。`术语表.tsv` 先写 46 条再动笔，正文一次写完没有出现同词异译（唯一的漏网是章标题「克莱因」与小节「Klein」，属于跨文件回扫漏，见校订日志 #4）。建议在纪律里加一句：「合稿前必须 `grep` 每个术语的英文原形，逐条确认正文没有残留」。
4. **译注可追溯**。Q005、Q006 两条译注都能追到疑点清单里的编号，读者可以顺着编号看处理理由。这个「译注 ↔ 清单编号」的闭环很好用，建议推广到所有卷。

## 二、卡住的地方（建议改纪律或改工具）

1. **通读义务与产能冲突**。§1.0 要求 >150 页的书「每章开译前完整细读该章」，216 页的书 = 四次完整细读 + 四章翻译，单会话不可能。本次的处理是「细读第 2 章 + 其余三章目录级速读」，并在通读笔记里给每章标了「细读 / 速读」。**建议**：纪律增加「范围声明」一步——试点卷允许按章声明范围，但必须在 BRIEF 与通读笔记里写明「哪几章是细读、哪几章只到目录级」，禁止默默降级。
2. **「完成」的最低配置对书不适用**。`17_仓库理念与上传规范.md` 要求「成品 PDF」，但同一批文档又说「书籍不发成品 PDF」（版权）。本次按后者办（`main.pdf` 不入仓，只留预览图）。**建议**：把这两条合成一条判定规则——「期刊/讲义发 PDF；已出版专著只发源码 + 预览图，PDF 本地留存」，写在规范里，别让每个工程自己猜。
3. **资料卡有两种格式，没有一句话说清用哪个**。`datasets/<集>/cards/**.json`（结构化、可进插件）与 `资料卡/00–04*.md`（五件套）并存。本次两种都做了：JSON 卡进库给插件检索，五件套 md 给人读。**建议**：纪律里写明「JSON 卡是机器可检索层，五件套是人的阅读层，两者都由同一份校订后的底稿派生」，否则后来者会以为其中一种是历史遗留。
4. **`09_thinking` 的人工批准是硬闸门**。R6 要求 `approve --auditor <真人>`，agent 不能自批；本次的决策链只能写进 `work/`，等真人批准后再考虑入 `09_thinking/chains/`。这不是 bug，但意味着「思维链入库」在当前流程下**必然滞后于交付**。**建议**：给试点工程一个「候选链」目录约定（比如 `work/chains/`），文件格式按 R3 写（七段、≤12KB），批准后原样搬进 `09_thinking/chains/`，减少二次改写。
5. **kb 插件没有进工序**。SY07-11 的「开工必读」九步里没有「译前用 kb 插件检索」这一步，本次是自发加的。**建议**：把「`kb_brief` + `kb_search(layer=all)` 各一次，结论写进 `work/` 的检索记录」列为第 0.5 步；并把「插件 0 命中时的复核义务」写进去（因为 `kb_brief` 的否定结论不可信，见 `kb插件测试笔记.md` 问题 1）。
6. **`\figomit` 只有机制没有判据**。第 2 章无图，本次没用上；第 1 章的 Thurston 图、wiring 图属于「不画就读不懂」的图，`\figomit` 会把正文变成天书。**建议**：纪律给一条判据——「图被正文引用 ≥3 次且承载定义/构造 → 必须复刻；仅作示意 → `\figomit` + 图注翻译」。

## 三、工具侧的具体请求（给插件维护者）

1. `kb_brief` 0 命中时回报「译文层 N 段 / 原文层 M 段命中」，不要只说「库里没有」。
2. `kb_search` 的统一召回语义（AND 优先 + 放宽标注），并在输出里打印本次检索范围（是否含 draft）。
3. `kb_zh` 的 `around` 参数要么实现，要么删掉——现在传 0 仍返回五段，会让人误读上下文长度。
4. 卡片显示页码时，同时显示 `pages`（印刷页）与 `pdf_pages`（底本页），并标明「启发式抽取，引用前回源」。
5. **页码按连续段合并**，别把离散页码渲染成区间。现在 `pages=[68,70,71]` 显示成 `p.68–71`，读者会以为 69 也在（`lib/index.js:152` 直接取了首尾）。改成 `p.68, 70–71` 只需几行。
6. **`terms` 数组要渲染**，别 `JSON.stringify`。卡里 `terms:[{en:"Gamma model",zh:"Γ 模型"}]` 现在原样吐一坨 JSON；应显示成 `Gamma model / Γ 模型`，多条用「；」连接。
7. **卡内 prose 的 LaTeX 要么约定禁用、要么插件剥除**。`kb_card` / `kb_brief` 里能看到 `$\Sigma$`、`\emph{双解析}`、`\Id`。本卷已定「prose 用 unicode 数学、LaTeX 只进 `formulas`」作为写卡规约，但老卡不会自己改；插件侧做个最小剥除（`$`→空、`\emph{x}`→`x`、宏表映射）成本很低。
8. **`kb_brief(work=…)` 请保留并写进文档**。这是本次最好用的入口：给一个作品号，直接列出该作品全部卡 + 跨书线索，等于「这本书的入场券」。但 `kb_brief(query=…)` 仍只查卡片层且严格 AND，两者行为差异应在文档里讲清（一个可信、一个不可信）。
9. **`export_plugin_data.py` 的 `--out` 必须防呆**（仓库侧已加）：指错一层会 `rmtree` 掉插件 `data/` 下的 `zh`、`src` 层。建议由插件文档说明「`data/` 下三层的来源与重建命令」，否则一次手滑就要从 `01_corpus_*` 重拷 40 MB。
10. **`ingest` 的 caveat 判断要用 `sources`**（仓库侧已修）：结构化卡写 `sources` 列表，旧判断只认 `source` 字典，导致 `datasets/*/cards/**` 全量被标「页码启发式抽取」，把「卡内自带页码」和「猜的页码」混为一谈——这正是插件最该避免的那类错误。

## 四、给下一卷的一句话

第 1 章（dimer）与第 3 章（TQFT）的图与公式密度是本章的 3–5 倍，建议**先把图复刻成 tikz 再写正文**，否则会陷入「文字写完、图补不上、编号全乱」的返工；第 4 章可以照本章的做法直接开（术语已并表，实结构部分已有 §2.3 打底）。
