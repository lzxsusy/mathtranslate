# 工程反馈：在一本 42 页讲义的翻译里，kb 插件到底帮了什么、误了什么

> 工程：SY05-30《模空间的几何与量子化》前言 + 第 2 章（Schaffhauser，Klein 曲面讲义）
> 时间：2026-11-24 · 规模：底本 42 页 / 68 个编号条目 / 26 个公式 / 48 条术语 / 10 张卡
> 使用者：lead（本卷译者，全流程一个人跑完）
> 版本：插件为仓库内 `dsh-kb`（`data/cards` 2,907 张 / 52 部；`data/zh` 48,765 段 / 84 工程；`data/src` 7,644 段 / 33 工程）

## 0. 一句话结论

**它现在是一个「卡片检索器」，而翻译时我要的是一个「论证定位器」。**
我知道某个命题的证明「一定在某本我们译过的书里」，但我没有一种可靠的办法问出「是哪一本、哪一节、哪一页」；插件给我的最好结果是「这一段字面上同时出现了这几个词」，最坏结果是「库里没有覆盖这个主题」（而其实有）。

所以要回答你的问题：**是的，就「帮我把书里的论证调出来」这件事，它现在明显不如 NotebookLM 那类整书问答，也不如 nLab 那种靠链接织起来的概念网。但这不主要是「模型不行」，而是数据模型和检索层的结构性错位。** 下面逐条说。

## 1. 我实际是怎么用它的

不是「打开插件问两句」，而是把它嵌进工序里。真实顺序：

| 阶段 | 我做的动作 | 目的 | 结果 |
|---|---|---|---|
| 开工前 | `kb_brief("Klein 曲面 实代数曲线 基本群 实结构")` | 看库里有没有现成卡，避免重复劳动 | ❌ 答「没有已核卡片覆盖这个主题」；但同库原文层有 20+ 段命中 |
| 开工前 | `kb_search("Klein surface", layer=all)` | 交叉验证上一条 | ⚠️ 卡片层 8 条几乎全是噪声（Hirzebruch 曲面、面算符、分次曲面）；原文层意外命中 `SY02-02 p.30` 的 Klein 分类，**恰好是本卷 (g,k,a) 的对应物** |
| 术语冻结 | `kb_card` 查已有译名（Higgs 丛等） | 避免同词异译 | ✅ 好用，`kb_card` 直接给「英文 → 中文 + 依据等级」 |
| 译 §2.2.2 | `kb_search` 找「实覆盖 / 增广 / 正合列」的既有论述 | 确认我没有把定义理解反 | ❌ 0 命中；靠我自己知道 SGA-1 与 Thurston |
| 译定理 2.1.5 | 想找 Harnack 不等式的另一个证明（底本只给微分几何证明） | 对照 | ❌ 卡片层 0；译文层命中的是 PDE 书里的 Harnack 不等式（同名不同物） |
| 译完入库 | `kb_brief(work="sy0530")` | 看本卷 10 张卡 + 跨书线索 | ✅ **本次最好用的功能**，一次给出 10 张卡 + `SY02-23`、`SY02-21` 两条链 |
| 交付前 | 用 `layer="zh"` 查自己译文 | 检查语料是否可检索 | ✅ 命中 |

一共 22 次调用（明细见 §8）。按「这次调用真的改变了我的下一步」来算：**7 次有用（32%）、7 次部分有用（32%）、8 次无用或误导（36%）**。

## 2. 六个具体事故（按疼痛程度排）

### 事故 1：命题的证明在别的书里，但我问不出来

这是你说的那个场景，也是我这次最需要的功能。真实过程：

我在译 §2.3 的定理 2.3.4（$\Phi$ 的像落在 $\kappa$ 的不动点里），证明里用到「$\kappa$ 关于 Narasimhan–Seshadri 复结构反全纯」这个事实，底本只写「见 [16]」。我想知道：**我们译过的书里，有没有人把这件事证过？**

我试的查询：

```
kb_search("covering space Galois correspondence fundamental group proof universal cover", layer="all")
```

返回：

- 译文层 #1：`SY01-08` 的一张**日文术语对照表**（`コンパクト化 & 紧化` 那一类）；
- 译文层 #2：`SY05-08` 的**术语一致性说明**（「酉」出现 66 处……）；
- 原文层：`SY05-14` 的 plus-construction 页、`SY02-10` 的 étale 基本群注记。

**没有一条是「覆盖空间的 Galois 理论」的正文。** 但我的库里其实有相关材料（`SY02-21` 附录讲 étale 基本群与局部系统），只是它没有被排上来。

为什么：查询里的 `proof`、`covering space`、`Galois correspondence` 被当成**必须同时出现**的词；中文语料里没有 `proof` 这个词；术语表那种「一行一个词对」的段落反而同时含有大量英文词，于是被排到最前。**这不是「书不够」，是排序把噪声排成了信号。**

### 事故 2：用英文定理名查不到中文译文（跨语言断裂）

「Schwarz 反射原理」在本卷有完整陈述（定理 2.1.11）和一段构造性证明。我用底本里的英文名查：

```
kb_search("Schwarz reflection principle", layer="all")
```

→ 卡片层 0；译文层 0（提示「有 1 段命中」但实际给的是术语表）；原文层给的是 `SY07-01` 的**参考文献页**和 `SY05-23` 的 spin 结构页。

换成中文：

```
kb_search("Schwarz 反射 原理 解析延拓", layer="zh")
```

→ 立刻命中本卷段 3、段 18、段 8。

**同一个东西，英文名 0 条，中文名 3 条。** 而翻译时我脑子里想的、底本上写的，都是英文名。插件自己就存着 1,956 条术语基（`termbase.jsonl`），**但检索时不用它做查询扩展**。这是最不该发生的断裂：数据在手边，却没接上。

### 事故 3：术语表、索引、参考文献被当成正文命中

上面几次查询里，反复出现同一批「段落」：

- `SY01-08` 段 2：19,670 字，整张日文术语对照表；
- `SY05-08` 段 3：12,809 字，术语一致性清单；
- `SY07-01` 段 2、`SY07-05` 段 3：同类；
- 原文层：`SY03-03` 的参考文献页（p.121、p.129、p.130）、`SY07-01` 的索引页（p.418）。

它们有个共同点：**字面上同时含有大量查询词，语义上信息量为零**。任何词法检索器都会把它们排到最前，除非你知道「这几段是表，不是话」。

插件没有这个知识：语料里 `env` 字段只有 `text/proof/theorem/...` 八个值，**没有 `table`、`bibliography`、`index`、`appendix` 这几类**；50,285 段里 46,539 段是 `text`（92.5%），表格与书目都被归进 `text`。所以排序器无法把它们降权。

### 事故 4：同一次调用里，提示语和行为自相矛盾

```
kb_search("Harnack 不等式 实代数曲线 实点 证明", layer="all")
```

返回的卡片层写着「没有命中已核卡片」，紧接着一行提示：「**提示：译文层有 3 段命中——加 layer="all" 一起看。**」

我已经传了 `layer="all"`，它还在叫我加 `layer="all"`。这种小 bug 本身不致命，但它让我不信任提示语：**当工具开始给「建议」而不是「结果」时，用户就得多花一次调用去验证建议。**

### 事故 5：`kb_zh` 的「读前后文」一次吐 5 段、约 4,000 token

```
kb_zh(pkg="SY05-30", para=3, around=0)
```

我要的是「段 3 本身」。它返回段 12、2、3、4、5 五段全文（含两段带 `\[...\]` 的长公式），标题还写着「前后各 2 段」。`around` 参数被忽略（`around=0` 仍给前后各 2）。对我这种上下文敏感的调用来说，**一次多花 3,000 token 是实质成本**；对自动流水线来说更糟——它会把预算吃光。

### 事故 6：「第 86 页」这个引用，一半来自卡片，一半根本不存在

我交付的资料卡里写「p.86–88」，那是卡片字段 `pages` 手填的。但如果要从**译文语料**里引一句原书的话，插件给的是「SY05-30 · 段 12」，没有页码。

实测：`01_corpus_zh/zh_paragraphs.jsonl` 共 50,285 段，**只有 4,023 段（8%）有 `page_orig`**；按作品算，**84 部里只有 3 部有任何页码锚点，81 部全空**。本卷 170 段，`page_orig` 全 `null`。

所以「定位到哪一页」这件事，插件现在只能靠卡片作者手填，不能靠语料自己算出来。而翻译/校对时最需要的恰恰是「这句话在原书第几页」。

## 3. 结构性诊断：不是书不够，是书没有被「结构化」

我把问题拆成六层，从数据到交互：

### 3.1 数据模型错位：卡是「结论」，需求是「路径」

插件的主体是 2,907 张卡，每张卡是「一个概念的摘要 + 定义 + 要点」。这对「这个概念是什么」有效；但翻译时我 90% 的检索需求是：

- 这个结论**在哪本书**里被证明过？
- 证明用了**哪些前置结论**？
- 前置结论又在哪里？

也就是**论证路径**，不是概念摘要。卡片的 `related` 字段是作者手写的，不是从正文的 `\ref`/引用关系里长出来的，所以它给不了「谁用了谁」。

### 3.2 检索是词法匹配，且是严格 AND，没有查询改写

三个具体后果，这次全踩到了：

1. **多词 AND 无回退**：`Schwarz reflection principle proof` 里只要有一个词（`proof`）不在语料，整条查询 0 命中，而不是退化成 `Schwarz reflection`。
2. **没有跨语言扩展**：英文查询打不中中文译文。术语基 1,956 条就在旁边，没接。
3. **没有停用词/重要度**：`proof`、`theorem`、`real` 这类词和 `Schwarz` 同权，噪声段落靠「词多」胜出。

### 3.3 语料没有「结构类型」，回答不了「证明在哪」

50,285 段里：`text` 46,539、`proof` 1,664、`theorem` 638、`definition` 414、`example` 539、`remark` 304、`lemma` 73、`proposition` 48。

**「证明」只占 3.3%，「定理/命题/引理」加起来 1.5%。** 也就是说，即使检索完美，语料也没有足够的类型信息让我问「定理 X 的证明段是哪一段」。本卷 68 个条目里，能被 `env` 正确标注的只是少数——因为提取脚本按「空行分段」，不认 LaTeX 环境。

### 3.4 没有引用锚点，页码是「装饰」

见事故 6：8% 的段落有页码，81/84 部作品全空。没有页码，就没有「可核对的引用」；没有引用，检索结果就只能当线索，不能当证据。**这直接决定了插件只能做「线索机」而不是「断言机」。**

### 3.5 段落粒度失控

61 段超过 2,000 字，最大的 **65,068 字**（`SY02-04` 段 2，一整篇引言被当成一段），其后是 19,670、17,873、12,809 字。后果：

- 检索命中一条 = 塞进几万字的上下文，等于没命中；
- 嵌入/重排都没法做（长度超限）；
- 「读前后文」功能在这种段落上直接失效。

### 3.6 可信度饥饿：67% 的卡默认不出现

2,907 张卡里 `draft` 1,947（67%）、`checked` 856、`verified` 104（3.6%）。默认检索只给 checked/verified，所以**三分之二的存量对使用者不可见**。这不是数据少，是「已核」这个状态太难拿到——没有批量复核工具，靠人一张张点。

### 3.7 没有反馈闭环

我这次找到 10 个问题，全靠自己记笔记。插件没有「这条结果没用」的按钮，也没有把「某次查询最终点了哪条」记下来。于是**下一次还是同样的排序**。NotebookLM 在这点上也不强，但至少它的 grounded answer 会告诉你「依据是这几段」，让你一眼看出对错。

## 4. 和 NotebookLM / nLab 比，差在哪

你提到 NLAD，我按两类工具理解，都对比一下（如果你指的是别的，结论大体不变）：

| 能力 | NotebookLM 类（整书问答） | nLab 类（概念百科） | 我们的 kb 插件 |
|---|---|---|---|
| 输入单位 | 整本书 / 整批文档 | 概念页 | 卡片 + 段落 |
| 回答方式 | 生成式回答 + 逐句引用 | 概念页互链 | 返回命中段落列表 |
| 引用粒度 | 段落/页码 | 页面 + 版本 | 段号（页码 8%） |
| 跨文档综合 | ✅ 强 | ⚠️ 靠人工链接 | ❌ 基本没有 |
| 论证路径 | ⚠️ 能给引用，不给依赖图 | ✅ 链接即路径 | ❌ 无 |
| 语义检索 | ✅ 向量 | —（靠人写） | ❌ 纯词法 |
| 可信度 | 引用可核 | 社区审阅 | draft/checked/verified，但 67% draft |
| 失败模式 | 幻觉 | 过时 | **静默 0 命中 / 噪声置顶** |

结论：**我们既没有 NotebookLM 的「整书理解 + 引用」，也没有 nLab 的「链接即路径」。** 我们有的是「2,907 张摘要卡 + 5 万段无类型文本」，卡和文本之间没有边。堆书本身不产生结构；NotebookLM 之所以好用，是因为它把「回答」锚定在「原文段落」上，而我们的卡片是**二次创作**，一旦离开原文就无法核对。

## 5. 怎么解决（按投入产出排序）

### P0：一天能做完的（纯检索层/渲染层）

1. **多词 OR 回退**：AND 命中 0 时自动降到 OR，并在结果里标注「放宽后命中」。
2. **停用词与权重**：`proof/theorem/definition/real/…` 降权；查询词按 IDF 加权（现在等价于「谁词多谁赢」）。
3. **表格/书目/索引降权**：用正则识别「一行多个 `&`」「`[数字]` 开头」「连续 `\bibitem`」的段落，`env` 里加 `table/bibliography/index` 三类，默认排在最后或折叠。
4. **跨语言扩展（最小版）**：用 `termbase.jsonl` 把中文查询扩出英文、英文查询扩出中文，各加权 0.5。
5. 修 `kb_zh` 的 `around`；给返回加 `max_chars`（默认 1,500 字/段，超出截断并标注）。
6. 修提示语：`layer="all"` 时不再提示「加 layer="all"」。
7. 修渲染：页码离散值不要渲染成区间（`pages=[68,70,71]` 不要显示 `p.68–71`）；`terms` 不要原样 `JSON.stringify`；卡片正文里的 LaTeX 做最小剥除。

### P1：一周量级（数据层，收益最大）

1. **段落级页码回填**：我们自己的 `make_corpus.py` 在切段时就知道源文件与页标记，把 `page_orig` 写进去。这一条做完，所有引用才成立。（本卷 170 段现在全 `null`，可以立刻验证。）
2. **命题索引（statement index）**：从译稿的 `\begin{theorem}`/`\begin{definition}` 与「定理 2.1.5.」这种行首编号抽取，生成 `(工程, 编号, 类型, 译本页, 证明段, 前置)` 六元组，单独一个表。**这一张表就能回答「这个命题在哪、证明在哪」**。
3. **长段切分**：>2,000 字的段落按语义边界（空行、`\item`、`\section`）切开，保留 `parent_id`。61 段的问题一次解决。
4. **卡片与段落连边**：每张卡的 `sources[].anchor` 已经指向 `源码/xxx.tex:行号`，把「卡片 → 译文段」的映射落库，检索时两边一起给。

### P2：一个月量级（检索质量）

1. **混合检索**：BM25 + 本地 embedding（bge-m3 一类，中文）召回，再用 cross-encoder 重排 top-50。不需要 GPU，CPU 跑 5 万段可以接受。
2. **「证明模式」**：输入命题名 → 返回 `证明段 + 前置结论列表 + 原文页`。这比通用搜索更贴翻译场景。
3. **依赖图**：从 `\ref`、卡片 `related`、正文「由定理 X」抽取边，支持「谁用了这个结论」。
4. **查询改写**：把「这个命题怎么证的」改写成 `(命题名) + (证明|proof) + (前置术语)`，再检索。

### P3：结构性建议（最重要）

**把卡片降级为「导航层」，把「段落 + 类型 + 页码 + 依赖边」升为「知识层」。**

现在的架构是「卡片是主体，原文是补充」，所以一旦卡片没覆盖，整个库就「没有」。应该反过来：原文段落是事实源，卡片只是它的一个视图（view），视图可以缺失、可以有多个。这样「库里有没有」这个问题永远问得清——因为原文在，就一定有。

## 6. 如果只能做一件事

做 **「命题级索引 + 页码 + 证明段指针」**。

理由：本次 11 次无用调用里，有 7 次是在找「这个结论的证明/出处」；而「这个概念是什么」用 `kb_card` 一次就够。翻译、校对、写资料卡，最贵的动作都是「定位到原文那一句」，不是「理解概念」。

判定标准也很清楚：**给我一个命题编号，30 秒内我能不能拿到「译本页 + 原文页 + 证明段 + 它依赖的三个结论」**。现在不能；做完 P1.1 + P1.2 就能。

## 7. 给下一个译者的使用建议（在插件改好之前）

1. **`kb_source(pkg, page)` 是最可靠的接口**——它直接给整页原文，不受排序影响。定位到「大概哪本书」之后，用它回源。
2. **`kb_card` 查术语**，比搜索可靠。
3. **`kb_brief(work=...)` 做开工前置包**，一次拿到本卷卡片 + 跨书线索，这是本次最省时间的一次调用。
4. **不要用 `kb_search` 的 0 命中判断「库里没有」**——先用 `layer="all"` 复核，再换中文/英文重试；仍 0 才可能是真没有。
5. **查证明时先想中文术语**（英文名经常 0 命中）。
