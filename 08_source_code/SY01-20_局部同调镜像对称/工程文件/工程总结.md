## 二、环境与依赖

- **编译器**：MiKTeX 26.5（XeLaTeX 4.18），`ctex` 用 `fontset=fandol`（不依赖系统字体）。
- **宏包**：amsmath/amssymb/amsthm/mathtools/bm、geometry、graphicx、xcolor、tcolorbox[most]、enumitem、booktabs、array、tikz、tikz-cd（+quotes 库）、caption、cite、hyperref、longtable、alphaurl（bst）。
- **Python**：仅用 PyMuPDF 做 PDF 文本抽取、页码映射投票、渲染抽检；其余全部是标准库。
- **并行**：8 名译手（独立 context）+ Lead 1 名；Lead 负责底本工程、术语冻结、样板章、集成、校验、文档与打包。

## 三、流水线（可复用的十步）

1. **底本固定**：从微信收到的 PDF 与 arXiv 原件比对（页数、元数据、文本层），`pdftotext`/PyMuPDF 抽出带页标记的纯文本。
2. **源码复原**：下载 arXiv LaTeX 源（`main.tex` 5 564 行 + `main.bib`），本地 `pdflatex` 重编译——注意：本地编译 51 页 ≠ arXiv 56 页，**不能用 SyncTeX 做页码映射**。
3. **页码映射**：写投票脚本，把源码按 (词, 行号) 展平，用每页文本的首/尾词做频率加权投票，并强制单调；再以 81 个 statement 编号（模拟 LaTeX 计数器）为锚点定上下界，得到 `work/page_start.json`（56 页 → 源码行）。精度约一段。
4. **分块**：按节边界把源文切成 15 块（ch00 样板 5 页、其余 4–8 页），每块生成 `_src` 原文 + 页码锚点；**切块必须在环境边界上**（见 §六.2）。
5. **术语冻结**：从库内 693 条冻结术语表挑出可复用项，补 150 条本项目术语（`work/terms_zh.tsv`），先冻结再并行。
6. **样板章**：Lead 亲译 ch00（引言前半，5 页），定版式、定理体例、三类方框写法、译注字数与位置；编译通过后才放译手。
7. **并行翻译**：8 名译手各领 1–2 块，写作用域互斥（各自 `chunks/chNN.tex` + `work/reports/`），每块自带编译自检 wrapper。
8. **集成校验**：全量合并编译 → 编号核对 → statement 序列比对 → 术语/病灶词 lint → 逐页目检。
9. **附加材料**：导读、术语表、页码对照、译注索引、勘误表全部由脚本从成品源码生成，避免手工不同步。
10. **打包发布**：`src/` + PDF + 文档 复制进 `shuyi/translations/SY01-20/` 与 `gitee_shuyi/08_source_code/SY01-20_局部同调镜像对称/`，提交推送。

## 六、遇到的问题与解决

1. **本地重编译页数与 arXiv 不符（51 vs 56）** → 放弃 SyncTeX，改用文本投票 + statement 编号锚点；错误率从「系统性前移一页」降到「±一段」。
2. **ch05/ch06 边界切在 figure 与 example 内部**（两侧都无法单独编译）→ 建立「切块只在环境边界」规则，写脚本检查全部 15 个切点，修正 ch05/06、ch11、ch14 四处；ch11 改为从 `\begin{dfn}` 起、ch14 改为从 `\begin{align*}` 起。
3. **批量引号替换误伤 tikz 标签**（`\arrow[r,"i_\infty"]` 被改成「」），13 行，编译报 pgfkeys 错 → 写环境状态感知的还原脚本；规则：**任何全局文本处理都不能碰 tikz 命令参数行**。
4. **概念框写错数学**（「轨道范畴」对象写成「$F$-轨道」）→ 译手发现后全书三处同改；教训：概念库条目也要过一遍数学审读，不能只信「看起来对」。
5. **PowerShell 内联 Python 吃掉 `$`** → errata 里 3 行公式损坏；规则：含 `$` 或反斜杠的内容只用 write/edit 工具或落 `.py` 文件。
6. **ch09 一个 `\end{prp}` 写成 `\begin{prop}` 的配对错误** → 全量编译时定位修复；说明单块编译通过 ≠ 集成通过，合并编译必须做。
7. **概念框重复**（ch08/ch11 都有「轨道范畴」、ch14 与 ch11 都有「dg vs A∞」）→ 脚本去重，保留一处长文 + 其余短「回顾」框。

## 七、经验总结

- **先定版式再并行**：样板章 5 页花的时间（含三类框的视觉调优、定理体例、编号验证）在 8 路并行时全部赚回来。
- **页码映射是译注本的地基**：没有可靠的「页 → 源码行」，就无法在译文里插页锚点，也无法核对逐页对照表。
- **脚本优先**：术语表、页码表、译注索引、勘误表全部脚本生成；手工维护的表格在并行编辑下必然不同步。
- **校验要分层**：单块编译（快）→ 全量编译（慢）→ 编号/序列/术语/病灶自动化比对（最慢但最值钱）→ 人工抽页目检。
- **批注的质量上限取决于概念库**：概念框先由 Lead 集中写好并标注出处（nLab / 文献），译手只做「就地引用 + 适配上下文」，避免 8 个人各写一套说法。
- **不要相信「看起来对」**：概念框数学错误、引号误伤、切块错位，都是「目检通过、编译通过」之后才暴露的——所以要有独立的自动化比对。
