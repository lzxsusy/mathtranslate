## 1. 术语裁决：eigenbrane 译「本征膜」，与「本征值」共用词根

- **任务意图**：全篇核心概念 eigenbrane（KW2006 §6 引入）译名在初译中已统一为「本征膜」，本轮需确认不是想当然，且与相邻术语（eigenvalue 本征值、eigenbundle 本征丛、eigenvector 本征向量）自洽。
- **关键动作**：① 查本库既有资料卡 `datasets/kw06/cards/concepts/eigenbrane.json`：定义为 $X_B\simeq B\otimes V$，并注「本征值是向量空间」；`datasets/glc` 中各卡沿用「本征层／本征函子」；② 回核 KW2006 原文 p.95 eq (6.22)、p.121 eq (8.10)，确认 "eigenbrane" 是「在算符作用下变到自身、差一个张量因子」的对象，与特征值语义同源；③ 中文「本征」是 eigenvalue 的既有译法（本征值、本征向量），保留词根最省读者认知成本，不另造「特征膜」。
- **验证证据**：`校对记录/索引术语.tsv` 中 `eigenbrane@本征膜` 计 5 处、`eigenvalue` 全篇作「本征值」；part3 正文 0 改动（`校对记录/ch03_issues.md` §一）；译注 4.1-1（`源码/part3_zh.tex`）已就「本征值是向量空间」单独作注。
- **结论**：借自英语的合成术语，**先查本库是否有先例、再回原文确认语义同源**，两条都过才动或不动。本例属「有先例、语义自洽」，冻结不译新名。

## 3. 算判型：$\alpha_{a,i}\in H^1(C,K^{1-d_i})$ 的指标是否抄错

- **任务意图**：§2.5 完全可积性中 $H_{a,i}=\int_C\alpha_{a,i}\mathcal P_i(\varphi)$，原译写 $\alpha_{a,i}\in H^1(C,K^{1-d_i})$。负指标看着可疑，须判定是译文错还是原文如此。
- **关键动作**：① 回到原文式 (2.19) 及上文：$\mathcal P_i$ 是 $\varphi$ 的 $d_i$ 次齐次多项式，取值于 $K^{d_i}$；② 用塞尔对偶算度数：与 $\mathcal P_i$ 配对的一次形式应落在 $K\otimes K^{-d_i}=K^{1-d_i}$，故 $H^1(C,K^{1-d_i})$ 正确；③ 取最低次 $d_2=2$（$\operatorname{tr}\varphi^2$ 对应 $K^2$）验证：$1-d_2=-1$，$K^{-1}=T$（切丛），即 $H^1(C,T)$，正是形变理论的余切方向，量纲自洽。
- **验证证据**：`工程文件/疑点清单.tsv` 第 3 行，结论「已解」，依据「原文 p.9 式 (2.19) 直接计算」；`校对记录/ch01_issues.md` §三 §2.5 条目；译注 2.5-1（塞尔对偶逐项展开，A 级：arXiv:1506.04293 §2.5）。
- **结论**：**符号可疑先算指标**，能算清的（次数、阶数、维数）一律算，算出来的结论比「看起来像笔误」可靠；本例判为无误，不动正文，只在译注里把算法写给读者看。

## 4. 公式复核：分歧除子次数与谱曲线亏格

- **任务意图**：§2.6.1 给出 $g_D=g_C+(N^2-1)(g_C-1)$，译文与原文一致；但读者最易在此处迷路（分歧除子度数 $\deg\mathcal R=2N(N-1)(g_C-1)$ 从哪来？），需要一条能自己验算的译注。
- **关键动作**：① 用黎曼–胡尔维茨：$2g_D-2=N(2g_C-2)+\deg\mathcal R$；② 判别式次数 $N(N-1)$ 即 $y$ 的临界点个数（每点 $N(N-1)$ 个分支点，重数计），乘以 $2g_C-2$ 得 $\deg\mathcal R=2N(N-1)(g_C-1)$；③ 回代得 $g_D=N^2(g_C-1)+1=g_C+(N^2-1)(g_C-1)$，与原文两处一致，另核 $N=2$ 的 $g_D=4g_C-3$ 与正文欧拉示性数论证吻合。
- **验证证据**：`源码/part1_zh.tex` 译注 2.6.1-1（A 级：原文 §2.6.1 式 (2.21)–(2.22)；A 级 Hitchcock 1987 = 文献 [21]）；`校对记录/ch01_issues.md` §三 §2.6.1 条目。
- **结论**：**能回代的公式一律回代**。译注的增量不在「重复原文说 $g_D=\dots$」，而在给出读者可以自己复算的那一步。

## 5. 约定型：$\int_C\omega=1$ 是原文自洽还是漏了系数

- **任务意图**：§7.1 译文「令 $\omega$ 为 $C$ 的凯勒形式的某个倍数，归一化 $\int_C\omega=1$」，配上 $F=2\pi d\,\omega$、$c_1(\mathcal L)=d$，看着像三处归一化打架，需要判定哪一处才是笔误。
- **关键动作**：① 对照原文 p.67：确实写 "normalize so that $\int_C\omega=1$"；② 自洽性检查：$c_1(\mathcal L)=\frac{i}{2\pi}F=d\,\omega$ 且 $\int_C\omega=1$ 时 $\deg\mathcal L=\int c_1(\mathcal L)=d$，与 $F=2\pi d\,\omega$ 一致；③ 若改成 $\int_C\omega=2\pi$ 或去掉 $2\pi$，反而会使 $d$ 与 $\deg$ 错位 → 判原文无误。
- **验证证据**：`工程文件/疑点清单.tsv` 第 4 行（结论「已解」，依据「原文 p.67 及其后 $c_1(\mathcal L)=d$ 的自洽性」）；译注 7-1 与 7.1 计算段落（`源码/part4_zh.tex`）。
- **结论**：归一化系数不能单点看，**要让三个相邻公式同时成立**才算自洽；这是一种「三条腿支撑」的判定，比对照单句更稳。

## 6. 字形不是文字：原文的 $\mathfrak F$、$\mathscr F$、$\mathsf F$ 三套字体

- **任务意图**：part3 译手报告「同一 Hitchin 纤维在 §5.3 记 `\cF`、§5.2/§5.4 记 `\FF`」，怀疑译稿一物二名，建议统一。但这会动公式符号，属 P2 边缘地带，必须先判清。
- **关键动作**：① 先看宏定义：preamble 中 `\cF` = `{\sf F}`（无衬线）、`\FF` = `{\eusm F}`（欧拉花体），**是两种字形，不是同一符号的两种写法**；② 用 `mutool draw -F stext` 抽原文 PDF 内嵌字体名，逐页统计：全篇 `EUFM10`（欧拉 fraktur）出现 F 142 次、`EUSM10`（欧拉 script）F 1 次、`CMSS10`（无衬线）F 在 PDF 第 25–28、59–61、66–67 页共数十次；③ 定位 §4.3/§5.2 原句 "supported on a chosen fiber 𝔉" 用的是 fraktur，§5.3 "𝖥 is a complex torus" 用的是无衬线 → **原文自己就在切换字体**，译文 `\FF`/`\cF` 的分布与之一一对应。
- **验证证据**：`allpages-.xml` 字体统计（`EUSM10`: M 202/D 38/P 29/G 26/A 4/F 1；`EUFM10`: F 142/su 5/g 2）；`校对记录/ch03_issues.md` 遗留条目的复核结论；part3 正文 0 改动。
- **结论**：**「一物二名」的怀疑必须先落到字形/字体层核验**。宏定义不同就说明作者/译者有意区分（或沿袭原文的排版习惯），统一反而制造错误。这条也提醒：`\def\FF` 在 preamble 里有先后两条定义，后一条生效——读符号先读宏。

## 7. 英文介词短语的义项：isomorphism "in families" ≠ 「族之间」

- **任务意图**：part4 §6.1 原译「符号 $\cong$ 指可以普适定义、因而也能在**族之间**给出的同构」，读起来别扭且语义可疑，需判定。
- **关键动作**：① 原文 "an isomorphism that can be defined in a universal way and which therefore also gives an isomorphism in families"——"in families" 修饰「同构」在参数族中的存在性（即与基底无关、可连续延拓），不是「族与族之间」；② 上下文紧接着用行列式线丛在 $\mathrm{Pic}(D)$ 上的族论证 (6.4)，"in families" 正是这些论证成立的前提 → 译「族之间」会把逻辑关系读反；③ 改为「因而也能**在族中给出的同构**」。
- **验证证据**：`校对记录/ch04_issues.md` 改动清单第 1 条（P2 唯一改动）；`源码/part4_zh.tex:28`；原文 §6.1 第二段 "in families" 出现处。
- **结论**：数学英语里 "in families" 是固定用法（在族中、随族变化），**不能按字面拆成「族之间」**；判定靠的是后文是否依赖这个语义，而不是词典释义。

## 9. 原文笔误的三种处置：改、照译、加注

- **任务意图**：本轮共登记原文疑误 18 处（part1 4、part3 10、part4 4），处置必须一致，不能各人一套。
- **关键动作**：① 分三类：**(a) 可算判且影响论证**（如 §5.2 两次写 $\mathcal L\to\mathcal L\otimes\mathcal O(q')$，据上下文第二处应为 $q''$）→ 正文照译原文，**另加译注**点明应为 $q''$；**(b) 纯笔误、不影响推理**（如 §2.4 $(w_2,\dots,w_n)$ 应为 $w_N$）→ 照译 + 登记，不改不注；**(c) 译者已按语义补正的**（§1 "and now it produces" 疑为 how）→ 保留译者处理，只登记；② 全部进 `校对记录/ch0N_issues.md` §二，统一格式「位置/原文/原译/改为(不改)/依据/页码」。③ 红线：原文 PDF 页码一律用印刷页（PDF 页 − 1），不许写「大概在某页」。
- **验证证据**：`ch01_issues.md` 第 5–8 条、`ch03_issues.md` 10 条、`ch04_issues.md` 4 条；part3 译注 5.2-2 即 (a) 类处置实例。
- **结论**：原文疑误的处置原则是**「读者能不能自己发现」**：读者会发现（前后矛盾、可算）的必须加注；读者不会察觉的照译登记即可。绝不允许把「我认为作者写错了」直接改成正文。

## 10. 工程判定链：附录 A 崩溃与 3 处 overfull 的连锁修复

- **任务意图**：译注落地后要自动生成附录 A（译注汇总）与附录 B（术语对照表），并保证编译 0 error / 0 overfull。
- **关键动作**：① `gen_appendix.py` 生成后首编译报 `! Argument of \enit@postlabel@i has an extra }`，定位到 `description[style=nextline]`：纯 article+enumitem 可复现，但只在加载本 preamble 时崩，与 CJK 无关、与 `\item[2.1-1]` 写法无关（换 `\item[A1]` 同样崩）→ 改用普通悬挂列表 `[leftmargin=5.8em,labelwidth=5em,labelsep=0.6em]`；② 重编译后剩 3 处 overfull（135.6pt / 12.7pt / 19.0pt），全部来自脚注里未断行的 nLab URL → 加 `xurl`，并用 `wrap_urls.py` 把 `\transnote{}` 内 19 处裸 URL 包成 `\url{}`（花括号配对定位、幂等、支持 `--check`）；③ 同时修 `gen_appendix.py` 的 `INDEX_RE`（原正则多吃一个右花括号）与跨文件节号计数器（四部分编号从 2.1-1 连续排到 7.2.2-1，不按文件重置）。
- **验证证据**：`工程文件/tools/build.sh` 审计输出 `errors: 0 / undefined: 0 / overfull: 0 / warnings: 109`、`pages: 74`；`wrap_urls.py --check` 由「19 处待包装」变为 0；附录 A 按节分组编号（2.2-1 … 7.2.2-1）在成品 PDF 第 64–69 页可用。
- **结论**：LaTeX 链条问题必须**先定位到最小复现再改**（本例排除了 CJK、标签写法两种猜测），否则容易在 preamble 里叠一堆无用的 padding；overfull 的根因往往是「不可断行的 URL」，`xurl` + `\url` 是成本最低的解法。

## 11. 既有资料卡核对：glc 卡对、讲义译注自相矛盾，上报不改卡
