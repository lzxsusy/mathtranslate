## 1. 起点：文本层为零

`pymupdf` 对 PDF 前 10 页调用 `get_text()` 全部返回空串 —— 说明整本书每页只有一张整页位图。这直接决定了后面所有工序：

| 决策 | 依据 | 代价 |
|---|---|---|
| 200 dpi 渲染全部 265 页为 PNG | 150 dpi 时上下标嵌套（如 $K^{pq}=\theta^p\Omega^{p+q}$ 的角标）已不可靠；200 dpi 是本机人工可读的下限 | 265 张图，约 20 秒/页 |
| 用 OCR 只做**定位**，不做转录 | 实测 tesseract.js(eng) 正文正确率约 95%，但公式系统性乱码：`V C U`（应为 $V\subset U$）、`€`（应为 $\in$）、`pov`（应为 $\rho_{UV}$） | 需要"公式一律回图"的纪律 |
| 公式、定义、定理陈述全部逐符号对页面图像核对 | OCR 乱码不可作为数学内容来源 | 单块耗时翻倍 |

**页码映射不是猜的**：目录在 PDF 第 7 页（罗马页 vii），第 1 章首页在 PDF 第 8 页且页脚印「1」→ **原书页 = PDF 页 − 7**；罗马页 iii 在 PDF 4 → 罗马页 = PDF − 1。此后所有 `[依据：原书 p.N]` 都按此换算，45 页处抽查两次（PDF 52 = 原书 45，页脚 45）确认稳定。

## 2. 编号系统：手写编号一定会错

原书把**命题、定理、引理、推论放在同一个计数器里**，编号形如 `1.2.3`（章.节.序），且正文交叉引用（"by 1.2.2 (iv)"）大量存在。

**决策**：不手写编号，用一个共享计数器自动生成：

```latex
\newtheorem{agitem}{条目}[subsection]
\renewcommand{\theagitem}{\thesubsection.\arabic{agitem}}
\newtheorem{proposition}[agitem]{命题}
\newtheorem{theorem}[agitem]{定理}
\newtheorem{lemma}[agitem]{引理}
\newtheorem{corollary}[agitem]{推论}
```

**思维链**：21 个块并行，任何一块插入或漏掉一个条目，后面所有编号连锁错位；如果编号是手写的，这种错位在合稿前根本看不出来，合稿后又要逐块改。让编号由计数器产生，则"插入/遗漏"退化成"计数器顺序错"，而顺序可以机器审计。

**验证方式（可复现）**：从成品 PDF 用正则抽取所有 `命题|定理|引理|推论 X.Y.Z`，按节分组检查是否等于 $1,2,\dots,n$。结果是 212 处命中、**实际 210 条、12 个节全部从 1 连续**；多出的 2 处是正文里的交叉引用（"命题 1.2.4."、"定理 2.7.10 的证明。"），属审计脚本的正常误报。

顺带发现一个**反直觉的结论**：全书没有 Definition / Example 环境——扶磊把定义直接写在正文散文里（"A presheaf $\mathcal F$ of sets on $X$ consists of the following data: …"）。OCR 里 15 处 `Definition` 全是 "by definition" 之类。所以"0 个定义条目"是忠实底本，不是漏译。

## 3. 术语：在没有 A 级中文依据时怎么裁决

纪律要求术语先冻结、有通行中译则用、查证按 A/B/I 分级。实际情况是**找不到 A 级中文依据**：

- 扶磊中文第一版（清华 2006）不在本机；
- 《代数几何学原理》全译第一分册的 PDF 用了损坏的自定义字体编码，正文抽出来是乱码；
- 李克正《代数几何初步》是纯扫描本，OCR 质量不足以做术语依据。

于是 Lead 裁决一批核心术语，标为 **P 级（Lead 裁决/通行译法）**，并在 `glossary.tsv` 记明：sheaf 层 / presheaf 前层 / section 截面 / stalk 茎 / germ 芽 / scheme 概形 / **proper morphism 固有态射**（明确不用"真态射"）/ separated 分离 / coherent 凝聚 / quasi-coherent 拟凝聚 / formal completion 形式完全化 / flasque sheaf 松弛层 / spectral sequence 谱序列 / derived functor 导出函子 / blowing-up 爆破。

两条具体教训：

1. **"direct limit" 的译法要一次定死**。初稿同时出现"定向集/正向系统/正向极限"和"有向集/有向系统/有向极限"，前者是大陆教材旧译，后者是 nLab 与多数中文文献的现译。统一为后者，用 `normalize.py` 全书替换（有向集 4 处、正向系统 4 处），并在样板块留一条译注说明理由，保留别名供读者对照。
2. **人名与专名不音译**：Spec、Proj、Ext、Tor、Čech、Cartier、Picard、Zariski、Grothendieck、Serre、Stein、Segre、Koszul、Jacobson、Mittag-Leffler、Yoneda、Hartshorne 一律拉丁写法。这与纪律的"禁音译（Koszul/Morita 等除外）"一致，也避免了"扎里斯基拓扑"这类读起来费劲的写法。

**索引键是个隐藏的坑**：`\index{拼音@中文|hyperpage}` 里拼音既是排序键又是唯一键。踩到的问题：

- 同键冲突：`zhiji` 同时被"直积"与"支集"占用（makeindex 会合并条目）；
- 语义重复键：`nijin` 被"拟紧"和"拟紧态射"共用；
- 拼音写错导致排序错乱：`shangtongdiaogun`（群应为 qun）、`kesheyue`（"不可约"丢了"不"，排到 K 组）、`fan`（"泛上同调函子"排到 F 组最前）、`nuote`（"诺特空间"）；
- `\v{C}` 里的花括号会让朴素正则扫描 `\idx{...}{...}` 错位。

处置：`check.py` 增加"索引键冲突/含大写键"检查，`audit` 类脚本统一用 `\idx\{([^}]*)\}\{([^}]*)\}` 但先做花括号规避；最终 167 个键 → 173 个索引项，排序抽查无误。

## 5. 精选推导片段（8 段）

### (1) $f^{\sharp}$ 还是 $f^{\flat}$？——三层证据定案

疑点：定理 2.5.10 的态射记号，OCR 读作 `f'`，一位译手怀疑是 $f^{\flat}$（flat），另一位认为是 $f^{\sharp}$（sharp）。这类上下标在 200 dpi 下确实难辨。

证据链：
1. **同页邻近对照**：原书 p.204 定理 2.5.10 的陈述处，同一符号与 $f_*$、$f^*$ 并排出现，1200 dpi 局部放大后可读为 $\sharp$；
2. **字形**：p.205 处该字符是"两竖 + 中横、底部中空"，而 $\flat$ 是"竖杆 + 闭合碗形"，放大 600 dpi 后形态清楚；
3. **模板 IoU**：把 MiKTeX 生成的 $\sharp$ 与 $\flat$ 样本按同尺寸栅格与书上字形做交并比，$\sharp$ 0.377 vs $\flat$ 0.217。

结论：$\sharp$，不改。**教训**：单靠"数学上说得通"不能定符号——$\flat$ 在这里也说得通，只有像素证据能定。

### (2) p.199 的 $j^*\mathcal G'=\mathcal G|_U$

疑点：等式右边出现 $\mathcal G$，但本书此前只定义过 $\mathcal G'$，$\mathcal G$ 是"未定义符号"。

推理：上下文是在 $U\subset X$ 上讨论，$j\colon U\to X$ 是开浸入，旁边所有式子都以 $|_U$ 形式出现；写成 $\mathcal G|_U$ 意味着 $\mathcal G$ 是 $X$ 上的层，但该层在本节未引入。最省假设的读法是 $\mathcal G_U$（$\mathcal G$ 在 $U$ 上的限制，本书 p.17 起就用 $\mathcal F_U$ 这个记号）。

处置：**照录原书印法**（不改），加译注写明"$\mathcal G$ 在此前未定义，疑本应作 $\mathcal G_U$；译文照录"。理由：读者若对照原书，看到的应是同一个式子；改了就变成"译本与原书不一致"。

### (3) "原书漏了正向极限记号"——其实没漏

疑点：译注称正则谱序列定义 (i) 的 $Z_\infty(E_2^{pq})=Z_k(E_2^{pq})$（$k\gg 0$）漏了 $\varinjlim$ 记号，应补成 $\varinjlim_k Z_k$。

推翻过程：回图看 p.151 的原式 —— 同页"双正则谱序列"定义 (i) 就是**这样印的**；这是标准写法：$Z_\infty=\bigcap_k Z_k$、$B_\infty=\bigcup_k B_k$，在正则/双正则谱序列中固定 $(p,q)$ 后 $Z_k,B_k$ 当 $k$ 足够大时稳定，故 $Z_\infty=Z_k$。两种写法（有向极限 vs "对充分大的 $k$"）说的是同一件事。

处置：译注改写为"正当性说明"而不是"纠错"，来源改为 `[依据：原书 p.151 (i) 与本节谱序列定义 (b)]`。**这是本工程最典型的一类错误：把"我没见过这种写法"误判成"原书错了"。**

### (4) unique up to *unique* isomorphism 不是啰嗦

原文：定理 2.7.10（Grothendieck 存在定理）末句 "unique up to unique isomorphism"。

初译：两处都写成"在同构意义下唯一"。复核时发现限定词被吃掉：无向极限/极限的泛性质只保证"在同构意义下唯一"，而这里多一个 unique 是有内容的——**同构本身唯一**（不是"存在一个同构，随便挑"）。这在下降论证里会被引用。

处置：改为"在唯一同构意义下唯一"。**教训**：`unique up to unique isomorphism` 是代数几何的高频固定表述，不能按字面省略重复词。

### (5) p.220 的 $M'$ 还是 $M''$

原文（命题 2.6.8 的 (ii)⇒(iii)）："…$H^i(X,\mathcal F\otimes M)\to H^i(X,\mathcal F\otimes_A M')$ 是满射"。

图追踪：该段正在用短正合序列 $0\to M'\to M\to M''\to 0$ 的两行长正合列做五引理式论证；上面那张图第二行的第二个箭头是 $H^i(\mathcal F\otimes M)\to H^i(\mathcal F\otimes M'')$，且论证结论正是"$H^i(\mathcal F\otimes M)\to H^i(\mathcal F\otimes M'')$ 满"。所以原书的 $M'$ 是排印错误。

处置：正文按 $M''$ 译出 + 译注写明原书印法（照录原则的例外条款：照录会明显致误时按正确含义译，并留痕）。

### (6) §2.4 习题 3：从半句话重建一道四问长题

缺口：只有一句"…是外微分"。要补 (1)–(4)，只能靠页图像 + 上下文。

推理骨架：题面设 $R=\mathbb C[t_1,\dots,t_n]$、$f\in R$，问的是 $\Omega^\cdot$（代数 de Rham 复形）与 Koszul 复形 $K^\cdot(\partial f/\partial t_i;R)$ 的同构 —— 因为 $\mathrm df\wedge$ 在 $\Omega^\cdot$ 上恰是 Koszul 复形的微分，这是 Cartier 引理的标准练习；接着 $(\theta d+df\wedge)^2=0$ 给出变形复形（deformed de Rham / 一次 $\theta$ 的 Hodge 型复形）；(3) 的滤过 $F^p=\theta^p\Omega^\cdot[\theta]$ 产生 $E_1^{pq}\Rightarrow H^{p+q}$；(4) 把双复形 $K^{pq}=\theta^p\Omega^{p+q}$ 的 $d_1=df\wedge$、$d_2=(-1)^p\theta d$ 写清，说明这是同一构造的另一个谱序列。

处置：按此重建四问，并加译注说明原书 (3) 有两处记号是照录（$F^p$ 下标印作 $\mathbb G_m^n/\mathbb C$、谱序列右端印作 $\Omega^n[\theta]$），提醒读者按题面开头与本节其余处的 $\Omega^\cdot[\theta]$ 理解。

### (7) p.115 "for every" 后面是不是脱了 $n$

原文：习题 2(6) "…if and only if for every we have $\lim_{m\to\infty}a_n^{(m)}=0$ uniformly in $n$…"。`for every` 后面直接接 `we`，明显缺一个对象。

候选：$n$（对每个 $n$）或 $m$（对每个 $m$）。回图放大 p.122 顶部确认**原书就是这样印的**，确实脱字；从语义看应是"对每个 $n$，$\lim_m a_n^{(m)}=0$ 关于 $n$ 一致"。

处置：归入"存疑"档：正文按可读性补出一个 $n$ 的读法并加译注说明"原书作 `for every we`，此处按上下文理解为对每个 $n$"，同时在疑点清单标注"未完全定案"。**这类无法用证据闭环的疑点，宁可标存疑也不装作定案。**

### (8) 212 ≠ 210：审计脚本的误报也要落账

机器抽出 212 处编号，实际 210 条。差的 2 处分别是"命题 1.2.4."（正文交叉引用）与"定理 2.7.10 的证明。"（证明标题）。若不核对就按 212 报数，会把"交叉引用"当成"重复条目"；若按 210 报而不解释差异，后续审计者会重新踩一遍。

处置：审计脚本 `audit_numbering.py` 的输出里保留"212 抽出 / 210 实际 / 2 处误报及其位置"，让数字可解释，而不是只给一个"OK"。

## 6. 事故复盘

### (1) PowerShell 读改写把 26 KB 中文 TeX 变成乱码（最严重）

一位译手用 `(Get-Content -Raw $f) -replace 'a','b' | Set-Content -Encoding UTF8 $f` 想把一个术语批量替换。Windows PowerShell 5.1 的 `Get-Content` 默认按系统 ANSI（本机 CP936）读**无 BOM 的 UTF-8** 文件，于是每个中文字被拆成两个拉丁字符，再以 UTF-8 写回 —— 文件结构还在，字符全毁：502 个 `0x7F`、6 个 `U+FFFD`，以及"设→讁、是→昁、，→！"这类成片错字。文件在编辑器里打开仍像"差不多能读"，很容易被漏过。

**判据**（现在写进流程）：任何非 ASCII 文件被脚本回写后，用 `[IO.File]::ReadAllBytes()` 扫 `0x7F` 与 `U+FFFD`，非 0 即视为损坏；`check.py` 也加了同样的字节扫描。

**恢复**：损坏文件是并行产物，没有 git 历史可回退。解法是从 DSH 的会话转录里重放该译手对这个文件做过的全部写操作：`~/.dsh/sessions/.../session.v4.jsonl.zstd` 用 Python `zstandard` 流式解压，按顺序抽出 1 次 `write` + 19 次 `edit` 的入参，在工作树重放，重建出 26,008 字符、SHA256 与原记录一致的文件。

**固化规则**：中文 `.tex` 只用 read / write / edit 三类工具写；禁止用 PowerShell 管道回写文本；批量替换一律走 Python 脚本（显式 `encoding='utf-8'`, `newline='\n'`）。

### (2) 批量替换规则过宽，改坏了一个术语

`normalize.py` 里一条 `\{(平坦的)\}` → `平坦态射` 的规则，本意是把"平坦的态射"收紧，结果把 `\emph{平坦模}`（flat module）一起改了。原因是匹配没有锚定到"态射"。

处置：手工改回，并把该规则加上"后面必须是 `态射`"的断言。**教训**：批量替换必须 dry-run + 命中清单人工过一遍，且每条规则都要问"这个前缀还可能是别的词吗"。

### (3) `build.ps1` 的三处环境坑

- **编码**：Windows PowerShell 5.1 读无 BOM 的 `.ps1` 时按 ANSI 解码，脚本里的中文路径变成"婧愮爜"，编译直接找不到文件 → 脚本必须存为 **UTF-8 with BOM**；
- **`$ErrorActionPreference='Stop'`**：xelatex 会往 stderr 写正常信息，Stop 会把它们当致命错误中断 → 改 `'Continue'`，靠 `main.log` 判定；
- **日志重定向**：不能把 xelatex 的 stdout 重定向到 `main.log`（它自己要写这个文件），必须用 `build_passN.log`；成品文件名里的中文用 `[char]0x4EE3` 这类码点拼，避免脚本编码再次介入。

### (4) `Missing character: There is no 。 in font [lmroman10-regular]`

某块把一个中文句号写进了行间公式末尾（`\[ ... 。\]`）。渲染时该字符被静默丢弃，只有 `main.log` 里有一行 missing character —— 肉眼看 PDF 是"公式后面少个句号"，极难发现。
