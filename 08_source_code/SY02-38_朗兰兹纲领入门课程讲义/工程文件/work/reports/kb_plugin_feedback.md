# 本地知识库插件（kb_locate / kb_ctx / kb_get）实测反馈

- 测试者：Lead（DSH agent）
- 日期：2026-11-26
- 测试场景：翻译 Anschütz《朗兰兹纲领入门课程讲义》（SY02-38）过程中的术语/定理核查
- 调用次数：`kb_locate` 6 次、`kb_ctx` 1 次、`kb_get` 1 次
- 结论一句话：**可用的“坐标定位器”，不是“问答器”**；在“我知道概念名、要一条可引用陈述”的场景下很有价值，在“我不知道该查什么词、只说一句困惑”的场景下覆盖率会被虚词和英文专名系统性拉低。

## 2. 发现的问题

### 2.1 英文专名不入词表，覆盖率被系统性低估
`satake`、`deligne`、`galois`、`hasse`、`eichler` 在 Query 术语化时被判 `missing`：库内词表以中文术语为主，英文原词多数没有别名条目。结果是**关键概念被当成“缺词”计入分母**，同一句查询的覆盖率因此被压低 20–40 个百分点。建议：概念词典为每个中文术语补英文别名（`Hasse invariant / Hasse 不变量`），或在打分时把「英文词 C 与库内术语 T 的中文等价」作为软匹配。

### 2.2 疑问虚词进入 `unknown` 并计入缺失
`why` 里出现「为什么给出」「上的」「什么是」「三个」「它和」「的尖」等，`unknown` 把它们与真正缺的概念（`反射域`、`局部分`）混在一起，还被提示「删掉它们，换成库内术语重问」。建议：内置中文停用词表（疑问词、量词、连词、方位词），在术语化前过滤，且**不计入覆盖率分母**。

### 2.3 覆盖率与“答案性”不相关
第 5 条 100% 覆盖却是假阳性（讲的是 Shimura 数据族的同构，不是定义本身）。覆盖率只衡量词面重合，不能替代「这是不是定义/定理的规范陈述」。建议在输出里区分 `kind`（definition/theorem/text）并优先 definition/theorem；本插件已有 `kind` 字段，但未用于排序——若把「查询以『什么是/定义』开头时对 definition 单元加权」做成默认策略，会显著提升实用性。

### 2.4 `kb_get(work, number)` 的编号歧义（真实踩坑）
`kb_get(work="SY02-24", number="4.7")` 返回的是 §5.4.2 的「式 4.7」（`SY02-24:5.4.2:equation:4.7`），而不是 §4.7 节。返回的坐标只有源码行号（`源码/chapters/ch05.tex:461`），没有原书页码，无法直接引用。建议：`number` 解析支持 `节号.编号`（如 `4.7.3`）或要求 `section` 参数；无页码时明确提示「此单元无原书页码，不可作引用坐标」。

### 2.5 `kb_ctx` 表现好
`kb_ctx(SY02-09:9.2:theorem:9.2.3)` 正确给出【陈述】+ 同节注记 + 相邻编号陈述，并明确说明「同节没有找到 proof 单元」。这种「有就说有、没有就说没有」的行为对引用核对非常有用，建议保持。

### 2.6 延迟
`kb_locate` 56–747 ms（首次含引擎加载约 300 ms），`kb_ctx`/`kb_get` 均在 1 s 内，作为本地索引可以接受。

## 3. 建议优先级

1. **术语别名（中文↔英文）**——影响最大，直接决定覆盖率是否可信。
2. **中文停用词过滤**——低成本，去掉 `unknown` 噪音。
3. **`kind` 感知排序**——「什么是 X」优先 definition，「定理 X」优先 theorem。
4. **`kb_get` 编号消歧 + 缺页码显式提示**——避免把「式 4.7」当成「§4.7」。
5. 可选：查询里出现「为什么/关系/同余」等推理词时，明确告知「本工具只做定位、不给推导」，并给 2–3 个改写示例（现有 `gaps` 已部分做到）。

## 4. 在本次翻译中的实际用法

- 术语冻结前用 `kb_locate` 对齐 SY02-09/SY02-24 的既有译法（`nebentypus`→旁特征、`moderate growth`→适度增长）；
- 疑点清单里 2 条外部核对（Goren 的 Hilbert 模形式讲义、Hasse 不变量的讲义）由 `kb_locate` 提示的库内条目引导到原文，再走外部 A/B 级来源确认；
- `kb_ctx` 用于确认「库内某定理有没有证明」，避免把「库内有陈述」误当成「库内有证明」。
