# 编译说明 · SY01-23

## 环境

- **TeX**：TeX Live 2023+ 或 MiKTeX（需 `xelatex`、`biber`、`latexmk`；模板用到 `elegantbook` 与 `xeCJK`）
- **字体**：Windows 下用 `SimSun / SimHei / KaiTi`（默认设置）；Linux 需把这三种字体替换成同族字体，或改 `main.tex` 的 `fontset`
- **无需 Python**：索引 `index-zh.tex` 已生成好，页码走 `\pageref*`，重编译自动更新

## 一键编译

```powershell
cd 源码
pwsh ./build.ps1            # 或：latexmk -xelatex main.tex
```

产物：`build/main.pdf`（530 页，约 24.4 MB）。日志：`build/main.log`。

## 手动命令（等价）

```powershell
xelatex -interaction=nonstopmode -halt-on-error main.tex
biber --input-directory=. --output-directory=build main.bcf
xelatex -interaction=nonstopmode -halt-on-error main.tex
xelatex -interaction=nonstopmode -halt-on-error main.tex
```

四步缺一不可：`biber` 在第二遍 `xelatex` **之后**（要先有 `.bcf`），最后还要再跑一遍让交叉引用与目录稳定。

## 已知坑（都已在 `.latexmkrc` 里处理）

1. **biber 必须 `--input-directory=.`**
   否则 biber 会按 kpathsea 找到系统里某个同名的 `references.bib`（例如 MiKTeX 自带的 `feupphdteses/references.bib`），bbl 只有 5.8 KB、参考文献全错或全空。加上该参数后 bbl ≈ 143 KB。

2. **原来 `.latexmkrc` 里 `$biber` 指向 `python3 tools/run_biber.py`**
   Windows 上没有可用的 `python3`（`WindowsApps` 那个是 stub，退出码 9009），latexmk 直接失败。现已改为直接调 `biber`。

3. **不要在别的目录跑 latexmk**
   若当前目录上层还有别的 `main.tex`（例如 `C:\Users\admin\Downloads\main.tex`），容易编错文件并 `exit 12`。务必 `cd` 到本 `源码/` 目录。

4. **中文斜体警告无害**
   `Font shape TU/KaiTi(0)/m/it' undefined` 是 KaiTi 没有斜体字形导致的回退，PDF 里中文强调用正体显示，不影响正确性。

5. **`references.bib` 不要改回弯引号/Unicode 连接号**
   xeCJK 会把 U+2019 当 CJK 标点加宽（PDF 里出现 `Almgren’ s`）、把 U+2013 两端加空格。现文件已规范为 ASCII `'` 与 `--`。

## 校验（可选）

```powershell
pdffonts build/main.pdf          # 应全部 emb=yes
pdftotext -layout build/main.pdf out.txt   # 抽取文本应与交付 PDF 完全一致
```

本工程在 2026-11-14 从干净目录实编译验证：exit 0、530 页、24,434,480 B，抽取文本与交付成品逐字一致（1,895,725 字符）。
