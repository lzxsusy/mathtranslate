## 1. 底本双通道：文本抽提 + 页面图目视，先钉死公式再动笔

- **任务意图**：原文 15 页、公式密集，且本译本要「一字不改地」复现 (2.1)–(5.1)，不能靠记忆或 OCR 猜字符。
- **关键动作**：① 用 pymupdf 抽全文到 `work/fulltext.txt`（763 行，带 `===== PAGE n =====` 分页标记），同时把 15 页按 170 dpi 渲染成 `work/pages/p001–p015.png`；② 对关键式 (2.1) 不在文本层下结论，而是打开 `p002.png` 逐字符核对 `F − φ∧φ = 0` 与 `Dφ = D⋆φ = 0`（⋆ 为 Hodge 星算子，文本层易与 `*` 混淆）；③ 全篇 6 节的分页起点（§4 起 p5 末、§5 起 p7 末、§6 起 p10 末）也据页面图登记。
- **验证证据**：`work/fulltext.txt` 的 `(2.1)` 两行与 `p002.png` 一致；译稿 `源码/sections/sec2.tex` 用 `gathered` 复现两行，编号随节得 (2.1)。
- **结论**：**公式字符必须以页面图为准，文本层只用于定位**——这条在 ⋆、∨、上下标处救回了至少三处潜在误抄。

## 2. nLab 词条先验存在性，再取「Last revised」，不存在的词条一个都不引

- **任务意图**：用户要求「查 nLab 并批注」，但 nLab 词条名不等于直觉命名（如 `SYZ conjecture`、`hyperkähler quotient` 都不存在），引错 URL 等于伪造来源。
- **关键动作**：① 写探测脚本对 60 余个候选 slug 批量发 HEAD/GET，只保留 HTTP 200 的，404 的一律排除（实测 404：`SYZ+conjecture`、`hyperkähler+quotient`、`moduli+space+of+flat+connections`、`'t+Hooft+operator`、`complex+symplectic+manifold` 等）；② 对 200 的再抓 `Last revised on …` 日期，成功 30 条写入 `work/nlab_index.tsv`；③ 抓不到日期的 10 个词条（如 `Hitchin+fibration`、`mirror+symmetry`）在脚注中省略日期，只写「2026-11-15 访问」，**不猜日期**。
- **验证证据**：`work/nlab_index.tsv` 30 行；生成器报 `nLab 索引缺失: ['Hitchin+system']` 时按「缺日期即省略」处理，未编造。
- **结论**：来源可追溯的底线是**每条 URL 都真实打开过**；「日期不明就写访问日」比补一个看似精确的日期更诚实。

## 3. 译注单一真源：一份 Python 数据 → 脚注宏、附录、TSV 四个产物

- **任务意图**：46 条译注既要以脚注出现在正文，又要在附录 B 汇编、在 TSV 供审校；手写三份必然漂移。
- **关键动作**：① 把译注写成 `工程文件/tools/notes_data.py` 的 `NOTES` 列表（字段 `id/sec/kind/nlab/ref/text`，`text` 为 raw LaTeX）；② `gen_tables.py` 一次生成 `源码/gen/notes_macros.tex`（`\zhnt{id}` 展开为【译注 x.y】+注文+来源行）、`源码/sections/appendix_notes.tex`、`源码/sections/appendix_glossary.tex`、`工程文件/译注清单.tsv`；③ 正文只写 `\zhnt{4.5}` 这样的 id，不写注文。
- **验证证据**：六个 sec 文件中 `\zhnt{}` 的 id 去重计数 = 46，与 `NOTES` 长度 46、TSV 46 行一致；按节 {1:6, 2:8, 3:8, 4:7, 5:7, 6:10}。
- **结论**：**正文与附录不可能不一致，因为它们来自同一份数据**；改注只改 `notes_data.py` 再重跑生成器。

## 4. 术语冻结表先行：38 条术语 + 18 个记号

- **任务意图**：同一术语（如 `ramification`）在 §4 与 §5 分别是「分歧」与「野分歧」的基词，若前后译名不一，读者会以为换了概念。
- **关键动作**：① 通读阶段先冻结术语（A-model/B-model、Higgs bundle、Stokes matrices、isomonodromic deformation、moduli stack、tame/wild ramification …），写入 `GLOSSARY`；② 记号单列 `SYMBOLS`（`\YC`、`\MH`、`\LG`、`B`、`\Bun_G` …），正文首次出现给英文原文，其后只用中文；③ 附录 A 表 A1/A2 由生成器排出，正文与附录同源。
- **验证证据**：附录 A 表 A1 共 38 行、表 A2 共 18 行（p29–p31）；正文首现括注英文的抽查 12 处均一致。
- **结论**：**术语表在动笔前定，不在译完后补**——补的时候已经改不动 46 处脚注了。

## 5. 「原文一字不改」的边界：发现符号约定不一致，只批注不改正文

- **任务意图**：§4 原文写 `U = exp(−2π(α − iγ))`，若按 `φ = β dr/r − γ dθ` 与 `A = α dθ` 直接算平行移动，得到的是 `exp(2π(α − iγ))`，两者差一个符号。
- **关键动作**：① 不判断谁对谁错、更不改公式，只在【译注 4.5】里写出计算过程与差异；② 注文明说「原文取此式，与我们算得的差一个符号约定；此处按原文照录」；③ 同节其余译注（4.1–4.4、4.6、4.7）也只解释不复写。
- **验证证据**：`源码/sections/sec4.tex` 正文式 (4.1)(4.2)(4.3) 与原文逐字符一致；`notes_data.py` 中 id `4.5` 的 text 含该符号差异说明；附录 B p34 可见。
- **结论**：**译者的职责是让读者看见差异，不是替作者消掉差异**；凡「疑似笔误」一律走批注通道。

## 6. 脚注体例：5 条原注 + 46 条译注，来源分三级且逐条落地

- **任务意图**：读者要能一眼分出「Witten 说的」与「译者加的」，且每条补充都能追到出处。
- **关键动作**：① 原注用 `\yz{...}`（展开为【原注】），共 5 条，位置与原文一一对应（p1 三条、p6 一条、p11 一条）；② 译注用 `\zhnt{id}`，来源三级 A（原文/经典文献）/B（nLab 等，须与 A 交叉核对）/I（本库内部或纯由原文推得，标「译者按」）；③ B 级一律带完整 URL 与访问日期。
- **验证证据**：全文脚注连续编号（p22 止于 51 号）；附录 B 逐条列出「来源：A / B / A+B / I」；`译注清单.tsv` 的 kind 列可统计。
- **结论**：**「谁说的」比「说了什么」更需要体例保证**；三级来源让 nLab 这类社区来源永远处于被核对的位置。

## 7. 排印检修六连：字形、数学模式、TikZ 选项、URL 百分号、缺字、表宽

- **任务意图**：中文 + 数学 + TikZ + URL 混排，xelatex 首轮必炸；要的是「日志干净」而不是「能出 PDF」。
- **关键动作**：① SimSun 无小型大写字形 → 封面 `\scshape` 改 `\bfseries`；② 正文「Hodge 星算子原文作 \star」缺 `$` → 改 `$\star$`；③ TikZ `>={\Stealth[...]}` 被当成箭头名 → 改 `>={Stealth[...]}`；④ nLab URL 里 `%C3%A4` 的 `%` 在 TeX 读入时是注释符，导致 `\appnote` 报 `runaway argument` → 生成器把 `%` 转义为 `\%`；⑤ 表 A1 说明栏裸写 `σ` → `Missing character`，改 `$\sigma$`；⑥ 表 A1 列宽 0.24/0.30/0.40 溢出 9.37pt → 调成 0.22/0.27/0.41。
- **验证证据**：最终 `main.log` 只剩 Underfull hbox/vbox（中文断行常态），**无 Overfull、无 `!` 错误、无 Missing character、无 undefined reference**；PDF 41 页。
- **结论**：**「没有报错」不等于「排版对」，但「日志里没有 Overfull 与缺字」是必要条件**，逐条修完才进入目视环节。

## 8. 前置页页码体例：roman ii–iv 与正文 arabic 1–37 分离，目录点线统一

- **任务意图**：初版目录把「译者凡例」记成 2、「摘要」记成 3（阿拉伯数字），与正文第 2、3 页撞号；且只有 3.1、6.1 两条有引导点，其余没有。
- **关键动作**：① 把 `\pagenumbering{roman}` 提到 `\begin{document}` 之后、封面之前，使凡例=ii、摘要=iii、目录=iv，正文另起 arabic 1；② 在导言区用 `\@dottedtocline` 重定义 `\l@section`、`\l@subsection`，统一点线引导与缩进。
- **验证证据**：`main.pdf` p4 目录：凡例 ii、摘要 iii、§1 起 1、参考文献 18、后记 20、附录 A 25、附录 B 28；各级条目点线一致。
- **结论**：**页码体例是「读者第一眼就信不信这本书」的问题**，与内容质量同等对待。

## 9. 图 2 依赖链两次重排：从「节点打架」到「竖排 + 侧框 + 虚线回指」

- **任务意图**：用户要求后记「清楚展示全文框架与逻辑推导链条」，一张图胜过三段文字。
- **关键动作**：① v1 用 `right=of` 横排，节点互相压框、虚线穿过正文 → 废弃；② v2 改为竖排 §1→§5（`text width=7.2cm`，`below=1.35cm of` 逐级定位），§6 单列右侧虚线框（`right=1.9cm of n4`，`minimum height=3.9cm`）表示「四维来源」；③ 实线表示推导依赖、虚线表示第 6 节对第 1 节「模空间应读作叠」的反向修正，箭头标签统一 `font=\scriptsize, fill=white` 以免压线；④ 第一次渲染发现 §6 框文字溢出边框，加 `minimum height` 并把注文压到 5 行以内。

## 10. 译注 6.10：为什么「四元数李群」不存在，而超凯勒商可以替代辛商

- **任务意图**：原文 §6.1 末尾一句「四元数李群不存在，所以用超凯勒商代替辛商」是全文最陡的一跳，读者几乎必然卡住。
- **关键动作**：① 先说明四元数李群要求李代数带三个满足四元数关系且与括号相容的复结构 I,J,K，非平凡情形下不存在（可用 Jacobi 恒等式直接推出矛盾）；② 再说明超凯勒商绕开的办法：同时取三个矩映射 µ_I, µ_J, µ_K，以 µ⁻¹(0)/W 代替辛商 µ⁻¹(0)/W，结果仍是超凯勒流形；③ 最后回到原文：Hitchin 正是用它把 M_H(G,C) 实现为「C 上 (A,φ) 对」被 Maps(C,G) 的超凯勒商；代数几何的 Higgs 丛叠只记住 I，故原文说它「过于强调一个复结构」。
- **验证证据**：`源码/sections/appendix_notes.tex` 中译注 6.10 全文（p41）；来源标 A+B，引 Hitchin (1987a)、Hitchin–Karlhede–Lindström–Roček (1987) 与 nLab `hyperkähler manifold`、`symplectic quotient`。
- **结论**：**最能体现「译注补原文之未展开」的样本**——一句原文、三段补充，且每段都能追到 A 级或 B 级来源。
