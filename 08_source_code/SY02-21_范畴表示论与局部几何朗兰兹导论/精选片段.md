## 1. 编号体制：数字在前、带句点、与段落共享计数器

**现象**：算稿前先看原文页面图像（`工程文件/work/pages/p003.png`）。§2 首段的编号印作「2.1.1.」，紧接正文，**编号在前、带句点、不加粗**；定理印作「Theorem 3.2.10.」+ 斜体正文。更关键的线索：同一小节里「Theorem 3.2.10」之后紧接着是「Theorem 3.2.14」——中间隔了三个编号，说明定理环境与 `\subsubsection` 共用计数器。

**判定**：这是 amsart 的 `\newtheorem{...}[subsubsection]{...}` 加 `\numberwithin{equation}{section}`。若用 ctexart 默认的「定理 1」「定理 2」独立编号，全书的交叉引用会整体错位。

**处理**：`源码/preamble.tex` 里全部定理类环境均写 `[subsubsection]`，并用

```latex
\newtheoremstyle{zhthm}{3pt}{3pt}{\itshape}{}{\bfseries}{.}{0.5em}%
  {\thmname{#1}\thmnumber{ #2}\thmnote{ (#3)}}
```

把「**定理 3.2.10.**」的句点放在标签之后（amsart plain 的 head spec 为 `.`），公式用 `\numberwithin{equation}{section}`。

**验收**：`工程文件/scripts/num_reconcile.py` 从原文 PDF 与译本 PDF 各抽一遍 `\d+\.\d+\.\d+\.` 序列，312 vs 287 处出现；唯一「缺失」是 3.3.13——因为它带可选注，印作「3.3.13 (Beilinson–Bernstein, [BB81]).」，句点跑到括号后面去了，属抽取正则的伪影。`index_gaps.py` 逐小节核对无缺号。

## 2. `\ssszh`：run-in 且编号不加粗

**现象**：原文的段落编号不是标题行，而是「2.3.3.　We recall that…」这样与正文同行的 run-in 编号，且数字本身是正体（`工程文件/scripts/fontcheck.py` 在原 PDF 上打印出的字体是 **CMR10**，不是 CMBX10）。

**判定**：不能用 `\subsubsection{}`（会另起一行、加粗、带间距），必须自定义一个「只推进计数器、然后把编号和正文接在一起」的宏。

**处理**：

```latex
\newcommand{\ssszh}[1][]{\par\medskip\noindent\refstepcounter{subsubsection}%
  \thesubsubsection.\enspace
  \if\relax\detokenize{#1}\relax\else\textbf{#1}.\enspace\fi\ignorespaces}
```

带标题的少数几处（§4.4「Duality」「Character sheaves」、§6.10 的五个小标题）用可选参数 `\ssszh[对偶性]`，印作「4.4.3. **对偶性.**」，与原文一致。

**验收**：`fontcheck.py` 在译本上打印「4.4.7.」的字体为 LMRoman12-Regular（不加粗），标题「特征标层」为 FandolSong-Bold；页面图像 `my_p37.png` 目视确认。

## 3. 定理的可选注：两种排法都要保留

**现象**：原文 1093 行把作者名写在**环境正文**里：

```latex
\begin{theo} \label{t:bbloc}(Beilinson--Bernstein \cite{beilinson-bernstein81}) The functor ...
```

而 1434 行的同类定理用**可选参数**：

```latex
\begin{theo}[Beilinson--Bernstein, \cite{...}]
```

前者印作「Theorem 3.2.10. (Beilinson–Bernstein [BB81]) The functor…」，后者印作「Theorem 3.3.13 (Beilinson–Bernstein, [BB81]). There is…」。

**判定**：不是笔误，是作者的两种写法（一处把出处当正文开场，一处当定理标题的注）。

**处理**：两处都照原样译，不统一。译文分别印作「**定理 3.2.10.**（Beilinson–Bernstein [BB81]）函子…」与「**定理 3.3.13**（Beilinson–Bernstein，[BB81]）. 有交换图…」。

**验收**：`my_p16.png`、`my_p26.png` 目视；这也是 `index_md.py` 必须允许「第三段后无句点」的原因（见第 1 条）。

## 4. D-模 还是 D模：与 SY02-16／17 对齐

**现象**：`01_corpus_zh/数语规范/TERMS.tsv` 的 T0269 把 D-module 记作「D模」（无连字符），但 SY02-16《算术与几何朗兰兹纲领》与 SY02-17 的**正文**通篇写「D-模」。

**判定**：术语表是候选记录（`candidate` 状态），已出版译本的正文才是事实标准；且「D-模」与「$\fg$-模」「$\widehat{\fg}_\kappa$-模」的写法一致，若写「D模」会与后两者不齐。

**处理**：全书统一「D-模」，在 `glossary.tsv` 中把依据记为「SY02-16/17 正文；TERMS T0269 作 D模」，把分歧留在档里而不是留在正文里。

**验收**：`term_consistency.py` 把「D模」列为废弃写法，全书 25 个正文章节命中 0。

## 5. placid → 「平缓」：无既有依据时的定名流程

**现象**：placid ind-scheme 在 TERMS.tsv 与 SY02-16/17 的 glossary 里都查不到；原文对它的唯一解释是「一类无限维簇，使得 D-模的通常定义仍然成立」。

**判定**：不能音译（placid 无通行音译），不能生造一个与「光滑」「正规」混淆的词。取 placid 的「不剧烈、可控」义，定名「平缓」，并在首见处括注英文，让读者能回查。

**处理**：`glossary.tsv` 记 `placid ind-scheme	平缓归纳概形	I`，并在 §5.3.3 首见处写「平缓归纳概形（placid ind-scheme）」。

**验收**：`lang_lint.py` 未报「生造词」类问题；`04-术语文献勘误.md` 第 2 节单列此条，注明「TERMS 无条目，依据 I」。

## 6. intertwining operator → 「缠绕算子」

## 7. 原文笔误 E4：\sM 与 \sN 互换

**现象**：§4.2 例 4.2.25 的 D-模版本写

$$\sM\boxtimes\sN\simeq\pi_X^!\sN\overset{!}{\otimes}\pi_Y^!\sM,$$

而紧接上一段的 QCoh 版本写 $\pi_X^*\sM\otimes\pi_Y^*\sN$。

**判定**：函数 $!$-拉回是逐分量作用，$\sM$ 应拉回到 $X$ 侧、$\sN$ 到 $Y$ 侧；原文把两者写反了。这是**数学笔误**，不是排版问题。

**处理**：按纪律**不擅改**——照原文排印，加译者注给出正确形式，并登记 `errata.tsv` E4。译者注用规定格式：

```
[译者按（上下文推断，无外部依据）：原文此处把 M 与 N 的位置写颠倒了……本译本照原文排印，读者按此理解即可。]
```

**验收**：`my_p31.png` 目视；`errata.tsv` 第 4 行；`04-术语文献勘误.md` 表内 E4。

## 8. 一个 `\label` 放错位置，整节公式编号偏移 1

**现象**：附录 A.2 首次编译后，把译本公式序列与原 PDF 序列逐项比对（`chk_appendix_num.py`），发现 (A.1) 落在 $D_X$ 的 $x^a\partial^b$ 单项式上，而原文的 (A.1) 落在 $\delta'_x$ 例中的 $\xi_i$ 单项式上——整节公式编号整体多 1。

**判定**：原文的 `\label{PBW}` 挂在 $\xi_i$ 那条编号公式上，$x^a\partial^b$ 那条是 `\[ \]`（不编号）。我初读时把两者搞反了。

**处理**：把 $x^a\partial^b$ 改回 `\[ \]`，`\label{PBW}` 移到 $\xi_i$ 的 `equation` 上。改后序列 (A.1) PBW → (A.2) e:vivaflatsections → (A.3) e:gaga → (A.4) e:rhconn → (A.5) e:fllat → (A.6) 无名 → (A.7) e:flatsec，与原文逐项吻合。

**验收**：`chk_appendix_num.py` 输出 orig/mine 两列完全对齐；`eq_reconcile.py` 全书编号公式 72=72。

## 9. `\xymatrix` 画 bar 复形：从 49pt 超宽到 0

**现象**：§4.2 的 bar 复形公式 (4.3) 用 `\xymatrix` 排两列、三组箭头，编译报 `Overfull \hbox (49.0pt too wide)`。

**判定**：`xymatrix` 的列宽由最长单元格决定，而此图有三列 $\Hom_{\DGCat_{\on{cont}}}(\dots)$，天然比版心宽。

**处理**：按期逐级降字号并**每级都重新量**：`\small` 仍超 29pt → `\footnotesize` 变成 0pt 但公式编号被挤到下一行 → 最终 `\scriptsize`，编号回到同行。教训写在 `工程文件/reports/02`：图类 Overfull 不能一次拍脑袋定字号，要「改一档、量一档」。

**验收**：`my_p31.png` 目视 (4.3) 与编号同行；`main.log` 中 Overfull 计数 0。

## 10. 5 条 `Missing character: There is no ^^S`

**现象**：加入 §6.10 后，`main.log` 突然出现 5 条

```
Missing character: There is no ^^S in font [lmroman8-regular]:mapping=tex-text;
```

每条后面还跟一行孤零零的 `!`。之前 80 页都是 0 缺字，所以这是新引入的真问题。

**定位过程**：① 用 `grep -n` 把 5 条告警与上下文的 `Citation 'restrictedvar3' undefined`、`Reference 'e:etalelang' undefined` 对齐，锁定在 ch23；② 写最小 `test.tex`，只 `\input{chunks/ch23}`，仍复现 5 条，排除与其他章节的交互；③ 把可疑写法缩成四行探针（`\on{Shv}^{\on{\acute{e}tale}}` 等），单条即触发。

**判定**：`lmroman8` 是 8pt（上标/脚注字号），`^^S` 是 OT1 编码的槽位 19。`\acute` 在 math 模式下生成的正是这个槽位的重音字符；xelatex 用的 unicode 字体没有该槽，于是缺字。

**处理**：`工程文件/scripts/fix_etale.py` 把 5 处 `\on{\acute{e}tale}` 一律改成 `\text{étale}`（真 Unicode 的 é）。

**验收**：`grep -c "Missing character" main.log` = 0；`my_p78.png` 上标 `Shv^{étale}` 正常。

## 11. 三重对账：标签、编号条目、公式

**做法**：三条独立证据链，任何一条 mismatch 都不收工。

| 对账项 | 脚本 | 结果 |
|---|---|---|
| `\label` 集合（原文 vs 译文 chunks，先剥掉 `\iffalse` 块） | `label_reconcile.py` | orig 132 = mine 132，缺 0、多 0、悬空 `\ref` 0 |
| 编号条目序列（从两份 PDF 逐页抽） | `index_md.py` + `index_gaps.py` | 288 条、29 个分组，逐小节无缺号 |
| 编号公式序列 | `eq_reconcile.py` | 72 = 72 |

**为什么不信 PDF 端单条比对**：pymupdf 抽取会把脚注文字混入正文流（原文 `full.txt` 里就出现过「3.3.18」这类假编号），所以编号的**存在性**以 PDF 为准、编号的**归属**以源码结构为准。两条腿走路才敢说 mismatch = 0。

## 12. 术语一致性脚本抓到的最后一处硬伤

**现象**：`term_consistency.py` 把「环群」列为废弃写法（应为「环路群」），跑完报 ch17 命中 1 次。

**定位**：§6.7 结尾「由上述，形式上可推出：**环群**对应于 $\sigma$ 上摩天楼 $\Vect$ 的『不可约』范畴表示」——漏了一个「路」字。

**处理**：改「环路群」。这是我肉眼校对了 57 页都没发现的一处，纯靠脚本兜住。

**意义**：术语一致性检查不只是「翻译统一」的卫生工作，它同时是**错字检测器**——一个不该出现的二字串出现在正文里，几乎总是掉字或串行。
