## 1. arXiv e-print：本任务最关键的一次调用

```bash
curl -sS -L -o /tmp/kw06src.tar "https://arxiv.org/e-print/hep-th/0604151"
```

- 返回 HTTP 200 / 404,835 B（gzip），解包得到：
  - `glshort.tex` 616,783 B / 11,886 行（harvmac 宏包源码）
  - `glshortspare.defs` 27,357 B：**348 条公式号、47 条节号、146 条文献号**的映射表
  - 20 个 EPS 图（gla0-1 … gla7-9）
- 为什么关键：KW06 的公式全部是 harvmac 的 `\eqn\label{...}` 编号式，**编号由 defs 文件统一给出**。
  有源码与 defs，就能保证「原文式 (2.15) ↔ 译文式 (2.15)」严格一一对应；没有源码就得从 PDF
  的排版反推，231 页里 348 个公式，几乎不可能不出错。
- 评价：★★★★★。这是整个工程能在数小时内推进的前提。

## 2. XeLaTeX / MiKTeX 26.5

- 路径：`C:\Users\admin\AppData\Local\Programs\MiKTeX\miktex\bin\x64\xelatex.exe`；字体 simsun/simhei/msyh 齐全。
- 用法：`tools/check_shards.py` 逐片编译英文脚手架；`tools/check_zh.py` 逐片编译中文译稿；
  `tools/build.py` 3 遍编译整本、打印页数与错误。
- 效果：36 片脚手架最终 36/36 零错误；整本 PDF 从 179 页（全英文基线）开始往下走。
- 踩到的坑（真实记录）：
  1. `\usepackage{mathtools}` 与本工程 preamble 组合下，`equation`+`aligned` 内的 `\sqrt`
     报 `! Missing control sequence inserted.`（最小用例可复现，原因未明）；删掉 mathtools 即好。
  2. LaTeX2e 原生支持 `{\bf 4}`、`{\cal H}` 等老式字体开关，**不要**盲改成 `\mathbf`/`\mathcal`
     ——自动转换会在 `_{\cal B,...}` 处吃掉花括号。
  3. `\m@th` 必须包在 `\makeatletter` 里。
- 评价：★★★★★。编译不只是「出 PDF」，它是最便宜、最客观的翻译测试。

## 3. subagent 并行翻译

- 实测并发上限 **8**；共派 11 批（每批 2–3 片），至报告撰写时已完成 6 批、22 片。
- 关键设计：每个 subagent 的 prompt 里强制三件事——
  (a) 先读完 BRIEF/SPEC/GLOSSARY 与 **Witten 2008 短综述、Frenkel 2009 综述**；
  (b) 只写自己名下 `zh/` 与 `logs/`，不许改 skel/preamble/macros；
  (c) 必须跑 `tools/check_zh.py` 到零错才算完成。
- 效果：译稿质量稳定（每片 3–8 条译注、术语首现中英对照、公式锚与 skel 逐项一致），
  且每个译者都留下了结构化日志（覆盖范围、P1/P2、检索记录）。
- 风险与对策：并行度越高，术语漂移风险越大 → 用 `GLOSSARY.tsv`（111 条）+ SPEC 固定译法表（60 条）
  预先钉死；发现冲突由 lead 在 `logs/` 与 `注疏/` 汇总。
- 评价：★★★★☆。省时间，但**前提是规范足够硬**；规范一软，并行只会放大不一致。

## 9. 给下一次的建议

1. **凡是 arXiv 上的文献，第一步永远是取 e-print**，不要从 PDF 反推公式。
2. 并行翻译之前，把 SPEC 写成「机器可检查的条款」（禁命令清单、锚点计数、术语表），
   否则并行只放大不一致。
3. 每片编译（片级冒烟）比整本编译有效得多：错误定位从「231 页里找」变成「33K 字符里找」。
4. 术语检索走**中文译名 → 本地知识库**这条路径；概念解释走 **web_search → 原文/综述**。
5. 记忆类插件（hindsight）在这台机器上要先配 key，否则不要写进流程依赖。
