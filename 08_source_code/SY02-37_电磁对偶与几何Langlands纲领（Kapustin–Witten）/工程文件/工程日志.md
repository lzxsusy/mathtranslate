## 一、为什么先抓 arXiv 源码

pdftotext 得到的正文可用，但公式全散了。真正的转折点是：

```bash
curl -sS -L -o /tmp/kw06src.tar "https://arxiv.org/e-print/hep-th/0604151"
```

得到 `glshort.tex`（616,783 B / 11,886 行，harvmac 宏包）+ `glshortspare.defs`（27,357 B，
含 348 个公式号、47 个节号、146 个文献号的映射）+ 20 个 EPS 图。
于是公式、编号、`\cite`、节结构全部不必手抄——这是能在一晚上完成 176 页译注本的根本原因。

## 六、这个工程踩过的坑（详见 `reports/校对报告.md` 第三节）

1. harvmac `\nref`/`\lref` 都**不打印编号**，误当 `\ref` 会散出 82 个孤立 `[N]`；
2. `\def\bf#1{\mathbf{#1}}` 进文本模式必炸（参考文献 106 处）；
3. `\usepackage{mathtools}` 与 ctex/amsmath 组合下 `equation`+`aligned`+`\sqrt` 报 `Missing control sequence inserted`；
4. LaTeX2e 原生支持 `{\bf 4}`、`{\cal H}`，**不要**画蛇添足转 `\mathbf{4}`（会吃掉下标组的花括号，一次把 36 片全转坏）；
5. 自建脚手架必须逐片冒烟编译（`check_shards.py` + `bisect_shard.py`）。
