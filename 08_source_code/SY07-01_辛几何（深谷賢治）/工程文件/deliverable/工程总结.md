## 二、工作流（九个阶段）

沿用《学术PDF翻译标准作业手册 v2》的九阶段，但针对**扫描件＋日文**做了三处改写（下表中标 ★）。

| # | 阶段 | 产出 | 实际耗时 |
|---|---|---|---|
| 1 | 能力探测 | TeX / Python / 字体 / 可写路径 / 镜像编译冒烟 | ~10 min |
| 2 | 底本尽调 | 页数、页码映射、图/表/公式/陈述普查（`work/probe/`） | ~20 min |
| 3 | 素材制备 ★ | 425 页 200 dpi 页图 + 逐页文字层 + `full.txt` + `tags.txt` + `figures.tsv` | ~15 min |
| 4 | 工程骨架 | `preamble.tex` / `main.tex`（`\InputIfFileExists` 逐块注入）/ `build.ps1` / `check.py` / `verify_pdf.py` | ~20 min |
| 5 | 规范冻结 ★ | `STYLE_GUIDE.md`（含扫描件特则）+ `BRIEF.md` + `TIMELINE.md` + `glossary.tsv` | ~25 min |
| 6 | 样板章 | Lead 亲译第 1 章（20 页）＋ 前 3 页先作为文风样板 | ~40 min（与其他阶段并行） |
| 7 | 分块并行翻译 | 8 名译者，13 个原始块 → 实际 16 块（二次拆分） | ~70 min |
| 8 | 合成与三重 Gate | 静态检查 / 真编译 / PDF 回读 / 过宽公式修复 / 字符清洗 | ~40 min |
| 9 | 打包交付 | `deliverable/`（PDF + src + build + log + 批注 + README） | ~10 min |

> 与 SOP v2 的 136 页英文论文相比，本项目**底本尽调与素材制备更重**（扫描件、日文、公式不可信），**翻译阶段被切成更多更小的块**（见 §三）。

## 三、团队与分块（本项目最值得记录的部分）

### 3.1 硬约束：成员上限 8

`spawn_teammate` 在本环境的上限是 **8 名成员**（含 Lead 之外的所有队友）。尝试创建第 9 名时报 `Team member limit 8 reached`。

**应对**：**不新建，复用已完成的成员**。队友是 durable 的，完成一块后用 `send_message` 直接派下一块；已完成成员的上下文虽已很满，但往往还能再做一个 10–18 页的小块。

### 3.2 分块策略

- 按**节边界**切，每块 10–22 页（原计划 18–40 页，实际证明 40 页块会超出队友上下文，见 §3.3）。
- 第 6 章（130 页）被拆成 8 块：`ch06a`(18p) / `ch06a2`(15p) / `ch06b`(18p) / `ch06b2`(15p) / `ch06c`(11p) / `ch06c2`(13p) / `ch06d`(7p) / `ch06d2`(14p) / `ch06e`(10p) / `ch06e2`(10p)——实际 10 块。
- 每块任务书固定写：页段（原书页 + PDF 页）、chunk 文件名、节标题归属、图清单、tag 范围、是否写章末评注。

| 波次 | 成员 | 块 |
|---|---|---|
| 第 1 波 | tr01–tr06 | ch02a, ch02b, ch03, ch04a, ch04b, ch04c |
| 第 2 波 | tr07, tr08 | ch05a, ch05b |
| 再分配 | tr01→ch06a, tr04→ch06a2, tr02→ch06b, tr03→ch06b2, tr03→ch06c, tr04→ch06c2, tr06→ch06d, tr04→ch06d2, tr05→ch06e, tr02→ch06e2 | |
| 书末 | Lead（后记、参考文献）、tr02（追记） | backmatter, references, afterword |

### 3.3 上下文预算（血泪教训）

- **tr01**：做完 ch02a（32 页）+ ch06a（18 页）后上下文接近上限，拒绝 ch06c（24 页），只肯做 4 页——事后证明它的判断正确。
- **tr06**：做完 ch04c（24 页）+ ch06d 前半（6 页）后上下文耗尽，停在 p.338，由 tr04 接 ch06d2。
- **结论**：40 页以上的块对 `deepseek-flash` 这类上下文，**实际吞吐约 25–30 页/成员**（公式密集块更少）。下一个项目应按「**公式密度**」而非「页数」分块：公式密集区每块 ≤ 15 页，叙述性区每块 ≤ 25 页。

### 3.4 边界处理规则（有效）

写进 `BRIEF.md` 的四条，实际使用中零返工：

1. 章标题只由该章第一个 chunk 写；节标题只由「该节起始页」所属 chunk 写。
2. **跨页/跨块句由「句子起始页」所属 chunk 写完**，下一块从该句之后接续。
3. 块首若非新节开始，直接续写正文，不写标题。
4. 块尾的页标记必须与下一块块首的页标记**首尾相接**（不允许重叠）。

仍出现的两处问题：
- `ch06c2` 与 `ch06d` **都写了 (6.68)**（跨块句归属判断分歧，且两边各自看页图都合理）——合同后删掉 `ch06d` 的副本，并把 p.332 末句补齐（「令 $\Omega(u,v)=\sum\omega^{ij}u_iv_j$，则 (6.67) 成为…」）。
- `ch05b` 开头重复了 `ch05a` 已写的跨页句——由 tr07/tr08 两人自行沟通删掉。

> **教训**：跨块句规则要再补一条「**块尾最后一句若是跨页句，写完之后在文件末尾用注释登记该句**」，并让检查脚本自动比对相邻块的首尾句。

## 四、质量体系（三重 Gate + 交叉核对）

### Gate 1：静态检查（`check.py` / `verify_all.py`）

- `\tag` 集合 vs `tags.txt`：MISSING / EXTRA / DUPLICATE 三个列表必须全空（本项目最终 238/238，另有追记 A.1–A.12 作为已知例外登记）。
- 花括号配平、`\begin/\end` 配对（栈式）、`$` 成对、禁用命令（`\documentclass`/`\ref`/`\cite`/`\label` 等）、UTF-8 无 BOM、无 U+3000、无 Markdown。
- 页标记覆盖：原书 p.1–372 中只允许空白页（p.20）缺失。
- 图清单 vs `figures.tsv`：57/57。
- 章节清单：6 章 / 28 节与预期一致。

### Gate 2：真编译（`build.ps1`）

- LuaLaTeX ×3，镜像到 ASCII 可写目录（本机 `lualatex` 不能写非 ASCII 路径 / Desktop）。
- 判据：`file:line` 错误 0、`Undefined` 0、`Missing character` 0、`Overfull` 0。
- 本项目最终：**0 / 0 / 0 / 0**，337 页。

### Gate 3：成品 PDF 回读（`verify_pdf.py`）

- 238 个编号公式逐一以 `(x.y)` 出现在 PDF 文本中（238/238）。
- 6 个章标题、57 个图题、字体全部子集嵌入、无 `??` / U+FFFD。
- 目视抽页 8–10 页（最密公式页、图表页、附录页、后记/追记页）。

### Gate 4：交叉核对（人工）

- 每块回执含「tag 数 / 图数 / 陈述编号清单 / 存疑与笔误清单」。
- Lead 抽查：公式密集页（§6.5 Schouten 括号、§6.2 GW 不变量、§5.2 Floer）逐页比对页图。
- **未做**逐句回译与全员交叉校对（时间不够），这是本项目最大的质量缺口，见 §七。

## 五、技术要点与踩坑清单

### 5.1 扫描件＋日文 OCR（本项目最特殊的一点）

1. **文字层不可信**：日文 OCR 会把 `ー`→`一`、`入`→`人`、`基`→`墓`、`ミラー`→`ミラ一`，公式基本是乱码（`鈭?`、`；；`）。**正文意思可信、公式必须回页图**。
2. **页图 200 dpi 足够人读**，但公式小字要 400–600 dpi 裁图（`crop.py --box 左,上,右,下 --dpi 600`）。
3. **页码映射**：原书页 = PDF 页 − 10（前置页另有偏移：PDF 3–10 = 罗马页 v–xii，PDF 11 = 原书 p.1）。
4. **图在扫描页里**：没有可提取的矢量图，必须按坐标裁图。裁完必须 `read_image` 复核：完整、不截断、不带相邻正文/图注残影。本项目 57 幅图全部人工复核，其中 fig6.5、fig6.13、fig6.29、fig6.32 重裁过。

### 5.2 LaTeX 工程

| 坑 | 现象 | 解法 |
|---|---|---|
| 过宽 display 公式 | Overfull 最高 197pt | 用 `\resizebox{0.97\linewidth}{!}{$\displaystyle …$}` 包住（12 处）；`\emergencystretch=6em`、`\tolerance=3000` 消除段落级 overfull |
| 汉字缺字 | `・`(U+30FB)、`〜`(U+301C)、`⑳`、`｣`、`∘`、`■` 在 SimSun/LM 中无字形 | 全局字符清洗（`scan_kana.py`）：`・→·`、`〜→～`、`∘→$\circ$`、`■→$\blacksquare$` 等；生成脚本里对注释正文也做同样替换 |
| 希腊字母裸写 | `σ`、`ω` 在正文里缺字 | 规则写进 STYLE_GUIDE：一律 `$\sigma$` |
| 环境配对笔误 | `\begin{lemma*}…\end{lemma}` | `fix_env.py`：栈式配对，自动改成 `\end{lemma*}`（只改首尾名不一致者） |
| 未定义宏 | 译者用了 `\ev`、`\Cr`、`\Lag` 等 | 集中宏表补进 preamble（`\ev=\operatorname{ev}` 等） |
| 附录页眉 | `\chaptermark` 写死「第 X 章」，附录显示「第A章」 | 改用 ctex 的 `\CTEXthechapter` |
| 章末评注跨页 | tcolorbox 被切开、留大片空白 | 可接受；如需避免可设 `breakable=false` 或调位置 |
| 参考文献破折号 | OCR 的 `--` 被 ctex 当全角破折号 | 生成脚本统一 `--`（en-dash） |

### 5.3 内容层面的坑

1. **陈述编号是「每章一个连续序列」**（定義/定理/補題/注意/問題 共用），不是按类独立计数——LaTeX 自动计数器会错位，**一律手工抄编号**。
2. **□ / ■ 的语义**：陈述末尾 □、证明末尾 ■；陈述后紧跟证明时原书无 □ → 用带星号环境（`lemma*` 等）。这条规则写进 STYLE_GUIDE 后，13 个块基本一致。
3. **公式编号 OCR 漏检**：式 (4.16) 在文字层完全丢失，靠译者回页图补上；`tags.txt` 是「参考清单」而非「真值」，验收以页图为准。
4. **A∞ 记法**：原书排作上标 $A^\infty$，中译本按通行记法统一为 $A_\infty$（并在批注说明），否则全书 300+ 处混排无法收拾。
5. **译名一致性**：`Kähler 锥` vs `凯勒锥`、`补题` vs `引理`（后者是把日文「補題」误译）——靠最后的全局术语扫描修掉 28 处。

### 5.4 协作层面的坑

1. **8 人上限**导致不能「新开一波」，只能复用已完成成员 → 上下文吃紧。
2. **块拆分文件命名**要在 `main.tex` 里同步加 `\InputIfFileExists`，否则文件写了但不进书（`afterword.tex` 一度漏加，PDF 里整段追记消失，靠回读发现）。
3. **进度看板**：`TIMELINE.md` 维护「块→负责人→状态」，完成一块就划掉，避免重复派单。
4. **停止要显式**：tr06 在上下文将尽时主动停在页边界、**不写 DONE 标记**、留接续说明——这是正确的做法，应写进规范。

### 6.2 模板

- `build.ps1`（本机镜像编译，含 -Chunk 单块草稿模式）
- `preamble.tex`（B5 + ctex + 陈述环境 + 星号版 + takeaway/chapterreview + 常用宏）
- `main.tex`（chunk 注入，缺文件也能编译）
- `STYLE_GUIDE.md` / `BRIEF.md` / `TIMELINE.md` / `glossary.tsv`

### 6.3 对《数学文献翻译纪律》与 SOP v2 的增量建议

1. **扫描件项目**应新增一步「OCR 质量分级」：正文/公式/页眉分别评级，并把「公式一律回页图」写成不可协商项。
2. **分块上限按公式密度**：公式密集区 ≤ 15 页/块，叙述区 ≤ 25 页/块；上下文预算应写进任务书。
3. **跨块句**：除了「开始者写完」，再加「块尾跨页句登记」与「相邻块首尾句自动比对」。
4. **编号唯一性**要跨块检查（本项目出现过 (6.68) 重复），`check.py` 的 DUP 检查必须全局。
5. **字符白名单**：编译后扫描 `Missing character` 并按字符表修，而不是逐个 debug。
6. **成员上限**：多智能体项目要在 BRIEF 里写明「成员数上限」与「再分配协议」。
7. **边界保存**：上下文将尽时允许「停在页边界、不写 DONE、留接续说明」，这比写半成品好。

## 七、不足与改进

| 不足 | 影响 | 改进方向 |
|---|---|---|
| 参考文献自动转录未校对 | 404 条中 45 条因 OCR 丢方括号并入相邻条目，部分人名/刊名有讹（如 `Stasheff`→`St eff`、`Symplectic`→`Symplec— tic`） | 有干净文字层的版本可直接解析；扫描件则应人工校 404 条的姓名与刊名（约 2 小时） |
| 原书索引未收 | 无法按原书索引检索 | 可据 `glossary.tsv` + 页标记生成「中文术语→译本页」索引 |
| 无逐句回译、无全员交叉校对 | 可能有漏译/误译未被发现 | 下一个项目应保留 30–40 min 做「A 校 B」的交叉校对（SOP v2 的 Gate 4） |
| 追记与正文的对读提示只在批注里 | 读者可能忽略 | 已在阅读指南里明确要求「第 6 章必读追记」 |
| 章末评注/本节重点为译者所加 | 与原书体例不同 | 已用开关（`\showtakeawayfalse` 等）可一键隐藏，并在 README 声明 |
| 单会话 3.5 小时、无中途交付 | 风险集中在一次编译 | 可改为「每完成 2 章编译一次、先出一版可读 PDF」 |

## 八、复现步骤（给下一个同类项目）

```powershell
# 1. 建工程目录并复制底本
# 2. 探测环境（TeX / Python / 字体 / 可写路径）
# 3. 底本尽调：页数、页码映射、图/公式/陈述普查
python work/tools/prep.py            # 页图 + split + tags + figures.tsv
# 4. 骨架：build.ps1 + preamble + main + check/verify
# 5. 规范：STYLE_GUIDE / BRIEF / TIMELINE / glossary
# 6. Lead 先译一个样板章（20 页以内），冻结文风与体例
# 7. 分块并行（每块 10–22 页；8 名成员为上限；完成后立即再分配）
# 8. 合成：check.py → build.ps1 → verify_pdf.py
# 9. 字符清洗 / 过宽公式 / 环境配对 / 记法统一（脚本 + 人工抽查）
# 10. 重新编译到 0/0/0/0 → pack.py → deliverable/
```

**最小验证集**（每次改动后跑）：

```powershell
python check.py                 # tag / 环境 / 页标记
powershell -File build.ps1      # 编译（看 file:line / undefined / missing char / overfull）
python verify_pdf.py            # 成品回读（tag / 章 / 图 / 字体）
```
