## 0. 本轮做什么

对 Yao YUAN《Langlands Program: an introduction》（英文原稿 198 页）的中译《Langlands 纲领导论》（TeX 工程，成品 140 页）做三件事：

1. **逐页校订**：对照英文原稿 198 页，修正译文中的真错（数学错误、漏译、错译、术语、语言病灶）；
2. **加学生向译注**：对「书上第一次出现、但没有展开解释」的概念，参考 nLab 等 B 级源加脚注（这是本轮新增的增量，上一轮为了「不加说明」把这些全删了）；
3. **交报告**：每讲一份分讲报告，Lead 汇总后整书编译、审计、入库、发布。

**不变的前提**：不重写译文风格；不动编号与 label；不补写原书没有的段落。只改真错，只加译注。

## 4. 六步工作法（每讲都按这个来）

**第 1 步 通读**：先把 `chapters/lectureNN.tex` 整章读一遍（不看原文），在脑子里建结构：这一讲有哪几节、哪些定义/定理、编号体系、哪些公式带图。
**第 2 步 对照**：按页读 `work/orig_text/pNNN.txt`，逐段对齐原书与译文。凡涉及**公式、定理陈述、表格、上下标、量词、等式两端的符号**——一律打开 `work/orig_png/pNNN.png` 逐符号核对，不信抽出来的文本。
**第 3 步 改错**：按下面 §5 分级处理，只改 A/B/C 三类，E 类按规则登记。
**第 4 步 加注**：按 `work/注记清单.tsv` 里该讲的必注项（`必注=1`）全部完成，再自选 2–4 个（清单里 `必注=0` 的优先，也可以自己找——只要符合 §6 的定义）。
**第 5 步 自检**：`python work/check_build.py NN` 必须 PASS；再从头读一遍改动后的章，确认脚注没把版面挤坏、术语前后一致。
**第 6 步 报告**：写 `work/reports/chNN.md` 和 `work/notes/notes_NN.tsv`，然后给 Lead 发消息。

## 5. 校订分级

| 级 | 名称 | 处理 |
|---|---|---|
| **A** | 数学错误 | 必改。定义/定理/证明里的条件、量词、符号、指标、公式、数值写错。 |
| **B** | 漏译/错译 | 必改。整句漏译、语义反转、术语误译、参考文献条目信息错、图表编号对不上。 |
| **C** | 语言病灶 | 必改。见 §7 清单。 |
| **D** | 风格性润色 | **不改**。可改可不改的一律不动（本轮不是重译）。 |
| **E** | 原书笔误 | 保留正文 + 加 `% [Tutor Note: ...]` 行注释 + 登记。见下。 |

**E 类规则**（原书自己写错，不是译者的错）：

- 原书笔误，而译文已经按正确写的：在译文对应行的**下一行**单独加一行注释
  `% [Tutor Note: 原书 pN 作 ……，译文按正确写法处理。]`（行首 `%`，不会印进 PDF）。
- 原书笔误，而译文照抄了错：**不要悄悄改**。先判断：若属于纯记号笔误（如上下标写反、漏下标），改正正文 + 加 Tutor Note 说明「原书如此」；若涉及数学内容判断，正文保留原样 + 加 Tutor Note 存疑，并在报告「遗留问题」里写明，交 Lead 裁决。
- 译文自己的错，不要写 Tutor Note，直接改（那是 A/B/C 类），在报告里记一行。
- 所有 Tutor Note 都要在 `notes_NN.tsv` 里登记（状态写 `tutor-note`），Lead 要汇总成疑点清单。

**报告格式**（`work/reports/chNN.md`）要有四节，表格用 Markdown 表格：

## 6. 译注规范（本轮核心增量，最容易做坏的地方）

### 6.1 宏与位置

- `\znote{...}` → 生成脚注，自动加粗「【译注】」；**有外部来源时必须用它**。
- `\znoteplain{...}` → 生成脚注，加粗「【译者按】」；**没有任何可靠外部来源时才用**。
- 位置：紧跟在该概念**首次出现处**（术语后、标点前）。优先挂在**正文句子**上；若该概念只出现在定义/定理/引理框内，可以挂在框内（实测会渲染在框内，可接受，但注意分页——挂完必须编译看那一页）。不要把脚注挂在章标题、节标题、参考文献条目里。
- 同一概念全文只注一次（在首次出现处）。后面重复出现不注。

### 6.2 一条译注写什么（三选一，不要写成小论文）

- **(a) 定义展开**：书上直接拿来用、但没给定义的概念。给出精确定义 + 一句辨析。例：射有限群、反常层、全不连通、t 结构。
- **(b) 背景直觉**：为什么这里要引入它、它在整条逻辑链里干什么。1–2 句。
- **(c) 易错点**：最容易读错/混淆的地方。例：「指数 vs 阶」、「射有限 vs 有限」、「完备化 vs 闭包」。

**篇幅**：80–220 个汉字 + 来源那一句。超过 300 汉字就砍，或拆成两条（不同概念）。

**禁止**：
- 复述书上紧接着就会讲的内容（那是浪费版面）；
- 夹带个人观点、评价、习题解答；
- 把 nLab 的英文句子直译照抄（要自己组织中文，只取事实）；
- 引用知乎/百度百科/CSDN/简书/公众号/B站笔记/个人博客/AI 摘要（零容忍）；
- 编造 URL、修订日期、定理号、页码。

### 6.3 来源与写法（硬性，会被脚本审计）

**(1) nLab 富条目**（`work/nlab/INDEX.tsv` 里 `chars≥300` 且 `status=OK`）：

```
[来源：nLab "perverse sheaf"，\url{https://ncatlab.org/nlab/show/perverse+sheaf}（Last revised 2026-10-16；2026-11-14 访问）。]
```

`last_revised` 直接从缓存文件第二行 `last_revised:` 抄，不要自己编。

**(2) nLab 条目很薄（chars<300）、或没有 nLab 条目，但本讲参考文献里有 A 级教材**（各讲末尾 `references` 环境里列的那些书，本来就带章号）：

```
[来源：Ireland--Rosen, \textit{A Classical Introduction to Modern Number Theory}, 2nd ed., GTM 84, 第 16 章（本讲参考文献）；并见 nLab "L-function"，\url{...}（Last revised 2024-07-07；2026-11-14 访问）。]
```

只允许引用**本讲参考文献里真实出现过的书**，章号也必须是本讲参考文献里给的那个，不许自己补章号。

**(3) 完全找不到可靠来源**：

```
\znoteplain{……（上下文推断，无外部依据）}
```

宁可用 (3)，也不要编来源。审计会抽查 5 条核对真实性。

### 6.4 nLab 怎么查（省时路线）

1. 先查 `work/nlab/INDEX.tsv`：`注记清单.tsv` 里已经给了候选 slug，多数已经抓好缓存，直接读 `work/nlab/L<N>_<name>.md`。
2. 缓存没有 → 自己去抓：
   ```
   cd <本地路径>
   python nlab_fetch.py yourlist.tsv
   ```
   `yourlist.tsv` 每行 `<文件名>\t<slug1>,<slug2>`（逗号分隔多个候选，脚本取第一个存在的）。
3. 不知道 slug → 本地全站索引模糊找：
   ```
   python nlab_index.py perverse sheaf
   ```
   （输出所有同时含这两个词的 slug）
4. 还是找不到 → 用 `(2)` 或 `(3)` 的办法。别在找 slug 上耗超过 5 分钟。

## 7. 语言纪律（§5，必改项）

必删病灶：
- 「被……所……」→ 直接用主动或「由……」
- 「进行……的讨论/研究/计算」→ 直接动词
- 「对于……而言」→ 「对……」「就……而言」或删掉
- 「使得……得以……」→ 「使……能……」
- 连续三个「的」
- 单句超过 60–70 个汉字（拆句）
- 「以及」堆叠（超过一处就改写）

格式：
- 中文全角标点（，。；：？！（）「」）。
- 英文术语、数字与汉字之间留半角空格：`Galois 扩张`、`$p$ 进数`、`第 3 讲`。
- 行内公式后的句末标点放在公式**外面**：`由 $e=1$ 得……，故 $e'=1$。`
