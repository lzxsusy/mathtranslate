# 工程总结：物理学家用代数拓扑（EN01）中文译注本

## 一、缘起与定位

底本是立川裕二（Yuji Tachikawa，Kavli IPMU）2025 年 7 月定稿的研究生课程讲义 *Algebraic topology for physicists*（206 页）。作者在致谢中自述：这是他把散落在各处的「物理学家需要的代数拓扑」汇成一处的尝试，内容「远多于课上所讲」，且刻意保持讲义的随性与不严格。因此本工程的目标不是做一本教科书式的中文重写，而是**忠实的中文译注本**：正文逐句对应，术语统一，公式逐符号回页图核对，作者的笔误只登记不改动，另加少量批注与每节/每章的导览，帮助中文读者把它当讲义读下去。

文献号 **EN01**（英语讲义第 1 号），主题域 05 辛几何·拓扑·纽结与指标定理，已登记入 `学术翻译总纲/04_编号登记表.csv`。

## 二、工程结构

```
EN01_立川裕二_物理学家用代数拓扑_中文译注/
├─ 00_原文/notes.pdf            底本（206 页）
├─ src/                         XeLaTeX 源码（ctexbook，B5）
│  ├─ main.tex  preamble.tex  build.ps1
│  ├─ frontmatter/  chunks/  figures/  appendix/
├─ work/                        中间产物：页图、逐页文本、草稿 PDF、校对报告
├─ tools/                       全部自建脚本（见第五节）
├─ reports/                     分章交付报告（13 章）
└─ deliverable/                 成品：PDF、README、术语对照表、译注汇总、本文件
```

`work/pages/pNNN.png` 是 160 dpi 的页图（1360×1760 px ↔ 612×792 pt），是全工程唯一可信的「原文」；`work/en/chNN.txt` 是分章文字层提取，只用作检索底稿，任何公式、定义、编号都必须回页图核对——文字层在跨行连字符、上下标、希腊字母上系统性出错（例如 p.8 把上一行行末的 `m` 粘到 `are` 上，变成 `mare`）。

## 三、流程

1. **勘察**：核对页映射（原书印刷页 = PDF 页，偏移 0，由 p.4 与 p.129 的 Part 扉页证实）；用 PDF 书签与文字层建章节目录；普查 277 个编号陈述、37 幅内嵌手绘图、11 张排版表格的分布。
2. **素材制备**（`tools/prep.py`）：160 dpi 页图、逐页文本、整本合并文本、分章文本、陈述清单 `statements.txt`、图表普查表。
3. **术语冻结**（`deliverable/术语对照表.tsv`）：先由 Lead 依「中文学界通行译名优先、无通行译名保留英文、人名一律不音译」建底表，冻结后才允许并行；各章再提交增补，由 `tools/merge_terms.py` 合并（最终 672 条）。术语在正文与术语附录两处同步，附录由 `tools/gen_terms.py` 从 TSV 生成，不手写。
4. **样板章**：Lead 亲自完成第 1 章（含表格、编号公式、脚注、四条本节重点与章末评注），据此定下 preamble 宏、陈述环境、图/表/公式/批注体例，并写成 `译者手册.md`（264 行施工规范）——这是并行施工的唯一契约。
5. **并行翻译**：8 名译者按共享任务板（8 个任务、写权限互斥）各领 1–2 章，一人一章，先 `claim` 后施工；每章交付 = `chNN.tex` + 图 + `reports/chNN.md` + 术语增补 + 单章编译日志。
6. **静态审查**（`tools/audit.py`）：逐章核对页锚点是否齐/不重/递增、陈述编号与 `statements.txt` 是否一致、`\tag` 编号与页文本是否一致、图数量与文件是否存在、批注密度是否 ≤1‰。
7. **交叉校对**（Gate4）：A 校 B，互不修改对方 chunk，只产出 `work/review/<目标>_by_<自己>.md` 三段式报告（必须改 / 可选改 / 疑问），并给出可直接替换的文本；Lead 逐条与页图核对后落改，再重编译。
8. **合并与交付**：整书 3 pass XeLaTeX 编译，Gate2 判据（file:line 错误 / `!` 错误 / 缺字 / Overfull / 未定义引用全为 0），再回读成品 PDF 检查书签、图表、字体嵌入，最后打包 deliverable。

## 四、体例要点（与《数学文献翻译纪律》的对应）

- **陈述环境**：编号照抄（`\begin{definition}{2.1}` → 「定义 2.1.」），灰底方框只用于原书本身就是灰底的陈述；原书**无框**的 Remark 与收束性讨论段（原文以右下角 ⌟ 收尾）译为普通段落并以 ⌟ 标记，全书 17 处。
- **公式**：全部手工 `\tag{2.1}`，正文裸引用「(2.1)」，不用 `\eqref`。
- **图**：`tools/crop.py` 按页图裁切（300 dpi），手写标注不重绘；题注译「图 X.Y：……」，并保留原编号。ch13 有 6 处谱序列图在原书中被编号为公式，按原图裁切成「图形公式」，编号不变。
- **表**：一律 `tabular` 重排，不裁图；**禁用 `longtable`**（见第六节事故 1）。
- **批注**：`% [Tutor Note: ...]` 源码注释，编译时隐藏，全书 22 条、密度 ≤1‰；`tools/gen_notes.py` 汇总为 `deliverable/译注汇总.md`。
- **笔误**：正文按最合理读法译，同时登记；不改数学内容（连 (13.96)/(13.97) 这种看似矛盾的 $H_4$ 计算也照录，由校对者用万有系数定理证其不矛盾）。
- **新增体例**：每节末「本节重点」（40–90 字）、每章末「本章回顾与评注」（150–250 字），由 preamble 的 `\showtakeaway` / `\showchapterreview` 开关全局控制，可一键关闭还原成纯译本。

## 六、遇到的问题与解法

1. **`longtable` 在本机 MiKTeX 上必炸**。跨页长表一律报 `Infinite glue shrinkage found in box being split`（`p{}`/`l`/raggedright 各种列型均复现，220 行最小样例可重现）。术语附录改用 `multicols{2}` + 悬挂缩进手工排版；大表则缩字号压一页或拆「（续）」两张。已写入译者手册禁区。
2. **首轮整书编译疑似死循环**。xelatex 长时间高 CPU 无输出、日志停在「第 13 章」，像 hyperref 书目循环；用 `main_tA.tex`（仅 Part I）、`main_tB.tex`（仅 Part II）二分与单 pass 重跑后确认：全部可编译，是首次运行时 MiKTeX 字体/格式初始化造成的假死，非文档缺陷。教训：判定「卡死」前先给足超时并把编译切分成可二分的最小单元。
3. **缺字**。术语表 Note 列混入裸 Unicode 数学（`α`、`ℏ`、`C²/Z₂` 等），`lmroman10-regular` 无字形，报 `Missing character`。改为 LaTeX 数学（`$\alpha$`、`$\C^2/\Z_2$`）后归零。
4. **附录转义**。`gen_terms.py` 里「数学模式与普通文本」混排：`$` 与花括号配平时按 LaTeX-lite 处理，数学外转义 `\_^#%&~`；否则 `\ref` 之类会被当成真命令。曾因调用点仍用 `esc()` 而非 `texify()` 把 `$G$` 排成 `$G$` 的字面，修好后附录 12 页干净。
5. **跨页归属**。chunk 按章切分，但有些页半属两章（p.102 上半是第 6 章末的 Hurewicz 定理、p.141 上半是 §9.5、p.170 顶部是 §11.6.2 收尾）。逐一按页文本裁决归属，并把裁决写进 `audit.py` 的章节页段与例外表（`EXCLUDE_STMT`、`EXTRA_TAG_PAGES`），避免"两份都译/两份都不译"。
6. **表格数据错误**。交叉校对在 ch11 抓出表 9 的 `pin⁻`/`spin` 两行错位、表 8 的 grading 列把 `+` 写成 `✓`——两处都用原书 p.169/p.160 页图与 p.170 正文交叉证实，Lead 落改后重新目检渲染件。这类错误只有「另一人逐格对页图」才抓得到，是 Gate4 最值得投入的地方。
7. **中文路径与编码**。PowerShell 控制台默认 GBK，Python 输出中文须 `PYTHONIOENCODING=utf-8`；写文件一律指定 `encoding='utf-8'` 与 `newline='\n'`。XeLaTeX 在中文路径下可直接编译，无需镜像目录（旧手册里「lualatex 不能写中文路径」的结论不适用于本机 MiKTeX + xelatex）。

## 七、量化结果

- 底本 206 页 → 译本 **232 页**（B5，含目录、参考文献、20 页术语附录）。
- 13 章、277 个编号陈述、780 条编号公式、37 幅手绘插图（另 ch13 6 处图形公式，合计 43 个图像对象）、11 张排版表格、64 条参考文献。
- 交付包源码经「解压到空目录 → build.ps1」从零复现：BUILD OK，日志五项判据全 0，产出 PDF 与交付件同为 6,024,737 B。
- 正文 **73,844 字**，22 条批注，105 条原文笔误与疑点登记，672 条术语对照。
- 编译：整书 3 pass，`file:line=0 fatal=0 missingchar=0 overfull=0 undefref=0`，书签随 PDF 输出。

## 八、分工与协作

Lead 负责：勘察与页映射、术语冻结、样板章与 preamble/编译链、译者手册与任务板、静态审查工具、跨页裁决、逐条落改交叉校对意见、整书编译与成品回读、README/术语表/译注汇总/工程总结。

8 名译者各领 1–2 章（ch02 / ch03+refs / ch04 / ch05+ch06 / ch07+ch08 / 引言+ch09+ch10 / ch11+ch13 / ch12），文件所有权互斥；校对阶段交叉配对，互相只写报告不动对方文件。**一人一章 + 术语先冻结 + 交叉校对**是这套流程能跑通的三根柱子。

## 九、经验与遗留

- **先冻结术语再并行**：术语表不在手边时，同一概念会被译成两三种写法，事后 grep 统一的成本远高于事前冻结。
- **页图是唯一真相**：文字层在公式、上下标、连字符、希腊字母上不可信；所有「看起来对」的公式都要回图。
- **体例写进手册、写进脚本**：能自动检查的（锚点、编号、图数、批注密度）就不要靠人眼；`audit.py` 让 8 个人交回的稿子在格式上先齐平，人只用来判断数学与文风。
- 遗留：参考文献按原文自动转录，未逐条与出版信息核对（已在 README 声明）；个别手绘图保留了原页留白以免切掉手写标注；原书 p.120「$F^{\rm geometric}$ 是真正的 1-形式」等疑似笔误按原文照录并加注，未改数学。
