# 口径 · 每个数字是怎么来的

> 本文件定义「数译」仓库里每一个对外数字的**含义、算法与边界**。
> 机器可读的实测值在 [`stats.json`](stats.json)，由仓库根目录的 `make_stats.py` 生成；
> 本文件是它的说明书。两者冲突时以 `stats.json` 为准（并应立刻修 `make_stats.py` 的 bug）。

## 0. 一条规则

**数字只从 `_meta/stats.json` 来。** 具体做法：

1. 生成：`python make_stats.py --write` —— 同时写 `_meta/stats.json` 与 `README.md` 的 `<!-- STATS:BEGIN/END -->` 块；
2. 引用：其它文档要写数字，就从 `stats.json` 抄当前值，并在句子附近说明口径（或直接写「见 `_meta/stats.json`」）；
3. 拦截：`python tools/check_numbers.py` 会扫描所有说明文件，出现下表 §4 的退役数字即报错，CI/提交前必跑；
4. 校验：`python make_stats.py --check` 校验 README 统计块与实测一致。

历史上这个仓库反复出现「同一件事 3–6 套数字」（2026-11-15 的 `AUDIT` 记了 6 套，2026-11-20 的 `ASSESSMENT` 又记了 3 套）。
根因不是算错，而是**手写数字**与**统计边界变了却没人重算**。所以现在把「算法」和「文件」分开：算法固定在本文件，值固定在 `stats.json`。

## 1. 当前口径表

| 指标 | 定义（怎么数） | 边界（不含什么） |
|---|---|---|
| **译注工程（部）** | `08_source_code/` 下 **被 git 跟踪**的 `<SYxx-yy>_中文名/` 目录数，一个目录算一部 | 不含 `papers/`（威腾研讨班）、`03_translations_meta/`、`datasets/`、`site/` |
| **带完整 LaTeX 源码** | 该工程目录下被跟踪的 `.tex` 文件 **≥1** | 「有 `源码/` 目录」≠「有源码」：`SY02-11` 的 `源码/` 是空目录/不存在，按 `.tex` 计为无源码 |
| **仓库文件数 / 字节数** | `git ls-files` 列出的**工作区**文件与字节 | 不含 `.git/`、未跟踪文件（如本地草稿、`datasets/_internal/`）、Release 附件（会话分片、成品 PDF） |
| **`.tex` 数 / 插图数** | 被跟踪的 `*.tex` 数；`figures/` 下的 `.png/.jpg/.jpeg/.pdf` 数 | 不含 `03_translations_meta/` 里的元数据文件 |
| **成品 PDF（预印本类）** | `03_translations_meta/_PDF清单.tsv` 中 `成品直链` 以 `http` 开头的行 | 不含只在本地保留的图书成品、不含仓内任何 PDF；页数只数这些公开行的 `成品页数` 之和 |
| **中文段落语料** | `01_corpus_zh/zh_paragraphs.jsonl` 的行数 | — |
| **唯一段落** | 按 `para_id` 去重后的条数 | `para_id` = 段落内容 sha1 前 16 位，跨工程同文同号 |
| **含公式段落** | `text` 中同时不含 `$` 与 `\begin{` 的段视为「纯文字」，其余计入 | 门槛很松（一个行内公式即算），因此百分比偏高（约 86%）是**设计如此**，不是错误 |
| **汉字数** | 逐行 `zh_chars` 字段求和（抽段时统计的汉字数） | 不含公式、不含标点以外的 ASCII |
| **语料覆盖工程** | 语料中出现过的 `pkg` 去重数 | 小于「工程数」是正常的：无 `.tex` 的工程抽不出段落 |
| **近重复标注** | 带 `near_dup_of` 字段的段数（MinHash-LSH，Jaccard ≥ 0.8，保留不删） | 是**下界**：`SY01-23` 与 2026-11-15 追加批未跑 MinHash |
| **原书页码锚点** | 带 `page_orig` 字段的段数 | 只有解析出 TeX 页锚的工程有；不代表全书页数 |
| **术语基** | `01_corpus_zh/termbase.jsonl` 行数；另按 `status`（confirmed/candidate）与 `lang`（en/ja/other）分 | 「条」是**行**，同一术语在不同工程出现会计多次 |
| **资料卡** | `datasets/<集>/cards/**/*.json` 的文件数，一文件一卡 | 不含 `md/` 渲染版、`index.jsonl`、`excerpts.md`；`leanstmt` 的卡在 `cards/statements/` 下 |
| **形式化陈述对齐** | `datasets/leanstmt/cards/statements/*.json` 中 `verification.status` = `certified`（Lean 编译通过、0 sorry）与 `gap`（有 `sorry` 的缺口卡）的条数 | `.lean` 文件数与 `sorry` 出现次数来自 `datasets/leanstmt/lean/`；`sorry` 是**出现次数**，不是卡片数 |
| **精选轨迹** | `02_trajectories/traj_selected.jsonl` 行数 | 原始会话流在 `06_sessions_raw`（Release 附件） |
| **原始会话分片** | `06_sessions_raw/_attachments.json` 的 `parts` 总数与 `total_bytes` | 分片本体在 Release `v1.0.1` 附件，不在 Git |
| **底本类型分布** | `RELEASE_REGISTER.csv` 逐部台账的 `底本类型` 列计数 | 台账 113 行 = 113 部；「待复核」是**尚未定类型**，不是错误 |

## 2. 页数：只在能实测的地方说

- 有实测的只有成品 PDF：`_PDF清单.tsv` 的 `成品页数`（公开行合计见 `stats.json` → `pdf.pages`）。
- **全库译本页数没有实测来源**。旧文档里的「11,404 页」「10,376 页」「10,443 页」都来自不同时期的估算，已退役。
  需要页数时，要么按 `_PDF清单.tsv` 逐部相加（只说这 41 部），要么在具体工程里数 `\newpage`/PDF 页数并注明方法。
- 因此「¥/页」这类派生指标，只允许用**当次能复算的页数**做分母，并在同一句里给出分母来源。

## 6. 什么时候必须重算

- 增删 `08_source_code/` 工程、增删 `.tex`/插图；
- 重跑语料抽取（`01_corpus_zh/_build_corpus_v3.py` 或增量脚本）；
- 新增/修改资料卡集（`datasets/*/cards/`）；
- 改 `_PDF清单.tsv`、`RELEASE_REGISTER.csv`、`_attachments.json`。

顺序：`make_stats.py --write` → `tools/build_site.py`（站点取数）→ `tools/check_numbers.py` → `tools/check_manifest.py` → 提交。
