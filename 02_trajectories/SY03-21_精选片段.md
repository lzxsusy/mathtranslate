## 1. 底本选 arXiv 源码，不从 PDF 反推

**任务意图**

> 一本 128 页的讲义要译成中文，第一件事是确定「以什么为底本」——如果从 PDF 抽文字层，公式、编号、脚注、参考文献都会在源头失真。

**关键动作**

1. 从 `https://arxiv.org/e-print/hep-th/0512172` 下载 e-print（gzip 压缩的单个 `houches.tex`），解压到 `work/houches.tex`；
2. 原 PDF（128 页）只用于核对版面与公式图像；
3. 旧中译本（86 页）只抽取文字层放在 `latex/ref/<id>.txt`，定位是「措辞参考」，不是底本。

**验证证据**

- e-print 138,005 B → 解压后 467,679 B、**9,222 行**；
- 原 PDF 128 页，成品 126 页——页数差来自中文排版，不是内容缺失；
- 正文、公式编号 `(1.1)–(9.22)`、脚注、参考文献、`\index` 条目全部继承源码，QC 可以逐项计数（见第 6 条）。

**结论**

底本一旦定成「源码」，后面所有保真校验才有可比对象：编号、脚注、引用都能按计数对齐；PDF 只承担「版面长什么样」的职责，不承担内容。反过来若从 PDF 反推，后面每一条 QC 都失去基准。

## 2. 旧中译只承接「哪里容易错」，不承接译文

**任务意图**

> 桌面上有一份旧中译（86 页、1.6 MB）。它能不能直接当译文基线，省掉重译？

**关键动作**

1. 把旧中译文字层按块放进 `latex/ref/<id>.txt`，要求译手「只参考措辞与术语，数学一律以 `en` 块为准」；
2. 读旧中译时同步记录**原文笔误**与**旧译笔误**，汇成笔误表，正文照原文排、只在说明/译注里注出；
3. 旧译公式经 PDF 文本层压平（`⊗` 下标丢失、符号变乱码），逐条与源码核对后不采用其数学。

**验证证据**

- 旧中译 1,603,746 B、158,151 字符、86 页；笔误表 **17 处**，后续又有补充；
- 例：e03b 中 `$\pa_t^n$` 应为 `$\pa_t^m$`；`a sn embedding`；`over over $\Bun_n$`；`as as follows`；`the the`；`$\text{\tt f}_{q}(\K)$` 应为 `$\text{\tt f}_{\K}$`；
- 新成品正文按原文照排（含疑似笔误），另列「已知问题」并写进 `工程说明.md`。

**结论**

旧译真正的价值不是「省一遍翻译」，而是**一份踩过坑的地图**：哪些地方原文有笔误、哪些地方 PDF 文本层不可信。把它当基线会把 17 处错误带进成品；把它当参照，反而让新译在同样的位置多看一眼。

## 3. 「数学一字不动」：4 位译手，一条口径

**任务意图**

> 4 位译手并行开工，`\text{}` 内英文、交换图节点标签算不算「要译的文字」？不统一就会一半中文一半英文。

**关键动作**

1. 对照 `docs/STYLE.md` 第 23 条判定：**数学环境内部一律逐字符保留**，包括 `\begin{CD}` 节点标签、`\boxed{...\text{...}}` 里的英文；只有环境之外的正文与图题才译；
2. 给 tr1–tr4 发同一条澄清消息，要求已译的块自查改回；
3. 用 `work/math_diff.py` 对 `en` 与 `tex` 做公式计数复核。

**验证证据**

- e00 的 `\boxed{...\text{holomorphic rank $n$ bundles}...}` 保留英文，被判为正确做法；
- e03a 出现一处「善意修正」：`$D_V$` → `$\D_V$`。`math_diff` 报 `只在 en 出现: {'$D_V$': 1}`、`只在 zh 出现: {'$\\D_V$': 1}`，定位到「其中 $D_V$ 在 $\C$ 上的作用经由 $\la$」，编辑回退为 `$D_V$`；
- 回退后该块公式计数重新对齐。

**结论**

「看起来更对」不能压过「与原文一致」：疑似笔误进笔误表、进译注，不进正文。4 人一致靠两件事——一条书面口径 + 一个能数出来的复核脚本，不靠口头约定。

## 4. 47 条译注：宁可写「nLab 无条目」，也不编链接

**任务意图**

> 译注不能停在「某概念是什么」，要说明它**怎么发生的**（谁、哪一年、哪篇文献）。素材从哪来、没有素材怎么办？

**关键动作**

1. 两个 nLab 调研任务并行：A 线（算术/几何朗兰兹）25 条，B 线（共形场论/物理）22 条；
2. 写作只引真实存在的条目；对没有独立条目的概念，如实写「nLab 无独立条目」，不给假链接；
3. 统一用 `zhunote` 环境，最后用 `gen_notes.py` 汇总成译注索引。

**验证证据**

- 成品共 **47 条译注**（A 25 + B 22），全部落在 `latex/tex/*.tex` 的 `zhunote` 里，可被 `\zhnote` 汇总；
- **8 个概念**在 nLab 无独立条目，按「不编链接」处理，只写事实与出处类别；
- 编译后 47 条全部进入 PDF，无一条游离在正文外。

**结论**

译注的可信度取决于「读者能不能去核」：有链接给链接，没有就直说没有。数量（47 条）是结果不是目标；把「无条目」也写进正文，反而让这批注更可信。

## 5. 并行拆分的单位是「文件」，不是「章节」

**任务意图**

> 9 章正文 + 3 部分读书笔记，单会话做不完；多人并行最怕互相覆盖、口径漂移。

**关键动作**

1. 原文按节切成 **17 块**（e00…e09d，每块 8.7K–32.4K 字符），4 位译手各领一组，写入范围是各自的 `latex/tex/<id>.tex`；
2. 读书笔记独立成册（`notes_main.tex` + `notes/p1..p3.tex`），3 位作者各写一部分，与译本共享 `preamble.tex` 但文件不重叠；
3. nLab 素材、讨论稿各由独立成员产出，lead 只做口径、合稿与验收。

**验证证据**

- 17 块全部到齐并 `\input` 进 `main.tex`，成品 126 页；读书笔记由 `notes_main.tex` 独立编译出 **68 页**；
- 每块任务书里写明字符数与文件路径，块与块之间无写入重叠；
- `main_smoke`（英文块 + 中文导言区）先跑到 153 页，证明中文排版链路在译稿进来前就是通的。

**结论**

拆分粒度选「文件」而不是「章节」，写冲突从机制上消失；lead 的时间花在统一口径和验收上，而不是合并冲突。

## 6. 结构守恒：先把「漏译/多译」变成可数的问题

**任务意图**

> 17 块、4 个人，怎么快速发现某块漏了公式、少了脚注、改了结构？

**关键动作**

1. 写 `work/qc_check.py`：逐块比对 equation、align、`CD` 图、label、`\ref`、`\cite`、`\index`、footnote、subsection 的**计数**，并扫「未译英文长串」；
2. 每块输出一份报告到 `reports/`，17 块全跑；
3. 计数不等先当缺陷查，不先争论文风。

**验证证据**

- e08a 计数全等：equation 13、`$$` 26、label 18、eqref 22、secref 1、thmref 2、ref 25、cite 11、index 9、footnote 5、subsection 3；段落 47→51（只多 4 个译注段）；环境平衡 28/28、花括号 delta 0；
- 17 份 QA 报告全部通过后才进入合稿；
- 未译英文长串扫描在早期就抓出过残留。

**结论**

「译得对不对」无法机检，但「结构是否守恒」可以。先把可数的缺陷清零，剩下的才是真正需要人判断的语义问题——顺序反过来会淹死在文风争论里。

## 7. 公式逐字符核对，且必须先剥离译注

**任务意图**

> 公式保真不能靠肉眼。逐字符比对时，译注里也有公式，怎么区分「正文变了」和「译注新增」？

**关键动作**

1. 写 `work/math_diff.py`：展示级公式按段落**逐字符**比对，行内公式按**多重集**比对；
2. 比对前先剥离 `zhunote` 环境，只比正文；
3. 差异逐条定位到具体块与行，人工裁决后回改。

**验证证据**

- 抓出 e00 一处展示公式**缺结尾句号**，补回后计数对齐；
- e04 出现行内差异，追查为译注插入导致，属预期差异，不改正文；
- e08a 直接跑会报 **9 处「只在 zh 出现」**，全部位于四条 `zhunote` 内；剥离后 display 31/31 顺序与逐字符一致、行内多重集一致。

**结论**

比对工具必须知道「译注不是正文」，否则假阳性会淹没真问题。这条经验后来写进 QC 报告：先剥离、再比对、再裁决。

## 8. 译注里的 ≃、≅、⊂：Unicode 直排会炸编译

**任务意图**

> 译注是中文正文，作者顺手写了 `≃`、`≅`、`⊂` 和自定义宏 `\PP`，编译却报错——错在哪？

**关键动作**

1. 查 `main.log`：`Missing character: There is no ≃ in font ...`、`Undefined control sequence \PP`；
2. 判定：中文正文里的数学符号也必须走数学模式，不能裸 Unicode；
3. 改为 `\simeq`、`\cong`、`\subset`，并在导言区补 `\PP` 定义，全量重编。

**验证证据**

- 修复后主书 **126 页、0 error、0 missing character、0 undefined**；
- 读书笔记 68 页同样干净；
- 问题全部出现在译注插入之后，正文块未受影响。

**结论**

`zhunote` 里写的是中文，但符号仍属数学；「Unicode 能显示」不等于「字体有该字形」。译注工序必须和正文用同一套数学宏，否则每加一批注就多一轮编译排查。

## 9. 编译判据：看日志，不看 latexmk 的退出码

**任务意图**

> `latexmk` 经常 exit code 1，但 PDF 明明生成了。到底算不算编译失败？

**关键动作**

1. 统一判据：`main.log` 无 `^! ` 且出现 `Output written on main.xdv (...)` 即成功；
2. 把 MiKTeX 的「更新提醒」单独识别，不当错误；
3. 用 `main_smoke` 做链路验证：从只有 titlepage 的 1 页开始修，直到 153 页。

**验证证据**

- `main_smoke.xdv` 从 1 页 → 135 页 → 153 页，最终无 `!` 错误；
- 多轮 `latexmk` exit 1 但主书 126 页、笔记 68 页正常输出；
- 判据写进 `latex/build.ps1` 注释与 `工程说明.md` 的「已知坑」。

**结论**

退出码反映的是工具链状态（更新、缓存、辅助文件），不是排版正确性。把判据固定在「日志硬错误 + 输出页数」，CI 和人工才不会互相打架。

## 10. 验收：交付一串可复算的数字

**任务意图**

> 怎么证明「整本书完整交付」，而不是「感觉译完了」？

**关键动作**

1. 清掉 aux 全量重编两遍，检查页数、缺失字符、undefined reference；
2. 核对 `\index` 条目由 xelatex 重生成（130 余条），术语表与 `TERMS.md` 一致；
3. 把全部数字写进 `工程说明.md`，与 `成品/` 两个 PDF 一起交付。

**验证证据**

- 主书 **126 页**（原 128 页）、**47 条译注**、正文 7.58 万汉字；读书笔记 **68 页**、约 5.4 万汉字；
- `main.ind` 正常生成、索引 130 余条重生成（索引键暂保留英文，已记录为已知问题）；
- 术语表 **261 条**；工程目录 **347 个文件**、**17 份 QA 报告**；两次全量重编均 0 error / 0 missing / 0 undefined。

**结论**

交付物的可信度来自「别人能照着复算」：页数、条数、文件数、编译判据都写成数字，任何一项对不上就能立刻定位。工程说明不是总结陈词，是验收清单。
