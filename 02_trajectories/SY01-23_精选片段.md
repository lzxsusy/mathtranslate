## 1. 「哪个版本的原文」先证伪，再讨论页码

**任务意图**

> 用户给了微信里收到的一份 z-lib 版 PDF，同时要求"把 Clay 研究所的原文下载下来"——两份文件是否同一本、能否混用？

**关键动作**

1. `curl -L https://www.claymath.org/library/monographs/cmim04.pdf` → 5,020,938 B；
2. 对微信 z-lib 版与 Clay 官方版各算 SHA256；
3. `pdfinfo` 比页数/页面尺寸（697 页 / 612×792 pt）。

**验证证据**

- 两份 SHA256 同为 `84230A5C…F5F4`——**"另一个来源"其实是同一份文件**；
- `pdftotext -layout` 抽出 1,891,233 字符，有完整文字层，不需要 OCR。

**结论**

"下载原文"这一步的价值不在获得新文件，而在**把底本钉死成可引用的一串哈希**：后面所有比对都以这份 PDF 为准，报告里能写出底本 SHA256，别人复现时不会对错书。省下的争论远大于下载本身。

## 2. 页码映射：印刷页 −10，但译文页码不可互推

**任务意图**

> 译本 530 页、原书 697 页，怎么把"中文第 300 页"接到"英文某页"上？

**关键动作**

1. 按 `\f` 把 `full.txt` 切页 → 第 N 段 = PDF 第 N 页；
2. 用目录自证：原书 Preface 在印刷 vii、PDF 7–9 → **原书印刷页 = PDF 页 − 10**；
3. 译本每个段落前都有 `\SourceParagraph{id}{原书PDF页号}`（2 929 个）→ 只认这个页号。

**验证证据**

- 试过反例：拿"译本印刷第 300 页"去开原书 PDF 第 310 页，内容是 5.1.3 相交形式，而译本第 300 页讲的是 5.8 稳定性条件空间——**完全错位**；
- 换成 `\SourceParagraph` 页号（原书 PDF 304）后，Table 1 与 "PROPERTY 5.1" 逐字对上。

**结论**

两套页码之间没有任何线性关系，**任何"页对页"的直觉都会错**。唯一的对齐键是源码里的锚点；这条规则后来写进了报告和工程 README，避免下一个接手的人重犯。

## 3. biber 读错了 bib：一份同名文件把文献全换掉

**任务意图**

> `latexmk` 全程 exit 0，产物 531 页，看起来"编译成功"了。

**关键动作**

1. `build/main.bbl` 只有 **5,830 B**，而 `references.bib` 有 91,883 B、476 条——体量对不上；
2. 查 `.log` 里 biber 的实际输入；`biber --input-directory=. --output-directory=build` 重跑；
3. 比对前后 bbl。

**验证证据**

- bbl 从 5,830 B → **143,300 B**；PDF 里参考文献从残缺变成 476 条齐全；
- 原因：biber 按 kpathsea 找到了 MiKTeX 自带的 `feupphdteses/references.bib`，**文件名碰巧相同**。

**结论**

"exit 0" 不等于"编对了"。凡是**外部工具读文件**的环节（biber/bibtex/makeindex），都要检查"它到底读的是哪一份"——用产物体量和条目数交叉验证，比看日志更可靠。这条已写进 `.latexmkrc` 与 `编译说明.md` 的"已知坑"第 1 条。

## 4. python3 是 stub：构建脚本在 Windows 上从没跑通过

**任务意图**

> 原工程注释说"用脚本跑 biber 保证 PATH 环境"，但换到这台机器就 exit 12。

**关键动作**

1. 读 `.latexmkrc`：`$biber = 'python3 tools/run_biber.py %O %S'`；
2. `python3 --version` → `exit 9009`（Windows 应用商店 stub，不是真解释器）；
3. 改成直接调 `biber` 并补 `--input-directory`（见上一条）。

**验证证据**

- 改前：latexmk 首轮必失败，需要手工跑 biber 才能出 PDF；
- 改后：`latexmk -xelatex main.tex` 一条命令 4 遍全过，exit 0。

**结论**

"工程有脚本"≠"工程能复现"。接手别人工程的第一件事是**在干净环境里从头跑一遍**，把"隐式依赖本机 PATH"的地方全暴露出来——否则交付的源码在别人机器上就是死代码。

## 5. xeCJK 把 Unicode 弯引号当中文标点：`Almgren’ s`

**任务意图**

> 参考文献里出现 `Almgren’ s`、`Gel′ fand`、`243 – 271`，看起来像多了空格。

**关键动作**

1. 300 dpi 裁图定位（`pdftotext -bbox` 取词框 + `pdftoppm` 渲染 + PIL 裁切），确认不是视觉误差；
2. 写最小样例 `article + fontspec(TeXGyreTermesX) + xeCJK(SimSun) + biblatex`，分别排 ASCII `'` 与 U+2019；
3. 扫 bib 字符：U+2019 / U+201C / U+201D / U+2013 / U+2032 / 组合重音。

**验证证据**

- 最小样例：ASCII `'` 紧贴；U+2019 后面**多出约 0.25em**——xeCJK 把它归入 CJK 标点并加了间距；
- 修法：NFC 合成重音、U+2019→`'`、U+2013→`--`、U+2032→`'`、数学符号包 `$...$`；
- 复验裁图：`Almgren’s`、`Gel’fand`、`243--271`、`Journées` 全部正常。

**结论**

中文排版下**任何非 ASCII 标点都可能是 CJK 标点规则的受害者**，尤其出现在英文文献里时。修法要落在数据（bib）上而不是样式上——改 `\xeCJKsetup` 会波及正文所有标点。

## 6. 大章物理拆分：并发写同一文件 = 静默丢改动

**任务意图**

> 8 名校对员并发，ch03（572 段）与 ch05（699 段）各需要两人分担。

**关键动作**

1. `split_chapters.py` 在 section/段落边界切：ch03 在 `\SourceParagraph{ch03-3.3.4.6-004}{172}` 前切开；
2. `main.tex` 改 `\InputIfFileExists{chapters/ch03a.tex}`、`…ch03b…`；
3. 记 `_split_map.txt`：**ch03b 行号 = 原行号 − 2278、ch05b = 原行号 − 2220**；
4. 交付前 `merge_back.py` 合并，并**删除拆分件**。

**验证证据**

- 拆分后重建 exit 0；两人各改各的文件，无冲突；
- 合并后若保留拆分件，`main.tex` 若再误引一次就会出现 **727 个重复 label**（aux 里可见）；删除后 1 521 个 label 全唯一。

**结论**

并发安全不能靠"说好别改同一个文件"，要靠**文件系统层面的物理隔离**；同时必须留下"偏移映射"与"合并"两个脚本，否则合并时行号全错。合并是交付前一步，不是可选项。

## 7. 图题只有「Figure 31」：`\BookNumberOnlyCaption` 不是漏译

**任务意图**

> 审计发现 68 个 figure 环境用了空题注，怀疑漏译。

**关键动作**

1. `figcap2.py`：按图文件名里的 `PDFpXXX` 取原书对应页，解析 `Figure N.` 开头的行；
2. tex 侧在 `\end{figure}` 处截断，比较"原书该行有没有说明文字"；
3. 对 4 个可疑项逐页渲染原书核实。

**验证证据**

- 原书 p560 实物：图下只有 `FIGURE 8`，没有说明文字 → 空题注是**忠实还原**；
- ch05 有 21 处"缺题注"实为**嵌在 equation 环境里的行内示意图**，本来就没有题注——首版脚本误报，修正判据后清零；
- ch05 图 1 原书同页有 `Figure 1.` 与 `Figure 1. The Lawlor neck.` 两行，译文"Lawlor 颈。"正确。

**结论**

"可疑"必须先降级成"待证"，再用**原书实物**裁决；审计脚本的第一版几乎总会把排版惯例误判成翻译缺陷。误报清单要保留在报告里，否则下次还会重查。

## 8. 日志的"原译"列 ≠ 现在的 tex：回查的假阴性陷阱

**任务意图**

> 201 条改动要做落地回查，脚本拿日志"原译"列去 tex 里找，报 3 条"未落地"。

**关键动作**

1. 打开 `chapters/ch03.tex` L2052–2053 与 L2243–2244 直接看；
2. 对照 `log_ch03a.md` #7/#9 的"改为"列。

**验证证据**

- tex 现为 `T'=T-\tfrac12\partial J,\quad \bar T'=\bar T+\tfrac12\bar\partial\bar J`——**"改为"列已落地**；
- 3 条"否"全部是把**旧版内容**（"原译"列记的 `+½/−½`）当目标去搜导致的假阴性；

**结论**

回查的基准必须是"改为"列，不是"原译"列；日志里同时保留两者是为了给读者看 diff，不是为了给脚本当索引。**任何核验脚本都要先问"我在证伪什么"**。

## 9. 「译者修原书笔误」一律保留：改回原文等于改坏数学

**任务意图**

> 校对员发现多处译文与原书**不一致**：原书 `(−1)^{deg φ}` 而译文用 `q^{deg φ}`；原书 thm 4.78/4.88 缺前提而译文补了限定；原书 `Stab⁰(X)` 而译文全书统一写 `Stab⁰(D)`。要不要"改回原文"？

**关键动作**

1. 逐处回原书页面确认差异真实存在（不是 pdftotext 假象）；
2. 判断"原文对还是译文对"：`q^{deg φ}` 在公式串里自洽，`(−1)^{deg φ}` 与之矛盾 → 原书笔误；
3. 定规矩：**数学上正确的修正与解释性限定一律保留**，只在日志标「原文疑误/译者补正」。

**验证证据**

- 本次共 9 类这类"差异"被保留（quintic 记号、`±i`、归一化常数、`1/4→1/3`、`(−1)^{degφ}`、thm 条件、`Stab` 记号、`2+ε` 修正、`c₁` 符号）；
- 反例检查：`√ Proposition 6.31`、`Proposition\n7.27` 这类"多出/缺失命题"是 pdftotext 把根号与跨行读坏——渲染原书 p454/p574 后确认计数一致。

**结论**

译本的职责不是"逐字复刻错误"，**"与原书不一致"本身不是缺陷**。判据必须是"数学对不对"，并且这个判据要事先写进校对手册、事后写进报告——否则每一轮复核都会把正确的修正再改回去一遍。

## 10. 批量替换必须带"期望命中数"

**任务意图**

> 术语/记号统一共 90 处，涉及 15 个文件，手工改容易漏、也容易改过头。

**关键动作**

1. 只读审计产出一致性清单（quintic 三种写法、`\mathcal Hom` 15、`\mathbb Z` 5、`\BookRef` 空格 57…）；
2. `fix_terms.py` 每条规则写成 `(file, old, new, expected_count)`；
3. **实际命中数 ≠ 期望值 → 整体退出**，一个字节都不写。

**验证证据**

- 首跑有一次 count 不符（审计期间别人刚改过 6 处），脚本直接拒绝执行 → 重新 grep 行号后再跑；
- 最终 90 处全部按预期命中，重建 exit 0，残留模式核对只剩**有意保留项**（ch01/ch05/ch07 共 6 处"五次超曲面"、ch06–08 的 `\mathbb Z` 无括号风格）。

**结论**

无计数的批量替换等于"猜着改"，而且改坏了很难回滚。**把预期写进脚本**，脚本就成了断言，而不是推土机。

## 11. "可复现"要证到干净目录，且只能说"文本一致"

**任务意图**

> 交付的 `源码/` 到底能不能在别处编出同一本书？

**关键动作**

1. 把 `源码/` 复制到 `DBMS_work/src_test`（空目录、无 build 缓存）；
2. `latexmk -xelatex main.tex`；
3. `pdftotext -layout` 比对两份 PDF，并 `Get-FileHash` 比对字节。

**验证证据**

- exit 0、**530 页、24,434,480 B**，与交付 PDF 完全同尺寸；
- 抽取文本 **1,895,725 字符完全一致**；
- SHA256 不同——因为 PDF 里带 `CreationDate`。

**结论**

"字节相同"是不可达的目标，硬写就是造假；正确表述是**"抽取文本完全一致 + 页数/体积一致"**。另外这一步顺手抓到一个事故：第一次跑错了目录（`Downloads` 下另有别人的 `main.tex`，input `sections/00-introduction`）→ exit 12 并产生一堆构建垃圾——**跑编译前先 `Get-Location`**，这条也进了"已知坑"。
