# 中文数学语体规范（STYLE_NL.md）

> 本文件管「把一段外文数学变成中文」这件事的写法层。术语与记号的**口径**在 `README.md`，
> 形式化对齐在 `STYLE_FORMAL.md`。适用于：译文 chunk、资料卡正文、内容索引、审校意见。

## 1. 句子层

- **书面语，不用口语**。禁「咱们」「说白了」「其实吧」；少用「我们」，除非原文就是 `we` 且是论证的一部分
  （数学写作里的 `we` 多译为「我们」是对的，但结论句不要用「我们可以看到」）。
- **逻辑连接词必须译出**：`Thus / Hence / Therefore / In particular / Consequently / It follows that /
  Conversely / On the other hand / Nevertheless` 分别是「因此 / 从而 / 所以 / 特别地 / 于是 /
  由此可得 / 反之 / 另一方面 / 尽管如此」。不要一律译成「因此」——连接词是论证地图的骨架，
  机械合并会让读者看不出哪一步是推论、哪一步是等价。
- **长句可拆，但拆点必须在逻辑连接词或从句边界**；不得把「设……，若……，则……」拆成三段
  丢掉了前提关系。英文的 `which` 从句在中文里常常要前置或另起一句，以读得顺为准，以不改变量词辖域为限。
- **不替作者下判断**。原文是「我们猜想」就译猜想，不能写成「可以证明」；原文是 `It is expected that`
  不译成「显然」。语气词（`clearly / obviously / it is easy to see`）照译，不删不加强。

## 2. 术语层

- 一律以该工程的 `工程文件/work/glossary.tsv` 和 `01_corpus_zh/数语规范/TERMS.tsv` 为准；
  两处都没有，按 `README.md` §3.4 登记，**不要自己造词然后继续写**。
- 首次出现写「中文（English）」；同一节内第二次起只用中文。人名、定理名、软件名不译（`README.md` §3.3）。
- 复合术语中心词后置：「同调镜像对称」「导出范畴的局部化」「Floer 同调的谱序列」。
  修饰语之间用「的」，不要堆成「同调镜像对称猜想证明思路」这种长串；超过四个定语的，
  在译注里给英文原词。
- 同一段落里一个术语只能用一种译名。写作时若发现脑子里冒出第二种叫法，那是 `CONFLICTS.tsv` 的候选，
  记下来交给 Lead，不要在正文里二选一。

## 3. 公式与记号层

- **公式只信页面图像**：`工程文件/work/pages/pNNN.png` 是唯一的原文依据；PDF 文本层提取的公式
  经常丢上下标、错识别 `\mathcal`，不得作为依据。
- **编号照抄，不手写**：`\begin{equation}` 的编号由底本决定；译文不得自行编号或改号，
  交叉引用一律用 `\eqref` / `\ref`。
- 行内公式与中文之间不加空格，但 `$f$ 是连续的` 这种「公式作主语」的句子，公式后加空格。
  不在中文里使用半角逗号、句号、分号——中文标点一律全角（公式内部除外）。
- 只用导言区已定义的宏（`README.md` §4）；chunk 里不写 `\newcommand`。需要新宏，
  在 `工程文件/BRIEF.md` 记一笔，由 Lead 加进 `preamble.tex`。
- 交换图用 `tikz-cd`；不使用 `\xymatrix`（未加载）。图内文字不译时保持原文，
  译了的要在图注里说明。
- 花体 `\mathcal`、黑板体 `\mathbb`、粗体 `\mathbf` 按底本用；不得用 `\mathbbm`、`\mathrsfs`。

## 4. 译注层（`yizhu` 环境）

译注只允许三种情形，每条 1–4 句，**不得补证明、不得展开作者没写的论证**：

1. **术语背景**：该术语在中文文献里不常见，或与常见译名不同（如「预层（前層）」的日文来源）。
2. **原文省略或含糊**：原文用 `etc.`、`and so on`、`the usual` 带过，而中文读者会卡住的位置。
3. **原文笔误**：符号写错、编号错、引用错。处理方式：**照译 + 译注指出正确写法**；
   排版错误（如上下标错位）可按数学意义改并注明。整条译注的格式：

```latex
\begin{yizhu}
原文此处为 $H^{1}(X,\mathcal{O}_X^{*})$，按上下文应为 $H^{1}(X,\mathcal{O}_X)^{\times}$。
\end{yizhu}
```

## 5. 标点与排版

- 全角：，。；：？！「」『』（）——……；半角只用于数学与拉丁文内部。
- 书名用《》，文章/论文用〈〉或引号；术语首次给出英文时用半角括号。
- 数字用阿拉伯数字；年份、页码、编号不转中文数字。区间用「–」（en dash），不用「-」。
- 列表：三级以内用「（1）（2）（3）」，不用「1. 2. 3.」混排；并列项内部不再套列表。
- 参考文献条目不译（保留原文），正文里的引用照抄编号。

## 6. 交付层（chunk）

- 每个 chunk 是**纯正文**，从 `\section` 开始，不带导言区、不带 `\begin{document}`。
- 末尾写页码对照注释：`% [原文 p4–p12]`，页码取页面图像的页脚。
- 图表标题（`\caption`）要译；图内标注视情况，译了就在图注说明「图内文字为译者所加」。
- 脚注照译，脚注里的文献信息保留原文。
- 交付前自查：① 每个公式都能在页面图像里找到对应；② 每个自定义宏都在 preamble 里；
  ③ 没有新增术语未登记；④ 译注条数与 `工程文件/work/yizhu_log.tsv` 一致。

## 7. 质量闸门

写完后跑（逐项都能机械判定）：

| 闸门 | 通过标准 |
|---|---|
| 术语 | 正文出现的每个术语都能在 `TERMS.tsv` 或该工程 `glossary.tsv` 里查到 |
| 记号 | `grep '\\newcommand'` 在 chunk 里 0 命中；每个自定义宏在 `preamble.tex` 有定义 |
| 公式 | 每个 `\begin{equation}` 的编号与页面图像一致；`\ref` 无悬空 |
| 译注 | 条数与 `yizhu_log.tsv` 一致；单条 ≤4 句；不含「可以证明」「显然」类增补 |
| 标点 | 中文语境无半角 `, . ; :` ；括号配对 |
| 页码 | 每个 chunk 末尾有 `% [原文 pXX–pYY]` |

其中「术语」与「记号」两项由 `tools/build_norm.py --check` 与 `tools/ds_lint.py` 覆盖，
其余由审校者按本表逐条过。
