# 术语对齐声明（与香蕉空间及其它中文来源）

> 版本 v1.0 ｜ 2026-11-27 ｜ 维护：Lead ｜ 数据表：`术语对照_香蕉空间.tsv`

## 一、这份声明要解决什么

中文数学圈对同一批对象有几套通行写法：

- 香蕉空间（bananaspace.org）用**完全胚空间／完美胚空间、钻石、斜置、进制空间、仿射胚环、块（shtuka）、错致层（perverse sheaf）、有理晶体（isocrystal）**；
- 李文威、李景辉等先生的教材又各有取舍；
- 本仓库已发布的四十余部译注本，因循自己冻结的术语表，用**完满空间、菱形、倾斜、adic 空间、affinoid、shtuka、反常层、等晶体**。

三方都不错，也都不构成“唯一标准”。我们不打算把已译的几千万字推倒重写——那会让同一批数学在仓库内部出现两套前后不一致的译本，代价远大于收益。**我们改为发布一张对照表**：读者在任何一个来源里遇到的写法，都能在这张表上查到我们对应的译名，反过来也一样。

## 二、表和声明的关系

`术语对照_香蕉空间.tsv` 是数据，本文件是它背后的约定。表的六列是：英文、本库译名、香蕉空间译名、关系、香蕉空间依据、说明。

“关系”只有六种取值：

| 取值 | 含义 | 读者该怎么做 |
|---|---|---|
| 一致 | 两边写法相同 | 直接用 |
| 异名 | 用字不同但可互认（如 solid：固体／固态） | 按本库译名读，遇到外部写法脑内替换 |
| 分歧（本库冻结） | 两边各有一套成熟写法，我们已冻结 | 同上；说明列给出取舍理由 |
| 分歧（保留原文） | 我们保留英文原词（adic、affinoid、shtuka、untilt 等） | 译注里已给出中文对应写法 |
| 无专条 | 香蕉空间没有独立条目或没有固定写法 | 以本库为准 |
| 无 | 香蕉空间完全没有涉及 | 以本库为准 |

## 三、我们为什么不“统一到外部”

1. **外部来源自身不统一**。同一个香蕉空间站内，“完全胚”与“完美胚”并用，“钻石”没有独立条目，“仿射 Graßmann 形”与“仿射 Grassmann 流形”并存。全站 2,356 篇文章、32 名活跃用户，它是重要的社区参考，但不是标准制定者。
2. **教材来源彼此也不同**。不同作者对 perfectoid、perverse sheaf、solid 的取舍并不一致，只选一家等于把另一家的读者排除在外。
3. **仓库内部一致性优先**。四十余部工程、两千余页成品已经互相引用（“见第 X 讲定理 Y.Z”“菱形上的 v-层”），改动一个核心词要牵动上千处断言。现有正文里 `完满` 417 处、`菱形` 352 处、`倾斜` 124 处、`反常层` 354 处——这些词已经是我们语料的公共货币。

因此我们的做法是：**旧工程只登记、不改正文；新工程优先取外部通行写法**。

## 四、三条承诺

1. **新工程优先对齐**：尚未开译的工程，术语取香蕉空间的既有写法；只有香蕉空间无专条或自相矛盾时，才退到本库冻结值。执行口径见 `04_playbook/templates/译文质量验收_璞玉条款.md` 的“术语三级取词”。
2. **每个分歧都可查**：凡本库与外部写法不同的术语，必须进本表；旧译本的译注里也会点明异名（如“学界亦作完美胚空间”）。
3. **可以重裁，但要有记录**：收到读者反馈或新证据（例如某写法在中文文献里已占绝对多数），我们会在 `_清洁/裁定表.tsv` 里重裁并同步本表，同时在 CHANGELOG 记一笔；不做静默改动。

## 五、怎么维护

- 新增条目：直接在 `术语对照_香蕉空间.tsv` 追加一行，`关系` 只填上表六种之一；`香蕉空间依据` 要写清是页面、导航框还是“无专条”，不写“据说”。
- 教材来源（李文威、李景辉等）的中英术语表，走 `intake/` 投稿箱 → `tools/term_intake.py`，生成 B 级冻结表；其异名同样登记进本表的“说明”列。
- 本库译名必须能在 `TERMS.tsv` 里找到；改动前跑 `python tools/term_align_check.py`。
- 引用本表时请连同版本号与日期一起引用，例如“据数译术语对照表 v1.0（2026-11-27）”。

## 六、致谢与边界

香蕉空间的条目对我们核对术语帮助很大，本表的“香蕉空间依据”一列就是证据留痕。但本文件不代表香蕉空间的立场，也不表示我们对其条目内容背书；引用以对方站点当日内容为准。
