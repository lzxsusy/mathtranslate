# 数语规范 v1.0

> 数译的「术语 + 记号 + 写法」总规范。本目录是**规范**，同目录的 `TERMS.tsv` / `SYMBOLS.tsv` /
> `CONFLICTS.tsv` / `MACROS.tsv` / `INDEX.md` 是**由 `tools/build_norm.py` 从源表生成的观测结果**。
> 规范写给三类使用者：写译文的人、写资料卡的人、写对齐卡（自然语言 ↔ Lean）的人与 agent。

## 0. 为什么要有这份规范

仓库里已经有三层资产，但它们的「说法」此前各写各的：

| 层 | 现有资产 | 过去的问题 |
|---|---|---|
| 术语 | `termbase.jsonl` 1,820 条 + 两部工程的冻结表（SY02-09 223 条、FUNCTORIALITY 209 条） | 同一外文有 12 组不同译名，33 组等级不一致，从未有机器闸门 |
| 记号 | `symbols_frozen_FUNCTORIALITY.tsv` 76 条；各工程 `源码/preamble.tex` 里的宏 | 550 个宏名在不同工程里含义不同；`\R` 一个名字有 6 种定义 |
| 写法 | 17 份 `工程文件/STYLE_GUIDE.md` | 各写一份，彼此不引用，新人要先读 17 份才知道共同约定 |

对「教人学数学」的读者，不一致只是硌眼；对**自然语言 ↔ 形式语言对齐**，不一致是硬错误：
同一个中文词指两个概念，形式化时就无法确定该映射到哪个 Lean 定义；同一个宏在两个工程里展开不同，
把陈述搬进 Lean 时就会静默地换了含义。所以这份规范的目标不是文风统一，而是
**让每一条术语和记号都有唯一标识、唯一含义、可追溯的来源**。

## 1. 三条硬规则

1. **一术语一译名**：同一外文术语在全库只有一个中文译名；同一中文名只对应一个数学概念。
   多义必须显式分列（如「范畴」与「2-范畴」），不允许靠上下文区分。
2. **首次出现给原文**：每部工程首次出现时写「中文（English）」，之后只用中文；
   人名、定理名、软件名不译（见 §3.3）。
3. **记号必须登记**：正文里用到的每个自定义宏，必须在 `工程文件/preamble.tex` 里有声明，
   并（新建工程时）在记号表登记读法与含义。禁止在 chunk 里临时 `\newcommand`。

违反这三条中的任何一条，译文仍可能读得通，但**不能进入对齐层**——对齐卡要求术语 ID 与记号可解析。

## 2. 来源分级（A / B / I / D）

每条术语都必须带等级，等级只表示**依据的强度**，不表示对错。

| 等级 | 含义 | 可以怎么用 |
|---|---|---|
| **A** | 原文页码 / 式号锚定：底本自己就是这么写的（含原文术语表、作者自定译名） | 可直接引用，不需要再查 |
| **B** | 外部权威：nLab、Stacks Project、标准教材、审定名词表，且给出链接或页码 | 可直接引用，但「依据」列必须能点开 |
| **I** | 本库定案：无外部依据，由仓主或 Lead 裁决 | 可用；重大术语的裁决理由要写进「依据」列 |
| **D** | 未标级 / 待考：从语料里抽出来但没查证 | **只作候选**，不进对齐卡，不改冻结表 |

现状（2026-11-21）：A 170 / B 152 / I 114 / **D 1,411**。D 级占 76%，是本规范最大的欠账：
它们大多是抓取时自动抽出的候选，需要逐条提级或删除（见 §8）。

## 3. 命名规则

### 3.1 结构

- 名词性条目：中心词后置（`homological mirror symmetry → 同调镜像对称`、`torus fibration → 环面纤维化`）。
- 形容词性条目允许以「的」结尾（`半稳定的`、`刚性的`），但必须在同一表里有对应的名词条目
  （`半稳定性`）或明确标注只作定语。
- 不新造四字词；优先用「……性」「……化」「……结构」「……范畴」「……理论」等常规后缀。
- 一个条目只表达一个概念。`A∞ 代数` 与 `A∞ 范畴` 是两条，不合并。

### 3.2 拉丁字母与中文的混排

- 人名、算子名、软件名保留拉丁写法，**中文与拉丁之间不加空格**（`Fourier–Mukai变换`、`t结构`），
  与「中文与英文单词之间加空格」的一般排版习惯相反——因为这类名称在数学排版里是一个词。
- 连接号用短横 `-`（`A-infinity`）或 en dash `–`（人名之间，`Fourier–Mukai`），同一工程内必须一致。
  现状里有 3 组只差空格/连接号的写法分歧，见 `CONFLICTS.tsv` 的「空格/连字符不一致」。

### 3.3 不译清单

人名（`Kontsevich`、`Fukaya`、`'t Hooft`）、定理名（`Riemann–Roch`、`Atiyah–Singer`）、
软件与语言（`Lean 4`、`mathlib`、`LaTeX`）、记号本身（`$\infty$`、`$A_\infty$`）一律不音译。
日文底本的汉字术语按「同形可用、异形从中文」处理：`前層 → 预层`（I 级，已裁决），
`圏 → 范畴`，`層 → 层`。

### 3.4 新增术语的登记

表外术语先查 `TERMS.tsv`；查不到按「学界通行译法 → 译注首次给英文 → 登记」三步处理。
登记必须带：外文、语种、中文、等级、依据、首次出现位置、工程。登记进
`01_corpus_zh/termbase.jsonl`（或该工程的 `terms_frozen_*.tsv`），**不要直接改 `TERMS.tsv`**。

## 4. 记号规则

1. **一符一义**：同一工程内一个记号只有一个读法和一个含义；同一读法只对应一个记号。
2. **宏只在导言区定义**：所有自定义宏在 `源码/preamble.tex` 声明；chunk 文件里不写 `\newcommand`。
   要加新宏，在 `工程文件/BRIEF.md` 记一笔，由 Lead 统一加。
3. **只用已加载的包**：`amsmath / amssymb / amsthm / mathtools / bm / tikz / tikz-cd`。
   禁止 `\mathbbm`、`\mathrsfs` 等未加载宏；花体用 `\mathcal`，黑板体用 `\mathbb`。
4. **跨工程不共享宏名**：`\R`、`\C`、`\Z` 这类单字母宏在各工程里定义不同（`\mathbb{R}` / `\mathbf R` / 图内 `2`），
   这正是 `MACROS.tsv` 记录的问题。跨工程搬运陈述时，必须按目标工程的导言区重新映射，不能直接复制。
5. **读法唯一**：记号表里「读法·中文名」列必须是口头能读出来的一句话（`读作 Fuk；Fukaya 范畴`），
   不是符号复述。

## 5. 四个表怎么读

| 表 | 列 | 用法 |
|---|---|---|
| `TERMS.tsv` | 术语ID、外文、语种、中文、等级、状态、依据、出处、来源 | 写作时查这张表；`术语ID` 是对齐卡与资料卡引用的外键 |
| `SYMBOLS.tsv` | 记号ID、记号、LaTeX、读法·中文名、含义、出处、依据、来源、分组 | 排版与形式化时查记号；分组沿用冻结表的小节名 |
| `CONFLICTS.tsv` | 类型、键、候选、来源、建议、严重度 | 「建议」是机械推断，**裁定权在仓主**；裁定后改源表 |
| `MACROS.tsv` | 宏、声明方式、声明数、不同含义数、出现工程数、判定、含义变体、出现工程、样例文件 | 形式化前先看这张表；`真冲突` 才是语义不同 |

`INDEX.md` 是四张表的摘要，含高严重度清单与宏的前 20 名。

生成流程：

```bash
python tools/build_norm.py           # 重建全部表
python tools/build_norm.py --check   # 闸门：表与源数据不一致则失败
```

改数据的顺序永远是：**改源表 → 重生成 → `--check` 通过 → 提交**。生成物不手改。

## 6. 与资料卡、对齐卡的关系

```
底本原文 ──► 译文（STYLE_NL.md）
   │            │
   │            └──► 资料卡（08_source_code/<工程>/资料卡/00–04）
   │                        │  抽陈述
   │                        ▼
   └──────────────────► 对齐卡（datasets/leanstmt/cards/statements/*.json）
                            │  机械校验
                            ▼
                        Lean 4 + mathlib（证明层，L3）
```

- **术语 ID** 是贯穿三层的键：资料卡引用术语ID，对齐卡的 `natural_language` 用该译名，
  Lean 侧的 `def`/`theorem` 名由译名音译/意译规则生成（见 `STYLE_FORMAL.md` §4）。
- 资料卡里的「结果清单 / 条款索引」（`01-结果清单.md`、`03-条款索引.md`）是对齐卡的第一来源：
  它们已经带编号、页码、前提，正是 L2 陈述层需要的字段。
- 记号表（`SYMBOLS.tsv`）目前只覆盖 FUNCTORIALITY 一部，是**已知覆盖缺陷**；
  没有记号表的工程，对齐卡只能依赖 `preamble.tex` 的宏声明。
