04质量亮点（应保留的部分）

  • 正文是真中文，不是「机翻感」。剥掉 LaTeX 后统计：44,031 段汉字占比 ≥80%，456 段 50–80%，只有 11 段低于 50%，且这 11 段经逐段核对全部是「纯公式块（\begin{array} / \begin{tikzcd}）」或「英文参考文献照排」，不是翻译失败。
  • 公式保真策略正确。没有把公式渲染成图片、也没有转成 Unicode 乱码，而是保留 LaTeX 源（479 处分行公式环境、\tag{} 4,928 段仍在），这对数学语料是唯一正确的选择——下游可以直接学到可解析的表达式。
  • 术语一致性有工程约束。1,627 条术语库带 ja/en/zh 三语与 SY02-09 的行级 source 字段，正文里「镜像对称」「同调镜像对称」「Fukaya 范畴」等高频词前后统一；抽样未发现同段内术语漂移。
  • 工程规范度罕见。有 MANIFEST、CHANGELOG、DATASHEET、许可文件、46 KB 的翻译纪律硬标准、可复跑的质检脚本。多数个人语料库交不出「第三方能独立跑一遍」的东西，这个能。
  • 重复率控制得当。3.5% 的重复几乎全部来自包内（目录、术语表、交叉引用复述），跨包仅 6 对——说明入库时有去重环节在工作。

06改进方案

阶段一：止血（1–2 人日，收益最大）

  • 补入 10 部缺失工程：跑一遍 _build_corpus_v3.py 覆盖 08_source_code 全部 81 个有源码工程，重建 jsonl 与 stats。验收：pkg 集合 ⊇ 81，汉字总量 ≥ 4,100,000。
  • 修 _append_pkg.py:87 的 UNWRAP：改为「命令名 + 成对花括号」整体替换（re.sub(r"\\(?:mathrm|text|mbox|operatorname)\{([^{}]*)\}", r"\1", s) 并循环到不动点），或直接复用 _tex_clean.py 里已有 _arg/expand 的正确实现。验收：语料中 [A-Za-z]}^{ 孤立闭括号归零；\mathrm{e}^{2\pi i} 段落复查为 e^{2\pi i}。
  • 展开工程自定义宏：从每包导言区提取 \newcommand 表，做 \R→\mathbb{R}、\C→\mathbb{C}、\Z→\mathbb{Z}、\dd→\mathrm{d}、\Spec、\QC、\ainf、\cF 等的映射，未识别的宏统一标 flags=unknown_macro。验收：17.6% 降到 0，且 flags 里能看到全部未识别项。
  • 回填引用编号：抽取阶段不丢 \ref/\eqref，改为按其指向的 \label 生成「式 (8.20)」样式；无法解析的段落打 flags=empty_ref 并从训练集剔除。验收：空括号 465 → 0（或全部带标记）。
  • 撤回 <本地路径> 污染：对语料与已发布 tex 同时跑一次反向修复（该占位符在原位恒为 \\），修完复查 placeholders=0。这是发布工具引入的，必须在源头（scrub_publish.py）加白名单，排除 \\ 与数学环境。

阶段二：切分与结构（2–3 人日）

  • 切分器加硬上限：单段 ≤ 3,000 字，超长时按段落/条目/label 边界再切；appendix_glossary/notes_index/terms.tex 归入 env=glossary|index|bib 而不是 text，并默认不进训练集。
  • 补 STRUCT 字段：env 已有 6 类，实际 95% 是 text，说明识别没生效；建议改为按「\begin{theorem}|lemma|proposition|corollary|definition|remark|proof|example 块」显式切片，并在段级记录 parent_env。验收：非 text 占比从 5% 提到 ≥25%（数学书的真实构成）。
  • 分级重做：tier 只有 A/B 而站点展示 A/B/C，两边必须收口。建议 A=人工校读、B=机器质检通过、C=有已知缺陷；并新增 reviewed_by / review_date 字段，让「A 级」变成可审计结论而不是作者的自我评价。
  • 去重键对齐：把 para_id 与内容哈希统一（当前唯一文本 42,954 < 唯一 id 42,955，说明同文本被算成两段），并把 near_dup 对 SY01-23 增量重算（DATASHEET 自己承认 1,418 是下界）。

阶段三：可信度（1 周，与数据修改并行）

  • 单一真源：只保留 zh_paragraphs_stats.json 作为唯一数字来源，README/DATASHEET/站点/台账全部由脚本从它渲染；每处数字后面强制带口径短语（「已入库 71 包 / 有译文 81 部 / 工程目录 96 个」）。验收：6 套口径合并为 1 套 + 1 条脚注。
  • 许可收口：删除「默认不用于任何模型训练」，或改为「语料 CC BY 4.0；成品 PDF 因底本版权不随库发布」。两者只能留一个，且要在 LICENSE 与 README 同时一致。
  • 译注来源：按台账自己的 A1/A2 分流，A1 批量补页码锚点（可自动化，预计覆盖 600+ 条），A2（外部定理/文献）逐条人工核并允许留空但标 source=none。验收：有来源比例 ≥80%，且 source=none 项在发布时可见。
  • 知识图谱要么补到 10 包以上、要么在文档里显式标「3 包试点，勿当全量」，并删掉 0 字节的 edges.jsonl 或补内容。

07不建议做的事

  • 不要为了把「96 部」做实而把 15 个仅 PDF 的工程硬算进语料。它们没有源码，抽不出可靠文本；正确的做法是在站点和 README 上把「96 个工程 = 81 有译文 + 15 仅成品」写清楚。
  • 不要按段删「疑似重复」。3.5% 的重复绝大多数是包内的目录/术语表，删掉会破坏书的完整性；应该在采样层去重（训练时按内容哈希抽样），语料层只标记。
  • 不要把 A2 类译注批量标成「原文上下文」。台账已经写明这是作弊路径，评审时我按这条标准核对过：41 条带来源的译注中未见此类伪造，这一点值得保持。
  • 不要用「汉字占比」当唯一质量指标。我最初用 ASCII 占比测英文残留，得到 12,167 段的荒谬结果（LaTeX 命令全是 ASCII），弃用后才看清真实情况：99.9% 段落是正常中文。
