硬性备忘录 01 · 论证精读与语料生产

MEMORANDUM-01 ｜ v1.0 ｜ 2026-11-18 ｜ 强制前置读本

适用范围：本库一切「挑文章 → 精读 → 造语料 → 评数据」的工作，无论执行者是人还是智能体。
效力：与任务书、brief、口头指令、旧习惯冲突时，以本文件为准。违反 §8 任一条红线，本次产出作废并登记 incident；连续两次同类违规，该角色停用。
读法：开工前通读 §0–§2；动笔前重读 §3–§5；交付前逐条走 §10 清单。
它不替代什么：不替代《数学文献翻译纪律》v2.x（翻译线），不替代各工程 brief（范围线）。它管的是判断的质量。

§0 三十秒版

七条。缺一条，就不算做完。

  1. 结论必须能被第三方用锚点复现。 不能复现的，叫笔记，不叫结论。
  2. 每条"对"必须配一条"看起来对但错"。 只收正确样本的数据，训不出判别力。
  3. 难度不是自评的，是测出来的。 唯一的难度货币是 obligation 失败率。
  4. 生成者不得当裁判，裁判不得看生成过程。 同一个人格既写又评，分数必然膨胀。
  5. 自报数字一律不采信。 字数、锚点数、claim 数，一律脚本现算，UTF-8 强制。
  6. 闸门没有产物，就是没执行。 quality_gate: self-assessed 等于未执行。
  7. 改进只能在新文献上认证。 在原文献上重评，是把同一张卷子做第二遍。

§1 第一性原理：我们到底在造什么

1.1 不是语料，是"判断的轨迹"

数学文本从来不缺。arXiv 每天都在长，Mathlib 有上百万条机器可查的证明。缺的是：

  • 作者跳过的那一步——他为什么觉得显然，补上它需要什么；
  • 一个论证为什么妙——它把哪个障碍绕过去了，绕法能不能搬到别处；
  • 一条错误路径怎么被修回来——错在哪、谁发现的、改了什么；
  • 同一个命题换一套记号/范畴还成不成立。

2026 年的数据工作反复证明这一点。AgenticCommons/formal-math-autoformalization 的说明写得很直白：Mathlib 有几百万条证明，稀缺的不是证明，是自然语言与形式化之间的配对（数据集说明）。QuantumQA 的工作顺序更值得抄：先做量子执行套件 SES 作为验证器，再堆 92,749 条样本，于是一个 8B 模型在量子专项推理上超过了 GPT-5（ACL 2026）。先有验证工具，再有数据规模——顺序反了，数据就只是文本。

1.2 三条推论

推论一：可验证性优先于正确性声明。
"这条是对的"没有信息量；"这条能被 Lean 编译/能被 sympy 重放/能被第二个独立的人用锚点复算"才有。所以每条数据必须带 how_verified，而不是只带 status: checked。

推论二：过程信号优先于结果信号。
SPARE 证明了步骤标注是 PRM 的真正瓶颈，单次结构化生成可以同时做步骤对齐与正确性判断，比 MCTS 快 2.3 倍、只需 16% 的训练样本就能 OOD 泛化（AAAI 2026）。ScalePRM 进一步证明：没有 ground truth 也能造 step-level 标签，靠多次独立验证聚合（ACL 2026）。"结论 + 一段解释"是最低价值形态；"状态 → 步 → 理由 → 反事实"才是可训练形态。

推论三：领域验证器优先于领域数据量。
同一条判据也解释了为什么"再收十万条中文数学段落"没有意义，而"把 2,000 条段落跑成难度分层 + 错误变体"有意义。

1.3 一个反直觉的结论：算力受限时，模型要做小

如果目标是提高智能而不是刷榜，推理成本比训练成本更致命。所以资源受限下的正确配方是：

模型做小、数据做精、训练做久、外挂记忆。

这不是省钱技巧，是能力结构的选择：小模型 + 高质量过程数据，可以在特定推理域逼近大模型；而大模型 + 脏数据，只会在 benchmark 上虚胖。腾讯 Hy4 flash（224B 总参、每 token 激活 12B、KV cache 降到 1/24）和 DeepSeek V4.1 Flash（prefill 8B / decode 16B，论文承认实质变化全在数据流水线）都在往这个方向走。

1.4 "高热数据"的正式定义

本库说的"高热"，不是"重要"，不是"难"，而是：

热度 ≈ p(1 − p) × 可迁移性 / 标注成本

其中 p 是模型在该单元上的 obligation 失败率。p=0 的数据模型已经会了，p=1 的数据模型完全够不着——两者都不热。最热的是 30%–70% 那一段，也就是"差一点就能做对"的地方。这条定义贯穿 §5。

§2 证据等级：把"对"拆成七级

任何 claim 必须标一个等级。不标等级 = 未完成。

级名称定义典型例子能否进"结论"
T0已证文内有完整证明，且可被独立复算BPS 质量公式 M=√2|Z|（给定电荷）能
T1引用定理依赖外部定理，标注出处且未曲解Γ(2) 由 M∞,M₁ 生成（引 Clemens）能，但须注明依赖
T2构造 + 验证猜出来，再用多重一致性检验钉住SW 曲线 y²=(x²−1)(x−u) 与 λ能，但须写"构造"，不能写"推出"
T3明确假设原文写明 assumption / ansatz"恰好两个有限奇点"（p24/p28）、du≠0（p34）不能，只能进"边界"
T4一致性论证物理动机、半经典图像、自洽检验磁单极凝聚 → 电禁闭（软破缺后）不能，须标"半经典"
T5条件性排除结论成立依赖未证判据p42 实轴走廊（依赖四维跳变判据）不能，须列出依赖项
T6proof-gap / 叙事只有 sketch、类比、"可以证明"p38 唯一性；"Riemann–Hilbert"式诠释不能，只能进"待办"

三条用法：

  • 降级必须写理由。 把 T3 写成 T0 是本库最常见、也最伤可信度的错误。
  • 一篇好论文的 T0 占比通常不到 30%。 这不是论文弱，是数学的常态。为了报告好看而抬级，等于自毁。
  • T5/T6 不是"没价值"，是"要标清楚边界"。 读者最需要的往往正是"这里到底证没证"。

本库实证：SEM-9407087 把 p42 从"已证的必要性排除"降到"条件性排除"，把唯一性从"定理"降到"proof-gap"，整份报告的可信度反而上升——因为读者终于知道哪里能踩、哪里会塌。

§3 精读协议：三席、三轮、三题

3.1 三席：都读全文，不许分章

席职责必须交的东西
结构席论证链：问题 → 策略 → 每个节点依赖什么 → 推出什么一条带页码的论证链；标出哪几步是严格证明、哪几步是一致性论证
计算席公式与计算：自己重推，不看别人的核对表≥6 条公式核对（公式号、页、结果：对/错/文字层坏/需页图）
文本席证据与批判：摘要的大 claim 正文是否真证了；有没有循环、缺口、未证假设每条大 claim 的 T 级；≥5 个可攻击点；与后续文献的连接

为什么必须都读全文：只读自己那一章的人，发现不了跨章的错误。本库实证：r01 把 (5.21) 的根号套在乘积上，只有独立通读并复算的 r02 抓到了；r03 初判 M7/M12 过严，是在重读备忘全文后自我更正的。

3.2 三轮：独立 → 质询 → 圆桌

第一轮：独立报告，物理隔离。
禁止互看、禁止共享草稿、禁止"参考一下别人怎么写"。每人 3,000–5,000 字，末尾一张 claims 表。

第二轮：交叉质询，只打锚点。
A 对 B 的质询，只能针对B 自己写下的 claim 与它自己引的页码/公式。不许泛泛评论"论证不够严谨"。九份质询（3×3 去掉自质询）是标准配置。

第三轮：圆桌三题，只裁三题。
Chair 从所有分歧里挑出三个最要命的，逐题要三方立场 + 反驳 + 裁决。题多了必然分散——本库教训：圆桌裁太多题，焦点涣散，等于没裁。

3.3 质询的五段式（格式硬约束）

## Qn（一句话标题）
- 目标：<被质询的 claim id + 原句>
- 原文锚点：[src p.N] / [eq x.y]，并引原文那一句
- 为什么可疑：<具体到代数、符号、逻辑步骤；能当场复算的写复算过程>
- 替代说法：<你认为正确的版本>
- 怎么检验：<读者按什么步骤能自己确认谁对>

缺任何一段，质询无效。

3.4 裁决必须写"改判条件"

裁决的含金量不在结论，在"什么证据能让我改判"。这句话逼裁决者把立场暴露成可检验的。示例：

"若能证明纯 SU(2) 的真实边缘稳定墙在实轴 |u|>1 段被穿过，或 u=±1 处存在非 BPS 的无质量多重态，则我改判为只证的弱版本。"

没有改判条件的裁决，视为表态，不计分。

3.5 禁止清单（出现即返工）

  1. 互相夸奖、互相引用以示友好；
  2. 复述摘要/引言当分析；
  3. 无锚点断言；
  4. "可能不严谨""值得进一步研究"——必须具体到哪一步、为什么不成立、怎么补；
  5. 把"我记得/普遍认为"写成"作者证明"；
  6. 把译本、OCR 文字层当原文（页图才是原文）；
  7. 用"作者显然知道"替作者补证明，却不标 [inference]。

§4 数据协议：一个 unit 的解剖

4.1 Schema（八字段，缺一不入库）

{
  "id": "SY05-25.u001",
  "state": "问题状态：已知什么、要求什么、卡在哪",
  "steps": [
    {"assertion": "这一步断言什么",
     "warrant": "凭什么成立（定理/计算/定义展开/类比）",
     "depends_on": ["u000", "eq 2.3"],
     "t_level": "T0|T1|T2|T3|T4|T5|T6"}
  ],
  "gap": {
    "where": "作者跳过的是哪一步",
    "why_skipped": "为什么他觉得显然（记号？旧结果？领域常识？）",
    "fill": "补出来的完整论证",
    "how_verified": "Lean 编译 / sympy 重放 / 第二人用锚点复算 / 交叉审一致"
  },
  "counterfactual": {
    "which_step": "如果哪一步不成立",
    "what_breaks": "具体哪个结论会崩，崩成什么样"
  },
  "variants": [
    {"wrong": "看起来对但错的版本", "error_type": "符号|指标|交换极限|充分当必要|悄悄放松条件", "why_tempting": "为什么容易上当"}
  ],
  "anchors": ["[src p.27]", "[eq 5.21]"],
  "difficulty": {"obligation_fail_rate": 0.55, "signals": ["jump", "load-bearing"]},
  "rights": "self|arxiv|book|rewritten"
}

4.2 六条硬规矩

  • 4.2.1 无锚点不入库。 锚点必须可解析到具体页/式，且该页确实支持这条断言。
  • 4.2.2 无 quote 不成边。 推理边必须带 evidence.quote（原文原句），不许转述。
  • 4.2.3 无 how_verified 的 gap 只是猜测。 标 status: draft，不许进 train。
  • 4.2.4 每条正确数据配 ≥1 条错误变体。 错误变体五类：符号/指标、极限交换、充分当必要、条件悄悄放松、构造对象错。变体同时是训练数据和评测题。
  • 4.2.5 反事实必须具体。 "如果这一步不成立"不行，要写"如果 (6.16) 的 ansatz 不成立，则 τ=b₁/b₂ 与 f 无关这一步失效，整条曲线周期比路线塌掉"。
  • 4.2.6 权利分层不混。 self 可公开；arxiv 限非商业研读；book 只进 _internal/，永不发布。混层即合规事故。

4.3 三个"可训练性"判据（新增，重要）

一条数据够不够格进训练集，问三句：

  1. 能被 8B 模型在 ≤5 个 in-context 例子里学会吗？ 学不会，说明它需要太多前置知识，是"阅读材料"不是"训练数据"。
  2. 能构造出让 32B 模型稳定答错的对抗题吗？ 构造不出，说明它太简单。
  3. 模型错了之后，能指出具体哪一步吗？ 指不出，说明它没有过程信号，只是答案。

三问全过 → train；过两问 → dev；一问不过 → reading。本库当前绝大多数数据应标 reading 或 dev，这是诚实的，不是丢人的。

§5 难度经济学：唯一的难度货币

5.1 Obligation 测试（标准操作）

对每个候选单元：

  1. 挖掉结论或关键中间步，把前文交给模型；
  2. 让它补，连续 k = 5–8 次，记录失败次数；
  3. 失败率 p = 失败次数 / k。

这就是该单元的难度分。不用问模型"这题难不难"——模型的自我难度评估与真实失败率相关性很低，本库 playbook/08 已经把"LLM 自评难度"列为反例。

5.2 分层处置

p处置理由
< 10%跳过模型已会，标了也不增加信息
10–30%进"巩固集"有用，但边际收益低
30–70%进"核心候选"最近发展区，热度最高
70–90%进"挑战集"，人判可能是真难，可能是表述坏
> 90%先查表述/前置大概率不是难度问题，是题目坏了

5.3 成本

49,000 段 × 8 次补全 ≈ 39 万次调用。按小模型价格算是几十美元量级，比人读一遍便宜两到三个数量级。这就是"机器能判的不许人看"的算术基础。

5.4 反例（本库真实教训）

  • 让报告人自己报 locator 数：自检 89、实算 94；自检 228、实算 132。自报不可信。
  • 用 Get-Content（默认 ANSI）读 UTF-8：字数虚高 1.7×（8,705 vs 5,013）。编码不锁，所有数字作废。
  • locator 命中率 93.3% 的稿子，仍可能有 15 个公式符号结构错。锚点命中与公式正确是两条检查线，不能互相替代。

§6 多智能体：数量不是变量，独立性才是

6.1 实证结论

本库跑过两版：

版本组织方式结果
v112 人并行，每人一节，互不干扰无讨论、无质询、无 diff，"八个自说自话"
v2全员通读 → 逐节轮值报告 → 三席质询 → 修订 → 复算前三轮所有实质错误都在质询环节被抓出

结论：讨论的价值不在"讲一遍"，而在"有人拿着原文找你的错"。 串行 + 三席质询比并行各写各的强一个量级。

6.2 三种正确的规模化

  • 纵深：同一个 unit 交给 N 个独立复算者。N=3 足够覆盖大多数错误；N=10 收益递减，因为错误有相关性。
  • 广度：N 篇不同文献并行。这是最容易吃到规模效应的方向——彼此不共享上下文，互不污染。
  • 对抗：生成者与判别者分离，红蓝对抗。判别者只看输出与锚点，不看生成过程。

6.3 反模式（占一条就是浪费）

  1. N 个 agent 同时写同一篇——会趋同、互相抄、评分膨胀。
  2. 共享上下文的多角色——角色会退化成同一个声音。
  3. 用 agent 数量当质量指标——101 个 agent 并行写同一篇，产出的不是 101 份独立判断，是一份判断的 101 个回声。
  4. 让写的人顺便打分——自己给自己判卷，没有例外。

6.4 角色分离硬规则

  • 证据官（数锚点、验页码）≠ 复算员（重推公式）≠ 质询者（找茬）≠ 裁决者（拍板）。
  • 生成者不得给自己打分；裁决者不得参与生成。
  • 0 产物的角色 = ROLE_ABSENT incident。 不是"他没意见"，是"他没干活"。

6.5 成本基线

一场 45 页论文的完整研讨：3 席 × 3 轮 + 9 份质询 + 3 份回应 + 圆桌 ≈ 20–30 次运行。超过 40 次同步写同一篇，是浪费；低于 10 次，是没跑完。

§7 门禁：self-assessed 不算执行

每个 gate 必须有机器可读的产物文件。没有文件 = 没执行。status: completed 只能由 gate_report.json 推导，不许手填。

闸名称必须产物通过条件失败模式

G1通读疑点清单.tsv未解项 = 0疑点还在，就开始写结论

  • 闸门失败要留证据，不许改状态绕过。

§8 红线十条

违反任一条，本次产出作废，登记 incident.jsonl。

  1. 编造锚点、页码、定理、引理、参考文献编号。
  2. 把译本、OCR 文字层、笔记当原文。 公式与符号一律以页图为准。
  3. 用 LLM 自评难度当难度分。 难度只能来自 obligation 失败率或人工抽检校准。
  4. 生成者自评、自审、自裁。
  5. 无 quote 建推理边，或用转述冒充原文。
  6. 把过程稿、初稿、已撤回的 claim 当结论。
  7. 自报数字不核算。 字数、锚点数、claim 数必须脚本现算，UTF-8 强制。
  8. 把 locator 命中当公式正确。 两条检查线必须分开跑。
  9. 未过闸门就标 completed / quality_gate: self-assessed。
  10. 用"可能不严谨""值得进一步研究"代替具体攻击点。

另有一条软红线，但同样计分：

  1. 用 agent 数量当质量指标。 规模化的正确维度是独立性与对抗性，不是并发数。

§10 开工前 12 问 / 交付前 12 检

开工前（12 问）

  1. 这次的产品形态是什么？20–35 页读书笔记？unit 集？bench？写不出来的，先别开工。
  2. 读者是谁？没读过原文的学生，还是同行？
  3. 有没有 brief.md 写明范围、禁区、验收？
  4. 原文的页图在哪？文字层能不能用？（默认：不能，只用于定位）
  5. 译本算不算"标准答案"？（默认：不算，它是第四份待核验输入）
  6. 三席怎么分？每席的必交产物是什么？
  7. 谁当证据官、谁当复算员、谁当裁决者？三者不能是同一人格。
  8. 这一轮要裁的三题是哪三题？
  9. 难度怎么测？obligation 的 k 取多少？
  10. 错误变体从哪来？谁筛？
  11. 权利分层是哪一层？能不能公开发？
  12. 这次要验证的假设是什么？什么结果会推翻它？

交付前（12 检）

  1. 每条 claim 有锚点吗？锚点指向的页真的支持它吗？
  2. 每个 gap 有 how_verified 吗？
  3. 每条正确数据有错误变体吗？
  4. 反事实具体到"哪一步、崩成什么"了吗？
  5. 质询有没有变成互相夸奖？
  6. 裁决有没有"改判条件"？
  7. 综合层是 UTF-8 吗？能回到上游 claim 吗？
  8. 自报数字重新算过吗？
  9. 公式都回页图核对过吗（不是只核 locator）？
  10. 有没有角色 0 产物？
  11. gate_report.json 齐吗？status 是从它推导的吗？
  12. 这次产出里，哪一条最可能被下一个读者打脸？先自己打一遍。

§11 资源受限的四条转移原则

（承 04_playbook/11_资源受限路线_v1.md，此处加两条）

  1. 判断贵，token 便宜。 把人的判断压到最少的决策点上；其余全部机器做。
  2. 重复即税。 同一个动作第二次出现，必须变成资产（脚本/模板/schema/检查器）。
  3. 机器能判的不许人看。 字数、锚点数、schema、编码、公式符号一致性，全部脚本化。
  4. 失败要便宜。 允许大量廉价失败，禁止昂贵的一次性完美。
  5. （新增）读者只读一次。 一页纸必须能独立成立；不能要求读者先读三份前置文档才看懂。
  6. （新增）第二次跑之前必须脚本化。 "这次先手工"是本库最大的返工来源。

§12 违规、复盘与版本

  • incident：每次红线记一条 {"id","date","role","redline","evidence","fix","status"}，进 _meta/incidents.jsonl。
  • lesson：每条复盘必须带 patch（改了什么）+ metric（怎么知道改好了）。只写"下次注意"的，不算。
  • 版本：本文件改动须写 changelog；旧版归档，不覆盖。
  • 复审：每季度删掉一条没有证据支持的条款。规则只增不减，最后一定变成没人读的经文。
