# 11 资源受限路线 v1：把「正牌军」的经验压成零预算做法

> 版本 v1（2026-11-14）｜ 配套：[`06_流程提效_v1.md`](06_流程提效_v1.md)（执行层）、`tools/translate_kit.py` v1.1
>
> **参照对象**：北大 BICMR AI4M 团队 2026-10/11 的两次形式化——庞加莱猜想（arXiv 2610.08329，约 2.5 万美元）与 Weil 猜想（`weil-conjectures.merten.dev`，约 7–8 万美元）。
>
> **这份文件不新增翻译纪律**，它回答两个问题：**他们哪几条做法在零预算下仍然成立？哪几条只属于"钱多"？**

---

## 0. 差距不在智力，在预算结构

| | 他们 | 我们 |
|---|---|---|
| 人 | 数学家主笔 + 3 名有数学训练的 AI 工程师 + 9 人作者组 | 1 人 + 智能体 |
| 钱 | 2.5 万 / 7–8 万美元，几乎全是订阅与 API | 单部目标 **5–6M 计费输入**（见 06 §4） |
| 产出 | 2 个项目、各数月 | 106 部译注工程（93 部带 LaTeX 源码）、49,035 段语料、402 条精选轨迹 |
| 稀缺资源 | **数学家的注意力**（他们反复强调审阅是瓶颈） | **同一个东西：我们的注意力** |

这张表决定了取舍：

> **凡是"用钱换规模"的做法一律不学；凡是"用判断换结构"的做法全部学。**

他们能烧 550 万行代码、开两个 orchestrator、让 bot 在 Zulip 上互相谈分工——那是 8 万美元买来的并行度。我们买不起，也不需要：**翻译不是搜索问题，是理解问题**，一块 3–4K token 的原文，瓶颈从来不是吞吐。

## 1. 四条转移原则

| # | 原则 | 他们的原型 | 零预算形态 |
|---|---|---|---|
| P1 | **判断贵，token 便宜 → 把人的判断压到最少的决策点** | 90 个经人审的 milestone 陈述变成全项目固定接口；审阅从事后改到事前 | 每块一张 10–15 行**译前契约卡**，人审 3 分钟，审完才准动笔 |
| P2 | **重复即税 → 第二次出现的东西必须变成资产** | 陈述/定义/blueprint 全进仓库，网站可逐层进入 | 固定前缀（纪律摘要→通读笔记→术语→契约）+ 文件交接，吃满前缀缓存 |
| P3 | **机器能判的不许人看** | Comparator + Nanoda 独立内核、CI 编译合并、性能诊断文档 | `kit check/gate` 把能机器判的从 6 条扩到 9 条，模型只看红旗 |
| P4 | **失败要便宜** | 早期路线整条报废（约 50 万行白写），靠重启止损 | 一块 3–4K token，废一块 ≈ 0.25M，git 可回滚；契约先行让"废"发生在动手前 |

## 2. 对照表：他们的机制 → 我们的落地物

| 他们的机制 | 他们为什么这么做 | 我们的零预算版 | 落在哪 |
|---|---|---|---|
| **90 个 milestone 陈述 = 固定接口** | 早期任务是"一章/一节"，没有可独立检查的终点，导致局部正确的证明围着错误定义堆积 | **译前契约卡**：块范围、一句话主题、断言清单、关键定义、记号约定、前提依赖、公式图清单、**明确不做的**、下游接口 | `work/contracts/chNN.md`；`kit contract` 生成，`gate` 检查 `状态: 已审` |
| **陈述审两遍**（书面 vs 来源；再看 elaborator 展开后） | 源码里的隐式参数/假设只有展开才看得见 | 第一遍：契约里"原文开头 + 公式与图清单"对位；第二遍：`statements.tsv` 记每条定理的**假设条数**，脚本比对译前译后 | 契约卡 + `work/statements.tsv` |
| **审阅前移** | "审代码"要审无穷多行；"审陈述"只需审 90 个 | `状态: 已审` 才准开工；`gate` 用 mtime 检查"通读/契约早于落笔" | `kit gate` |
| **归因三分法**（数学缺口 / 实现问题 / 协调问题） | 卡住时先分类再动作，否则用错力气 | 疑点清单加 `归因`、`下一步` 两列；未填不许过 gate | `templates/疑点清单_表头.tsv` |
| **定义先行**（48% 代码是共享基础设施） | 定义设计错了，后面全是白工 | `definitions.tsv` 硬闸门：≥5 条、来源列填充 ≥60%、与 glossary 不冲突 | `work/definitions.tsv`；`gate` |
| **SHEAF 剪节点**（54,000 → 28,600） | 证明常找到更短路径，被绕过的节点要剪掉 | **译注也要剪**：密度红线 3 条/千字；`\routenote` 只写"作者为什么这样走"，不写"额外的知识" | `kit check` 译注密度提示 |
| **路线漂移事故**（模型自建 ∞-范畴，剪掉 2,000 节点） | 自主运行会离开人定的 blueprint | `check` 比对原文与译文的定理/定义环境数，比值越出 `[0.6, 1.6]` 报红 | `kit check` 路线偏离 |
| **网站 graph / document / progress** | 让人能在任意粒度进入，且声明与代码对齐 | **不建图数据库**。`statements.tsv` + 现有 site 已够；真需要时再上 | 不做 |
| **Archon Horizon / Orchestra / Zulip / Taxis** | 多机、多人、多 agent 的协调 | **不做**。文件交接（`handoff/`、`reports/`、`cost_log.tsv`）已等价；单人串行没有协调问题 | 不做 |
| **给 agent 的性能诊断文档** | 长尾问题会反复咬人 | 我们的对应物就是 `work/check_report.md` 归档 + 纪律 §11 踩坑速查 | 已有 |

## 3. 新增工件（谁写、何时写、谁审）

| 工件 | 写的人 | 时机 | 审的人 | 不合格的后果 |
|---|---|---|---|---|
| `work/contracts/chNN.md` | 译手（智能体草拟） | 开本块**前** | Lead（3 分钟） | `gate`/`contract --check` 拦下 |
| `work/definitions.tsv` | 通读段 | A 段结束 | Lead | `gate` 拦下（新工程） |
| `work/statements.tsv` | 通读段 | A 段结束 | Lead 抽检 | `check` 提示 |
| 疑点清单三列（归因/下一步/状态） | 通读段 | 疑点逐条查时 | Lead | `gate` 拦下（新工程） |
| `\routenote{…p.N…}` | 译手 | 译每块时 | `check` | 缺页码报红 |

> 注意：**契约不是长篇大论**。10–15 行、填完一屏。写成半页纸就说明你在写第二份通读笔记，那是浪费。

## 4. 成本账：同一本书，两种做法

| | 他们（单项目） | 我们（单部 40–60 页） |
|---|---|---|
| 算力 | 2.5 万 / 7–8 万美元 | 5–6M 计费输入（06 §4） |
| 人工 | 9 人月量级 | 通读 2–3 小时 + 每块审契约 3 分钟 + 校订 2 小时 |
| 返工 | 曾整条路线报废（50 万行） | 单块报废 0.25M，契约阶段拦下则几乎为零 |

他们的钱买的是**并行搜索吞吐**（模型可以试一万条路）；我们的钱买的是**理解质量**（一条对的路走到底）。所以**不学他们并行、不学他们自动剪枝的规模，只学他们把"人判断"放到最便宜的位置**。

---

## 5. 明确不做的事（防跑偏）

1. **不并行多 agent 译同一本书**。他们自己也踩过：接口没冻结时的并行只制造协调成本（重复劳动、不兼容版本）。我们的"并行"是"不同书之间并行"。
2. **不上昂贵模型档**（06 §7 已定）。他们的 $25k 里有一大块是"用最贵模型换速度"。
3. **不自建形式化、调度器、图数据库**。我们不是形式化项目，`\routenote` + `statements.tsv` 就是我们的"声明层"。
4. **不追求全自动**。他们最硬的结论恰恰是反自动的：*"Mathematical judgement sets the route, and AI makes it practical to carry the details all the way down."*
5. **不为省钱删公式核对**。纪律第 0 定律与"公式只信页面图像"一条不动。

## 8. 2026-11-20 补充：形式化是对齐层，不是替代层

资源受限不等于只做翻译。新增 [`15_形式化与自然语言对齐_2026-11.md`](15_形式化与自然语言对齐_2026-11.md)，
把“零预算”再推一步：用 Lean 陈述层做验证器，把已译好的定理变成 `(NL, Lean 陈述, 证明/缺口, 证据)` 四元组；
编译器给 0/1，人只审“陈述是否忠实”。这条路不需要大集群，先做 1,000 条对齐即可验证。
本文件 §0 的“用判断换结构”原则不变，只是判断的落点从“译前契约”扩展到“形式陈述”。
