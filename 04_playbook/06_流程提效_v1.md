## 0. 一句话

> 一部 49 页论文的全文只有 **2.7 万 token**；真正贵的是**几百轮对话里每轮重新计费的十几万上下文**。
> 所以提效的方向不是"少读"，而是：**读一次、记下来；每块只带这一块该看的东西；机械活交给脚本。**

## 1. 成本诊断（来自 11-10～11-13 的 8,744 次真实请求）

| 指标 | 实测 | 含义 |
|---|---|---|
| 计费输入 | 1,089.8M tok（4 天） | 缓存命中 97.8%，仍是大头 |
| 单请求上下文中位数 | 118.6K | 每轮都在为"历史"付费 |
| 上下文 >200K 的请求 | 8.1% | 长会话尾巴极贵 |
| 最贵会话 | 365 轮 / 58.5M、314 轮 / 57.8M、339 轮 / 55.0M | 轮数 × 上下文 = 成本 |
| 工具分布 | pwsh 3,487、read_image 2,130、read 1,693、edit 923 | 读图与逐页读占轮次 |
| 输出占比 | 8.326M tok ≈ 账单 26% | 在对话里复述译文很贵 |

对照一个真实底本（`2016Lec(1).pdf`，49 页，驹场镜像对称讲义）：

```
全书文本 100,015 字符 ≈ 27,324 tok
分 9 块，每块 6 页 ≈ 3.1–3.7K tok
```

**结论**：内容只占成本的千分之几。贵在三处——① 每个译手开工时重复加载 BRIEF/STYLE/术语表/页面图；
② 一个会话跨几十块，上下文越滚越大；③ 译文与审校意见在聊天里反复复述。

## 2. 优化后的流程：三段七步

```
准备(0) → A 通读段(1 个会话) → B0 立契约(脚本+3 分钟人审) → B 分章段(每块 1 个会话) → C 校订段(1 个会话) → 交付
```

### 第 0 步：准备（脚本，1 分钟）

```powershell
$py <python>; $kit = ...\04_playbook\tools\translate_kit.py
& $py $kit prep <底本.pdf> <工程>\工程文件\work --pages-per-chunk 6
& $py $kit budget <工程>\工程文件\work        # 先算账，超 60K/块就缩块
```

产出：`work/pages/pNNN.txt`（逐页）、`work/fulltext.txt`（**全文单文件，通读只读它**）、`work/pages.json`、`work/chunks.json`（分块计划）。

> 省掉的：通读时逐页 read 的 40+ 次往返；译手各自重新定位页码。

### A 段：通读（不可压缩的那一段，也是唯一一次全篇阅读）

**A1 通读**：1 个会话，`read work/fulltext.txt` **一次**，按纪律 §1.0 读完（≤40 页=全文一遍，一句不跳；公式第一遍允许不懂）。
**A2 落两件工件**：
- `work/通读笔记.md`（按 `templates/通读笔记_模板.md`，≤1500 字：主旨 / 论证地图 / 体裁清单 / 阅读顺序 / 给译手三条提醒）
- `work/疑点清单.tsv`（按模板表头，六类、三状态）
**A3 查证与冻结**：疑点逐条查（先本库、再 nLab/Stacks/EMS、最后 A 级文献），`未解`→0；`glossary.tsv` 建好、依据列填满。
**A4 样板段**：Lead 亲手译 1–2 页成 `chunks/sample.tex`，定文风与译注体例（纪律 §1.4）。
**A5 过闸**：`translate_kit.py gate <工程>` 必须返回 ✓。这是 G0 的机器版。

> 这一段就是"先通读、后落笔"本身，**不许省、不许换便宜模型糊弄**。成本 ≈ 一次 2.7 万 token 的阅读 + 几件工件的写作。

### B0 步：译前契约（脚本生成 + 3 分钟人审）

```powershell
& $py $kit contract <工程>            # 一次给所有块生成 work/contracts/chNN.md
& $py $kit contract <工程> --check    # 逐块校验：无 ⟨待填⟩、状态=已审、审阅签字非空
```

每张卡 10–15 行，写死**这一块的接口**：块范围 / 一句话主题 / 断言清单 / 关键定义 / 记号约定 / 前提依赖 / 公式图清单 / **明确不做的** / 下游接口 / 状态 / 审阅（体例见 `templates/译前契约_模板.md`）。

为什么这 3 分钟值回票价（借鉴自北大 AI4M 的形式化实验，理由见 `11_资源受限路线_v1.md`）：

- 他们的 90 个 milestone 陈述，让 agent 的产出从"一片正确但互相接不上"变成"可并行、可验收"；我们的对应物就是**每块的断言清单 + 下游接口**。
- 他们的教训是"审阅时机从事后改到事前"——**事后改一章的接口，等于重译**；事前 3 分钟，能挡掉"这一块用错了定义"。
- **「明确不做的」是防路线漂移的护栏**：他们有一次全自动跑偏、去建了不需要的 ∞-范畴机器，随后人工拉回并剪掉近 2000 个节点；我们对应的翻车是"译手自作主张补了一整套背景"。

> 契约不进 `gate` 就没人写。所以 `kit gate` 会检查：本工程所有块都有卡、卡里没有 ⟨待填⟩、状态为已审。旧工程用 `gate --legacy` 只提醒不拦。

### B 段：分章翻译（每块一个短会话）

每块开工用 `templates/章节译手任务书_模板.md`，输入**只有**：

```
译前契约卡(≤300 tok) + 纪律摘要(≤600 tok，任务书内) + 通读笔记(≤1.5K) + glossary 相关行
+ 上一块衔接卡(200 字) + 本块原文(3–4K) + 样板段(1K)
```

要求：
- **先完整读本块原文再动笔**（纪律第 0 定律照旧；只是不再重读全书、不再重读别人的块）。
- 公式回页面图：**只裁公式区域**（`crop.py`，200 dpi，单图 ≤1200 px）；不整页读图。
- 译文直接写 `源码/chunks/<chunk-id>.tex`；**不在对话里贴全文**；改稿用 patch，不整章重写。
- 收尾三件：`work/handoff/<chunk-id>.md`（200 字衔接卡）、`work/reports/<chunk-id>.md`（5 行）、`work/cost_log.tsv` 一行。
- **会话预算：≤15 轮、上下文 ≤30K**；到线就落盘收工，下一块换新会话。

### C 段：校订（脚本先跑，模型只看红旗）

```powershell
& $py $kit check <工程> --out 工程文件/work/check_report.md
# 再加：xelatex 编译、gen_notes、页映射核对、黑名单 grep
```

- `check` 覆盖：黑名单来源、译注（`\zhnote` / `\transnote` / `\tutornote` / `yizhu` 环境）缺来源、悬空 `\ref`、中文里的半角标点、TODO/待补残留、术语表覆盖率，以及 **v1.1 三条新红旗**：
  - **定理环境数偏差**：原文里 `Theorem/Lemma/…` 标题出现 n 次、译文里 `\begin{theorem}` 约 n 次（比值须在 0.6–1.6）；偏离 = 漏译或自行增补。
  - **`\routenote` 缺页码**：路线注必须带 `p.NN`，否则读者无法回查，它就不是"路线"而是空话。
  - **译注密度**：解释性译注 > 3 条/千字 → 提示"是否在替读者思考"，该合并或删。
- 模型只处理报告里被点名的位置 + 抽检 5 条译注来源（纪律 §9 不变）。
- 交付前 `gate` 再过一次（防止回改后通读笔记与 chunks 的先后关系被破坏）。

## 3. 九条硬规则（照做就能省，且不破规矩）

| # | 规则 | 省在哪 |
|---|---|---|
| R1 | **一块一会话**；会话之间只传文件（契约卡/通读笔记/衔接卡/术语表） | 砍掉"上下文越滚越大" |
| R2 | 通读只读 `fulltext.txt`（1 次 read）；页面图只裁公式区域 | 砍 read/read_image 轮次与图像 token |
| R3 | 固定前缀顺序不变（契约卡 → 纪律摘要 → 通读笔记 → glossary → 原文） | 命中前缀缓存，新增内容只有本块原文 |
| R4 | 译文落盘，不在对话里复述；改稿用 patch | 砍输出（账单 26%） |
| R5 | 每块只留 200 字衔接卡，不把上一块译文带进下一块 | 砍重复上下文 |
| R6 | 机械活全脚本：prep / budget / contract / gate / check / gen_notes / 编译 | 砍"用眼睛核对"的轮次 |
| R7 | 会话 15 轮 / 30K 封顶；`cost_log.tsv` 记账 | 让成本可见、可归因 |
| R8 | **先立契约、再动笔**；契约改了就重新签（不许"心里改了"） | 砍掉"事后才发现接口错了→整块重译" |
| R9 | 每块收尾把新定义/新记号回写 `definitions.tsv` 与 `glossary.tsv` | 砍掉"下一块自己重新定一遍" |

> 反面清单（这些"省法"一律禁止）：跳过通读直接机翻；只读摘要不读原文；把整章丢给模型"看着办"；用低质二手来源凑译注；为了省 token 删掉公式核对；**没有契约卡就开译**。

## 4. 预算与验收

对一部 40–60 页论文（9–12 块）：

| 阶段 | 会话数 | 单会话输入上限 | 预估计费输入 |
|---|---|---|---|
| A 通读 | 1 | 60K | ≤ 2M |
| B0 立契约 | 0（脚本）+ 人审 3 分钟 | — | ≈ 0.05M（脚本输出 + 人看） |
| B 分章 | 9–12 | 30K | ≈ 0.25M/块 → 2.5–3M |
| C 校订 | 1 | 40K | ≤ 1M |
| **合计** | | | **≤ 5–6M** |

契约的开销在 **人**（每块 3 分钟，9–12 块约 40 分钟），不在 token；省下的是一次"接口错了导致整块重译"（≈0.3–0.5M + 半小时）。

现状同类工程常见 10–40M（最贵会话 55–58M 的量级）。**目标：同质量下砍掉 50% 以上**；不以"少读"换。

验收看三样，缺一不算成功：
1. `gate` ✓、`check` 0 问题（或全部有解释）；
2. 抽检 5 条译注来源真实可查（纪律 §9）；
3. `dsh_usage_report.py` 里该工程的计费输入 ≤ 6M，且 `cost_log.tsv` 与账单对得上。

## 6. 试点（建议）

底本：`<本地路径>).pdf`（49 页，已用 kit 预跑：27,324 tok / 9 块，见 `数译发布\_pilot_2016Lec\work`）。

1. 按 A 段做通读笔记 + 疑点清单 + 术语表 + 样板段，`gate` 过闸；
2. 抽 2 块按 B 段译，`check`；
3. 记录每块轮次/token 到 `cost_log.tsv`，与旧流程同类工程对比；
4. 达标（质量不降、成本 ≤ 5–6M）后，把 v1 写进 `04_playbook/README.md` 的流程入口，作为默认做法。

## 7. 不做的事

- 不为了省钱改模型档位或降低推理强度——那会直接伤"读懂"这件事；
- 不把通读拆给多个 agent"各读一章"（纪律与研讨班经验都证明：没通读的人抓不到别人的错）；
- 不追求"一次会话译完全书"；长会话本身就是成本来源；
- 不改 `01_数学文献翻译纪律.md` v2.0 的任何条款；本文件是执行层的补充。
