# 译前契约（模板 · 规范说明）

> 每块开工**之前**写，10–15 行，写完给人审 3 分钟，签 `状态: 已审` 才准动笔。
> 用 `translate_kit.py contract <工程>` 自动生成每块的卡（含术语命中），本文件说明每栏为什么存在、怎么写。
> 依据：[`11_资源受限路线_v1.md`](../11_资源受限路线_v1.md) §2、[`06_流程提效_v1.md`](../06_流程提效_v1.md) B0。

## 一、卡的形状

```markdown
# 译前契约 ch03（p013–p018）

- 块范围: p013–p018（约 3,400 tok）
- 原文开头: （原文前两行，用来确认没拿错块）
- 一句话主题: 这一块要读者带走什么（≤40 字）
- 本块断言清单（可独立检查的结论，一条一行）:
  - 定理 3.1 给出 X 的局部模型；
  - 引理 3.4 是 3.1 的直接推论，不需要额外假设；
- 关键定义（本块首次出现的概念；必须同步进 work/definitions.tsv）:
  - stability condition = 稳定性条件  ⟨首次出现 p013⟩
- 记号约定（易混、易漏，尤其是原文默认省略的）:
  - 原文用 $\mathcal{F}^{(g)}$，此处保留；与 $\mathcal{F}_g$ 不同源；
- 前提与依赖（上一块给了什么、本块必须接受的假设）:
  - 假定上一块已证 $X$ 紧致；本块不再复述；
- 公式与图清单（编号 → 处理方式）:
  - (3.2) 重排；(3.5) 照抄；图 3.1 裁图 200dpi；
- 明确不做的（本块不展开、不引入的概念——防路线漂移）:
  - 不引入导出范畴语言；原文只用导出函子；
- 下游接口（下一块需要本块产出什么）:
  - 下一块要用 (3.5) 的记号与"紧致"假设，不得改写；
- 状态: 已审
- 审阅: Lead 2026-11-14
```

## 二、每栏的判据（写不出来就说明还没读懂这块）

| 栏 | 不合格的样子 | 合格的样子 |
|---|---|---|
| 一句话主题 | "本节讲镜像对称" | "把 A 模型的量子修正收进 B 模型的复结构" |
| 断言清单 | 抄目录标题 | 每条都能单独判断真假，且能被后面某处引用 |
| 关键定义 | 只填中文名 | 英文定名 + 中文定名 + 首次出现位置 + 为什么选这个中译 |
| 记号约定 | 空着 | 至少写出一个"原文没明说、但会影响公式对错"的约定 |
| 前提与依赖 | "承上文" | 列出上一块给的具体结论/假设 |
| 明确不做 | 空着 | 至少一条"本块不引入 X"（这是防跑偏的护栏） |
| 下游接口 | "供下一章使用" | 指出下一块**具体**会用到的对象/结论 |

## 三、三条硬规矩

1. **一屏写完**。超过 20 行，说明你在写第二份通读笔记——那属于 A 段，不属于契约。
2. **不许写「见原文」**。契约的价值就在于把"原文里有的"变成"这里写死的"。
3. **改了契约要重新签**。译到一半发现接口错了：先改契约、重新审，再继续；不许"心里改了"。
