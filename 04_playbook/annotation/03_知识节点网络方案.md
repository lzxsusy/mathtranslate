# 知识节点网络方案（concept 层）

> 目标：把「一篇一篇论文」变成「一个概念一个节点」的网络——同一个定理在几本书里出现、各书怎么证、哪篇论文的关键步骤用了它，都能一页看清。
> 前提：`02_精读标注规范.md` 的 unit/inference 已经能产出；本方案只解决「跨论文」这一层。

---

## 0. 一句话结论

**节点从 LaTeX 源码规则抽取，LLM 只做归并与类型补全，每条边必须挂原文证据；先 SQLite，10 万节点前不上图数据库；发布只发 ID、边、计数与自己的转述，不发原文。**

---

## 1. 数据模型（SQLite DDL）

```sql
-- 概念节点：永久 ID + 可变展示名
CREATE TABLE node (
  nid          TEXT PRIMARY KEY,          -- kn_<sha1(kind|msc|normalized_name)[:12]>
  kind         TEXT NOT NULL,             -- definition|theorem|construction|method|conjecture|example|object
  canonical_zh TEXT NOT NULL,
  canonical_en TEXT,
  field_msc    TEXT,                      -- 如 "14F05;18G80"
  one_line     TEXT NOT NULL,
  status       TEXT NOT NULL DEFAULT 'draft',  -- draft|reviewed|canonical|merged|deprecated
  created_by   TEXT NOT NULL,
  created_at   TEXT NOT NULL
);

-- 别名：同名异义靠 sense 拆分；一个 nid 多个 alias
CREATE TABLE alias (
  node_id    TEXT NOT NULL REFERENCES node(nid),
  text       TEXT NOT NULL,
  lang       TEXT,                        -- zh|en|symbol|abbr
  source     TEXT,                        -- 哪本书/哪个库
  kind       TEXT,                        -- preferred|variant|symbol|abbr
  confidence REAL,
  PRIMARY KEY (node_id, text, lang)
);

-- 出现：节点在哪篇论文的哪个位置、扮演什么角色、原句是什么
CREATE TABLE occurrence (
  oid        TEXT PRIMARY KEY,
  node_id    TEXT NOT NULL REFERENCES node(nid),
  paper_id   TEXT NOT NULL,
  locator    TEXT NOT NULL,               -- JSON: {tex_file,tex_lines} 或 {pdf_page,bbox,...}
  role       TEXT NOT NULL,               -- defined|stated|proved|mentioned
  quote      TEXT,                        -- ≤200 字，发布时只出这句
  confidence REAL,
  extractor  TEXT                         -- rule@v1 / llm@model / human
);

-- 边：每条边必须挂一个 occurrence 作证据
CREATE TABLE edge (
  eid        TEXT PRIMARY KEY,
  src        TEXT NOT NULL REFERENCES node(nid),
  dst        TEXT NOT NULL REFERENCES node(nid),
  rel        TEXT NOT NULL,               -- uses|proves|generalizes|specializes|analogous|contradicts|refines|instance_of
  conf       REAL,
  method     TEXT,                        -- rule|llm|human
  evidence_oid TEXT REFERENCES occurrence(oid),
  extractor_ver TEXT,
  status     TEXT DEFAULT 'proposed'      -- proposed|accepted|rejected|unresolved
);

-- 定义修订：同一概念在不同书里的定义版本
CREATE TABLE definition_rev (
  node_id  TEXT NOT NULL REFERENCES node(nid),
  rev      INTEGER NOT NULL,
  text_zh  TEXT,
  paper_id TEXT,
  valid_from TEXT,
  PRIMARY KEY (node_id, rev)
);
```

**三条不可妥协的规则**：
1. `nid` 是唯一永久标识，`slug` 只是展示名，改名不影响链接；
2. `edge.evidence_oid` 为空 ⇒ `status` 只能是 `proposed`，前端默认不显示；
3. 原文正文**永不入库**，只存 `quote`（≤200 字）+ 链接 + 自己的转述。

## 2. 构建流水线（6 步）

### 第 1 步：规则抽取（零 LLM）
输入 91 部书的 `.tex`；识别：
- 环境：从每本书导言区 `\newtheorem{...}` 收集环境名（不要写死英文全名！），再匹配 `\begin{env}`；
- 编号：`\label{}`、`\ref{}`、`\eqref{}`、`\cite{}`；
- 角色：环境内是 `defined` / `stated` / `proved`（`\begin{proof}` 归属最近定理）。
输出：`nodes`（初版按 `paper_id + label` 建，仅书内唯一）、`occurrences`、`edges`（rule 候选）。

> 这一步就能回答「这本书的定理依赖图长什么样」，不花一分钱。估算：44k 段中约 15% 是定义/定理 ≈ **6,000 节点**；每定理 3–8 条 ref ≈ **20,000–40,000 条候选边**。

### 第 2 步：书内归一
- 同一 `label` 的 `\ref` 指向同一节点；
- 把 `\begin{theorem}` + 紧随的 `\begin{proof}` 合成「陈述 occurrence + 证明 occurrence」；
- 解决 `\input`/`\include` 跨文件、`\newcommand` 宏展开（只展开一层，记录未展开宏）。

### 第 3 步：跨书聚类（候选对）
- 名称归一（大小写、连字符、所有格、`theorem of X` 模板）；
- 领域过滤：MSC 前两位相同才进候选；
- 定义首句向量 top-k（k=10）；
- 输出 `merge_candidates.tsv`：`src_nid, dst_nid, score, name_sim, msc_sim, vec_sim, evidence_quote`。

### 第 4 步：LLM 判 merge/add（只判候选对）
固定 prompt，只允许输出 `merge` / `add` / `uncertain`，**必须带一句 quote**；拒答即弃。
- `merge`：同一概念、可合并（如「Borel–Weil–Bott 定理」与「BWB 定理」）；
- `add`：名字像但不同义（如「凝聚层」与「拟凝聚层」）；
- 同名异义必须拆 sense（MathGloss 实测把 group 映射到消歧页 Q654302，就是没拆 sense）。

### 第 5 步：人工三道闸
1. **merge 全量审**（初期每天 30–50 对，宁可慢）；
2. **每类边抽 50 条**，precision ≥0.9 才放行；不达标回退 prompt 或规则；
3. **跨书冲突仲裁**：同一 label 在两本书里定义不同（如不同作者的「适度」），标 `definition_rev` 两版，不合并。

### 第 6 步：挂接 unit/chain
- 精读标注产出的 unit 通过 `concepts[]` 挂到 nid；
- chain 的 `move` 与关键 step 也挂 nid，形成「论文 → 概念」的双向索引；
- 这一步让「哪篇论文的关键步骤用了这个概念」可查。

## 3. 概念 ID 与命名

```
nid = "kn_" + sha1(kind + "|" + msc + "|" + normalized_name)[:12]
normalized_name = 小写、去空格/连字符、去 "theorem of" 前缀、保留所有格
```

- 例：`kn_5a8c3e0f7b21` = Borel–Weil–Bott theorem；
- `slug` 单独维护（`borel-weil-bott`），可随展示名调整；
- 永久链接只认 `nid`：`/k/kn_5a8c3e0f7b21`；
- 合并时保留被合并方的 `nid` 为 redirect，不 404。

## 4. 存储与检索

### 4.1 存储
- **主库 SQLite**（单文件、可 git 版本化、递归 CTE 够用）：`data/kn.sqlite`；
- 源真源仍是 JSONL/TSV（可 diff、可 review），SQLite 是索引；
- **10 万节点、百万边以内不换 Kuzu/Neo4j**——调研结论：这个量级图数据库没有收益；需要图算法时再 `ATTACH` DuckDB/Parquet 或导出子图。

### 4.2 检索（三路召回 + RRF）
1. **全文**：SQLite FTS5 over `alias.text + node.one_line + 定义首句`；
2. **向量**：`bge-base-zh` / `bge-m3` 对 `one_line + 定义` 做 embedding；
3. **图**：命中节点 1–2 跳邻居。
RRF 融合，权重起步 `1.0 : 1.0 : 0.2`（照 LeanExplore）；可选 LLM rerank。

### 4.3 可回答的问题（验收用）
- 「Borel–Weil–Bott 在哪些书里出现过？各自怎么陈述？」
- 「从『凝聚层』到『Serre 对偶』最短依赖路径是什么？每步证据在哪？」
- 「哪些论文的关键步骤用了『紧性论证』？」
- 「这个概念最早/最完整出现在哪本书？」

**路径解释只输出「边序列 + 每边 evidence_quote」**，不生成散文，避免幻觉。

## 6. 发布

### 6.1 页面
1. **概念页** `/k/<nid>`：定义、别名、出现书目（按 `role` 分组）、依赖边（每条带 quote）、相关论文的关键 step；
2. **论文链页** `/p/<PID>/chain`：问题状态 → move → 步骤 → 收口 → 反事实；
3. **难点清单页** `/p/<PID>/hard`：`score≥3` 的 unit，按分数排序，带 `why_hard` / `check`。

生成方式：从 SQLite/JSON 导出静态 JSON → 复用现有 `site/` 模板（无需新框架）；上线走 `mt_daily.py site`。

### 6.2 许可分层
| 层 | 内容 | 许可 |
|---|---|---|
| 事实层 | nid、边、计数、书目 | CC0 |
| 标注层 | 自己写的 one_line、why_hard、chain、译注 | CC BY 4.0 |
| 上游原文 | 只放链接与 ≤200 字短引用 | 不转发正文 |
| 特殊 | Stacks（GFDL）单独子图；zbMATH 评论（CC-BY-SA）不进 CC BY 库 | 隔离 |

### 6.3 引用与版本
- 每条出现/边记录 `extractor` 与版本；页面显示 `数据快照 <date> / <git tag>`；
- 数据集发布用 Zenodo DOI + RO-Crate/Croissant 元数据（后续）。


每阶段只认一个指标：**新增 accepted 边中，抽检 precision ≥0.9**；不达标不加量。

---

## 8. 三个必须避开的坑

1. **把名字当主键**：`group`/`ring`/`field` 是日常词；必须 `nid + alias + sense`。
2. **边无证据入库**：`generalizes`/`analogous` 是幻觉重灾区；无 `evidence_oid` 只能是 draft。
3. **许可证混装**：nLab 正文、Stacks GFDL、zbMATH 评论 CC-BY-SA 抓进同一个库再整体发 CC BY——必翻车。正文永不落库。
