# 数译知识网络：方案总览（v0.1）

> 目标：把「读论文」从一次性消耗，变成可积累、可检索、可发布的知识资产。
> 三个产物：**难点标注**（哪些步骤不平凡、为什么）、**思考链**（这篇文章的论证是怎么走通的）、**知识网络**（以概念节点而不是论文为载体的图）。
> 本包所有 schema / 示例 / 校验器已可运行；两周试点计划见 `05_两周试点计划.md`。

---

## 0. 一句话结论

**不要重造语料，也不要另起一套系统。** 现有仓库已经有三块半成品——`claims.jsonl`（73 条原子断言）、`通读笔记.md`（已含 70% 论证地图）、`proof_ui` 的 `proofmap.json`（步骤级依赖 + 非平凡标注）——缺的是**统一 schema、机器可读、跨篇概念 ID、以及一个确定性的质量闸门**。把这四件事补上，再用现有 `mt_daily` 发布链把结果推出去，就是最小可行路径。

## 2. 三路调研的关键结论（详见 `research/三路调研摘要与来源.md`）

1. **没有任何现成系统专门做「论文难点/不平凡步骤」标注**。最接近的是依赖图（TheoremGraph、KnowTeX、Paper Graph）、局部 obligation（ProofGap）、角色标注（CrowdMath，最好 macro-F1 仅 0.42）、论证图验证（LLM reviewer 不稳定）。→ **这块自建就是贡献点**，且有现成组件可拼。
2. **难度不能靠 LLM 自评，也不能用图深度代替**（Paper Graph 原文明确警告）。可操作的替代指标：**局部 obligation 补全失败率**——挖掉结论，让模型采样补 k=5~8 次，失败率越高越难；再用人工金标准校准。
3. **概念级知识图谱没有可复用 API**；但 LaTeX 源码里的定义/定理环境就是现成的节点与边。冷启动先规则抽取，LLM 只做归一与跨书合并；每条边必须挂证据，无证据不入库。
4. **发布层可照抄 LeanExplore 的配方**：StatementGroup 聚合 + 按拓扑序翻译/标注 + 三路混合检索（embedding / BM25 / PageRank，权重 1.0:1.0:0.2）。
5. **明确不抄**：自建 prover、端到端自动写论文、用 LLM judge 或图深度当难度裁判。

已核验的三条来源（其余 arXiv 号来自调研返回，引用前请按号复核）：

## 3. 四层数据模型（本方案的核心）

```
L4 概念层  concept   kn_<12hex>   跨论文的知识节点（定义/定理/构造/方法），alias 拆同名异义
              ▲ occurrence（节点在哪些论文的哪个位置出现，带原句）
L3 链条层  chain     一篇论文的思考逻辑链：问题状态 → 关键 move → 步骤序列 → 收口/边界/反事实
              ▲ 由 unit 串成，每个 step 说清 because / enables
L2 推理层  inference  premises → conclusion，带 relation / and_or / warrant / rule / evidence
              ▲ 每条边必须有一条原文 quote + locator
L1 单元层  unit      原子知识单元（定义/定理/证明步骤/断言/问题/方法），带 role + difficulty + 锚点
              ▲
L0 锚点层  locator   (page_orig, para_id) 或 (pdf_page, bbox, char_span, sha256, parser_ver) 或 (tex_file, tex_lines)
```

**为什么是这四层**：现有 `claims.jsonl` 只是 L1；`proofmap.json` 是 L2 的一个特例（只有 uses/proves 边）；`通读笔记` 是 L3 的自然语言版；`catalog.json` 是论文级的 L0。四层一套 ID 打通，才能同时满足「标注难点」「提炼思路」「建概念网络」三个需求。

### 3.1 单元（unit）
字段见 `schemas/unit.schema.json`，关键字段：
- `role`: `spine`（论证主线）/ `key`（关键但可绕）/ `routine`（常规）/ `gap`（原文跳步）/ `background`
- `difficulty`: `score` 1–5 + `dims`（D1 概念 / D2 缺口 / D3 技术 / D4 记号 / D5 迁移 / D6 验证 / D7 承重 / D8 表述）+ `why_hard`（一句话说清卡在哪）+ `check`（怎么自查真的懂了）+ `jump.missing`（原文省掉的步骤）
- `review.status`: proposed / accepted / rejected / needs_review / unresolved

### 3.2 推理（inference）
- `relation`: uses / proves / generalizes / specializes / analogous / contradicts / equivalent / defines
- `and_or`: **AND/OR 必须显式**——两条前提是「合取才够」还是「任一即可」，用二元边表达不了
- `rule`: 操作注册表 SUB / APPLY / EXPAND / COLLECT / COMPONENT / CONSTRUCT / COMPAT / COMBINE / OPAQUE，用来锁死「一步」的粒度
- `warrant`: 为什么这步合法（不是重复结论，而是补上「所以」）
- `evidence`: `{quote, locator}`，quote 必须是原文子串，否则拒收

### 3.3 链条（chain）
- `problem_state`: `known`（已知）/ `blocked`（卡在哪）/ `naive_fails`（笨办法为什么不行）
- `move`: 关键转身（新表示 / 新不变量 / 弱化条件 / 换范畴 / 构造辅助对象）
- `chain[]`: 有序步骤，每步 `because`（为什么这一步现在必须做）+ `enables`（它使能了谁）
- `closure`: 解决了什么 / 没解决什么
- `boundaries`: 假设、失效条件、可推广到哪
- `counterfactual[]`: **抽掉某步，论证哪里断**——这是检验「思考链是否真的抓住」的最硬指标
- `routes[]`: 同一结论的不同证法（A/B 路线）

### 3.4 概念（concept）
- `concept_id = kn_<sha1(kind|msc|normalized_name) 前 12 hex>`；`slug` 可变，**永久链接只认 concept_id**
- `alias` 拆同名异义（group/ring/field 是日常词，MathGloss 实测把 group 映射到消歧页 Q654302）
- `occurrence` 记录「在哪篇论文的哪个环境/标签出现、扮演 defined/stated/proved/mentioned 哪个角色」
- `related` 每条带 `evidence`（unit id 列表），无证据的关系只能是 draft
- 跨书重复定理先合并成**概念页**，再挂各书证法（LeanExplore 的 StatementGroup 思路）

## 4. 难点标注怎么做（详见 `02_精读标注规范.md`）

### 4.1 五级难度标尺（人机共用）
| 分 | 含义 | 判据 |
|---|---|---|
| 1 | 常规 | 定义展开 / 直接引用 / 标准计算，读者不应停 |
| 2 | 轻难点 | 单步非显然选择（换元、选覆盖、选基） |
| 3 | 明显难点 | 需 2–3 步组合或非标准构造，认真读会停一下 |
| 4 | 硬难点 | 论证承重墙，缺这步链断，同行也要想一阵 |
| 5 | 前沿/创新 | 论文核心贡献或长期未解处，审稿人级难点 |

硬规则：`spine/key/gap` 必须 ≥3 且写 `why_hard` + `check`；`gap` 必须写 `jump.missing`；`routine` 不得 >3。

### 4.2 主指标：obligation 补全失败率
1. 取该步结论（不取证明）；
2. 让模型在只给前文定义/定理的条件下补这一步，采样 k=5~8 次（温度 0.7~1.0）；
3. 失败率 ρ = 失败次数 / k；ρ 高 → 难；
4. 人工抽检 10%，与 1–5 分做一致性（目标 Cohen's κ ≥ 0.6）；
5. 记录模型名+版本+日期——**这是模型相对的测量，不是绝对真理**。

这条指标的价值：可复算、可对比、不依赖评审口味。它替代「让 LLM 直接打难度分」这种不可信做法。

### 4.3 标注流水线（一篇论文 30–60 分钟）
```
源码/PDF ──► 结构切片（定理/证明/步骤，带锚点）
          ──► LLM 起草 units + inferences（固定标签集，必须给 quote）
          ──► 确定性校验：JSON schema / 锚点存在 / quote 是原文子串 / 图无环
          ──► 人工只做三件事：改 role、补 why_hard、裁掉没证据的边
          ──► 写 chain.json（问题状态 / move / closure / 反事实）
          ──► 抽 10% 做金标准校准
```
> 确定性 gate 一律在 LLM judge 之前（调研结论④）。校验器：`tools/validate_annotations.py`，当前示例 6 units / 4 inferences / 1 chain / 3 concepts 全 PASS。

## 5. 思考链怎么提炼（详见 `02` 第 5 节）

不要从「文章结构」出发，从**问题状态**出发：

1. 先写 `problem_state`：作者动手前知道什么、卡在哪、笨办法为什么不行。三段写不出，说明还没读懂。
2. 找 `move`：全文只允许一个主 move（新表示/新不变量/弱化条件/换范畴/造辅助对象）。多个 move = 多条链，拆成 routes。
3. 把 move 之后的步骤挂到 unit 上，每步只回答「因为什么，所以现在必须做这一步」。
4. 写 `closure`：哪些被真正证明，哪些只是论证/类比/猜想。
5. 写 `counterfactual`：抽掉最关键一步，指出断点。**写不出反事实，说明链条是事后编的。**
6. 最后才写给人看的 500 字「思路概述」，且必须能由上面五步逐句支撑。

这套流程与现有 `04_playbook/01_数学文献翻译纪律.md` 的「先通读后落笔」完全兼容：通读笔记的「论证地图」升级成 `argument_map.yaml`，散文部分保留。

## 6. 知识网络怎么建（详见 `03_知识节点网络方案.md`）

### 6.1 冷启动（零 LLM，先出图）
1. 扫 91 部书源码，识别 amsthm 环境白名单（theorem/lemma/definition/... + 自定义名）；
2. 抽 `\label`、`\ref`、`\cite`、定理编号；
3. 生成 `nodes` / `occurrences` / `edges`（rule-based，method=rule）；
4. 估算：44k 段中约 15% 是定义/定理 ≈ 6k 节点；每定理 3–8 条 ref ≈ 2–4 万条候选边（候选≠已确立，需 review）。

### 6.2 合并（LLM 只判候选对）
- 候选：名称 + 领域（MSC）+ 定义首句向量 top-k；
- LLM 只回答 merge / add，必须给 quote，否则拒答；
- 三道人工闸：merge 全量审、每类边抽 50 条 precision ≥0.9、跨书冲突仲裁。

### 6.3 存储与检索
- **先 SQLite**（单文件、可版本化、递归 CTE 够用），节点 <10 万不急着上 Kuzu；
- 检索三路召回：alias+定义全文、向量、图 1–2 跳，RRF 融合；
- 路径解释只输出「边序列 + 每边 evidence_quote」。

### 6.4 发布
- 三类页面：**概念页**（kn_id 永久链接）、**论文思考链页**、**难点清单页**；
- 事实层（ID/边/计数）CC0；自有标注 CC BY 4.0；上游原文只存链接与 ≤200 字短引用；
- 复用现有 `site/` 与 `mt_daily.py site`，不另起炉灶。
