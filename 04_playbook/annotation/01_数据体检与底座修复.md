### 2.1 `env` 分布（最大问题）

| env | 段数 | 占比 |
|---|---|---|
| text | 42,041 | 95.25% |
| proof | 964 | 2.18% |
| example | 465 | 1.05% |
| definition | 266 | 0.60% |
| theorem | 212 | 0.48% |
| remark | 175 | 0.40% |
| proposition | 6 | 0.01% |
| corollary | 5 | 0.01% |
| lemma | 4 | 0.01% |

91 部数学书只有 212 段 theorem、4 段 lemma——**不可能是真实分布**。根因已定位到 `01_corpus_zh/_append_pkg.py:120-130` 的 `doc_env()`：

```python
envs = re.findall(r"\\begin\{([A-Za-z*]+)\}", chunk)   # 只认字母/星号，不认数字、下划线、连字符
...
return {"theorem": "theorem", ...}.get(e, "text")      # 只认英文全名；thm/lem/defn 一律 text
```

三个叠加缺陷：
1. **环境名白名单太窄**：`\begin{thm}`、`\begin{lem}`、`\begin{Theorem}`、`\begin{theorem1}` 全部落到 `text`；
2. **粗分类**：proposition / lemma / corollary / conjecture 全部并入 `theorem`，即使命中也无法区分节点类型；
3. **一块只取第一个非结构环境**：定理陈述和证明常在同一 chunk，先遇到 theorem 就返回，后面的 proof 丢失；`proof` 分支基本够不着。

另外 `_build_corpus_v3.py:30-41` 把「环境名表」当排版残渣切掉（这个方向没错），但清洗发生在抽取之后，救不回丢失的 env。

**结论**：不要试图修语料来获得结构。**直接从 LaTeX 源码建独立结构索引**（`\begin{...}` + `\label` + `\ref`），语料只提供中文文本与页锚点。14 部零 `.tex` 的工程再走 PDF 抽取。若将来重跑语料，`doc_env` 必须改成「从导言区 `\newtheorem` 收集环境名 → 允许多个环境 → 保留具体类型」，这是 P1 修复项。
