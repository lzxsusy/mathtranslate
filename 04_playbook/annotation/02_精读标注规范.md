# 精读标注规范（unit / inference / chain）

> 适用：一篇论文或一部书的「论证精读」阶段。目标不是复述内容，而是产出三类可检验的东西——**难点在哪、每步凭什么、整条思路怎么走通**。
> 配套：`schemas/`（字段定义）、`examples/`（真实样例）、`tools/validate_annotations.py`（确定性校验）、`templates/精读标注卡.md`（工作表）。

---

## 0. 产出物与文件布局

每篇论文一个目录，和原文、译文并列，不混进语料：

```
papers/<PID>/
├── annotation/
│   ├── units.jsonl          # L1 原子单元（定义/定理/证明步骤/断言/问题）
│   ├── inferences.jsonl     # L2 推理记录（premises → conclusion）
│   ├── chain.json           # L3 思考链（一篇一条主链，可多 routes）
│   ├── questions.jsonl      # 未解问题（无锚点断言只能进这里）
│   └── meta.json            # 原文 sha256、parser 版本、标注人、模型版本、日期
├── 通读笔记.md               # 人读的散文版（≤1500 字）
└── argument_map.yaml        # 机器读的论证地图（通读阶段产出，见模板）
```

`<PID>` 用现有工程 ID（`WIT-1989-JONES`、`SY07-08`），不要另起一套。

**唯一真源**：`annotation/*.jsonl|json` 是数据；页面、检索、统计都从它生成，不许反向手改生成物。

## 1. L1 单元（unit）

### 1.1 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `unit_id` | ✓ | `<PID>:<kind短名>-<稳定局部名>`，如 `WIT-1989-JONES:claim-c-s3-01`、`SY07-08:thm-2.4.1`。**一旦发布不复用、不改名** |
| `paper_id` | ✓ | 工程 ID |
| `kind` | ✓ | definition / theorem / lemma / proposition / corollary / construction / example / remark / proof / step / claim / question / method |
| `display_no` | | 人读编号（「定理 2.4.1」「(3.4)」「p.372」） |
| `label` | | 原 LaTeX `\label{}` 或印刷编号（`2.4.1`）；没有就留空 |
| `statement` | ✓ | 一句到三句，**自足**：不依赖上下文也能看懂在说什么 |
| `statement_tex` | | 关键公式的 TeX（发布时渲染） |
| `role` | ✓ | `spine` 论证主线 / `key` 关键但可绕 / `routine` 常规 / `gap` 原文跳步 / `background` 背景 |
| `difficulty` | ✓ | 见 §2（`score/dims/why_hard/check` 必填；`reader_trap/unlock/jump/confidence` 可选） |
| `locator` | ✓ | 锚点，见 §1.3 |
| `uses` | | 依赖的 unit/concept id（**只写直接依赖**） |
| `used_by` | | 反向索引，可由脚本生成，手写可空 |
| `concepts` | | 关联的 `kn_` 概念 id |
| `quote` | | 原文短引（≤200 字），发布时只出这一句 |
| `review` | ✓ | `{status, reviewers[], note}` |
| `provenance` | ✓ | `{annotator, source: paper\|reading_note\|translation\|reconstruction\|external\|claim, model, prompt_version, date}` |

### 1.2 好 unit 的判据

- **原子**：删掉它，论证会缺一块；它本身不需要再拆。
- **自足**：不写「由上式可得」，要写「由 (2.3) 的紧性可得」。
- **可定位**：锚点能让人 30 秒内翻到原文那一行。
- **可判难度**：`why_hard` 写的是「卡在哪」，不是「这步很重要」。

### 1.3 锚点（locator）优先级

1. `{tex_file, tex_lines}` —— 有源码时首选，最稳；
2. `{pdf_page, bbox, char_span, source_sha256, parser_version}` —— PDF 抽取时用五元组；
3. `{page_orig, para_id}` —— 语料已有页锚点时用（当前只有 8.25%）。

`meta.json` 必须记录原文 `sha256`；原文换版后，旧锚点标 `unresolved`，不静默复用。

## 2. L1 难度（difficulty）

### 2.1 五级标尺

| 分 | 名称 | 判据 | 典型例子 |
|---|---|---|---|
| 1 | 常规 | 定义展开、直接引用、标准计算 | 把定理条件逐条对一遍 |
| 2 | 轻难点 | 单步非显然选择（换元、选覆盖、选基） | 选一组好基让矩阵对角 |
| 3 | 明显难点 | 需 2–3 步组合或非标准构造，认真读会停 | 造一个辅助对象把两类估计接起来 |
| 4 | 硬难点 | 论证承重墙，缺这步链断，同行也要想一阵 | 关键的紧性/存在性论证 |
| 5 | 前沿/创新 | 论文核心贡献或长期未解处，审稿人级 | 新的不变量/新范畴 |

**硬规则**（校验器强制）：
- `role ∈ {spine, key, gap}` ⇒ `score ≥ 3`，且 `why_hard`、`check` 非空；
- `role = gap` ⇒ `jump.missing` 至少 1 条，写清「原文省了哪一步」；`jump.severity` 取 `small / medium / large`；
- `role = routine` ⇒ `score ≤ 3`；
- `dims` 至少 1 个；`why_hard` ≥ 10 字；`check` ≥ 6 字。

额外的两个可选字段（强烈建议写，发布页最有用）：
- `reader_trap`：读者具体会在哪误读（例：「看到 F_{ij} 就默认 A 是经典场」）；
- `unlock`：补哪段、查哪条、算什么例子能破（例：「先读 p.372 对『不能经典求解』的两条理由」）。

`dims` 取值：
`D1_conceptual` 概念新 / `D2_gap` 跳步 / `D3_technical` 技术重 / `D4_notation` 记号乱 / `D5_transfer` 需迁移其他领域 / `D6_verification` 需验算/核对 / `D7_loadbearing` 承重 / `D8_expository` 表述晦涩。

### 2.2 主指标：obligation 补全失败率（替代 LLM 自评）

1. **只给**该步之前的定义/定理 + 该步的结论，**不给**证明；
2. 采样 k = 5~8 次，temperature 0.7–1.0；
3. 用固定判分器判「补出来的证明是否成立/等价」（判分器可以是另一模型 + 规则，必须记录版本）；
4. `ρ = 失败次数 / k`；
5. 映射：ρ<0.2→1，0.2–0.4→2，0.4–0.6→3，0.6–0.8→4，>0.8→5（**待金标准校准，不写死**）。

**必须记录**：模型名+版本、日期、prompt 模板、判分器。这是「模型相对的测量」，不是绝对难度；换模型要重测关键样本。

### 2.3 人工校准

- 抽 20–30 个单元做金标准（两人独立打分，分歧先讨论再定）；
- 与模型分算 Cohen's κ，**目标 ≥0.6**；
- κ<0.4 ⇒ 标尺或样本有问题，停下来重写判据，不要扩量。

### 2.4 `check` 怎么写

写「读完怎么自证懂了」，不是「很重要」：
- 好：「合上原文，能否用一句话说出为什么这里必须取紧支撑，而不是 $C_c^\infty$？」
- 差：「这是关键步骤。」

## 3. L2 推理（inference）

### 3.1 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `inference_id` | ✓ | `<PID>:inf-<3位序号>` |
| `paper_id` | ✓ | |
| `premises` | ✓ | unit/concept id 列表，至少 1 条 |
| `conclusion` | ✓ | unit/concept id |
| `relation` | ✓ | uses / proves / generalizes / specializes / analogous / contradicts / equivalent / defines |
| `and_or` | ✓ | `and`（前提需合取）/ `or`（任一即可）/ `single` |
| `warrant` | ✓ | 8–120 字：**为什么**这些前提足以推出结论（补「所以」，不复述结论） |
| `rule` | ✓ | 操作类型，见 §3.2 |
| `evidence` | ✓ | `{quote, locator}`；quote 必须是原文子串，10–300 字 |
| `confidence` | | high / medium / low |
| `review` | ✓ | proposed / accepted / rejected / needs_review / unresolved |
| `provenance` | | 标注人、模型、日期 |

**无 evidence 的边不入库**：LLM 抽取 `generalizes` / `analogous` 幻觉率最高；没有原句支撑的关系只能是 draft，前端默认不显示。

### 3.2 操作注册表（锁「一步」的粒度）

| rule | 含义 | 例子 |
|---|---|---|
| SUB | 代入/展开定义 | 把 $f$ 的定义代进积分 |
| APPLY | 直接引用已有定理 | 用 Cauchy–Schwarz |
| EXPAND | 展开成更细的项 | 把行列式按行展开 |
| COLLECT | 汇总/合并若干情形 | 分三种情况讨论后合并估计 |
| COMPONENT | 取一个组成部分/特例 | 只看紧支撑部分 |
| CONSTRUCT | 造辅助对象 | 造截断函数、造逼近序列 |
| COMPAT | 验证相容/交换/自然性 | 验证图交换 |
| COMBINE | 两条独立论证合取 | 两条理由都成立才够 |
| OPAQUE | 原文这一步确实没展开（跳步） | 「It is easy to see that…」 |

**粒度规则**：一步 = 一个操作。需要两个操作才能说清，就拆成两个 unit；`OPAQUE` 只用于原文确实跳过、且你标为 `gap` 的地方。

### 3.3 AND/OR 为什么必须显式

二元边表达不了「两条前提**合取**才够」：抽掉任一条，结论都不成立；而 `or` 边抽掉一条仍成立。评审时这两种情况的处置完全不同。

### 3.4 warrant 反例

- ✗「由定理 2.3 可得。」——没说什么前提下、为什么适用；
- ✗ 重复 conclusion；
- ✓「由 (2.3) 的紧性，序列有收敛子列；再用下半连续性，极限点仍满足约束。」

## 4. L3 思考链（chain）

### 4.1 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `paper_id` / `chain_id` | ✓ | 一篇一条主链；副链加 `-alt1` |
| `thread` | ✓ | 一句话：这篇文章要回答的问题 |
| `problem_state` | ✓ | `{known[], blocked, naive_fails}`：动手前知道什么、卡在哪、笨办法为什么不行 |
| `move` | ✓ | `{unit_id, type, statement}`：全文**一个**主 move；类型如 new_representation / new_invariant / weaken_hypothesis / change_category / auxiliary_object |
| `chain[]` | ✓ | 有序步骤 `{seq, unit_id, because, enables[]}`；seq 从 1 连续 |
| `closure` | ✓ | `{unit_id, what_it_settles, what_it_leaves}`：分清「证明了/只是论证/仍是猜想」 |
| `boundaries` | | `{hypotheses[], fails_when, generalizes_to[]}` |
| `counterfactual[]` | ✓ | `{remove: unit_id, breaks[]}`，至少 1 条 |
| `routes[]` | | 不同证法：`{name, note, chain[]}` |

### 4.2 反事实检验（最硬的一条）

对最关键的一步问：**抽掉它，论证从哪里断？** 写不出具体断点（哪条结论失去依据、哪个估计失效），说明这条链是事后按章节顺序编的，不是作者真实的思路。

例子（WIT）：
- remove `claim-c-s3-01`（(3.4) 是算符约束，不是经典方程）⇒ 「不能经典求解」的两条理由失去对象，第③④步的合法性无从判断。

### 4.3 写链的顺序

1. `problem_state`（写不出三段，说明没读懂）；
2. `move`（只允许一个主 move；多了就拆 routes）；
3. `chain`（每步只回答「因为什么，所以现在必须做」）；
4. `closure`（区分证明/论证/猜想）；
5. `counterfactual`；
6. 最后才写给人看的 500 字概述。

## 5. 标注流程（一篇 30–60 分钟）

| 步 | 动作 | 人/机 | 产出 |
|---|---|---|---|
| 0 | 结构切片：按 `\begin{...}` 切定理/证明/步骤，带锚点 | 脚本 | `slices.jsonl` |
| 1 | 起草 units（只填能自足的；拿不准标 `needs_review`） | LLM | `units.jsonl` draft |
| 2 | 起草 inferences（固定标签集，每条必须 quote） | LLM | `inferences.jsonl` draft |
| 3 | 人工三件事：改 `role`、补 `why_hard`/`check`、删无证据边 | 人 | 定稿 |
| 4 | 写 chain（先 problem_state 和 counterfactual） | 人+LLM | `chain.json` |
| 5 | 跑校验器；不过就改，不许绕过 | 脚本 | PASS |
| 6 | 抽 10% 算 obligation 失败率，记校准表 | 脚本+人 | `calibration.csv` |
| 7 | 写 `通读笔记.md` 的「三条提醒」与 `argument_map.yaml` | 人 | 发布素材 |

### 分工
- **标注员**：LLM 起草 + 人定稿（同一人不能既标注又终审）；
- **审校员**：另一个人或另一个模型，只审「边是否有证据、warrant 是否成立」；
- **验收员**：跑闸门 + 抽检，签字。

## 6. 闸门 G2.5（插在「通读完成」与「开译/开研讨」之间）

必须全部满足才放行：

1. `validate_annotations.py <paper_dir> --strict` 返回 0；
2. **覆盖**：原文中 theorem/lemma/proposition/definition/proof 环境的 ≥60% 有对应 unit；每 10 页至少 5 个 unit；
3. **推理**：≥3 条 `accepted` 的 inference，每条有 `evidence.quote` 且能在原文找到（子串匹配，归一化空白）；
4. **链条**：`chain.json` 通过校验，含 ≥1 条 `counterfactual`；`closure` 明确区分「已证明/仅论证/仍猜想」；
5. **难度**：至少 1 个 unit `score≥3`；`score=3` 不超过总数 50%（防止「全打 3 分」）；
6. **人审**：审校员抽 10 条（含所有 `score≥4`）签字；未签字不得开译。

未过闸的常见原因：全是被动句转写、没有 warrant、锚点指向整节而不是那一步。

## 7. 反例（会被退回）

1. 只有 `statement`，没有 `why_hard` 和 `check`；
2. 每条边都 `confidence: high`，但 quote 是整段复制；
3. `warrant` 只是把 conclusion 换个说法；
4. 通篇 `score=3`；
5. `chain` 按论文章节顺序写「第一节…第二节…」；
6. `counterfactual` 写「抽掉它文章就不完整了」；
7. 把 LLM 自评的难度当最终分，不做校准；
8. 把「引理依赖图」当「论证结构图」（丢动机、类比、反例）；
9. 跨书合并概念过早（还没金标准就铺量）；
10. 发布时贴整节原文或整页 PDF。

## 8. 从 claims.jsonl 迁移

现有 73 条 claims 不废弃，做无损升级：

| claims 字段 | 迁移到 |
|---|---|
| `id`（如 `c-s3-01`） | `unit_id` 保留为 `<PID>:claim-c-s3-01`，旧链接不断 |
| `claim` | `statement` |
| `type` | `kind`：definition→definition，evidence→claim，interpretation→claim，conjecture→claim，open→question（同时进 questions.jsonl） |
| `anchors` | `locator`（逗号分隔的多个锚点保留在 `legacy_anchors`） |
| `source` / `confidence` / `status` | `provenance.source` / `provenance.confidence` / `review.status` |
| `counterpoints` | 新增 `counterpoints[]` 字段，原样保留 |
| 无 | 新增 `role`、`difficulty`、`premises`（由 inference 补） |

迁移脚本建议放在 `tools/migrate_claims_v2.py`，先 dry-run 出 diff，人工确认后写回。
