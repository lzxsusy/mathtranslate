# 译中检索与冲突上报（v1.0 · 2026-11-23）

> **这份文件解决一个问题：旧译不是真理，是「待验的假设」。**
> 我们已经在 `08_source_code/` 里堆了 130 个工程、1,820 条术语、49,322 段语料。
> 如果这些资产只能被引用、不能被质疑，它们就会变成负债：错误被后来的译文一次次复制，越堆越深。
> 所以从今天起，**译任何一篇之前先检索本库，检索到冲突必须上报，上报之后必须闭环**。
>
> 与任务书、旧习惯冲突时，以本文件与 [`01_数学文献翻译纪律.md`](01_数学文献翻译纪律.md) 为准。
> 本文件是《纪律》§2.5（术语来源）与 [`17_仓库理念与上传规范.md`](17_仓库理念与上传规范.md) §2（五层资产）的**执行细则**：
> 《纪律》规定"术语必须有据"，《理念》规定"上层只能引用下层登记项"，本文件规定**这套登记项怎么被检索、被质疑、被修好**。

---

## §1 三条主张

| 编号 | 主张 | 一句话理由 |
|---|---|---|
| P1 | **先检索，后落笔** | 同一个术语在库里已有唯一译名时，自造第二个译名就是制造分裂；分裂的成本由后来所有读者承担 |
| P2 | **冲突不是错误，未上报的冲突才是** | 发现两处不一致却只在心里记一笔，等于让下一个人从零再发现一遍 |
| P3 | **上报要可复现，纠正要留痕** | 一条上报必须带「查询串 + 命中条目 + 原文页码」，否则无法复核；一次纠正必须留「谁改、改哪、依据什么」 |

配套一条免责：**本文件不要求你证明旧译是错的才上报**。只要你的检索结果与旧译不一致，就可以上报，由裁定人判定是旧译错、你的译法错，还是两者都可用（需要区分语境）。

## §2 检索协议（译前必做，五步）

顺序固定：**术语表 → 术语基 → 卡片 → 译文语料 → 原文页**。前一步命中就停下用它，只有全部不命中才允许新造译名（并在本工程术语表登记）。

### 第 1 步：统一术语表（最高优先级）

```bash
cd /path/to/gitee_shuyi
grep -i -P "\t<英文术语>\t" 01_corpus_zh/数语规范/TERMS.tsv        # 精确匹配外文列
grep -i "<英文术语>" 01_corpus_zh/数语规范/TERMS.tsv               # 宽松匹配（含子串）
grep -i "<英文术语>" 01_corpus_zh/数语规范/CONFLICTS.tsv           # 该词是否已被机器判为冲突
```

判读：

- 命中且 `等级` 为 **A/B 且状态 frozen** → 直接采用，不允许改。
- 命中但 `等级` 为 **C/D（candidate）** → 可以用，但必须在译注或术语表里标「本库既有候选译名」，且不得据此判旧译错。
- 命中两条以上不同中文 → 这是 **C1 冲突**（见 §3），先上报，再按裁定结果动笔。
- 未命中 → 进入第 2 步；若第 2 步也不命中，则这是 **C2 冲突（术语缺失）**，登记后新造。

### 第 2 步：术语基（termbase，带工程与语种）

`TERMS.tsv` 是人读的合并表，`termbase.jsonl` 是机器读的源表（含 `pkg` 与 `lang`）：

```bash
python - <<'PY'
import json, sys
q = "<英文术语>".lower()
for line in open("01_corpus_zh/termbase.jsonl", encoding="utf-8"):
    d = json.loads(line)
    if q in d["foreign"].lower() or q in d["zh"]:
        print(d["pkg"], d["status"], d["foreign"], "→", d["zh"])
PY
```

判读：出现两个 `pkg` 译法不同 = C1；只在 `candidate` 里出现 = 未定案，可参与裁定但不能当依据。

### 第 3 步：资料卡（概念/定理/推导，带页码与引文）

本机插件 `kb_*`（数据源就是本仓库打包后的卡片与语料）：

- `kb_search(query="perfectoid", layer="cards")` —— 查概念卡的定义与出处；
- `kb_card(id="sy29/concept/perfectoid-space")` —— 读整张卡（含 `sources.pages` 与逐字英文引文）；
- `kb_stats()` —— 确认卡片库规模与可信度分布（当前 2,782 张，checked/verified 为主）。

判读：卡片里写的译名与页码，是**可直接进译注的 I 级依据**（《纪律》§2.5 的 I 级：本库既有译注/术语表/卡片）。若卡片与术语表打架，以术语表为准，并把卡片记为 C1 冲突的受影响对象。

### 第 4 步：译文语料（别人怎么译的）

```bash
python - <<'PY'
import json
q = "<中文或英文关键词>"
for line in open("01_corpus_zh/zh_paragraphs.jsonl", encoding="utf-8"):
    d = json.loads(line)
    if q in d.get("text", ""):
        print(d["pkg"], d.get("page_orig"), d["text"][:120].replace("\n", " "))
PY
```

或 `kb_search(query="...", layer="zh")`（按段落返回，带 `pkg` 与段号）。判读：同一术语在不同工程出现两种中文 = C1；同一工程内出现两种 = **C4 内部不一致**（优先修自己那本）。

### 第 5 步：原文页（最后一道，也是最硬的一道）

```bash
kb_source(pkg="SY02-29", page=3)        # 或 kb_search(query="...", layer="source")
```

判读：**旧译是否正确，只能回到原文页判**。语料层与卡片层都只是二手证据。凡是要判「旧译错」，必须在这一步拿到原文句子（英文/日文/法文原句）并抄进台账 `evidence` 列。

## §3 冲突分类（六类）与默认处置

| 类 | 名称 | 判据（怎么认出来） | 默认处置 | 例子（真实，均来自本仓） |
|---|---|---|---|---|
| C1 | 一外多中 | 同一外文术语在本库有两种以上中文，且都在 frozen/confirmed | 上报 → 裁定 → 改术语表（一次改动，三同步） | `stack`：T1094「栈」 vs T0052「代数叠」/T0720「模叠」 |
| C2 | 术语缺失 | 术语表与 termbase 都没有，但全库已有多个工程在用不同译法 | 上报 → 先补术语条目，再改译文 | `isocrystal`：SY02-05 作「同晶」，SY02-29 作「等晶体」，术语表无条目 |
| C3 | 译稿与冻结表不符 | 术语表有冻结译名，本工程用了另一个 | 直接改本工程（这是错，不是冲突），并在 `reports/` 记一笔 | `admissible`：表定「可容许」，SY02-29 混用「容许」4 处 |
| C4 | 同一工程内部不一致 | 同一文件/同一书内两种写法 | 直接改（按冻结表或按本工程已定为准），无需上报裁定 | `torsor`：SY02-29 内「torsor」25 处 +「挠子」7 处 +「扭子」5 处 |
| C5 | 旧译疑似误译 | 旧译的**数学内容**与原文不符（不只是用词） | 上报（P0）→ 找原文页 → 找第二处独立证据 → 裁定 → 改旧译并写 `reports/` | 待补：需真实案例，见 §6.4 的构造方法 |
| C6 | 出处缺失/不可核 | 卡片或译注的引文在原文页搜不到、页码对不上 | 上报（P3）→ 修卡片 → 通知该卡所属工程 | `verify_quotes.py` 报「搜不到」即属此类 |

处置矩阵（谁动、动哪里）：

| 类 | 谁可以裁 | 允许直接改的文件 | 禁止 |
|---|---|---|---|
| C1 | Lead / 仓主 | `termbase.jsonl` → 重跑 `build_norm.py`；译文按需 | 不改他人工程正文而不通知 |
| C2 | Lead | `termbase.jsonl` + 本工程 `glossary.tsv` | 不新增无依据译名 |
| C3/C4 | 任何译者 | **只改自己工程** | 不跨工程"顺手统一" |
| C5 | 仓主（Lead 可初裁） | 旧译工程正文 + `reports/` | 不静默改数学；必须留 diff 说明 |
| C6 | 任何译者 | 卡片 JSON + 引文 | 不改原文字段以外的内容 |

## §4 上报与闭环（五步）

```
① 复核   ② 登记   ③ 定级   ④ 裁定   ⑤ 执行 + 关单
```

### ① 复核：先证明不是自己看错

三条最低要求：回到原文页看过（§2 第 5 步）；至少查两个层（术语表 + 卡片，或术语表 + 语料）；记录**查询串原文**（日后要能复跑）。

### ② 登记：写进台账（一条一行）

```bash
python tools/conflict_report.py add \
  --kind C1 --severity P1 \
  --target "T1094 stack" \
  --claim "术语表把 stack 定为「栈」，但 T0052 algebraic stack=代数叠、T0720 moduli stack=模叠，同一词根两种译法" \
  --query "grep -i stack 01_corpus_zh/数语规范/TERMS.tsv" \
  --hits "T1094 栈（B,frozen,SY02-09）｜T0052 代数叠｜T0720 模叠" \
  --reporter "lead" \
  --source "SY02-29 全文用「叠」49 处，与 T1094 相反"
```

登记即产生状态 `open`，并立刻出现在 `_meta/冲突台账.md`（由工具生成，不手改）。

### ③ 定级

| 级别 | 含义 | 处理时限（自律） |
|---|---|---|
| P0 | 数学内容错误（公式、定理陈述、证明方向错） | 当轮必须处理，不许带着 P0 交付 |
| P1 | 术语分裂（同一概念两种译名，会影响检索与对齐） | 当轮处理，或写明为什么延后 |
| P2 | 体例漂移（空格、连字符、大小写、等级不一致） | 可批量处理 |
| P3 | 出处缺失（卡片/译注引文不可核） | 可延后，但不得进入对齐卡 |

### ④ 裁定：写结论与依据

```bash
python tools/conflict_report.py close --id CF-2026-11-23-01 --status accepted \
  --resolution "以「叠」为准：T0052/T0720 已是「叠」，且几何 Langlands 中文文献普遍作「叠」；T1094 改「叠」，代数栈/模叠不动" \
  --resolver "lead" --evidence "TERMS.tsv 三行 + 02_trajectories 用例"
```

`--status` 三选：`accepted`（按上报者的判断改）、`rejected`（不改，写清理由）、`deferred`（挂起，写清卡在哪）。

### ⑤ 执行 + 关单：改完再关

改完必须跑对应闸门（§5），把命令与结果追加到该行的 `note` 列，最后 `--status fixed`。**没有执行就不要关单**——关单是"改完了"的声明，不是"想通了"的声明。

工具会拦三种情况：`fixed` 却没有 `note`；`accepted/rejected` 却没有 `resolution`；`target` 指向的文件在仓库里不存在。

## §5 台账与工具

### 5.1 台账

`_meta/冲突台账.tsv`（UTF-8，TAB 分隔，一行一冲突），字段：

| 列 | 含义 |
|---|---|
| `id` | `CF-YYYY-MM-DD-NN`，工具自增 |
| `date` | 登记日期 |
| `reporter` | 谁发现（人/智能体名） |
| `kind` | C1–C6 |
| `severity` | P0–P3 |
| `target` | 冲突对象：术语 ID（`T1094 stack`）、文件:行、卡片 id |
| `claim` | 一句话说清「哪里不对、为什么」 |
| `query` | 可复跑的查询串 |
| `hits` | 命中的条目/页码/引文摘要 |
| `source` | 支持判断的原文页或第三处证据 |
| `status` | `open` / `accepted` / `rejected` / `deferred` / `fixed` |
| `resolution` | 裁定结论（一句话，含取舍理由） |
| `resolver` | 裁定人 |
| `resolved` | 裁定/关单日期 |
| `note` | 执行记录：改了哪些文件、跑了什么闸门、结果 |

`_meta/冲突台账.md` 是它的渲染版（`python tools/conflict_report.py md --write`，直接以 UTF-8 写盘——**不要用 shell 重定向**，Windows 控制台默认 GBK 会写坏中文），给不开终端的人看；`check` 会比对两者，防止手改 md。

### 5.2 工具

```bash
python tools/conflict_report.py add --kind C3 --target "SY02-29 源码/sections/s10" ...   # 登记
python tools/conflict_report.py list --status open                 # 待办
python tools/conflict_report.py list --severity P0 --status open   # 交付前必清零
python tools/conflict_report.py show --id CF-2026-11-23-01         # 看一条全文
python tools/conflict_report.py close --id ... --status fixed --note "sed 改 4 处，latexmk 0 error"
python tools/conflict_report.py check                              # 闸门：字段合法 + md 同步 + 交付前 P0=0
python tools/conflict_report.py md --write                         # 重新渲染（UTF-8 写盘）
```

`check` 的退出码：0 = 通过；1 = 字段不合法、md 不同步，或（加 `--delivery` 时）有 P0 未闭环。
平时提交前跑 `check`；交付前跑 `check --delivery`，与 `check_compliance.py` 同批。

## §6 三件套：反例 → 正例 → 检查方法

> 《纪律》§12 要求新增纪律必须给出三件。以下五组全部来自本轮真实工作（SY02-29 与全库盘点），不是假设。

### 6.1 「stack = 栈」

- **反例**：术语表 T1094 把 `stack` 定为「栈」，而 T0052 `algebraic stack` 是「代数叠」、T0720 `moduli stack` 是「模叠」。同一个 morpheme 在合成词里叫「叠」，在单词里叫「栈」——检索「叠」查不到 stack，检索「栈」查不到代数叠。
- **正例**：T1094 改「叠」，T0052/T0720 不动；术语表加注「栈」为退役译法；`build_norm.py` 重生成四表后 `--check` 通过。
- **检查方法**：`grep -i "stack" 01_corpus_zh/数语规范/TERMS.tsv`，看是否出现两条中文；再看 `CONFLICTS.tsv` 有没有把这条机器判出来（本例没有，因为「栈」与「叠」不是同一外文键——**机器判不出，只能靠人检索**，这正是本文件存在的理由）。

### 6.2 「isocrystal」没有条目

- **反例**：`grep -i isocrystal 01_corpus_zh/数语规范/TERMS.tsv` 无结果；但 SY02-05 译作「同晶」，SY02-29 译作「等晶体」23 处，两本书互相检索不到。
- **正例**：补术语条目 `isocrystal / 等晶体`（依据：SY02-29 全篇一致 + Fargues–Fontaine 语境），`note` 记「SY02-05 旧译同晶，待该工程重版时统一」；同时给 SY02-05 登记一条 C2。

### 6.3 「admissible = 可容许」被写成「容许」

- **反例**：术语表 T0036 `admissible` = 可容许（A, frozen），SY02-29 正文 4 处写成「容许」（s10 3 处、s11 1 处）——冻结表没被遵守，且「容许表示」在中文数学里另有含义（与 admissible 的「可容许」不同）。
- **正例**：改回「可容许」4 处，`xelatex` 复编译，`reports/r-*.md` 记一处；不登记裁定（C3 是错，不是分歧）。
- **检查方法**：`grep -c "容许" 源码/sections/*.tex` 与 `grep -c "可容许"` 对照；本库已经在 `check_numbers.py` 之外没有术语闸门，所以**每次交付前手动跑这一对 grep** 是硬要求。

### 6.4 「旧译数学上可能错」怎么抓（C5 的构造方法）

- **反例（本轮的近例）**：SY02-29 底本 p.15 印 `φ(Π⁺(ξ)) = (ξ/π)·Π⁺(ξ)`，而按同页定义 `Π⁺ = ∏_{n≥0} φⁿ(ξ)/π` 直接算得 `(π/ξ)·Π⁺`，两者互为倒数。**同一个作者、同一页、定义与函数方程打架**——这就是可上报的 C5 候选（存疑，未定案）。
- **正例**：登记 P0/C5，`query` 写「按定义展开 Π⁺ 后计算 φ(Π⁺)」，`hits` 抄两处原文（定义行、函数方程行），`source` 指 p.15 页面图像；状态 `deferred`（等第三方文献核 [10]），在译文里照排原文 + 译注说明，**绝不擅改数学**。
- **检查方法**：凡是「定义 + 断言」写在两处的，翻译时都要把定义代进去算一遍（[`16_译中验算与原文缺陷发现.md`](16_译中验算与原文缺陷发现.md) 的做法）；算不通就登记，算通了也要在 `trace-*.md` 留一行「已复算」。

### 6.5 「torsor」在同一本里三写

- **反例**：SY02-29 内 `torsor` 25 处、`挠子` 7 处、`扭子` 5 处，同一概念三种写法，读者会以为是三个东西。
- **正例**：统一保留英文 `torsor`（术语表 T1190 是 candidate，未冻结，不强制中文），首次出现处用「torsor（主齐性空间）」；`glossary.tsv` 加一行说明。
- **检查方法**：`grep -o "挠子\|扭子\|torsor" 源码/sections/*.tex | sort | uniq -c`；交付前三种写法必须收敛到一种（或二种，且第二种是首现括注）。

## §7 权限与边界

1. **只改自己工程**（《纪律》§4 铁律 1）。跨工程改动必须由 Lead 在本台账立一条 C1/C5 并写清影响面。
2. **改旧译数学**（C5）是三件事一起做：改正文 + 写 `reports/` 说明 + 在本台账关单。少一件都不算完成。
3. **不重构风格**。发现旧译「能读但不好读」，不属本文件范围：那是校订工程（见 [`07_整书对照校订流水线.md`](07_整书对照校订流水线.md)），不是冲突。
4. **裁定权**：C1/C2 由 Lead 裁定、仓主可否决；C5 由仓主裁定（Lead 可初裁并在 `resolver` 里标「初裁」）；C3/C4/C6 由发现者自行处理。
5. **一条冲突一个 id**。同一术语在不同工程各有一条 → 各登记一条，在 `note` 里互相引用，不要合并（合并会丢掉工程维度）。

## §9 维护

- 版本记在文件头；旧版留在 git 历史里，不另存副本。
- 新增一条规则，按《纪律》§12 补「反例 → 正例 → 检查方法」三件，并在 `04_playbook/README.md` 的必读顺序表里挂一行。
- 台账只增不删；作废的条目把 `status` 改成 `rejected` 并写理由，不删除行（删除会丢历史）。
- 每完成一部书，Lead 跑一次 `conflict_report.py list --status open`，把属于该书且已修的条目关掉；交付报告里带一句「本轮关单 N 条、新开 M 条」。
