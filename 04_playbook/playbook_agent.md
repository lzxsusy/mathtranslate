# 数译工程：agent 协作工作流与迭代经验

这份文档是**做这些译本时用的方法本身**——不是成品的一部分，而是「怎么把 300 页外文数学文献变成可出版的中文译注本」的可复现流程，
以及踩过的坑。目标读者是下一个接手的人（或下一个 agent）。

---

## 0. 一句话总结

> 拆块翻译 → 逐块机器自检 + 图页目视核对 → 术语表先行且锁定 → 章节级 QA 报告 → 合稿编译 → 交叉校对记录。
> 关键不在于「翻得懂」，而在于**每一页都能追溯、每一处公式都能回原页图画核对、每一个术语全库只有一个译法**。

## 1. 流水线（八步 → 实际目录）

| 步 | 动作 | 产物（包内位置） |
|---|---|---|
| 1 | 立项：编号 SYxx-yy、登记书目元数据 | `投稿信息.md` |
| 2 | 建工程骨架：preamble/构建脚本/风格指南 | `源码/main.tex`、`源码/preamble.tex`、`工程文件/build.ps1`、`工程文件/STYLE_GUIDE.md` |
| 3 | 写 BRIEF：本次翻译的目标、读者、禁区、体例 | `工程文件/BRIEF.md` |
| 4 | 分块翻译：按章/按节落 `chunks/*.tex` | `源码/chunks/`（或 `sections/`、`pages/`） |
| 5 | 逐块自检：术语一致、公式回图核对、译注分离 | `工程文件/reports/chNN.md`、`工程文件/work/` |
| 6 | 图与公式专项审计 | `工程文件/reports/figure_audit.md` |
| 7 | 合稿 + 编译 + 页数/目录校验 | `成品/*.pdf`、`工程文件/reports/final_pass.md` |
| 8 | 交付包：说明、清单、工程总结、术语表 | `工程文件/deliverable/` |

## 2. 十条硬规矩（都是从返工里换来的）

1. **公式只信页面图像，不信文字层。** OCR/文字层里 `\mathcal`、上下标、希腊字母经常全错；排版类错误（分式错位、`\sum` 上下限）在文字层里看不出来。
   做法：原 PDF 以 **150–200 dpi** 渲染成 PNG，逐符号目视核对；文字层只用来定位「这句在哪个文件、第几段」。
2. **术语表先定后译，且逐条反查。** 术语一旦进了 `术语表` 就是硬约束；后续章节出现新译法必须回改全局，不允许两种译法并存。
3. **译注分离。** 正文只放译文；译者的补白、出处、异文一律进 `译注`（脚注或每章末的「译注」节），否则读者分不清哪句是原作者说的。
4. **每块一报告。** `reports/chNN.md` 里写：本块完成度、存疑处（术语/公式/语义）、与前一章的衔接、下一块的前置提醒。这是给「未来的自己」看的台账。
5. **页数对账。** 译稿页数必须与原书页数一致（或逐页标注「合并/拆分」），否则目录与索引全错位。
6. **中文标点、英文术语留原文。** 首次出现给「中文（English, 缩写）」，之后统一用中文或缩写；不允许中英混排时乱加空格。
7. **公式环境统一。** 全书只用一套：`equation` + `align`，禁止 `eqnarray`；自定义宏集中在 `preamble.tex`。
8. **图不放文字里。** 图必须 `\includegraphics` 引用 `figures/` 下的独立文件，便于替换与审计。
9. **不做「意译式压缩」。** 数学文本省略一句，后面证明就断链；宁可长。
10. **每次改动可回滚。** `工程文件/work/` 保留中间稿；最终交付以 `成品/` 的 PDF 为准。

## 3. 目录约定（本仓库统一）

```
translations/SYxx-yy/
├── 投稿信息.md              元数据：原书信息 / 译者 / 版本 / 术语索引 / 分类
├── 工程文件/
│   ├── BRIEF.md             本次工程的目标与边界
│   ├── STYLE_GUIDE.md       体例：术语、标点、公式、译注、图表
│   ├── build.ps1            一键构建
│   ├── check.py / gen_notes.py / pack.py   自检与打包脚本
│   ├── reports/             分块 QA 报告（chNN.md、figure_audit.md、final_pass.md）
│   ├── work/                中间稿、逐页文本提取（p001.txt…）
│   └── deliverable/         交付清单、工程总结、术语表、译注汇总、阅读参考指南
├── 源码/                    main.tex + preamble.tex + chunks/*.tex + figures/*
└── 成品/                    *_中文译注本.pdf
```

## 4. 脚本清单（可复用）

| 脚本 | 作用 |
|---|---|
| `build.ps1` | xelatex 多趟编译 + 缺失字体/宏检测 |
| `check.py` | 术语一致性、中英标点混用、未翻译英文残留、交叉引用完整性 |
| `gen_notes.py` | 从译文里抽取 `\zhnote{}` 生成「译注汇总.md」 |
| `pack.py` | 按交付规范打包（PDF + 源码 + 说明 + 术语表） |
| `crop.py` | 按坐标裁原 PDF 页面成图，核对公式 |
| `lint.py` / `qa_all.py` | 批量跑 check + 统计页数与残留 |

## 5. 我（agent）这一轮的迭代经验

### 5.1 翻译质量相关

- **术语漂移是最大的隐性返工源。** 同一篇里 `Hecke eigensheaf` 前后译成「本征层/特征层」两版，肉眼极难发现，但 `check.py` 一跑就出来了 → 所以术语表必须在第 2 步就锁定，而不是最后补。
- **公式的「看起来对了」是陷阱。** 文字层的 `\alpha` 与 `a`、`\nu` 与 `v`、`k` 与 `\kappa` 几乎不可分辨；必须回图。
- **译注的价值在「为什么这样译」。** 只写「此处依 X 版」没有信息量；要写「日文原文省略主语，依上下文补为 X，见 p.37 第 2 段」。
- **日/法/俄三语各有雷区。** 日语：敬体与数学陈述要分离；法语：`le`/`la` 冠词化术语要统一；俄语：复合名词格变化不能逐词直译。

### 5.2 工程质量相关

- **页数统计必须来自 PDF 实际页数，不能靠文件数或章节数。** 早期用「ch 文件数 × 估算」统计，误差 20%+。
- **PowerShell 没有 heredoc**，多行脚本必须先落 `.py` 文件再执行；`Set-Content` 默认编码会把 UTF-8 中文注释写成 GBK 乱码（会毁掉脚本）。写文件用真正的 UTF-8。
- **Python 字符串里的 Windows 路径**：`"D:\x"` 会触发 `SyntaxError: (unicode error) 'unicodeescape'`，写 docstring 一律用 `r"""..."""`。
- **文件名是中文时**，终端输出容易乱码；判断内容用 `read` 工具/UTF-8 读取，不要靠 `Get-Content` 眼判。
- **大工程要分块 + 目录分治**：单文件超过 ~2000 行后，任何 agent 的修改都容易撞上下文上限；按章落 `chunks/` 是必要的。

## 6. 已知缺口（下一步该做的）

1. **术语索引覆盖率只有 16/83。** 数译投稿要求第 4 项元数据就是「术语索引（中/英/首次出现页码）」；需要补 69 部的术语表，并从 `.tex` 自动抽取「首次出现页码」（`\label`/`\pageref` 已在源里）。
2. **平行语料未成体系。** 原文 PDF 文字层 + 中文译文按段对齐 → 术语对照/句对，可用于术语一致性和译文质量评测（见 `corpus/`）。
3. **跨库术语合并。** 16 个术语表格式各异（csv/md/tex/json），需要统一到 `terms/terms.tsv`（中/外/学科/首次出现/出处）。
4. **DOI 与版本。** 每部应有 Zenodo DOI 与语义化版本号（v1.0.0 / 修订日期）。
