## 0. 一句话

**一张卡 = 一个自足的数学单元 + 一条可核的出处 + 一套可形式化的记号。**

三者缺一，卡就只是笔记，不能进数据集，更不能当形式化的起点。

本规范的优先级：**数学正确 > 出处可核 > 记号自洽 > 可形式化 > 文风**。前两项任一不合格，卡不得标 `reviewed` / `published`。

## 1. 适用范围与文件布局

### 1.1 什么算资料卡

`datasets/<set>/cards/` 下的每一个 JSON（`index.json`、`work.json` 除外）。卡的 `type` 决定它放在哪个子目录：

| `type` | 子目录 | 典型内容 | 现有数量（2026-11-27） |
|---|---|---|---|
| `concept` | `cards/concepts/` | 定义、定理、构造、猜想 | 1,373 |
| `derivation` | `cards/derivations/` | 一段证明/推导的拆步 | 199 |
| `correction` | `cards/corrections/` | 底本错译、笔误、漏译的订正 | 122 |
| `example` | `cards/examples/` | 可算例子、验证 | 68 |
| `statement` | `cards/statements/` | 自然语言 ↔ Lean 陈述对齐 | 43 |
| `remark` | `cards/remarks/` | 口径声明、旁注 | 22 |
| `conjecture` | `cards/conjectures/` | 猜想（含证明状态未定） | 1 |

> 新增 `type` 必须同时改本表、`tools/card_spec_check.py` 的枚举和 `11_card_audit/WORKFLOW.md`，三处缺一不可。

### 1.2 命名与 id

- 文件名：小写 kebab-case，`<slug>.json`，与 `id` 末段一致；同一集内不得重名。
- `id`：`<set>/<type 短名>/<slug>`，其中 `set` 必须等于 `datasets/` 下的目录名。短名约定：
  `concept`→`concept`，`derivation`→`deriv`，`correction`→`correction`，`example`→`example`，`statement`→（`leanstmt` 用 `gno1977-*` 形式，见该集 README），`remark`→`remark`，`conjecture`→`conjecture`。
- `related` 里引用别的卡必须写**完整 id**；不得只写 slug。
- 一卡一文件；不合并、不拆成 `part1/part2`。

## 2. 通用字段（所有 type 必填）

| 字段 | 类型 | 必填 | 规则 |
|---|---|---|---|
| `id` | string | ✅ | 见 §1.2；必须与路径推导出的 id 一致 |
| `type` | string | ✅ | §1.1 的七个值之一 |
| `track` | string | ✅ | 集内轨道：`A`–`H`/`O` 或 `§N.M`；与集 README 的轨道表一致 |
| `title` | string | ✅ | 中文短标题；不带句号；不把整个定义抄进来 |
| `summary` | string | ✅ | 1–3 句；说清“是什么 + 为什么重要”；不含未在正文出现的断言 |
| `question` | string | ✅ | 这张卡回答的具体问题；能独立读懂，不指代“上一节” |
| `sources` | array | ✅ | 见 §6；至少 1 条 |
| `related` | array[string] | ✅ | 0–8 条；每条是**存在**的卡 id；不写反向也成立的重复项 |
| `rights` | string | ✅ | 现行统一 `rewritten`；其他值须按 `COMPLIANCE.md` §4 审批 |
| `status` | string | ✅ | `draft` / `dev` / `reviewed` / `published`；语义见 §7 |
| `aliases` | array[string] | 推荐 | 英文名、原文编号、常见别译；不超过 8 条 |
| `provenance_note` | string | 推荐 | 一句话说明本卡相对底本的加工（重写/合并/补注/纠错），便于追责 |

**禁止**：顶层出现未登记的自定义键（如需扩展，先在本规范登记，再写进 lint）。

## 3. 分 type 必填内容

### 3.1 `concept`（主力）

| 字段 | 必填 | 规则 |
|---|---|---|
| `definition` | ✅ | `{ "text": string, "notation": string }`；`text` 是定义正文，`notation` 是本卡引入/沿用的记号表（可为空串） |
| `key_points` | ✅ | ≥3 条；每条**可独立核验**；不重复 summary；不用“显然”“众所周知”收尾 |
| `formulas` | 推荐 | ≥0 条；每条是独立可编译的 TeX 行内/行间公式；与 `definition.notation` 用同一套符号 |
| `theorems` | 按需 | 见 §5.2；每条必须有 `name`、`statement`、`proof`、`source` |
| `pitfalls` | 推荐 | ≥1 条；写**真实**易错点（底本歧义、常见误读、条件遗漏），不写“注意仔细”这类空话 |

### 3.2 `derivation`

必填：`goal`（要证/要算什么，自足）、`setup`（出发点与记号）、`steps`（`[{no,text,why?}]`，≥2 步）、`result`（结论，与 goal 对得上）、`gaps`（缺口清单；无缺口写空数组并在 `summary` 说明“完整”）。
每步 `text` 是“做了什么”，`why` 是“为什么可以这样做”（引理名/条件）；不得只写公式不写理由。

### 3.3 `correction`

必填：`location`（`§N.M` + 源码行号或 PDF 页）、`original`（底本原文，逐字）、`corrected`（改后文字，逐字）、`why`（错在哪：漏词/量词/符号/归属）、`note`（影响面：是否影响下游定理）。
`original` / `corrected` 必须能直接 grep 到底本或译文；不得只写“意思不对”。

### 3.4 `example`

必填：`setup`（参数、范围）、`computation`（可复算的步骤，≥2 步或一条完整等式链）、`result`（数值/结论）、`check`（如何独立验证：代入、极限、维数、已知特例）。
配套 `concept_refs`（被例示的卡 id，≥1）。

### 3.5 `statement`（自然语言 ↔ Lean）

必填：`source`（`{paper, arxiv, section, pages, anchor}`）、`natural_language`（`{zh, en}`，两语言都写）、`lean`（`{file, name, statement}`）、`dependencies`、`hypotheses`、`scope`、`backtranslation`。
`lean.statement` 必须是能通过 `lake build` 的完整陈述（含 binder 与类型）；`backtranslation` 必须与 `natural_language.zh` 逐句对应，不得偷换量词。

### 3.6 `remark`

必填：`statement`（这条注到底声明什么）、`why`（为什么值得单列：口径、反例、历史注记）。
不把 remark 写成“作者说……”的转述；有出处就进 `sources`。

### 3.7 `conjecture`

结构同 `concept`，但 `theorems[].proof.status` 必须是 `none` 或 `cited`，且 `summary` 首句必须出现“猜想/预期/尚未证明”之一；**禁止**把猜想写成已证定理。

## 4. 内容质量规则

### 4.1 定义（definition）

1. **量词与作用域前置**：先写“设……固定……”，再写定义；“存在”“任意”“唯一”不得省。
2. **等价 vs 单向**：`≃`/`≅` 与 `↪`/`↠` 分清；只说“同构”时要能指出逆映射在哪。
3. **不循环**：定义 A 不得用 A 自身或同义改写解释。
4. **适用范围写清**：底域、系数域、特征、曲线亏格、群是否约化/单连通，缺一不可（例：几何 Langlands 的系数域是 $e$，底域是 $k$，两者不可混）。
5. **记号只在本卡内自洽还不够**：与同集 `notation` 约定一致；冲突时以集 README/术语表为准。

### 4.2 定理（theorems）

```json
{"name": "定理 2.4.1", "statement": "……", "proof": {"status": "sketch", "steps": ["……"], "gap_note": "……"}, "source": "定理 2.4.1 / 原书 p.13"}
```

- **层级必须与底本一致**：定理/命题/引理/推论/断言/猜想不得升格或降格；底本未编号就写“讲义未编号”，不得自造编号。
- **条件齐全**：不可约/几何不可约、rank 条件、$k<n$ 之类的界，逐条对照原文；改写等价条件（如 `rank(E)>k` ↔ `k<n`）时不得把“改写”说成“取消条件”。
- **方向正确**：$A\Rightarrow B$ 不得写成 $B\Rightarrow A$；逆命题单独标“逆”。
- **证明状态**只有四种 canonical 值：
  - `complete`：步骤闭合、无外部引用缺口；
  - `sketch`：有主线但省略细节——**必须**有非空 `gap_note`，写清“省略了什么、在哪篇文献”；
  - `cited`：本卡不复述证明，只给引用（`source` 必须能定位到证明所在页/篇）；
  - `none`：无证明（定义、猜想、未证断言）。
  旧值 `gap`/`full`/`sketched`/`略证` 视为 legacy，返工时改成上述四值之一。
- `theorems[].source` 至少给“编号 + 页码”；证明在别页时写“陈述 p.X；证明 p.X–Y”。

### 4.3 公式与记号

1. 所有 `$…$` / `\[…\]` 必须编译通过；花括号、`\left/\right`、上下标配对。
2. 一个符号一个意思；同一集内不重复定义（`\check G` 与 `{}^L G` 不得混用而不说明）。
3. **归一化写清**：半扭转、$q^{1/2}$、$(-1)$ 平移、$[d]$ 维数移动，公式里出现就注明约定。
4. `formulas` 里每条独立成立，不依赖上一条的“同上”。

### 4.4 summary / question / key_points

- `summary` 是“电梯陈述”：读者只读这一句也知道卡在说什么；不得出现“本卡介绍……”这类空话。
- `question` 必须是一个**真问题**（能回答“为什么/是否/如何”），不是标题的重复。
- `key_points` 每条一个事实；不与 `summary` 逐字重复；不写“详见正文”。

### 4.5 pitfalls

只写**有依据**的坑：
- 底本明确提醒的（引页码/节号）；
- 审计/校订中实际抓到的误读（写“常见误读：……”）；
- 条件遗漏、记号冲突、归一化差异。
禁止编造“读者可能……”的泛泛提醒。

### 4.6 related

- 只连**语义相关**的卡：前置、对偶、特例、同定理的另一种形式。
- 每条 id 必须存在（lint 会查）；不连“同集随机卡”。
- 不要求对称：A 连 B 不代表 B 必须连 A。

## 5. 出处规范（sources）

### 5.1 canonical schema（新卡必须用）

```json
{
  "book": "Lin, Geometric Langlands (2025-08-08 修订版)",
  "section": "§2.4 仿射 Grassmann 簇与局部模型",
  "pages": [13, 14],
  "pdf_pages": [13, 14],
  "quote": "……逐字原文……",
  "anchor": "源码/chapters/ch02.tex:84-86（定理 2.4.1）；定义与扭曲积见 76-98 行"
}
```

| 字段 | 必填 | 规则 |
|---|---|---|
| `section` | ✅ | 精确到小节（`§N.M`）；无小节号时写章节标题 |
| `pages` | ✅ | **印刷页**列表，整数；覆盖本卡**自己的**定义/陈述（证明别页写进 `theorems[].source`）；不写区间字符串 |
| `pdf_pages` | 有偏移时 | PDF 页列表；与 `pages` 不同才写（当前多数集偏移 0，可省略） |
| `quote` | 推荐 | **逐字**原文（英文底本给英文；中文底本给中文）；转述不得放引号；跨行用 `……` 标省略 |
| `anchor` | ✅ | 可机械解析的定位：`源码/chapters/chNN.tex:L1-L2（说明）` 或 `§N.M；nLab "词条"（Last revised …）`；不得写“见原书” |
| `book` | 推荐 | 底本完整标识：作者、标题、版本/日期；同一集内写法统一 |

### 5.2 页码规则（血泪教训）

1. **页覆盖的是“卡自己的内容”，不是“相关背景”**：定义在 p.13、其后的构造在 p.14，`pages` 必须含 14；只有背景句在 p.14 时不必补。
2. **`\srcpage{N}` 会漂移**：标记常在段落/公式中间，甚至迟一页（ch14 §14.5）、缺页（ch11 缺 p.60、ch12 缺 p.64）、章首无标记（ch10、ch14、ch16）。**以 PDF 正文页眉/正文为准**，源码标记只作线索。
3. **目录页码不可信**（尤其书末几章），一律回正文核。
4. 底本自身页码错时：卡按**实际页**写，并用 `page_note` 说明“底本目录/标记误作 p.X”；不改底本、不沉默照抄。

### 5.3 证据等级与禁用来源

- **E1 一手**：原书 PDF、arXiv 原文、出版社页面、作者主页预印本 → 可作最终依据。
- **E2 权威二手**：nLab / Stacks Project / ProofWiki（须与 E1 交叉）、标准教材 → 只作强佐证，不单独定案。
- **E3 卡内推导**：只能证内部矛盾，不能证外部为真。
- **E4 记忆/直觉**：不可作证据。
- **禁用**：Wikipedia、博客、知乎/问答、内容农场、模型记忆；不得编造 URL、页码、引文。
- 说明性文字（“为什么重要”）可以无引文，但**事实断言**必须有 E1/E2。

## 6. `verification` 字段（线索，不是证据）

canonical：

```json
{"status": "partial", "checked_on": "2026-11-27",
 "checks": [{"entry": "nLab: Hecke eigensheaf", "url": "https://ncatlab.org/nlab/show/Hecke+eigensheaf",
            "asserts": "……逐字摘要……", "verdict": "supports"}]}
```

- `verdict` 词表：`supports` / `partial` / `unverified` / `contradicts` / `not_applicable`。
- `asserts` 必须是**当时**读到的原文摘要；卡正文改了，`asserts` 与 `verdict` 必须同步改（陈旧 verification 是 2026-11 审计里反复出现的缺陷）。
- `verification` 永远不能当作“卡对了”的证据；审计时必须回到 E1 原文。
- Lean 类卡可额外带 `lean_version` / `mathlib_rev` / `sorry_count` / `toolchain` / `checker`，不进通用判据。

## 7. 状态与权利

| `status` | 含义 | 允许的下一步 |
|---|---|---|
| `draft` | 机器初稿，未逐条核 | 只能内部检索；不得进发布集 |
| `dev` | 人工改过，未外部核验 | 可进站内预览；不得标“已核” |
| `reviewed` | 逐条对过 E1/E2，有 checks 记录 | 可发布；后续改动须重新核受影响字段 |
| `published` | 已进入对外发布流程 | 任何修改都要走返工流程并留痕 |

- 升级只能逐级（`draft→dev→reviewed→published`）；降级随时可做，须写原因。
- `rights` 现行统一 `rewritten`；`book` 派生只进 `datasets/_internal/`，永不发布（见 `COMPLIANCE.md` §4）。

## 8. 反模式（见到就打回）

1. **出处定位漂移**：页码差一页/一节；`pages` 漏掉定义所在的下一页。
2. **适用范围遗漏**：把“几何不可约”省成“不可约”；把“有效优势权”省成“优势权”。
3. **归一化/系数错**：半扭转、$q^{1/2}$、$[d]$ 平移、$(-1)^i$ 号。
4. **逻辑方向反转**：把充分写成必要；把“更一般形式”当成“取消条件”。
5. **定理/猜想层级混淆**：未编号定理自造编号；猜想写成已证。
6. **术语替换**：人名（Casselman–Shalika）、范畴名（IndCoh vs Coh）、群（$\check G$ vs ${}^L G$）混用。
7. **内部不一致**：summary 与 definition 相反；pitfalls 与 key_points 互相拆台；verification 引旧原文。
8. **定义弱化/量词错误**：漏“唯一”“任意”“存在”。
9. **证据强度夸大**：E2 当 E1；摘要级当正文级；“我记得”当依据。
10. **引文不逐字**：把转述放进引号；把中文译文当英文原文引。
11. **related 断链**：指向不存在的 id 或只写 slug。
12. **JSON/转义损坏**：控制字符、`\b`/`\v`、反斜杠未双写、整文件重排。
13. **卡片与 md 成品不一致**：改卡不改 md（或反之）。
14. **批量重排**：借返工之名全文件重写，制造无法审的 diff。
15. **空话填充**：pitfalls 写“注意仔细”，key_points 写“详见正文”。

## 9. 质量闸门与 lint

### 9.1 提交前必跑

```bash
python tools/card_spec_check.py --all           # 全库；有 hard error 时退出码 1
python tools/card_spec_check.py --set glc       # 单集
python tools/card_spec_check.py --paths <jsonl 列表>  # 批量返工队列
python tools/card_spec_check.py --all --strict  # 新卡/返工：legacy 形态也按 hard 计
```

- **hard**（必须为 0 才能标 `reviewed`/`published`）：JSON 可解析；通用字段齐全；`type`/`status`/`rights` 枚举合法；`id` 与路径一致；`sources` 非空且每条有 `section`+`pages`（或 `statement` 卡的 `source`）；`related` 目标存在；`theorems[].proof.status=sketch` 时有 `gap_note`；无控制字符。
- **warn**（可继承，返工时清零）：缺 `provenance_note` / `aliases`；`quote` 缺失；`pages` 与 `pdf_pages` 不一致却无 `page_note`；`formulas` 花括号不平衡；单卡 > 12 KB；`status=published` 但无 md 成品。
- **legacy 容差**（默认模式）：历史卡里已知的旧形态——`proof.status` 取 `gap`/`full`/`sketched`/`略证`；`id` 用 `bzg`/`kw`/`lawrge`/`pi`/`sy29`/`sy32`/`sy38` 旧前缀；`pages` 写成「128–130」文本区间或用 `pages_zh`/`pages_en`；`theorems` 条目是字符串；`sources[].section` 为空串——报为 `legacy_*` warn，不算 hard，便于先看清「历史欠账」与「新卡违规」两类。
- **新卡与返工卡必须跑 `--strict`**：legacy 形态也按 hard 计，交付时 hard=0、legacy=0。

### 9.2 发布闸门

1. lint hard = 0；
2. 每张 `reviewed`+ 卡至少有 1 条 `verification.checks` 或审计记录（`11_card_audit/` 下可查）；
3. 卡与 md 同步（`datasets/<set>/md/**/<slug>.md` 若存在，必须含同一 `id` 且关键字段一致）；
4. `git diff --check` 干净；不整文件重排。

## 10. 批量返工 SOP（按模板重做）

> 适用：一批卡质量差、要统一重写；或规范升级后做迁移。

1. **建队列**：`python tools/card_spec_check.py --all --strict --json _meta/card_spec_report.json`，按 set/type/hard 错误数排序（`--strict` 才把 legacy 旧形态算进队列）。
2. **分级**：P0 = hard 错误（不可解析/缺字段/断链）；P1 = 数学/出处错（major+）；P2 = 规范升级（schema/词表）；P3 = 文风/补 quote。
3. **冻结范围**：一次只做一个 set（或一个 type × 一个字段），避免跨集 diff 混在一起。
4. **重写**：按 §2–§5 模板重写；保留原 `id`；`provenance_note` 写“返工：旧版问题→新版依据”。
5. **对照**：逐卡 `git diff` 只应含目标字段；用 `apply_fixes` 式字段级编辑（`old` 逐字断言），不整文件重排。
6. **回读**：`json.load` 全过；`related` 目标仍存在；md 同步。
7. **复核**：同一批由第二人/第二个智能体盲审（可复用 `11_card_audit` 的双盲流程）；只有复核 issue 的卡才再改。
8. **留痕**：`fix_log`（每卡 before/after、证据、确认链）；报告写清“返工 N 卡 / M 处、未解决项”。
9. **提交**：一个 set 一个 commit；message 写 `cards(<set>): 返工 N 卡（规范 v1.0）`；push 前跑 §9.1。
