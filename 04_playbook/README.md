## 每次必做的三件事（对应《纪律》条款）

1. **开工前 —— 先通读，后落笔**（§0 第 0 定律、§1.0）
   不许拿到文件就逐词翻译。按篇幅分级通读，产出 `工程文件/work/通读笔记.md` 与 `工程文件/work/疑点清单.tsv`；
   **疑点清单「未解」必须为 0 才准译第一句**。通读笔记与疑点清单一并交给 Lead。
2. **动笔时 —— 术语与译注必须有据**（§2.5）
   术语先冻结，再动笔；概念拿不准 → 先查本库已交付工程与 `corpus/out/terms.tsv`，
   再查社区类来源白名单（nLab / Stacks Project / ProofWiki）与 EMS / DLMF / MathWorld 交叉验证，并顺着 References 落到 A 级原始文献。
   每条解释性译注必须带 `[来源：…]`（A / B / I 级）或 `[译者按（无外部依据）]`。
   **知乎、百度百科/知道、CSDN、简书、公众号、B 站与视频课笔记、个人博客、"XX 笔记"类网站一律不看、不引、不缓存**（§2.5.9 黑名单）。
3. **交付前 —— 走清单 + 数据卫生**（§9、§2.5.9）
   逐条勾 §9 六组清单；来源黑名单命中数必须为 0；语料导出条目 100% 标来源等级。
   **许可口径以 [`LICENSE`](../LICENSE) 与 [`COMPLIANCE.md`](../COMPLIANCE.md) 为准**：自产层（元数据、术语、方法、工程文档、脚本）**CC BY 4.0**；译文层（译文、译注、语料正文、译文源码）是演绎作品，**本库不另设限制（检索、研究、教学、训练均可）、可撤下**（2026-11-20 起）。
   与本条旧表述冲突的、写着"全库统一 CC BY 4.0 / 欢迎训练商用"或"默认不用于训练"的文字一律作废。

## 新增纪律怎么加

新增一条纪律，必须同时给出「**反例 → 正例 → 检查方法**」三件，否则不许写进去（§12）。
版本记录写在《纪律》§12，同步更新本文件与 `00_学术翻译总纲.md` 的版本行。

## 论文精读线（v0.1，2026-11-14 起）

翻译线之外，论文/研讨班另有一条 G2.5：读完不只要「通读笔记」，还要交 `units.jsonl`（难点）、`inferences.jsonl`（推理边）、`chain.json`（思考链）、`claims v2`（原子断言）。判据是 `annotation/tools/check_gate.py`（units≥5、带证据 inference≥3、chain≥1、claims≥50 且锚点齐），字段与反例见 [`08_论证精读与知识网络.md`](08_论证精读与知识网络.md)。**过 G2.5 不替代 G0–G7；翻译仍按《纪律》v2.0。**
