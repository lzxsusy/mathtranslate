# 数译 · 施工文件库（playbook）

> **这个目录是全部翻译工程的硬标准库，不是参考资料。**
> 任何人（含智能体）参与任何一部书的翻译、校订、译注、复核，**每次开工前、每次接手别人的稿、每次交付前**，
> 都必须按 [`01_数学文献翻译纪律.md`](01_数学文献翻译纪律.md) **v2.0** 执行。
> 与任务书、口头指令、旧习惯冲突时，以《纪律》为准；确实要破例，必须在工程报告里写明破例理由并由 Lead 签字。
> 版次：**v2.0（2026-11-13 生效）**。旧版 v1.0 只作历史存档：`归档\00_归档说明\_历史版本\数学文献翻译纪律_v1.0_2026-10-24.md`。

## 每次必做的三件事（对应《纪律》条款）

1. **开工前 —— 先通读，后落笔**（§0 第 0 定律、§1.0）
   不许拿到文件就逐词翻译。按篇幅分级通读，产出 `工程文件/work/通读笔记.md` 与 `工程文件/work/疑点清单.tsv`；
   **疑点清单「未解」必须为 0 才准译第一句**。通读笔记与疑点清单一并交给 Lead。
2. **动笔时 —— 术语与译注必须有据**（§2.5）
   术语先冻结，再动笔；概念拿不准 → 先查本库已交付工程与 `corpus/out/terms.tsv`，
   再查 nLab / Stacks Project / EMS / DLMF / MathWorld 交叉验证，并顺着 References 落到 A 级原始文献。
   每条解释性译注必须带 `[来源：…]`（A / B / I 级）或 `[译者按（无外部依据）]`。
   **知乎、百度百科/知道、CSDN、简书、公众号、B 站与视频课笔记、个人博客、"XX 笔记"类网站一律不看、不引、不缓存**（§2.5.9 黑名单）。
3. **交付前 —— 走清单 + 数据卫生**（§9、§2.5.9）
   逐条勾 §9 六组清单；来源黑名单命中数必须为 0；语料导出条目 100% 标来源等级；
   **本项目语料默认不用于训练**，任何要拿去训练的批次须先整库审计并由 Lead 书面批准。

## 新增纪律怎么加

新增一条纪律，必须同时给出「**反例 → 正例 → 检查方法**」三件，否则不许写进去（§12）。
版本记录写在《纪律》§12，同步更新本文件与 `00_学术翻译总纲.md` 的版本行。
