## 0. 结论先行

**赞成做页面层，但要把“页面”定义成非权威层。** 三条边界先立住，否则会造出比现在更危险的东西：

1. **页面不生产数学断言。** 页面只负责选材、动机、阅读顺序、依赖图；定义与定理一律从词条**转引**（transclusion），不手抄。手写页面是“看上去最像知识、实际最不可核”的一层，必须用机械规则堵死。
2. **不是推翻卡片，是给卡片换命名空间。** 现有 1,887 张卡里的事实与引文是资产；问题在 `id = <文献集>/<type>/<slug>` 把知识钉死在文献上。做法是“卡片降为证据、词条升为知识单元”，旧 id 全部进 alias 表，零破坏迁移。
3. **先做 1 个主题页 + 1 篇文章页跑通闸门，再谈批量。** 不要一上来建 88 个页面——页面一多，没人复审，就会退化成又一份“看起来对”的语料。

一句话形态：**L0 证据（逐字引文）→ L1 词条（概念级、全局 id）→ L2 页面（nLab 式导航与叙事，只转引）→ L3 导出（静态站 / 训练 JSONL / 依赖图）**。

## 1. 现在的问题：不是“卡不够多”，是“卡的组织轴错了”

### 1.1 命名空间绑死文献，跨文献链接在机制上不可能

`tools/card_spec_check.py` 的 `related_broken` 检查要求 related 目标**在本批 ids 内**；而 id 必须以集名开头（`sy0246/concept/...`）。于是：

- 同一个“Hecke 特征层”在 `sy0246`、`glc`、`gaits04`、`bdh` 各有一张卡，互相不能 `related`；
- 想引用别的集，只能复制一份定义——复制就会漂移；
- 文献一多，“同一概念 N 份正文”是必然结果，不是偶然失误。

这是结构问题，靠审校抓不住：审校只能保证“每张卡自洽”，保证不了“同一概念在全库一致”。

### 1.2 已经有词条层，但它和卡集互不相通

- `datasets/encyclopedia/` 已有 **88 条**概念词条（`geometry/geometric-langlands`、`geometry/bun-n`、`algebra/hecke-operator`、`algebra/langlands-correspondence` …），schema 是“定义 + 定理 + 例子 + 坑 + related + sources”，正是词条层该有的样子；
- 但它的 `sources` 只有 `{book, section, pages}`，**没有逐字引文、没有锚点、没有 verification**——按 playbook 23 的证据标准，它目前是“B 级线索”，不是“可核证据”；
- 卡集有逐字引文与锚点，却没有全局 id；两边各说各话。

### 1.3 没有“阅读单位”，训练语料是碎片

14 张卡按 `§0–§7` 排是论证线，按 id 排是字母表。模型拿到的是“定义、定理、引理”互不连接的片段；人拿到的是目录而不是导论。nLab 的价值不在词条多，而在**页面把词条串成一条可读的路**。

### 1.4 主题轴已经存在，但是坏的

卡片的 `track` 字段本可以当主题轴，实际是混用的：`A/B/C/D…`（383/275/264…）与 `几何 Langlands`（14）、`W08`（14）并存。没有任何一张表规定“哪些 track 合法、父子关系是什么”。

## 2. 目标结构

```
L0 证据 evidence ── 逐字引文 + 印刷页 + PDF 页 + TeX 行/译稿行 + 外部 URL + 等级(A/B/I)
        ▲
        │ 被引用（每条断言至少一条 evidence，或标明“卡内推导 E3”）
L1 词条 entries ── 全局 id（category/slug），一个概念/定理/构造一条
        │           定义、claims[]（带稳定锚点）、variants[]、examples、pitfalls、links[]
        │ 被转引（不复制正文）
L2 页面 pages ──── 主题页（nLab 式）+ 文章页（综述篮子）
        │           导言、依赖图、阅读顺序、开放问题；数学内容一律 {{transclude}}
L3 导出 exports ── 静态站、训练 JSONL（page, entry, claim, evidence 四元组）、依赖图
```

**文章页 vs 主题页**（两者都要，但职责不同）：

| | 文章页（article page） | 主题页（topic page） |
|---|---|---|
| 回答 | 这篇文献讲了什么？依赖谁？能拆出哪些词条？ | 这个概念是什么？到主定理要经过哪几步？ |
| 骨架 | 书目 → 一句话贡献 → 依赖图 → 逐节导读（每节挂词条） → 可拆条清单 | 导言 → 定义（转引） → 主结果（转引） → 证明路线 → 例子/坑 → 相关页 |
| 例 | “Laumon 906 导读”“Scholze 1252 导读” | “几何 Langlands 对应”“Hecke 算子与 Hecke 特征层” |
| 数量 | 一文献一页，随译注工程增长 | 一主题一页，长期稳定，可吸收多篇文献 |

用户说的“先用一篇文章做篮子”= 文章页；“nLab 那样的页面”= 主题页。两者用同一套 schema，只是模板不同。

## 3. 页面规范（这是防错的关键）

### 3.1 front-matter

```yaml
---
id: page/geometric-langlands
title: 几何 Langlands 对应
aliases: [Drinfeld–Langlands 对应, 几何 Langlands 纲领]
kind: topic            # topic | article
status: reviewed       # stub | draft | reviewed | published | stale
reviewed_by: [lead, reviewer-b]
reviewed_on: 2026-12-05
entries: [geometry/geometric-langlands, geometry/hecke-eigensheaf, geometry/bun-n, ...]
parents: [page/langlands-program]
order: 20
compiled_from:         # 生成时写入，用于检测词条漂移
  geometry/geometric-langlands: sha256:ab12…
  geometry/hecke-eigensheaf: sha256:cd34…
---
```

### 3.2 正文三条硬规矩

1. **每个含数学的段落，至少挂一个 `{{entry:…}}` 或一个引文块；否则 `kb_check` 直接 fail。**
2. **定义、定理、引理不得手抄**：写 `{{transclude:geometry/hecke-eigensheaf#def-1}}`，构建时把词条正文原样嵌入并标注来源；页面里手打的“定理 2.2 说……”一律视为未验证断言。
3. **页面自己的话只允许三类**：为什么读这一页、几条路线怎么选、去哪里看证明。作者概括单段 ≤ 2 句，且不得含新的数学内容词（“于是”“因此”开头的推理句禁用）。

### 3.3 样板（几何 Langlands 页的开头，示意）

id: page/geometric-langlands

## 4. 词条规范：在现有 encyclopedia schema 上扩展

沿用 `datasets/encyclopedia` 的 `category/slug` 与字段，新增四个：

| 新字段 | 作用 |
|---|---|
| `claims[]` | 每条可独立引用的断言：`{anchor, kind: definition/theorem/lemma, statement, proof:{status,steps,gap_note}, evidence:[…]}`；`anchor` 形如 `#thm-fgv`，页面与训练语料都引它 |
| `variants[]` | **同一概念在不同文献条件不同**时并列，不强行统一：`{source, statement, difference}` |
| `evidence[]` | 逐字引文：`{quote, book, section, pages, pdf_pages, tex_anchor, translation_anchor, url, grade}`；生成器断言 quote 能在 PDF 文本层命中 |
| `verification[]` | 沿用 playbook 23 的 `{entry,url,asserts,verdict}` |

`related` 保留为兼容层，新增 `links[]`（全局 id + 关系类型 `generalizes/specializes/uses/proved-by/contradicts`），lint 要求全解析。

**variants 的真实用例**（这次审校抓到的）：Hecke 特征层，Laumon 定义 2.1 要求 $K$ 不可约，FGV §1.1 只要求 $K\neq 0$。这不是谁错，是两套约定；正确做法是词条里并列两条，页面显式写“读哪篇时用哪套”。

**从卡片到词条的映射**：

| 卡片字段 | 词条字段 |
|---|---|
| `id` (`sy0246/concept/x`) | alias → 新 id `geometry/x`（或 `algebra/x`） |
| `definition.text` | `definition.text`（+ `claims[#def-1]`） |
| `theorems[]` | `claims[kind=theorem]`，`source` 并入 `evidence[]` |
| `sources[].quote/pages/anchor` | `evidence[]`（一条一条保留，不合并） |
| `verification.checks` | `verification[]` |
| `related` | `links[]`（先机械改前缀，再人工定关系类型） |
| `pitfalls` / `examples` | 原样 |

## 5. 链接、别名、去重

1. **全局 id** = `category/slug`（沿用 encyclopedia），全库唯一，不再含文献名。
2. **redirects.tsv**：`旧 id → 新 id`，迁移脚本自动写；`kb_check` 允许旧 id 解析（给 warning 不给 error），保证旧文章、旧 JSONL、外部引用不断。
3. **合并规则三条**：
   - 同概念 + 同定义 + 不同出处 → **合并**为一条，evidence 累加；
   - 同概念 + 条件/约定不同 → **不合并**，写 `variants[]`，页面并列；
   - 名字像但层级不同（“Hecke 算子” vs “Hecke 特征层”；“对应” vs “定理”） → **拆**，用 `links[generalizes]` 连接。
4. 冲突登记沿用 `_meta/冲突台账.tsv`，词条级新增 `conflicts[]` 指向台账行号。

## 6. 质量闸门（针对“看上去对、实际错”）

### 6.1 六条机械检查（`tools/kb_check.py`，CI 必过）

| # | 检查 | 失败等级 |
|---|---|---|
| K1 | 所有 `{{entry:…}}`、`links[]`、`related`、redirect 可解析 | error |
| K2 | 每个数学段落 ≥1 链接或引文块（页面层） | error |
| K3 | 引文逐字：`evidence.quote` 在 PDF 文本层与 TeX 源码双源命中（允许 `…` 省略） | error |
| K4 | 页码一致：`pages == pdf_pages`，否则必须有 `page_note` | error |
| K5 | `compiled_from` 的 hash 与当前词条一致，否则页面标 `stale` 并拒绝发布 | error |
| K6 | 层级、`proof.status`、`gap_note` 合法（沿用 playbook 23 §4.2） | error |

### 6.2 两条人工检查

- **词条**：作者 + 盲审（审校者不看作者意图，只看“陈述—引文—页码”是否对得上）；critical 问题必须第三方仲裁。
- **页面**：编辑（结构/可读性）+ 事实审（逐段问“这句的根据在哪”，答不出就删或转引）。

### 6.3 发布指标（每季度复算）

- 页面断言挂链率 **100%**（K2 的逆向统计）
- 断链 **0**、孤儿页面 **0**、`stale` **0**
- 词条 E1（一手）覆盖率 ≥ 80%；E2 交叉率 100%
- `reviewed` 及以上占词条总数 ≥ 60%（达不到就冻结新增，先复审）

**这条“达不到就冻结”是从 `04_playbook/25` 的教训直接搬来的**：当前 1,887 张卡里 `draft` 占 45%，继续铺量只会稀释。

## 7. 迁移路径（每阶段都可独立交付）

### P0 · 样板周（约 3–5 个 agent 轮次）
- 定稿 `schema/{entry,page,evidence}.schema.json`；
- 把 `sy0246` 14 张卡迁成词条（预计 10 条新词条 + 4 条并入 encyclopedia 已有条目），写 `redirects.tsv`；
- 建两页：`page/geometric-langlands`（主题）与 `page/laumon-906`（文章），全部转引、零手写定理；
- `kb_check` 通过 + 一次盲审。

**验收**：页面里手打公式数 = 0；K1–K6 全绿；两页可独立阅读。

### P1 · 工具链（约 1–2 周）
- `kb_check.py`（六查）、`kb_build.py`（Markdown → 静态 HTML，带 hover 预览与反向链接）、`kb_graph.py`（依赖图/环/孤儿）、`kb_export.py`（训练 JSONL：`{page_id, entry_id, claim_anchor, statement, evidence, status}`）；
- 把 encyclopedia 88 条接上 `evidence[]` 与 `pages`（先补 20 条高价值条目的逐字引文）；
- 静态站雏形（本地构建，发布后置；canonical/Pages 的坑见 `04_playbook/25` §0.7）。

### P2 · 主题合并（约 3–4 周）
- 目标：词条 120–160、页面 12–18；
- 合并对象：`sy0246`（Laumon 906）、`SY02-45`（Scholze 1252）、`benzvi_glc`、`glc`、`gaits04`、`bdh` 的 Langlands 相关卡；
- 处理已知 variants（Hecke 特征层的不可约性、GL(1) 的“proper”两义、FGV 定理 vs 猜想的口径）；
- 全库 lint + 一次跨集盲审。

### P3 · 规模化
- 51 个卡集按主题分批迁；**旧集冻结只读**，新内容只进词条层；
- 导出给 `dsh-kb` 插件（当前快照 2,938 卡）走 JSONL，不直接读仓库。

## 10. 风险与取舍

| 风险 | 处理 |
|---|---|
| 页面变成“第二真相源” | 转引 + K2 检查；页面手打定理一律 fail |
| 过度合并，抹掉文献差异 | `variants[]` 显式并列；合并只在“同定义”时做 |
| 迁移工作量爆炸 | 只迁高价值主题；旧卡集冻结不改，靠 redirect 兼容 |
| 页面数量上升但无人复审 | 每页 `reviewed_by` + 季度指标；未复审页面不进静态站索引 |
| 静态站维护成本 | P1 只在本地构建；发布等 P3 且先修 canonical/Pages |
| nLab 缓存被误当证据 | 明确 E2 定位；`evidence[].grade` 只允许 A/B/I，不允许“nLab” |
| 与 `dsh-kb` 快照不同步 | `kb_export.py` 产出 JSONL 作为唯一接口，插件只读导出物 |
| 版权 | 页面是原创综述；引文单处 ≤60 字、带出处；不整段翻译原文 |
