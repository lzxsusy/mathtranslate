# 15 · 形式化与自然语言对齐路线（2026-11）

> 定位：不是“再译一部书”，而是把已有的译注/资料卡/校对判断变成**可被编译器判对错**的数据。
> 上游：`11_资源受限路线_v1.md`、`08_论证精读与知识网络.md`、`09_thinking/README.md`。
> 结论先行：**在国产算力占比少的前提下，我们买不起“更多偏好标注”，但买得起“更多可验证样本”。形式化是唯一能自动生成正/负标签的数学环境。**

## 1. 为什么是现在

三个事实同时成立：

1. **成本结构已经证明“写”比“读”贵**：本期输出 token 占 45.6%（¥1,112.56 / ¥2,437.38）。靠人写更多译文，边际成本不会降。
2. **已有资产的瓶颈是“不可验证”**：119 部、49,322 段语料、1,095 张资料卡，但真正过编译器、`sorry` 为 0 的陈述只有 21 条；402 条轨迹只有动作，没有推理。
3. **形式化刚起步、但骨架已立**：`datasets/leanstmt/` 现为 39 条陈述（21 certified + 18 gap），6 个 `.lean`，22 处 `sorry` 全部记账；toolchain `leanprover/lean4:v4.36.0`、mathlib `d33c49ca`。量还小，正适合按正确 schema 扩。

**目标不是“把整本书形式化”**，而是建立一条流水线：

```
NL 原文/译文 → 抽取定理与定义 → Lean 陈述 → 证明或缺口 → Mathlib 依赖 → 可验证样本
```

每一环都留下 `(自然语言, 形式陈述, 证据, 判定)` 四元组。编译器给出 0/1，人只审“陈述是否忠实”。

## 2. 对齐的四层对象

| 层 | 内容 | 例子 | 判定者 |
|---|---|---|---|
| **L1 术语对齐** | 英/中术语 ↔ Lean 常量 | `univalence` ↔ `IsUnivalent` | 术语表 + 人 |
| **L2 陈述对齐** | 自然语言命题 ↔ Lean `Prop` | “紧黎曼面上的全纯向量丛可分裂” ↔ `∃ ...` | 人 + 类型检查 |
| **L3 证明对齐** | 证明步骤 ↔ tactic 脚本/缺口 | 原文证明第 3 步 ↔ `exact ...` | 编译器 |
| **L4 反例对齐** | 错误断言 ↔ `¬` 命题/反例 | 资料卡 14 条 ✗ ↔ Lean 反例 | 编译器 + 人 |

L2 是主战场：它决定“模型能否把一句数学话变成可检查的对象”。L4 是最高价值：**一个被推翻的断言 = 一条负样本 + 一个反例证明**。

## 3. 数据 schema（先定，再写）

> **2026-11-21 更新**：本节最初设想的 `formal/align/statements.jsonl` 已被
> `datasets/leanstmt/cards/statements/<track>-<s|g><NN>.json` 取代——一条陈述一个卡，
> 带 `natural_language{zh,en}` / `lean{file,name,statement,imports}` / `backtranslation` /
> `verification{status,toolchain,mathlib_rev,sorry_count}` / `gaps[]` 全套字段，
> 由 `index.jsonl` 汇总。**字段表、字段含义与验收闸门以
> [`01_corpus_zh/数语规范/STYLE_FORMAL.md`](../01_corpus_zh/数语规范/STYLE_FORMAL.md) §2、§7 为准**。
> 下面保留 v0 schema 作为设计理由的记录（硬约束仍然有效，只是字段名按新 schema 落地）。

文件（v0 设想）：`formal/align/statements.jsonl`（一行一条，UTF-8，禁止嵌套大对象）

```json
{
  "id": "SY01-26:p112:thm:3.4",
  "volume": "SY01-26",
  "page": 112,
  "section": "3.2",
  "nl_en": "Let E be a holomorphic vector bundle on a compact Riemann surface...",
  "nl_zh": "设 E 是紧黎曼面上的全纯向量丛……",
  "lean_file": "Formal/SY01_26/Ch03.lean",
  "lean_decl": "holomorphic_bundle_splits",
  "lean_statement": "theorem holomorphic_bundle_splits ... : ... := by",
  "hypotheses": ["CompactSpace X", "IsManifold ..."],
  "proof_status": "proved",
  "mathlib_deps": ["ComplexManifold", "VectorBundle"],
  "checker": "lean4 v4.x + mathlib commit",
  "verified_at": "2026-11-20T14:00:00+08:00",
  "reviewer": "李泽轩",
  "notes": "原文未说明有限维；已补 Finiteness 假设"
}
```

硬约束：

- `proof_status` 只能是 `proved / gap / axiom / counterexample`；`gap` 必须写 `sorry` 位置与缺口类型（缺定义/缺引理/缺假设）。
- `lean_statement` 必须能单独通过 `#check`；不允许把整段证明塞进字符串。
- `hypotheses` 必须显式列出原文没有、但 Lean 需要的假设（这是“翻译损失”的主要来源）。
- `mathlib_deps` 只记顶层命名空间，避免版本漂移导致全表失效。
- 每条必须有 `reviewer`；机器生成的候选标 `reviewer: pending`，不得计入覆盖。

## 4. 课程（T1–T4）

| 阶段 | 任务 | 输入 | 输出 | 目标量（2026 全年） |
|---|---|---|---|---|
| **T1 陈述翻译** | NL 命题 → Lean `Prop`（可含 `sorry`） | 已核验资料卡/定理段 | `lean_statement` | 600 条 |
| **T2 缺口修补** | 给 `sorry` 的陈述补证明或补假设 | T1 输出 + Mathlib 检索 | `proof_status: proved/gap` | 250 条 |
| **T3 整证明** | 从陈述到完整 tactic 证明 | 教材定理 | 完整 `.lean` | 100 条 |
| **T4 反例/修正** | 错误断言 → `¬` 命题/反例 | 资料卡 14 条 ✗、校对 issues | `counterexample` | 50 条 |
| 合计 | | | | **1,000 条** |

**季度目标只有一个：certified 从 21 条做到 100 条**（`gap` 卡不计入）。做法是先做 **SY01-26（复几何/向量丛）** 与 **SY07-08（同调代数/HMS）** 各 20 条样板，验证 schema 与工时，再扩到 100；T1–T4 的 1,000 条是全年批次的上限，不是季度指标。2026 全年再看能否到 10,000 条。

**为什么从这两部开始**：SY01-26 已有 24 张核验卡 + 403 页校订版 + 153 个单元 JSON，术语最稳定；SY07-08 有 209 页、术语统一记录、结构清晰。不要从最难的 Langlands 主定理开始。

## 5. 训练用法（算力少时的优先级）

1. **拒绝采样 + 编译器过滤**：让模型生成 Lean 陈述/证明，只保留 `lake build` 通过的；这是零人工标签的正样本。
2. **错误信息做负样本**：编译错误类型（unknown identifier / type mismatch / unsolved goals）是天然的分类标签，可训练“定位错误”的小模型。
3. **课程学习**：T1 → T2 → T3；先用 1,000 条对齐数据做 SFT，再用编译器 reward 做 RL（GRPO 类），reward = 通过与否 + 证明长度惩罚 + 依赖合理性。
4. **检索增强**：Mathlib 声明检索（`exact?`/`apply?`/`loogle`）作为工具，不把 7.3GB 依赖塞进上下文。
5. **蒸馏**：用强模型生成候选，编译器过滤后蒸馏到小模型；这比人工标注便宜两个数量级。
6. **不做什么**：不做大规模人类偏好标注；不训练“数学聊天”；不用 LLM 当裁判替代编译器。

## 6.5 资料卡 → 对齐卡：陈述从哪里来（2026-11-21 新增）

对齐卡不能从译文里随手摘句子——那样抽出来的是「一段话」，不是「一条命题」。陈述必须从**已经过人工条款化**的资产里抽：

| 来源 | 位置 | 为什么合适 | 现在的量 |
|---|---|---|---|
| 工程内资料卡 | `08_source_code/<编号>/资料卡/01-结果清单.md`、`03-条款索引.md` | 每条已带定理/定义编号、陈述要点、前提、原文页码与译本页码；`01` 是命题表，`03` 是定义表，天然对应 L2 的「命题」与「定义」两类 | 8 个工程有五件套（速览/结果清单/论证地图/条款索引/术语勘误） |
| 数据集卡片 | `datasets/<集>/cards/**/*.json` | 已过 `ds_lint` 与人工复核，`status=reviewed/published` 的断言可直接进 L2/L4 | 21 集 1,095 张（reviewed 265 / published 66） |

**抽取流程（一步不能省）**：

1. 从资料卡 `01`/`03` 取一行 → 记录 `源工程 / 条款编号 / 页码 / 前提列表`。
2. 把自然语言命题改写成**自足命题**：量词与前提显式化（「设 $X$ 是紧黎曼面」不能丢），复合陈述拆成多条。
3. 写对齐卡 `natural_language{zh,en}`：`zh` 用译文原句（不重译），`en` 用原文句（没有原文就留空并在 `notes` 说明）。
4. 写 `lean{statement}`，先过 `#check`；依赖能定位的写进 `dependencies`，定位不到就是 G1（缺定义）。
5. `lake build`；`sorry` 逐条记进 `gaps`，`verification.sorry_count` 必须与实际一致。
6. 盲翻回译（`backtranslation`）：只看 Lean 陈述、不看中文，回译成中文，与第 3 步比对；不一致 → G4（陈述歧义）。
7. 更新 `datasets/leanstmt/index.jsonl`，跑验收闸门（STYLE_FORMAL §7 的 8 项）。

**这一层的产能指标不是「条数」，是 `certified` 条数**——`gap` 卡是负债表，不是成绩单。
2026-Q1 的目标因此定为 **100 条 certified**（现有 21 条），而不是 1,000 条草稿。

## 7. 质量闸门

- **G1 陈述忠实**：两位审阅者独立判断“Lean 陈述是否等价于 NL 命题”；不一致则标 `disputed`，不进训练。
- **G2 可编译**：`lake build` 0 error；`sorry` 必须显式计数，`proof_status=proved` 不允许残留 `sorry`。
- **G3 假设透明**：`hypotheses` 必须列出原文没有的假设；隐藏假设视为不忠实。
- **G4 反例可复现**：`counterexample` 必须是可编译的 `theorem ... : ¬ P`，不能只写“有反例”。
- **G5 链覆盖**：每 20 条对齐至少 1 条批准链；`09_thinking/check` 通过。

## 8. 风险与对策

| 风险 | 表现 | 对策 |
|---|---|---|
| 陈述漂移 | 把“紧”悄悄换成“有限” | G3 强制列假设；两审 |
| `sorry` 膨胀 | 90% 标 gap 却算“完成” | 统计 `proved/gap` 比例，gap 不计入 KPI |
| 版本漂移 | Mathlib 升级后全表失效 | 记录 commit；每季度重编译，失效条目降级 |
| 只做简单题 | 全是 `simp` 能关的引理 | 按“依赖深度/证明长度”分层抽样，难例单列 |
| 形式化与译文脱节 | Lean 陈述与书中定理无关 | schema 强制 `volume/page/section`，抽检 10% |
| 算力误判 | 以为需要大集群 | 先单机 1 张卡 + Lean REPL；1,000 条不需要训练大模型 |

## 10. 一句话

**页数是库存，对齐才是产能。** 在算力受限的条件下，最划算的投资不是再买卡，而是把每一句已经译好的数学话，变成编译器能判对错的一条记录。
