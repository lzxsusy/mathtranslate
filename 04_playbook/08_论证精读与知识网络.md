# 08 · 论证精读与知识网络（G2.5）

> 版次 v0.1（2026-11-14）｜ 适用：所有翻译工程 + 研讨班 + 论文精读
> 定位：在《纪律》v2.0 的「先通读、后落笔」之上，加一层**可机器检查的精读产物**；不替代 G0–G7，只新增 G2.5。
> 方案全文：`annotation/00_方案总览.md`；字段规范：`annotation/02_精读标注规范.md`；概念图：`annotation/03_知识节点网络方案.md`。

## 0. 一句话

读完一篇论文，除了「通读笔记」，还要交出三样东西：**难点单元（unit）**、**推理边（inference）**、**一条思考链（chain）**；三者都有锚点、都能被脚本校验；积累后由 `claims` + `concept` 汇成以知识节点为载体的网络。

## 1. 什么时候做

```
立项 → 通读（G0）→ 术语冻结（G2）→ 【G2.5 精读标注】→ 分块翻译 → ... → G7 交付
```

- **G0 仍然只管翻译**：通读笔记 + 疑点清单未解 = 0，才准开译。
- **G2.5 管「精读交付物」**：新增 unit/inference/chain/claims；不过不影响开译，但**不交付**精读成果。
- 研讨班：把 G2.5 放在 S2（问题史）之后、S3（主论证）之前，作为 claims 的下限检查。
- 论文（非书）同样适用；只是没有逐章翻译，直接产出标注包。

## 2. 三样交付物

| 产物 | 文件 | 最小要求 |
|---|---|---|
| 难点单元 | `annotation/examples/units.jsonl` 或工程内 `work/units.jsonl` | 单篇 ≥ 5 条；每条有 locator + difficulty + review |
| 推理边 | 同上目录 `inferences.jsonl` | ≥ 3 条；每条有 premises/conclusion/warrant/evidence.quote |
| 思考链 | `chain.json` | ≥ 1 条；问题状态 → move → 步骤 → 收口 → 反事实 |
| 原子断言 | `claims/<paper>_claims_v2.jsonl` | 锚点 100%；新增 premises/mode/warrant/role |

字段定义与反例见 `annotation/02_精读标注规范.md`；数据模型见 `annotation/schemas/`。

### 2.1 什么算「难点/不平凡」
不要问 LLM「这一步难吗」，用四个可观察信号：
1. **obligation 缺口**：把结论挖掉，让模型补全，连续 k=5–8 次失败 → 高难度候选；
2. **jump**：原文用 `One can show / It is easy to see / similarly` 带过，且缺至少一条前提；
3. **load-bearing**：被 ≥ 3 个后续节点引用（图上的 in_degree / PageRank 只作线索）；
4. **notation/transfer**：换记号、换范畴、跨领域搬运，且原文没有解释。
任一命中 → 标 `role: key|gap`，并在 `difficulty.why_hard` 写一句人话；**低置信必须标黄，不许装确定**。

### 2.2 三条硬规矩
1. **无锚点不入库**：unit 必须有 `locator`（page_para / tex 行 / PDF bbox 三选一）；claim 必须有 `anchors`。
2. **无 quote 不成边**：inference 的 `evidence.quote` 必须能在原文找到；找不到就进 `questions`，不算边。
3. **难度不靠自评**：LLM 只给候选与理由；最终分由 obligation 失败率 + 人工抽检校准（κ≥0.6 才扩量）。

## 3. 与现有工作流的接法

### 3.1 通读笔记（`templates/通读笔记_模板.md`）
在「论证地图」后加一节 **`## 6. 论证地图（机器可读）`**，贴 `argument_map.yaml`：
```yaml
paper_id: SY07-08
deps:   # 谁靠谁；只写有 \ref 或明说的
  - from: prop:1.1
    to: prop:1.2
  - from: thm:2.5
    to: prop:1.5
gaps:   # 原文跳步/带过的地方，先记候选
  - where: "§2.6 proof, after (2.6.3)"
    why: "It is easy to see that ... 未说明紧性从哪来"
    severity: medium
key_steps: [prop:1.5, thm:2.7]
```
生成方式：先跑 `build_structure_index.py` 出候选边，再人工删/补；**不许直接把机器边当论证边**。

### 3.2 章节译手任务书（`templates/章节译手任务书_模板.md`）
在「本块任务」加三行：
```markdown
- 本块有 <n> 个不可平推步：<label 列表>；译文不得把它们译成「显然/易证」。
- 所有 `\begin{theorem|lemma|proposition|definition}` 必须保留原 `\label`；缺失的要补并登记。
- 原文 gap（One can show / It is easy to see 带过）在译注里标 `[难点]`，并回填疑点清单。
```

### 3.3 claims（`claims v2`）
- v1 的 73 条 WIT claims 已迁移：`annotation/claims/wit_claims_v2.jsonl`（只加字段，不改正文）。
- 新 claim 必须写 `premises`（引用了哪些 claim/unit）、`mode`（AND/OR）、`warrant`（为什么这步成立）。
- `review.status = unresolved` 的 claim 不进入阅读笔记正文，只能进 questions。

### 3.4 mt_daily（每晚 21:30）
- 先只加文档约定，不改自动链：在精选片段规范里加一类「论证精读」任务（意图 → 关键步 → 证据 → 结论），`curate` 时允许 `精选片段.md` 出现该模板。
- 等 D3 试点稳定后再改 `mt_daily.py` 的 `CURATION_NAME` / `TRAJ_DIR` 逻辑。

## 6. 发布层（先不发布，先把口径定死）

- 发：节点 ID、边、计数、自写一句话、难度标注与理由、思考链（自有版权）。
- 不发：原文整段、译文整节、页图、PDF。
- 许可：事实层 CC0；标注/笔记 CC BY 4.0；上游（nLab/Stacks/zbMATH）只存 ID + 链接。
- 页面：`/k/<kn_id>`（概念）、`/p/<paper_id>/chain`（思考链）、`/p/<paper_id>/hard`（难点清单）。
- 发布前必须过 `check_gate.py` + 版权扫描（见 `annotation/06_发布与合规.md`）。

## 7. 反例（照抄会翻车）

1. **把引理依赖图当论证图**：只有 uses 边，没有 warrant、动机、类比 → 读者还是不知道为什么难。
2. **LLM 自评难度**：同一段两次打分能差 2 级；必须 obligation 失败率 + 人工校准。
3. **过早跨书合并概念**：先单书内闭环，再谈跨书；否则 alias 一锅粥。
4. **无证据边入库**：`generalizes` / `analogous` 是幻觉重灾区；没有 quote 只能是 draft。
5. **为了覆盖率把公式/图表都建成节点**：节点爆炸、PageRank 失真；先定理/定义级。
